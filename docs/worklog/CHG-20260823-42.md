# Worklog — CHG-20260823-42

Second consecutive round where both seats returned `not sound`, and the second where the worst
finding was in a change I had described as done.

## The one that matters

A migration that silently, permanently truncated an operator's history.

I reproduced it before touching anything, because a seat's summary is not evidence:

```
legacy conversation: 7 turns, duplicate_seqs=[2]
turns imported: 3 of 7        HALF-POPULATED
second import: skipped        -> permanent
```

What makes this worse than an ordinary bug is the paper trail. `docs/DATABASE.md` §6 states the
required behaviour **in bold**, four sections above the section CHG-41 quotes when it says the
schema was implemented "exactly as designed". I read that file. I implemented from it. I wrote a
change record claiming an importer that was "lossless and reversible", and verified it against a
**clean** 306-turn fixture — the one input structurally incapable of detecting the failure.

That is the third time in this project I have tested the case that cannot fail: the `NAME_MAX`
vocabulary test, the audit's inert guard, and now this. The pattern is not carelessness about tests.
It is that I write the test from the same mental model as the code, so it exercises the path I was
already thinking about.

The counter-move that has actually worked, every time: **make the input hostile before claiming the
property**. Both seats did that; neither of my tests did.

## The lock sitting unused on the object it protects

`store.Connection` carries `runner_lock`. `_locked`'s docstring says "Every entry point takes it".
Every entry point in `store.py` does. `SqliteBackend` took it nowhere.

This is the defect class at its purest — the constraint existed, was documented, was on the very
object, and was not used — and I wrote both halves within a day of each other.

fable-seat's evidence is the part worth keeping: two writers, one connection, and **two turns
vanished with no `write_errors` entry**. Not refused. Not reported. An append that returned success
was rolled back by the other thread's transaction exit. `_guarded` exists precisely so an archival
failure cannot be silent, and it was silent, because the thing it guards was undermined from below.

## The guard that guarded nothing

CHG-40 said the audit's guard would catch "deleting a call shape from its list". fable-seat gutted
the list and both tests passed. I repeated the sabotage rather than take it on trust: same result.

The guard re-scanned the test file against **its own hardcoded tuple**. It never ran the audit. Two
copies of the same vocabulary, agreeing with each other, testing nothing.

The fix is structural rather than a better assertion: one scanner, called by the audit and by twelve
cases that each feed it a module containing exactly one write. Repeating the sabotage now fails
seven of them by name.

And widening the shape list immediately overshot — `str.replace`, `dataclasses.replace`,
`Conversation.open`, thirty false positives. The same over-broad rule from the other direction, in
the change fixing an over-broad rule. I narrowed it to what can be identified syntactically and
**wrote down what cannot be**, which is the only honest version.

## What I did not fix, and why

The server's double-walk. `_advance()` runs outside `_lock`; `attach()` gates only on version. That
is the *source* of the concurrency, and closing it belongs in `server.py` with its own thought about
what should happen to an attachment posted mid-walk — reject it, queue it, or suspend the walk.
Each is a behaviour change for an operator, not a lock.

What this change does instead is make the consequence non-destructive: serialised, refused where it
must be, and visible in `write_errors`. That is a smaller claim than "fixed", and it is the one the
code supports.

## Not claimed

**That this answer is right.** Three previous rounds in this project found the fix carried the same
defect class as the thing it fixed, and CHG-38 — itself a fix for a review — did it again in its own
regression test. This has not been reviewed.
