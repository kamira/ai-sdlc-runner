# Worklog — CHG-20260823-34, the blank-spec refusal

The first change recorded by the machinery built in CHG-20260823-33. The cast is at
`docs/recordings/chg-34.html`; this is the part it cannot show.

## Where the finding came from

Not from reading the code. From **running** `examples/tide-spa/scenarios.py`, which was written as
documentation and immediately behaved differently from what the documentation was going to say.
Scenario C — a plan with `scope`, `objective` and `expected_outputs` set to `""` on the build nodes
— completed all 24 nodes, 25 asks, four files, exit 0. Nothing refused it and nothing warned.

The cause, in `workorder.py::_check`:

```python
missing = [f for f in required if f not in supplied]
```

The presence of the *key*. `render()` then copied the blank into the order it dispatched.

This is worth naming precisely: it is the project's dominant defect class — a name standing in for a
constraint — sitting inside the work-order builder, which is the module whose whole job is to refuse
orders that are not truthful. Reading it did not find it. Running it did.

## The panel

Both seats, asked independently, returned **`refuse-blank`** and named the same split without
conferring.

**Refuse (6):** `scope`, `objective`, `instructions`, `done_criteria`, `acceptance_predicate`,
`workdir`.

**Allow blank (3):** `input_artifacts`, `expected_outputs`, `idempotence_probes`.

Both seats independently checked the repository's own plans before proposing a rule, and both
reported the same figure: `expected_outputs` is `[]` on 14 of the 15 nodes in `examples/plan.json`,
because review and gate nodes genuinely produce nothing. A blanket "all nine must be non-empty" rule
refuses the repository's own example — the same coarse check inverted.

Both also raised, unprompted, the same adversarial case: a caller writing `scope: ""` to mean "the
whole repository". Both would refuse it. `""`-meaning-everything and `""`-meaning-nobody-filled-it-in
are indistinguishable to every reader downstream, and the second is the finding.

### Where they disagreed, and what settled it

codex-seat: both boundaries for all six fields.
fable-seat: `instructions` at render time only, because the engine may fill it in between.

**Settled by the code, not by averaging.** `engine.py:512-520` joins any `--instruction` text onto
the node spec's own, and line 515 reads:

```python
own = spec.get("instructions") or ()
```

which explicitly tolerates a falsy value. A plan that leaves every node's `instructions` blank and
supplies the text on the command line is coherent and works today. A load-time check on that field
would refuse it — this same defect inverted, one field over.

So: **five fields at both boundaries, `instructions` at render only.** fable-seat's asymmetry, on
the strength of one line neither seat could have settled by argument.

## What the fix cost elsewhere

**One test fixture, and it was worth looking at rather than patching.** `test_store.py` built
`spec = {field: "" for field in NODE_SPEC_FIELDS}` — enough keys to satisfy a check that only
counted them. The honest question was whether this was a legitimate plan my rule broke. It was not:
that test is about which *model* gets dispatched, and the spec only ever needed to exist. Given real
content, it passes.

That is the only thing in 1182 tests the rule refused, which is the evidence that the field split is
right — and `test_the_example_plan_survives_the_rule_it_documents` now pins both example plans
against it permanently.

## The three that moved together

Scenario C's outcome inverted, so:

- `examples/tide-spa/README.md` — the results row, and the whole scenario C section
- the results table's surrounding argument (C moved from "the exception" to the load-time column)
- `tests/test_example_tide_spa.py` — the test that asserted the **broken** behaviour on purpose

That last one is why it was deliberately written to fail. It worked exactly as intended: the fix
could not land without the documentation moving in the same commit, and the failing test said so in
its own assertion message.

## Not claimed

**That every blank is now caught.** Three fields may still be blank, by ruling. Scenario C blanks
`expected_outputs` and the refusal does not mention it — correctly.

**That a non-blank field says anything useful.** `scope: "x"` passes. This rule distinguishes
*something* from *nothing*, which is the distinction the old check failed to make; it does not judge
quality, and no check here does.

**That the load-time and render-time checks are identical.** They differ by one field, on purpose,
and the difference is documented at both ends.
