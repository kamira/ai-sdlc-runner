# Worklog — CHG-20260823-36

Recording at `docs/recordings/chg-36.html`. This is what it cannot show.

## How this started

The ask was a new SPA project — a local week-ahead forecast with current conditions in the middle —
**driven through the web page**, and recorded. The previous round's recording had been driven from
Python against the HTTP API, which is close enough to the console to be misleading: it exercises the
same routes but proves nothing about the page.

So this one went through the served console: the brief typed into `#instruction`, `start the run`
clicked, `approve merge` clicked. Three instructions, one approval, 803 turns.

## What driving the real page found

**`runner serve` did not start.** Before any of it could happen, the dashboard crashed on launch
with a `TypeError` out of `pathlib`. The `serve` subparser declared `--settings` with
`default=None`, shadowing the global flag whose default exists so nobody has to pass it.

Worth dwelling on: the traceback named `pathlib.Path.__new__`. Nothing in it said "flag", "settings"
or "serve". A crash whose message points away from its cause is the expensive kind, and this one
sat in the plainest possible invocation of the dashboard.

The general test matters more than the specific one. `test_every_subcommand_that_takes_settings_gets_a_usable_default`
walks every subparser, because the defect is not "serve is wrong" — it is "a subparser can shadow a
global flag and drop its default", and any command can acquire that tomorrow.

**`start the run` is not `add to the brief`.** My second instruction went in through the wrong
button and silently replaced the first. Nothing failed. I only noticed by exporting the conversation
and counting `instruction` turns: two typed, one recorded.

I did not file this as a defect and I want the reasoning on record. Two verbs, two routes, two
clearly labelled buttons — the console is not wrong. What is true is that the failure is *silent*,
and the place it surfaces is the conversation record, which is exactly what that record is for. So
it became scenario B rather than a bug report.

**An agent that cycles, and the cap that caught it.** My weather agent picked the next module by
which file was missing. On the second walk all four existed, so it answered with the last module
forever and the flow went round until:

```
EngineError: walk exceeded 200 steps — the flow is cycling without progress
```

The runner catching a bug in the thing it was driving rather than in itself. A timeout would have
said "slow"; the cap said what actually happened.

**And then the same bug, already shipped.** `examples/tide-spa/agent.py` had it too. I did not find
that by reading — I found it because `examples/demo/build.py` drives an agent until it reports
itself finished, and tide-spa's never did. A generator that refuses to finish is a better test than
the test I would have written.

## Decisions

**A second example rather than a sixth scenario.** Scenarios D and E — no token, non-loopback
`Host` — cannot be reached from `runner run` at all. Bolting them onto `tide-spa` would have meant
one driver with two transports and a flag to pick between them; the honest split is by *path*, not
by count.

**Demo pages generated, not committed as artefacts.** A page copied once is a screenshot with an
`.html` extension. `tests/test_demo_pages.py` regenerates and byte-compares, so the pages cannot
drift from the agents. This is the same rule the example READMEs already live under: a number in a
document that nobody re-measures stops being true quietly.

**`examples/` moved so the three are siblings.** Two of the three already had their own README while
the third's files sat loose at the top of `examples/`, which made `examples/README.md` try to be
both an index and one example's documentation. Seven references followed the move, and a test now
walks every relative link in every example README — because a restructure that leaves dead links
claims a structure that is not there.

## Not claimed

**That the console's JavaScript is under test.** The scenario driver speaks the routes the page
speaks, with the same headers and the same version discipline. The page's own click handlers are
exercised only by me having clicked them.

**That the weather forecast is a forecast.** It is a deterministic curve from a fixed seed. The page
says so in its own footer, and it makes no network request — which the brief asked for and a test
asserts.

**That three examples cover the runner.** They cover the plan, the CLI path and the console path.
Nothing here exercises `--seat-model`, a real multi-model panel, or the ship effects.
