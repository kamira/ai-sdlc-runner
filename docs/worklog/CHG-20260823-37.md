# Worklog — CHG-20260823-37

Recording at `docs/recordings/chg-37.html`.

## The one decision worth writing down

Every other page in `examples/demo/` is regenerated on each build and byte-compared against the
committed copy. That is what stops a demo page becoming a screenshot with an `.html` extension.

A recording cannot work that way. It carries wall-clock timestamps, so a page rebuilt from a fresh
run differs from the committed one on every build, and the comparison would have to be dropped for
exactly the page most likely to go stale.

Three options, and I want the rejected two on record:

1. **Drop the comparison for this page.** Cheapest, and it removes the guarantee from the file that
   needs it most.
2. **Normalise the timestamps away before comparing.** Then the test passes while the page is wrong
   in the one dimension a *recording* exists to show. A check that ignores the thing under test is
   this project's signature defect.
3. **Record once, commit the conversation, render from that.** The run is real, the page is
   reproducible, and the byte-compare keeps working unchanged.

Three. The cost is a 320 KB fixture and the fact that it is a snapshot — both stated rather than
discovered.

## What that cost, honestly

The first capture of this run was **902 KB**. It was bloated by two redundant re-walks, caused by
the agent bug CHG-20260823-36 fixed — an agent that picked the next module by which file was missing
could not report itself finished, so every follow-up instruction re-walked everything.

I regenerated it after the fix and got 306 turns instead of 803. The ceiling test carries that
reason in its message, because "the fixture got big" and "something re-walked that should not have"
are the same event and the second is the useful sentence.

## The scrub, and the mistake in it

The `opened` turn records the journal directory. My first pattern matched a Windows path as it looks
on disk — `C:\Users\…` — and matched nothing, because inside a JSON string every separator is
doubled: `C:\Users\…`. The fixture would have shipped with my temp directory in it and the check
would have said it was clean.

Caught by running the generator and grepping the output rather than trusting the regex. `make_fixture.py`
now refuses to write a fixture with a surviving path, and a test checks the committed one — two
places, because the generator runs by hand and the test runs on every push.

## A test that read the wrong field

`test_the_recording_replays_a_real_console_driven_run` first searched the rendered page for
`"kind": "instruction"`. It failed — the shipped exporter's payload carries `verb`, not `kind`;
`kind` only existed in a scratch page I had built earlier and was reading from memory.

I rewrote it to load the conversation and assert on turn kinds there. Better for a second reason:
the page's field names are the exporter's business, and a test pinning them would fail on a rename
that changed nothing.

## Not claimed

**That the fixture stays current.** It is a snapshot, refreshed by hand. The suite guarantees the
page matches the fixture — not that the fixture matches today's runner. A conversation-schema change
would need it regenerated, and nothing here notices on its own. That is the honest cost of option 3.
