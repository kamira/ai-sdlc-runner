# Worklog — CHG-20260823-41

The clause that had been open longest.

## Why it sat for four rounds

`docs/DATABASE.md` described `conversations` and `turns` in full — columns, constraints, and a whole
section on the columns that are deliberately *absent* — while saying, every round, that no code
created them. Two seats reviewed that design and corrected it twice.

What stopped me starting was the design's own closing line: the proposition is "corrected but still
unreviewed in its corrected form", and "implementation should not start on the assumption" a fourth
round finds nothing. That is a reasonable warning and it is also, read a certain way, a permanent
one. The operator said 「把對話儲存也搬到 sqlite」, which settles it: implement, then have it reviewed.

## What the design already got right

I followed it rather than re-deciding it, and two of its choices earned their keep immediately:

**No `opened_at`.** It would be a second copy of the OPENED turn's `at`. `SELECT at FROM turns WHERE
conversation_id = ? AND seq = 0` is the answer, and the column would have been a second truth about
one fact.

**`body_json` holds only the body.** The envelope has its own columns. The shipped code once had a
body key overwrite `seq` and `at`, so this is a fix cast as a schema.

## The thing worth having done it for

CHG-35 removed Mongo and TinyDB and had to write down that a duplicate `seq` was now "reported and
refused nowhere". I recorded that as the one guarantee that removal genuinely weakened, and said it
was the first line that would have to change if a writer ever became concurrent.

`PRIMARY KEY (conversation_id, seq)` is that line changing:

```
UNIQUE constraint failed: turns.conversation_id, turns.seq
```

Refused by the database, at the write. Not by a convention, not by a comment.

The foreign key needed more care. `REFERENCES conversations(conversation_id)` enforces nothing
unless the *connection* sets `PRAGMA foreign_keys = ON` — per-connection, OFF by default. `store.py`
already set it; I asserted the pragma in a test rather than the schema, because a constraint that
looks declared and does nothing is precisely this repository's recurring defect.

## The import, and what I refused to make it do

Two temptations, both declined:

**Migrating automatically on first open.** Convenient, and it would move an operator's data without
being asked. The listing showing nothing until you run one command is a worse first minute and a
better property.

**Merging a conversation that already exists.** It would mean deciding what to do about a turn whose
`seq` matches and whose body differs, and there is no answer to that which is not a guess. So it
skips, and says which.

The source directory is never deleted. A migration that removes its own source has no way back if it
was wrong.

## The check I am most pleased with

`examples/demo/build.py` renders the demo recording by importing the JSONL fixture into a throwaway
database and exporting from **that**. The page came out byte-identical to the one rendered directly
from JSONL.

So the importer is exercised on every build, against a real 306-turn conversation, and if it ever
stops being lossless the demo's existing byte-compare fails. That is a better test than the one I
would have written, and it cost one function.

The fixture stays JSONL on purpose: a committed fixture has to be readable in a diff, and a
`.sqlite` file is not.

## Not claimed

**That this is reviewed.** The design was. This implementation has had no round, and the design's own
warning about fourth rounds applies to it at least as much.

**That anyone's existing store is migrated.** It is importable. An operator who upgrades and starts a
run will find their old conversations absent from the listing until they run one command — which is
the honest cost of not moving data without being asked.
