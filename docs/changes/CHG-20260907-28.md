## The finding, and the citation that was wrong

The finding as it was handed to me said *"`GET /run`'s snapshot carries `assignable`"*. It does not.

```
PYTHONPATH=src python -c "from ai_sdlc_runner import server; s = server.RunState().snapshot();
                          print(len(s), 'assignable' in s)"
21 False
```

The key is on **`GET /config/nodes`** (`server.py:1270`), and that correction is the whole shape of
this record rather than a pedantry - see the next section. The rest of the finding stands, and
**every line number below is at `3a8caf2`**, the pinned baseline, not at this change's own tip -
the comment corrected here is six lines longer than the one it replaces, so the writer that was at
`server.py:1270` is at `:1276` afterwards:

```
writer      src/ai_sdlc_runner/server.py:1270      "assignable": list(store_mod.MODES_THAT_USE_MODELS)
document    docs/API.md:117                        the jsonc block
            docs/API.md:125-126                    "so the console can grey them out"
code prose  src/ai_sdlc_runner/server.py:1268      "so the console can grey out the rest"
test        tests/test_store.py:444                asserts the value, never a reader
console     src/ai_sdlc_runner/console/index.html  ZERO mentions
```

`grep -rlI "assignable" . --exclude-dir=.git` returns eleven files. Two are the writer and the
document, one is the test, two use the word in a different sense (`server.py:1062` and
`store.py:355` say *"assignable and invisible"* about a registry split; `test_workstream_risk.py`
means the set of nodes a workstream may touch), and the rest are historical records. The shipped
console mentions it **0** times, reads `/config/nodes` once at `index.html:785`, and hands the body
to `drawModels()`, which touches `assign.by_model` (`:313`) and `assign.models` (`:315`) and nothing
else.

**And there is nothing to grey out.** The console's only `POST`s are `/run` (`:749`),
`/run/instruct` (`:762`), `/attachments` (`:776`) and four run paths through `act()` (`:724`).
It has no per-node configure control at all, so the sentence describes a control that has never
existed - it is not a consumer that was lost, it is one that was never built. The key and the
sentence arrived in the same commit, `22f6ace` (CHG-20260823-25, #57), and no record since has
named a reader.

## Why the wrong citation mattered: the two rules, and the route neither reaches

Had the key really been a snapshot key, it would already have been guarded and this record would
not exist. CHG-20260903-29 built exactly that guard after six snapshot keys reached no front end:

```
tests/test_server.py:1244  test_every_key_the_server_sends_reaches_the_console
                           iterates server.RunState().snapshot()      -> 21 keys, no `assignable`
tests/test_server.py:2330  test_every_report_field_is_rendered_or_written_down
                           iterates engine.RunReport().as_dict()      -> 30 fields, no `assignable`
```

CHG-20260903-49 was written because the first of those rules was cited as covering a scope it does
not cover - *"a field that never enters the snapshot cannot fail a rule that iterates the
snapshot"* - and it closed the gap it found, for `RunReport`. **`GET /config/nodes` is a third
surface, and no rule of any kind watches its response keys.** That is the defect this record fixes;
the misleading sentence is the instance that revealed it.

## `source` is the second silence, and it already had a record

`GET /config/nodes` also sends `source`, and `docs/API.md:121-124` argues for it in the strongest
terms this document uses: *"A console showing the merged result with no provenance could not say
that it had - and an override nobody can see is worse than no override."* The shipped console
renders exactly the merged result, through `by_model`, and says nothing about where any of it came
from.

This is **not** new, and it is not this record's to build. ACC-20260903-39 reservation 2 wrote it
down already:

> **The console renders no assignments at all.** The defect seat reported that it never reads
> `source`; measured, `node_models`, `seat_models` and `assignments` appear zero times in
> `console/index.html`. The server half was a defect and is fixed; the console half is a **missing
> feature**, and building it is not a defect fix. Named in the change, not folded into it.

Two things about that paragraph, and both belong here rather than in a diff.

**Its measurement is true by name and false by content.** The console has rendered assignments since
`02b4e29` (CHG-20260823-12) - `git log -S "assign.by_model" -- src/ai_sdlc_runner/console/index.html`
returns that one commit, **nine days** before `-39` (`02b4e29` is 2026-08-25; that record is dated 2026-09-03) - so *"renders no assignments at all"* was already
wrong when it was written. The three names are indeed zero; the content is on the page. That is the
exact distinction CHG-20260903-49 later had to invent `_reaches_console` for, six days after this
sentence relied on the other reading. It is corrected here by being said out loud, not by editing an
accepted record.

**The fact `source` carries reaches a person as a count - and the field itself still reaches
nobody.** `cli.py:1208-1212` prints *"from the store: N assignment(s) the plan did not name"* on
`run`, and `cli.py:1692-1694` prints *"N assignment(s) from the plan override it"* on `serve`.
Never per assignment, and never in the browser.

**That distinction cost two drafts of one inventory line, and the second seat is what forced it.**
The first draft said the fact was nowhere; the first seat corrected it to the `risk_settled` idiom
from `NOT_ON_THE_CONSOLE` - *reaches the terminal only* - and the second seat refused that too, on a
measurement: neither `cli.py` line reads this response. `run` counts `assignment_source` directly
and `serve` calls `store_mod.overrides(...)` itself, so the terminal prints the same *fact* computed
a second time from the store. **A related fact computed independently is not a consumer**, and an
inventory whose purpose is to be argued with cannot describe one as if it were. The entry reads
*read by nothing*, names the two independent counts beside it, and keeps the correction in the line
so nobody re-derives the comfortable version.

The provenance marker in `drawModels` is a **separate record**. Where it sits, how plan precedence
is explained, and how a node with both a plan and a store row reads are design questions this record
does not answer.

## The decision, and the two it is not

Put to both seats before any code was written, with the measurements above.

**codex:** option (2) generalised into a rule - *"not scope creep. The defect is demonstrably the
uncovered `/config/nodes` response surface, not merely one misleading sentence."* Required that the
rule derive its keys from the real route rather than a fixture, and that the inventory reject stale
entries and entries that have since acquired a consumer.

**fable:** option (2) with the rule, and corrected what the rule would show: **four** keys, not two,
because the name-based reading is the only one available here - `_reaches_console`'s content half
walks `snapshot()`'s AST for `report.<attr>` and cannot see a fold that happens inside `do_GET`.
Added that the same console claim lives in code prose at `server.py:1268` and that fixing only the
document leaves the claim standing; that `source`'s fact reaches the terminal as a count; and that
option (1)'s stated premise is half wrong.

They agree, so there is no tie to break. What the two rejected ends cost:

**(1) REMOVE the key and the paragraph.** Cheap in code - four lines across
`server.py`, `test_store.py` and `API.md`. Its stated ground was *"an unread key in a documented
schema is a claim the server makes and nothing tests the meaning of"*, and **the second half of that
is false, measured**: the meaning is enforced at `store.py:428-433`, where a node whose mode is not
in `MODES_THAT_USE_MODELS` is refused with a sentence, and `tests/test_store.py:466` tests that
refusal by name. What the key adds is that a client can refuse *before* posting. `GET /flow` gives
each node's `mode` (`server.py:1209`) and nothing else in the API says which modes accept a list, so
removing it means every client hardcodes three mode names.

**A draft of that sentence went further and cited a guard that does not exist**, and the second
seat caught it: it claimed CHG-20260902-19 task 8 and
`test_the_assignable_set_is_read_from_the_graph_rather_than_listed` *"exist to prevent that literal
on the server side"*. Measured, that test asserts on `graph.module_cycle()` - `"engineer_build" in`,
`"qa_accept" not in` - and task 8 reads *"the assignable set is read from the graph"* about
`engine._workspace`. Both are about the **nodes** a workstream may touch. That is the other sense of
the word, which this record's own grep table assigns to that same file two sections above - so the
draft contradicted its own measurement four pages later, to borrow authority it had not earned.
`MODES_THAT_USE_MODELS` is a three-member tuple at `store.py:55` and no test protects it from
becoming a literal anywhere. The cost of option (1) does not need the borrowed guard and is stated
without it: a schema contraction on a live route, against no measured saving, leaving the `source`
gap and the seventh key exactly where they are.

**(3) BUILD the consumer.** Not one value on a page. There is no per-node configure control, so
"grey out the rest" starts by building the control: render every node with its current assignment,
join `/flow` for modes, `POST /config/nodes` under the run-version check (`server.py:1282-1286`), handle
a stale tab and a refusal, show which rows the plan owns and the console may not overwrite, and
decide list editing separately for `single`, `model_panel` and `pool`. A product feature with no
requester, needing its own acceptance. Both seats said so independently.

## What ships

1. **`docs/API.md` stops describing a console that does not exist.** The `assignable` paragraph says
   what the key is for - a client refusing before it posts - and says plainly that no shipped console
   reads it and there is no node-configuration control to grey anything out. The `source` paragraph
   keeps its argument, which is sound, and gains the clause that the console it describes is the one
   this repository ships.
2. **`server.py:1268` loses the same claim**, for the same reason: a comment is where the next reader
   looks first, and `_console_code()` strips comments precisely so one cannot stand in for the thing.
3. **`test_every_key_of_the_node_config_route_is_named_by_the_console_or_written_down`** - the keys
   come from a **live `GET /config/nodes`**, not a list, and each must be named in `_console_code()`
   or carry a reason in `CONFIG_NODES_NOT_NAMED_BY_THE_CONSOLE`. Stale entries and entries the page
   has since acquired are both refused, following `-49`.

   **The verb in that name is `named`, and it was `drawn` until a review seat blocked on it.** The
   guard reads comment-stripped page text for the identifier, so a dead
   `var schemaNames = ["by_model", "models"];` would satisfy it while `drawModels` read neither.
   Proving a key is *rendered* needs a harness that runs the page and this repository has none, so
   what the guard holds is the boundary CHG-20260904-13 drew - a comment cannot stand in for the
   thing - and the name now says exactly that. `-29`'s rule reads names too, under the word
   *reaches*; this record does not repeat the verb, and says why rather than quietly not repeating it.
4. **`test_no_fold_named_in_the_node_config_inventory_is_absent_from_the_route_or_the_page`** - the
   two "folded into `by_model`" reasons are the only claims in the inventory a test can check, and
   they are checked: the carrier they name in backticks must be a key of the same response *and* be
   named on the page. This is the `test_no_exclusion_is_justified_by_a_flag_the_runner_does_not_have`
   move - an inventory whose whole purpose is to be argued with cannot carry an unchecked claim. The
   fold itself is real, and separately measured: the route appends every `node_models` entry to
   `by_model[*].nodes` and every `seat_models` entry to `by_model[*].seats`, and `drawModels` draws
   both. What the guard refuses is a carrier the route does not send or the page never mentions; it
   cannot refuse one mentioned inertly, which is the same boundary as above.
5. **`test_the_page_documents_this_route_and_promises_no_reader_it_does_not_have`** - the other half
   of the accounting, and the half that holds the doc fix. Its first assertion is
   `test_the_models_sketch_enumerates_the_payload_it_claims_to`'s move applied to the second sketch
   on the page: the fence's **top-level** keys, by outer indentation, must equal what the live route
   sends. `docs/API.md` listed ten keys for `GET /models` while the route shipped eleven
   (CHG-20260907-14) and this route's sketch had nothing holding it at all. Its second assertion is
   a rule over the inventory: a paragraph introducing a key no console names may not talk about the
   console without denying it. **That half holds words, not meaning**, the denials are a closed set
   named in the test, and the docstring says so rather than implying more.

## Registry

`node-config-accounting`, nine entries, every one naming a **test node**. Each of the six
assertions in the three guards is reached by at least one, measured rather than assumed - the two
that share an anchor say which assertion they fire:

```
mutation                                                    objector, and the assertion it reaches
a seventh key joins the route in silence                    -drawn-or-written-down   unlisted
a key leaves the route and its inventory entry stands       -drawn-or-written-down   stale
a key acquires a console reader and keeps its entry         -drawn-or-written-down   named_but_listed
the console stops naming the one key it draws by name       -drawn-or-written-down   unlisted
the carrier ... is not a key any more                       -no-fold-named           absent
the carrier ... reaches no console                          -no-fold-named           undrawn
the page's sketch stops enumerating what the route sends    -promises-no-reader      equality
the page goes back to promising a console that greys four   -promises-no-reader      denial
the page stops saying the console ... is the shipped one    -promises-no-reader      denial

all 9 caught.
```

The first two share an anchor and were separated by measurement, not by reading: adding a key
reports `['seventh']` from `unlisted`, dropping one reports `['assignable']` from `stale`. The two
console entries share their anchor for the same reason - one line carries both *a drawn key stays
drawn* and *the carrier two folds name is one a reader can see*, and reverting it must not look
like reverting only the first.

**One fix is deliberately unregistered, and the registry says why at the code.** `server.py:1268`'s
comment carried the same false claim as the page and is corrected here; no mutation of it can be
caught. `_console_code()` strips comments from the *console*, which is what stops a comment
satisfying the console rule, and nothing reads `server.py`'s comments at all. A second vocabulary
check over source-file prose would pin the wording of a comment and nothing else - the class this
repository's own records name as its recurring defect. The page is the copy three surfaces are
written against (`tests/test_mutation_check.py:174`), and the page is the copy pinned.

## Risk & rollback

- **No behaviour changes.** The route answers `['assignable', 'by_model', 'models', 'node_models',
  'seat_models', 'source']` before and after, measured against a live server on both trees.
- **A key added to `GET /config/nodes` now carries an obligation**: draw it, or write down why not.
  That is a real cost and it is the same one CHG-20260903-29 accepted for the snapshot. It is the
  point.
- **The inventory is hand-written**, like `NOT_ON_THE_CONSOLE` and with the same limit: a key nobody
  adds to it fails the rule rather than passing it, which is the safe direction, but a *reason*
  nobody keeps true is prose. Task 7 makes the one part of a reason that can be checked, checked.
- **Four of six keys inventoried reads badly**, and that is honest rather than a reason to soften the
  rule into something that would pass. Two of the four are folds and say so.
- Rollback: revert. The document goes back to promising a control that does not exist, and the route
  goes back to having no accounting.
