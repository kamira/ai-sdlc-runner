## Read this first

`do_POST` turns an absent field into the empty string:

```python
out = runner.approve(version, str(body.get("gate") or ""), body.get("node_id"))
out = runner.reject(version, str(body.get("gate") or ""), body.get("node_id"), ...)
out = runner.rule(version, str(body.get("node_id") or ""), str(body.get("branch") or ""))
```

and `_answering`'s guards were written `if gate and …` / `if node_id and …`, so an empty value
**short-circuited both and no check ran at all**. Measured:

```
_answering(gate="")                          accepted, no check ran
_answering(node_id="")                       accepted, no check ran
_answering(gate="acceptance", node_id=…)     refused correctly

and then, on EVERY subsequent walk:
  Approval(gate="")     EngineError: approval for gate '' does not exist
  Rejection(gate="")    EngineError: rejection names gate '', which does not exist
  Ruling(node_id="")    EngineError: ruling names a node that is not in the flow
```

`state.approvals` is append-only with no removal route, so the run is **unrecoverable short of
`POST /run`**. That is CHG-20260903-23's L-25 defect arriving by the empty-string road — into the
helper `CHG-20260903-44` extracted *"so a fourth decision method cannot now be written without
asking the question."* The question was asked. It answered nothing.

## And the rule that was supposed to hold the helper accepts a method that guards nothing

The seat planted a fourth method and ran it against the rule `-44` shipped:

```python
def veto(self, version, gate, node_id) -> None:
    self._answering()                       # named, given nothing
    self.state.rejections.append(
        engine.Rejection(gate=gate, node_id=node_id, run_id=None, reason="veto"))
```

```
against the rule as shipped   .......... SURVIVED, 1 passed
```

It asked *"does the token `_answering` appear"* and *"does the token `run_id=` appear"*. Neither is
the property. `run_id=None` is the literal `Approval`'s own docstring calls *"the wrong one for an
answer typed into a console after a stop"* — the exact value `-44` was written to stop `reject` and
`rule` passing.

**Third rule of mine this round that counts what is written rather than what must be true**, after
`-41`'s (blind to a missing append, fixed in `-46`) and `-46`'s own (blind to a keyword-form
resolution, the seat's L-19, still open). The rule now asks that `_answering` receives the values
the method takes, and that `run_id` is read from what the helper returned.
