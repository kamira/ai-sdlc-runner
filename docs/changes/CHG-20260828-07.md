# CHG-20260828-07 — a change class was one scalar per run, and a programme's parts are not one type

- Project: ai-sdlc-runner
- Branch: claude/chg-20260828-07-class-per-workstream
- Date: 2026-08-28 (UTC+0)
- Type: a scalar becomes a mapping, the same way risk already did
- Proposed by: reservation 4 of ACC-20260827-20, written when change classes shipped
- Risk: **high** — it decides when a gate stops less often, on a programme with several parts
- Autonomy: high
- Related: CHG-20260827-20 (change classes), CHG-20260827-18 (risk per workstream — the shape this
  copies), CHG-20260827-22 (sub-planning, which is where several workstreams come from)

## The gap, which this repository disclosed about itself

`ACC-20260827-20`, reservation 4:

> **The class is a run-level scalar.** CHG-20260827-18 made risk per-workstream; a class is not. A
> programme with a `standard` copy tweak and a `normal` schema change gets one class for both, and
> the strictest reading is not applied because there is nothing to compare. This composes badly with
> workstreams and is not addressed.

CHG-20260827-18 made risk per-workstream on the argument that *"a schema change, a copy tweak and a
payment path are not the same risk"*. They are not the same **type** either: one may have been
assessed and pre-authorised while the one beside it has not.

One class for the whole run means a person who assessed the copy tweak pre-authorises the schema
change as well — **silently**, which is the one thing a change class must not be.

## The shape, copied from risk deliberately

A node **in** a workstream reads that workstream's class. A node in **none** — `pr`, `merge`,
`close_out`, everything before the split — reads `policy.combined_class`, which is the analogue of
`strictest` and leans the same way:

* **any part without an in-force class → `normal`.** A part nobody pre-authorised means the change
  is not pre-authorised. Reading the loosest would let a `standard` copy tweak carry an unassessed
  schema change through the door they both pass — exactly the error `_grade_in_force` avoids by
  reading the strictest rather than the loosest.
* **any `emergency` → `emergency`.** Both relaxing classes turn `confirm` into `auto` identically,
  so the gate is the same either way; `emergency` carries the obligation to review afterwards, and
  reporting it as `standard` would drop the half that is not about gates.
* otherwise `standard`.

Expiry composes through it: a part whose assessment lapsed is a part nobody assessed.

## The refusal is where the safety is

`--change-class` is repeatable and takes an optional `WORKSTREAM=` prefix. **A bare class is refused
when the plan names several workstreams**, and the refusal shows how to say what was meant:

```
--change-class was given for the whole run, and the plan names 2 workstreams: ['copy', 'schema'].
A class says a person assessed a TYPE, and one sentence cannot have assessed all of these — it
would pre-authorise parts nobody looked at. Name the workstream:
--change-class copy=standard:who:2026-12-31
```

Refusing rather than applying-to-all is the whole point: applying it would be the runner deciding
that one assessment covered work the assessor may never have seen.

**One workstream or none is one type**, so the run-level form still works — which is every plan
written before this.

## Observed end to end, not argued

Same plan, two workstreams, differing only in the flags:

```
copy classed only          -> stopped at: merge — confirm at risk low ... state: suspended
copy and schema classed    -> class relaxed: merge ... would have been 'confirm'
                              stopped at: done
```

## Risk & rollback

- With no class declared, nothing changes: `normal` everywhere, which is what every gate already did.
- The change can only make a relaxation **harder** to obtain than the run-level scalar did — every
  path that previously relaxed now needs every part classed, or a refusal at the command line.
- Rollback: revert. A bare class returns to covering a whole programme silently.

## Status

**Accepted** — see [ACC-20260828-07](../acceptance/ACC-20260828-07.md).

### Not claimed

**That per-workstream classes are the right granularity.** A workstream is what the plan happens to
declare. Two modules inside one workstream still share a class, and nothing here asks whether they
should.

**That anybody assessed anything.** `authorised_by` is what the operator typed, per workstream now
rather than per run. More places to type a name is not more assurance that a person looked.
