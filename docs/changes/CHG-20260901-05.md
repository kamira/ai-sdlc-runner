## A capital `R` turned the whole rename gate off

The gate added last round re-matched the verb with its own hand-rolled `renamed to\s+`(\w+)``,
**case-sensitively**, while `_REMOVED_BY` matches its verbs under `(?i:)`. So the ordinary spelling
at the start of a sentence — the one this very table already pins for `Removed in CHG-…` — made
`re.search(phrase, said)` return `None`, the `and` short-circuit skipped both halves of the gate,
and the defect closed two rounds earlier came back:

```
REFUSED  <the ghost> was renamed to `helper` in CHG-20260901-01.   <- the pinned row
EXCUSED  <the ghost> was Renamed to `helper` in CHG-20260901-01.
EXCUSED  Renamed to `x` in CHG-20260901-01: <the ghost>.
```

Reachable by the shift key. The cause is that the phrase was spelled out a second time, in the
gate, while `_removed_by` held the first — so the two drifted, and the flag was in only one of them.
It is built once now, by `_renamed_to`, and every consumer of case-insensitivity goes through
`_case_free`, so dropping the flag is one edit reaching both.

The same second spelling kept a literal space between `renamed` and `to`, the last one in a rule
that writes `\s+` everywhere else. In a hard-wrapped ledger the break falls there as readily as
after `to`, so the wrap was refused — one word from the wrap the round before had just fixed.

## Attribution was clause order, not scoping

"A rename excuses this test only if it is **this test's** rename" was implemented as `quoted +
_SPAN + phrase` — does the name appear *somewhere before* the verb. `_SPAN` crosses any amount of
prose, so:

```
REFUSED  The fixture was renamed to `<live>` in CHG-…; <the ghost> is unaffected.   <- pinned row
EXCUSED  <the ghost> is unaffected; the fixture was renamed to `<live>` in CHG-….
EXCUSED  <the ghost> is one of them, and the helper was renamed to `<live>` in CHG-….
```

The pinned row put the ghost after the rename, so it measured the clause order, not the shape. What
a regex can check is **adjacency**: `_ATTACHED` allows connective words between the name and the
verb and nothing that introduces another subject — no other backticked name, no `;`, `:`, `,` or
sentence punctuation. Whether a sentence is *about* this test is a question about English; this
refuses where it cannot tell.

That has a cost and it is now a row: `` <the ghost>, the halt case, was renamed to `X` `` is
refused for its commas. A refused true sentence is recoverable — drop the aside, or write
`removed in` — where an excused ghost is not.

## The refusal told the operator to overwrite work it could not account for

Two ways, both in the message written last round to stop a different destructive remedy.

**`recoverable` left out `mutated`** — the only field that can tell an edited file from a mutated
one, and the whole basis of the `now == mutated` / `now == original` / else fork. On a file holding
somebody's unrelated edit:

| record | what happens |
|---|---|
| complete | *"it matches neither the text a killed run mutated nor the text that was there before, so somebody has edited it since"* — file untouched |
| `mutated` removed | *"Put the `original` this record names back by hand, then delete it."* |

The automated path refuses that write; the message issued when the record loses the field that path
needed hands the same write to the operator. `DESTRUCTIVE_SHAPES` could not see it — its fixture
always writes `victim == mutated`, so the one state where the advice destroys something is the one
that table cannot produce.

**And the `owner` branch said it would not act, then said to act.** *"Without a usable one this
cannot tell a killed run from a live one, so it will not act"* — followed by *"put the `original`
back by hand"*, which is that act. Against a real live child, the same pid spelled `12752` and
`"12752"` gets opposite advice about the same run, and the second writes the original over a live
run's mutated file: the corruption this field exists to prevent, after which the run measures
unmutated source and reports NOT CAUGHT. Last round's fix had deleted both guards that stood
there — the hazard clause and the *"if you know no run is active"* precondition — and replaced them
with an unconditional imperative.

## And it told them the one command that works is worthless

record is most useless. The branch also named no way out, while `begin()` opens the record with

## A test that pinned nothing

`test_a_capital_is_not_a_safe_proxy_for_a_sentence_end_here` was removed in CHG-20260901-05: it
compiled its own regex and never touched `_SENTENCE_END`, so reverting that constant to the
capital-only rule it argues against left the test **green**. Its floor was unreachable — 4195 of
8600 against `0.33`, needing 1357 boundaries to flip — and 98.4% of its numerator was punctuation,
backticks and digits, so deleting every lowercase follower in the ledger still left it at 0.4798.
It measured "this ledger contains a lot of `` `x`. `y` ``".

Replaced by two tests that can fail: `test_the_sentence_rule_ends_a_sentence_a_capital_would_not`
drives `_SENTENCE_END` against the capital rule over the five openings the census counts, and goes
`5 failed` under that revert; `test_the_ledger_writes_the_openings_the_capital_rule_would_have_missed`
checks those openings are actually written here, with per-shape floors a tree could cross.

That sentence is also this round's own use of the rule under repair — the ledger lint refused this
record until the removal note was written, which is the remedy its refusal names.

## Two figures attached to reverts that do not produce them

The conformance seat re-ran every measurement in the previous round's acceptance. Nine of the
eleven bounds, the whole census, all eight widenings and every floor row reproduced exactly. Two
did not, and both are the same shape as the defect that round was about.

**Task 3's `6 failed` was `0`.** The guard written to forbid *"delete before restore"* asserts
`said.index("delete") > said.index("back by hand")` — and the condemned wording contains *"putting
the `original` **back by hand** may overwrite a live run's source"*, a warning **against**
restoring, 107 characters before it says delete. It satisfied the guard it was written to fail.
Nothing in that module produces 6. The remedy is genuinely pinned now, at **`7 failed`**, by this
round's assertion that an `owner`-broken restore must be conditioned on no live run — which is the
same fix the defect and risk seats asked for independently.

**And `_REMOVED_NO_RENAME` was added by that change, not the one it blamed.** `git log
-S"_REMOVED_NO_RENAME"` returns one commit; `3a49c57` carries a single spelled-out constant. The
two-copy state existed only inside that change's own working tree. The measurement — one copy
patched leaves every row green — is real, and is why the phrase is built once; the attribution was
invented, in the section whose subject is figures produced by an edit other than the one named.
