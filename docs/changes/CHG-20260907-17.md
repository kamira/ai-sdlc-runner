## The class

An assertion that cannot fail for the reason it names. Two shapes, both decidable from the syntax
tree, six sites among 21 disjunctive assertions in `tests/`:

```
test_server.py:2875         or True        sock.recv(200) or True
test_settings.py:383        or True        "not vouched" in picks.stream.getvalue() or True
test_probes.py:71           or True        (… / "origin" / "feature").exists() or True
test_documented_numbers     or True        here.exists() or True          — deliberate
test_conversations.py:623   weaker branch  '"waited": null' … or "waited" in page
test_schemas.py:230         weaker branch  "computed, never stored" … or "computed" in body
```

One reviewer refused this as a headline — *"of 40 hits, only three are load-bearing"* — which was
right about the count. What changed the judgement was the consequence: **this round's own repair
walked over one of these escape clauses and nothing said so.** CHG-20260907-14 reworded
`docs/SCHEMAS.md`, the strong branch went false, the weak branch caught it, and the guard stopped
guarding in silence.

## Two of the six were hiding something

**`test_server.py` never opened a stream.** The request carries no operator token, so
`GET /run/events` answers `401 Unauthorized` and closes. `recv(400)` returns the 401 headers —
truthy, so *"the stream did not open"* passes — and the read after the sleep returns the buffered
error body, so `or True` was never even consulted. **The guard for a shipped change measured a
refusal.** The line above it said `operator_token = …__dict__  # unused; token comes from the
request below`; nothing below carried one.

Reverting each half of the repair:

```
no token   assert b'200' in b'HTTP/1.1 401 Unauthorized'   1 failed
no publish (a bare recv, as before)                        1 failed
```

The publish matters because `_stream` blocks on the queue and sends nothing of its own: without it
a strict read waits out the socket timeout whether the stream is alive or closed, which is how the
`or True` came to be there. And the opening frame is now **drained** rather than sampled — the old
`recv(400)` took the first four hundred bytes of a longer snapshot, so a later read returned the
old frame's tail.

**`test_conversations.py` asserted nothing about escaping.** It read
`assert "&lt;img" in page or "<" in page`. The replay embeds turns as JSON inside a `<script>`,
so the escaping is the six characters `<` and `&lt;` never appears — while `"<"` in
Python source is the single character `<`, true of any HTML. One branch had the wrong expectation,
the other was a missing backslash. **The product was right the whole time**, and removing the
tautology is what showed the other branch had always been false.

## The other four

- **`test_settings.py`** — `_Picks._rows` truncates the working buffer on every menu read, so the
  refusal the screen prints is wiped before the assertion sees it. `_Picks` keeps a transcript now
  and the assertion reads `said()`. The buffer still truncates, because parsing one menu's rows as
  the next menu's is what the truncation is for.
- **`test_probes.py`** — the test is named for a stale remote-tracking ref and built none:
  `git push --delete` prunes it. The scenario is `git update-ref -d refs/heads/feature` **in the
  bare remote**, and the stale ref is confirmed with `git rev-parse --verify` rather than a file
  path, because after `pack-refs` the path is absent while the ref resolves.
- **`test_conversations.py:623`** — the second spelling never occurs (`json.dumps` uses the default
  separators) and the third is true of any replay. One assertion now.
- **`test_documented_numbers.py`** — deliberately non-operative, and its message said so. Every
  argument for keeping it as an assertion fails: it never fails, so the message never prints; the
  name it referenced is dropped with it; and a comment is exactly as greppable. **A statement that
  cannot fail is a comment.**

## What ships as a rule

`test_no_assertion_is_written_so_that_it_cannot_fail` refuses both shapes, with **no exception
list** — the one deliberate site has a form that is not an assertion, so there is nothing to
exempt. Planted both ways:

```
or True                            FLAGGED
weaker branch                      FLAGGED
two JSON spellings (legitimate)    allowed
upper and lower (legitimate)       allowed
```

## What the rule does not see, stated rather than implied

- A clause trivially true for the container's **type** rather than by substring —
  `"<" in page` was one, and only reading found it.
- A fallback reached only when the branch above it succeeded, which is tautological when evaluated
  rather than by syntax (`test_sandbox.py`).
- An assertion whose subject was bound to a name first: `operator_token = httpd…__dict__` then
  `assert operator_token is not None`. My detector reports **zero** of that shape, because the
  assert's expression is a plain name — reading found it, scanning did not.

A syntax rule holds the shapes it knows. Saying it holds the class would be the same false
assurance this record is about.
