## What these four have in common

The design under review is about **a permission reaching the person who needs to see it**. Prototyping
it turned up four places where this repository already fails that, on `main`, today. The suite —
1934 tests at the time — catches none of them.

| | the mechanism | what was wrong |
|---|---|---|
| D1 | `POST /config/halts` | the console configures a routing its own runs ignore |
| D2 | `policy.recipients` | the list names every owner; the sentence names the first |
| D3 | the guard over the suspension schema | reads one of three literals, and passes |
| D4 | six `RunReport` fields | declared, written, emitted nowhere |

## D1 — the console honours everybody's halt routing except its own

`POST /config/halts` is documented (`docs/API.md:172`), wired (`server.py:836` → `_route_halt` →
`store.set_halt_recipient`), and read back by `cmd_run` (`cli.py:885`, `:969`). `cmd_serve`'s
`make_config` never passed it, and `RunConfig.halt_routing` defaults to `{}`.

Measured, same project, same operation, the two commands:

```
store round-trip after POST /config/halts: {'deploy': 'sre-oncall'}
operation: {"description": "ship it to production", "kind": "deploy", ...}

runner run    told: ['sre-oncall', 'operator']     <- the project's own function
runner serve  told: ['release',    'operator']     <- policy.HALT_ROUTING's default
```

So every permanent halt raised in the console went to the built-in default, whatever the project had
configured **through the console's own API**. `ACC-20260827-19` reservation 3 states the opposite in
as many words: *"`serve` reads the routing; the console has no page for it."* It has had the page for
a while. It did not have the reading.

The one wiring test, `test_a_routed_halt_reaches_the_projects_own_function_through_the_cli`, calls
itself *"the seam nothing else covers"* and drives one of the two callers.

### The fix, and why it is re-read per walk

`store_mod.halt_routing(db)` inside `make_config`, not captured at startup — the rule the file
already states for node models: *"Resolved per walk rather than captured once, because a value
captured at startup is how the defect happened."* Halt routing is editable from the console
mid-session, so capturing it would rebuild that defect beside the one being fixed.

## D2 — a halt crossing two kinds named one owner everywhere a person reads

`policy.recipients`' docstring gives the case exactly:

> `secrets/prod.env` is a credentials file *and* sits in something called production, so it crosses
> `deploy` and `access` and **both owners are answerable for it**.

The list was right. The sentence built from it was `told[0]` plus the operator:

```
policy.recipients : ('release', 'security', 'operator')
report.halts      : told = ["release", "security", "operator"]     <- correct
report.halt_reason: "...This one is for release, and the operator." <- security is gone
```

`cli.py:1075` iterates `report.halts` itself, so `runner run` was right. Every **other** delivery
surface carries `halt_reason`: `RunState.snapshot()["reason"]`, which the console renders at
`index.html:445` and `:524`, and `conversation.close(why=...)`, which is the durable record. A
console operator reading a halt on `secrets/prod.env` was told it was for `release`; `security`, who
is equally answerable, was named nowhere they could see.

`tests/test_halt_routing.py:169` pins `told` exactly — including its order, deliberately. It never
read the sentence built from it, which is how a list that was right the whole time reached people as
a name that was wrong.

## D3 — the guard over the suspension schema read one of three literals and passed

`docs/API.md` §4 says **"Every kind of suspension carries the same keys"**. That claim is false and
its own guard could not see it:

```python
block = inspect.getsource(engine).split('report.suspended = {')[1].split("}")[0]
```

`engine.py` has **three** `report.suspended = {` literals — an ordinary gate, an intake survey, an
undecided panel. `[1]` is the first. Measured:

```
keys the guard inspected : 9   ['branches','gate','gate_when','incomplete','node_id',
                                'risk','run_id','undecided','verdict']
keys a suspension carries: 15  (+ 'missing','options','problems','safety','reason','verdicts')
emitted and undocumented : 4   ['problems','reason','safety','verdicts']
the console reads        : all four   (index.html 469, 478, 505)
the guard reported       : nothing
```

`split("}")[0]` would also have truncated the survey literal at `"safety": {k: list(v) for ...}`, so
widening the split alone is not the fix.

**Test-the-test.** With the four keys stripped back out of the page: the old guard **passes** and the
new one fails. Its failure mode was a false pass, not a wrong answer, which is why the page drifted
under it.

### Both halves are fixed

The guard brace-matches every literal, and the page documents all fifteen keys — grouped by which
question carries them, and its false claim replaced by the true one: nine keys always, six more
depending on the question.

## D4 — six fields declared, written, and emitted by nothing

```
declared on RunReport, absent from as_dict():
  ['change_class', 'halts', 'relaxations_by_class', 'risk_agreed', 'risk_proposed', 'risk_settled']
```

Absent from `docs/SCHEMAS.md` §13 and from every `--json`, snapshot and console. They survived only
in `cmd_run`'s stdout footer. Two of them say the opposite in their own docstrings:

- `halts` — *"Recorded rather than only printed, because 'who was told' is a fact an audit asks
  about months later, and **a message on somebody's terminal is not a record**."*
- `relaxations_by_class` — *"A relaxation nobody can enumerate afterwards is a relaxation nobody
  can audit."*

Both were exactly a message on somebody's terminal.

`test_the_run_report_entry_lists_every_field_the_report_emits` checks **emitted ⊆ documented**, which
a field passes for free by never being emitted. The other direction had no test; it does now, with no
exemption list — a field the report should deliberately withhold does not exist yet, and when one
does it should be argued for rather than skipped by a name in a set nobody is forced to read.

## Risk & rollback

- **D1 changes who is paged.** A project that configured halt routing and ran through the console has
  been reaching the built-in default; after this it reaches the function it configured. That is the
  fix, and for anyone who built a habit around the wrong name it will read as a change.
- **D2 makes an existing sentence longer** on halts crossing more than one kind. Nothing parses it —
  it is prose in a report — but it is prose that appears in the durable conversation record.
- **D4 widens `as_dict()` by six keys**, which widens every `--json` payload and the snapshot. Both
  are documented as open shapes and both are pinned by tests that now check both directions.
- **`report.halts` reaching `as_dict()` puts halt recipients into any exported run.** That is what
  its docstring asks for, and it means a name like `sre-oncall` now travels with the record.
- **Not fixed here, and named:** `serve` has no `--change-class`, so `change_class` and
  `class_by_workstream` cannot be passed by the console at all. That is a gap in what a console can
  declare, not this drift, and it is the one entry in task 3's exemption list.
- Rollback: revert. Each of the four is independent of the other three.
