## The finding

`tests/test_documented_numbers.py` holds forty-eight assertions over numbers stated in prose, and
its `DOCS` tuple names **twelve** files. `docs/API.md` — the page that documents the public `/flow`
payload — was not among them, and shipped `// all 28` nodes against a graph of 31 until an hour
before this record, with the guard for that class one directory away.

The obvious repair is to add the file. Measured first, it **fails**:

```
AssertionError: API.md says eighteen fields; there are 17
FAILED tests/test_documented_numbers.py::test_the_work_order_field_count_matches
```

on `docs/API.md:58`, which reads *"Thirteen of `Node`'s eighteen fields."* — and that sentence is
**true**: `Node` has 18 fields and 18 minus the five it names as withheld is 13. The guard was

```python
actual = len(workorder.WORK_ORDER_FIELDS)          # 17
if re.search(rf"\b{word}\s+fields\b", body, re.IGNORECASE):
    assert value == actual
```

which matches **any** `<word> fields` in any scanned document and compares it to the work order's
field count, without checking what the sentence is counting.

The same file records this class one screen away, in
`test_the_readme_says_how_many_nodes_a_run_actually_visits`: *"a check on the right number against
the wrong referent."* This is its mirror image — the sentence is right and the check is wrong about
what it counts — and it is the neighbouring assertion.

**Why it had survived** is the sharp part, and neither I nor the first reviewer had it right: not
that no scanned document states another collection's field count, but that across all twelve files
the rule had exactly **one** live subject — `docs/structure/data.md`'s *"Seventeen fields, listed
in `workorder.WORK_ORDER_FIELDS`"*, which is true. `docs/API.md:58` is the second sentence it ever
met.

## The reviewers disagreed, and the disagreement was worth more than either answer

One proposed a machine-checkable marker above each claim. The other refused it — *"an allowlist
nothing forces anybody to write"* — and proposed **A with a zero-width window**: the referent is
not *near* the number, it is *inside the matched phrase*, as an identifier the check resolves.

Put back to the first reviewer, which had rejected proximity as "a guessed boundary", it withdrew
its own proposal:

> *"The zero-width form answers my objection. C becomes unnecessary and, here, weaker: an author
> can omit an optional marker and leave a claim unchecked. Under the proposed A, omission of a
> resolvable referent is itself a failure."*

A paragraph-scoped window — the narrowest windowed variant — was measured and **fails on the true
sentence**: `data.md`'s heading is a separate paragraph from its claim, so a paragraph-scoped
search returns *no referent* on a correct sentence.

## Building it refuted the clause both had agreed on

The agreed design says a bare `<word> fields` matching no anchored form must **fail**. Applied to
the fourteen files, five claims resolve and **nine** bare matches remain — and most are not claims:

| where | what it is |
|---|---|
| `design.md` ×3 | a design alternative that was **refused**, quoted to say why curating lost |
| `data.md` | a quotation of the sentence this document replaced |
| `engine.py` ×2 | past tense — what was true before a change |
| `settings.py` ×2 | a real claim, counted by a different guard (below) |

Quoting a sentence that was wrong, to say why it was wrong, is this repository's **convention**:
`test_the_defect_logs_table_sums_to_the_total_it_states` says in as many words that
`docs/defect-log.md` *"quotes its own historical wrong figures on purpose"* and is excluded from
the sweep for that reason. A rule that refuses every unreferenced count refuses the convention, and
the repair would be to reword records of rejected designs.

A syntactic escape was measured and dropped. **"Sentence-initial or bold"** is wrong twice, in
opposite directions: it scores `engine.py`'s past-tense *"Six fields lived only in…"* as a claim,
and `SCHEMAS.md:473`'s *"**closed** — nine fields, four of them required"* as a mention, because the
bold is on "closed". A tense heuristic on top would be a guess with a grammar attached.

## What ships

1. **The claim grammar.** A count is checked where the sentence names what it counts —
   `<count> fields, listed in \`module.NAME\`` and `<count> of \`Node\`'s <count> fields`.
   `module.NAME` may be a sequence or a dataclass, because `models.Model` is a class and refusing
   it would push a true sentence into the mentions list.
2. **Digits as well as words.** They were skipped entirely, which left `docs/API.md`'s
   `{…8 fields…}` unread. One occurrence — so reading them cost one decision, and skipping a whole
   notation is how a sweep acquires a blind spot nobody remembers choosing.
3. **The mentions, pinned by sentence.** Keyed on the whitespace-normalised sentence, not on how
   many times a phrase appears in a file: both reviewers reached that independently, because a
   count is blind to meaning — deleting one bare *"three fields"* and adding another elsewhere in
   the same file keeps the count, and so does rewriting a quotation into an assertion. A table cell
   is its own unit, so an edit to a neighbouring cell does not fail the key.
4. **A reason on every entry**, and a failure message that puts *name the referent* first. One
   reviewer's warning, verbatim: if the message presents the mentions list as an equal alternative,
   authors take the one-line path and the list becomes this rule's `--undeclared allow`.
5. **`test_settings.COUNTS_SETTINGS` widened** to `(?:settings|fields)` with an optional `the`.
   `settings.py` says *"**Two of the three fields do change whether a stop happens**"* — bold,
   present tense, counting `FIELDS` — and escaped the guard written for exactly that class because
   it says `fields` and the pattern said `settings`. The leak, measured: grow `FIELDS` to four,
   correct the two documents that name it, and that sentence keeps saying three, green. The guard
   now sees **four** sentences, and a planted `FIELDS == 4` makes all four disagree.
6. **`docs/API.md` and `docs/SCHEMAS.md` join `DOCS`** — which could not happen before, because
   the field rule fired on `API.md`'s true sentence. The referent was the finding; the file list
   was the symptom.
7. **`test_api_schema.py`'s `/flow` guard rewritten.** It asserted
   `f"{sent} of \`Node\`'s" in PAGE or "Thirteen of \`Node\`'s" in PAGE` — the first clause is
   **never true** (`sent` is the integer 13, the page spells the word), so the guard was the
   literal, with a typed `sent == 13` beside it. Neither looked at the **eighteen**, and `Node`'s
   field count moved six times in the preceding month (8, 10, 13, 14, 16, 17, 18). It is a
   partition now: the words are read as numbers, both derived, and the withheld fields are checked
   by **name**.

## A mistake of mine the harness caught

The first three mutations for this change edited the **assertions themselves** — `assert X` to
`assert True or X` — and named the file containing them as the catcher. `mutation_check` reported
`NOT CAUGHT` and `ANCHOR GONE`, and it was right: disabling an assertion and then running the file
that contains it can only pass. Rewritten to break what the guard guards — a document's stated
count, a document's referent, and the payload a claim describes — the same three came back
**3 of 3 CAUGHT**.
