## Read this first, and note where the fourth renderer sits

```
renderer     duplicate_seqs  incomplete_lines  write_errors
markdown          -                Y                Y
html              -                -                -
playback          -                -                -
csv               -                -                -
```

**`duplicate_seqs` reached no renderer at all** — not even the one that carried the other two.
`import_file_store` computes it and lists it **first** among the damage it refuses to import
silently:

```python
damage = []
if document.get("duplicate_seqs"):
    damage.append(f"duplicate seq {document['duplicate_seqs']}")
```

A flag that is computed, named as damage by the importer, and then shown to nobody on the way out
is the shape this ledger keeps finding — and this time the export path had never been swept.

## And the one renderer that crashes is the one with no banner

```
at = 1234 (a turn whose timestamp is not a string)

  _playback   _seconds(1234)                 -> None            survives
  _html       (1234 or "").replace("T"," ")  -> AttributeError   crashes
```

`import_file_store` explicitly enumerates malformed turns — *"turn(s) with no seq"* — as damage it
expects to find. **So the store `_html` crashes on is exactly the store it was going to be handed**,
and it is the renderer that would have said nothing about the damage anyway.

## The fix is one reader, not four banners

`_damage(document)` returns the damage as sentences, and all four renderers call it. The point is
not the three flags; it is that **a fourth flag now arrives everywhere or nowhere**. Before, three
flags were read inline in one renderer out of four, so adding a fourth meant remembering four
places and the existing three were already only in one.

Two of the four needed a place to put it:

- **`csv` gets a `#` comment row.** CSV has nowhere structural for a document-level fact, and a
  spreadsheet shows a leading `#` line as a row of text — visible, which is the point. **A strict
  reader will parse it as data; that is the cost**, and it is smaller than handing someone a
  clean-looking sheet cut from an interrupted write.
- **`playback` gets a `__DAMAGE__` placeholder** beside its existing meta line. `html` folds it into
  `stats`, which is already the line where the page says what it is.

## Risk & rollback

- **Task 7 changes the shape of a CSV export** for a damaged store only. A clean store's CSV is
  byte-identical to before. A strict reader handed a damaged one gets an extra row it will treat as
  data — which is the trade, and it is written down rather than discovered.
- **Task 1 changes three published artefacts** (`html`, `playback`, `csv`) for damaged stores.
  Nothing changes for an undamaged one.
- **Task 6's coercion makes `html` render `1234` as a timestamp** rather than crashing. That is a
  wrong-looking timestamp shown honestly, next to a banner saying the store is damaged — which is
  better than a traceback and better than a clean page.
- **Task 4's rule reads the importer's source with a regex.** A flag named some other way — through
  a variable, or in a helper — slips past it. Narrow on purpose, and the docstring says so.
- Rollback: revert. `duplicate_seqs` reaches nobody again, three exports say a damaged store is
  clean, and `html` raises `AttributeError` on the store the importer expects to find.
