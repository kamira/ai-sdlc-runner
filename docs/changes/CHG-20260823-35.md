## Why this was still open

The ruling was given, reviewed by both seats, and merged **as design**. Three changes later
`--store {file,tinydb,mongo}` was still in the CLI. Found while reading `export --help` for
something else.

That gap is the shape of a defect this repository refuses everywhere else: a decision that looks made
and does nothing. Merging the design closed the argument, not the surface.

## Scope: one clause of three, and why

| | clause | here? |
|---|---|---|
| 1 | *只留 sqlite + file，移除 mongo 和 tinydb* | **yes** |
| 2 | *file 只作為 server 的 config 才處理* | no — conversations into SQLite is a migration with an importer |
| 3 | *sqlite 也包含 model 模型配置* | already done: `store.py` holds `models`, `node_assignments`, `seat_assignments` |

Doing (1) alone leaves `file` as the only conversation backend, momentarily at odds with (2). Three
backends where the ruling wants one is *further* from (2) than one backend is, so this is a step
toward the ruling rather than away from it.

(2) is deferred on the design's own words: `docs/design/sqlite-only.md` says the proposition is
"corrected but still unreviewed in its corrected form" and that "implementation should not start on
the assumption" a fourth review round finds nothing. That is a change needing a review round, not a
rider on a deletion.

## What came out — about 250 lines

Most of it was not backend code. It was **Mongo URI hardening**: `local_mongo_uri`, `_unix_socket`,
`_hardened`, `MONGO_OPTIONS`, `LOOPBACK_HOSTS`, and eleven tests.

That was some of the most carefully reasoned code here. `MongoClient` performs topology discovery,
so a loopback *host* was never the check — a loopback seed that turns out to be a replica-set member
is read from the server and every member it names gets connected to. It needed a single-host
`mongodb://` URI, a host that round-trips to loopback, an option **allowlist**, and
`directConnection=true` forced on the client. An earlier denylist version was got past twice by a
seat: `?proxyHost=…` keeps the seed loopback and routes through somebody else's SOCKS proxy, and
`?replicaset=` walked past a check spelled `replicaSet`.

Deleting it is right and it is still a loss of reasoning, so the README keeps the summary of *why*
it was that shape. Someone will propose a remote store again and the argument should not have to be
rediscovered.

`--store-uri` and `--store-remote` went with it: no store can be off this machine now, so there is
no locality to relax, and a flag that no longer changes anything is the "looks configured and does
nothing" refused everywhere else here. The relaxation `cmd_export` recorded for it goes too — there
is nothing truthful left to record.

## A retired backend is refused by name, not as unknown

```
$ runner export --store mongo
error: the mongo store was removed in CHG-20260823-35; the model registry lives in
SQLite (`store.py`) and conversations in the file store
```

`unknown store 'mongo'` would read as a typo to someone whose config worked last week. `BACKENDS`
stays a tuple — of one — so an actually unknown kind is still refused rather than defaulted: "I
asked for X and got a directory" is this repository's oldest mistake.

## The one guarantee this genuinely weakened

A duplicate `seq` was **refused at write time** by Mongo's unique index and TinyDB's check. Neither
exists now. `file` cannot refuse one without a read per append, so a duplicate is **detected at read
time and prevented nowhere.**

Found by reading a comment that had become false — it said "refused by the two backends that can",
and there are no longer two backends that can. Nothing failed. That sentence would have survived the
removal still claiming a guarantee nothing kept, which is the defect class this project's log is
full of.

Now stated in the module, in the README, and in a test that appends a duplicate `seq` directly to the
file and asserts the reader *reports* it. Acceptable because the design declares one writer per
conversation — and it is the first line that must change if that stops being true.

## Risk & rollback

- **Removes two configurable backends.** An operator with a local mongod and a `--store mongo`
  config gets a refusal naming this change.
- **Removes two flags.** Any script passing them now fails at argument parsing rather than silently
  ignoring them, which is the intended direction.
- One guarantee weakened, documented above rather than discovered later.
- Rollback: revert. No governance definition, gate or risk grade changes.

### Not claimed

**That the ruling is implemented.** One clause of three. Conversations are still in the file store,
which clause 2 says they should not be.

**That nothing used these backends.** Nothing here did, and no test exercised them against a real
server — the eleven Mongo tests all tested the URI *string* rules. What is claimed is that this
repository's own suite and examples are unaffected.

**That the removed reasoning is preserved.** A README paragraph is a summary. The full argument is in
the git history and in `docs/design/reviews/conversation-store-*`.
