## Why it is withdrawn

The conformance seat set the terms in round seven: *re-pin, make every citation true, and if the
next round cannot land conditions 1, 2 and 4, withdraw it on `CHG-20260903-24`'s reasoning.* The
seventh draft landed conditions 1 and 4 and did not land condition 2.

### The residue is one table row, and that is why it decides

Task 9's done-when survived the seventh draft **byte-identical to the sixth**:

```
| 9 | It reaches the durable record, attributed to the signer | **new code**: the existing note is
guarded by `here != DEFAULT_CLASS`, and this is not a class | ... |
```

Three things are wrong with it at once. It carries the **dead polarity** — the tree reads
`if here == policy.DEFAULT_CLASS or not verdict.get("gate"):` — outside the table the record exempts.
It says **new code** and *this is not a class*, both of which the record's own body retracts four
sections above. And the record **affirmatively certifies** that no such text remains: *"The four
rows above are the only place the dead addresses and the dead quotation still appear."*

That is a compliance claim recorded as discharged while it was not, which is verbatim the defect
this record convicts its own third draft of, in the paragraph where it convicts it. Four rounds is
enough evidence that this record cannot make its own correction claims true in the same pass it
states them.

**And the self-check that certified it was mine.** It grepped `here != policy.DEFAULT_CLASS`; task
9's row spells it without the `policy.` prefix. A negative result is only as good as the pattern
that produced it — which is this record's own sentence, applied to the person verifying it.

### Two statements the seventh draft added are false, and both are mine

- **Price item 2** said registering the class makes `combined_class` *"report the registered class
  instead"*. Driven: `combined_class([name])` returns `standard`, and so does
  `combined_class([name, "standard"])`, because the function ends
  `return "emergency" if "emergency" in seen else "standard"`. **Task 21 in the same document says
  exactly this** — *is not reported as `standard`* — so the price table contradicts a task. The
  probe that measured it printed `standard`; it was written up as its opposite.
- **The headline's split-workstream reason** said `class_by_workstream` *"carries no review date"*.
  Measured, `policy.class_in_force` refuses a class without one, per workstream. The true reason is
  the record's own, 285 lines below: `combined_class` degrades to `normal` unless **every** part is
  individually signed, and `cli._change_classes` refuses a run-level class outright.

### The merits point the same way, and would have without the citations

```
marginal reach, single workstream    0     the default shape, and the one the headline is about
marginal reach, split workstreams    1     the cell the signing rule deliberately withholds
cells the enabling step OPENS        5     plan_confirmed · feasibility_confirmed ·
                                           before_dispatch @medium · pr@high · merge@low
```

Task 18 registers the mechanism as a class in `policy.CLASSES`. `policy.relax(graded, klass)`
**takes no node**, and `ChangeClass` has four fields — `name`, `relaxes`, `reviewed_after`, `note`
— none of them node-aware. So a registered class is hand-typeable at `--change-class` (`cli`
validates by `if name not in policy.BY_CLASS:` and nothing else) and reaches **every** `confirm`
cell, the one-way door included.

Task 18 was amended in the seventh draft to say *and bounded to the predicate*. **There is no
mechanism for that bound and there cannot be one where task 18 puts it**: the predicate reads
`graph.Node` fields, and `logical.md`'s *"`policy` depends on nothing"* is the rule that killed this
record's own fourth draft. The only per-node arrival point is `engine._class_in_force`, which
returns before `node` is read on a single-workstream run — the default. A done-when is not a
mechanism.

So: a record whose headline is *marginal reach zero* would ship a typed route to `merge@low` to
narrow one cell it does not reach on the default shape. Its own Risk section already wrote the
ruling — *if that is not worth the price, this record should be refused* — and the refuser's
argument, unanswered through eight rounds, is the design that survives: **binding the predicate to
the route rather than to a class**, which takes marginal reach to −2 and makes 「merge 永遠留一個人」
true on `main` for the first time.

## What is kept, and where it goes

Unusually, the findings are all true and two of them outlive the proposal.

- **`policy.relax` consults no node.** This is the real discovery in the record, and it is the fact
  that makes the record unbuildable. It goes to `README.md` § *Known gaps* under its own entry,
  because it is a property of the program rather than a proposal about it.
- **Two requirements have no owner.** 「可以依節點 by pass」 is named in three records and deliverable
  by none — this record's task 2 forbids naming nodes, and `CHG-20260903-24` is withdrawn. And
  `CHG-20260901-15`'s **second** half is now what its first half became: re-issued into a record
  that produced nothing. Both go to *Known gaps*, which is where this ledger already puts a
  requirement nothing enforces, and where a later record can strike them out.
- **The 10-vs-13 measurement**, which three seats verified independently at two different shas, and
  which is the honest statement of what a per-node predicate would narrow. It belongs to the
  record that builds it.
- **The default-install finding** — `_adjudicate` sits inside `node.mode == graph.MODEL_PANEL and
  len(configured) > 1`, so at `plan_confirmed@medium` with no model configured nothing adjudicated.
  `CHG-20260904-11` shipped `adjudication_here`, which is a per-node runtime answer to *did anything
  look?* — the question this record's static predicate could only approximate. That is a better
  foundation than this record had, and it arrived after it.
