## Read this first: the marginal reach is zero cells

```
cells a project may pre-authorise standingly : 1     plan_confirmed @ medium
cells already reachable on `main` by a class : 5     including that one
marginal reach over `main`                   : 0
```

Every `confirm` cell is already lowerable today by a `standard` or `emergency` class. The whole
delta is **who** may pre-authorise and **for how long** — a project setting rather than a signed,
dated, self-expiring declaration. That is the thing to accept or refuse.

The mechanism is not merely equivalent to the class route; it is **strictly narrower**. A
project-level default change class — the obvious cheaper alternative — lowers all five `confirm`
cells including `merge@low` and `pr@high`. The derived predicate lowers one.

**And 「merge 永遠留一個人」 is still false on `main`.** `risk: low` plus a signed `standard` class
makes `merge` `auto`, and `_permanent_halt` passes because the shipped example plans declare merge
`{"kind": "ordinary"}`. This design cannot reach `merge`, which is not the same as securing it. That
requirement needs its own change and it is not this one.

### The entailment into CHG-20260903-24 does not hold, and is withdrawn

The first draft said `gate_when` *"also derives CHG-20260903-24's task 10 for free, so the exemption

### The entailment that does hold, and its condition

At an `after` gate the run has produced and recorded a judgement of its own before the door opens; at
a `before` gate nothing has looked but the clearance itself. A standing pre-authorisation is
defensible only where something other than the pre-authorisation looked.

**And that is conditional, which the first draft could not see because the measurement lives in
-24.** On a default install (`node_models = {}`) `pm_confirm` takes the single-ask path and produces
**no adjudication** — so at the one cell this design pre-authorises, nothing looked either. That is a
finding against this record and it belongs here, beside the zero.

## Where it lives: `policy.verdict`, and the reason it was abandoned is false

## The rung was copied; the contract it belongs to was not

`relax`'s bound is one half of a pair. The other half is `policy.class_in_force`, which refuses a
class with no `authorised_by` — *"A pre-authorisation nobody signed is a relaxation on nobody's
authority"* — and no `review_by`, and expires it back to `normal` past that date.

The class route to `plan_confirmed@medium` is signed, dated and self-expiring; a project table would
be anonymous and permanent unless both are required. **That is the entire marginal risk of this
design.**

And the two are handled differently: **an expired row degrades to "the gate stops"; only a malformed
one refuses.** A per-change class is typed this run, so refusal is right. A project table is ambient
and long-lived — raising on the review date would brick every run in the project. `class_in_force`
already has exactly this asymmetry; the honest sentence is *copy the contract, including the
asymmetry it already has*, not that no earlier draft said it.

## The headline number is 0 on one shape and 1 on the other, and the record said 0

The risk seat's R3, re-measured with the repo's own fixture:

```
a split programme, both workstreams pre-authorised by a person
  pm_confirm   class in force: standard   ->  reaches plan_confirmed@medium

a split programme, one workstream signed and one not
  pm_confirm   class in force: normal     ->  does NOT reach it
```

`pm_confirm` runs before `plan_scope`, so it belongs to no workstream, so `_class_in_force` takes
the combined branch and `policy.combined_class` reads *"any workstream without an in-force class →
`normal`"*. Upstream, `cli._change_classes` **refuses** a run-level class over a split programme
outright: *"one sentence cannot have assessed all of these"*.

So on a split programme the class route reaches that cell **only when every part is individually
signed and dated**, and a project table is ambient over the whole project with no analogue of
either guard. **Marginal reach there is 1, not 0** — and it is the one cell the class route was
deliberately built not to reach without every signature.

The words `combined_class`, `workstream` and *split programme* appeared **zero times** in this
record before this draft. The "strictly narrower" argument was measured on the `relax` cell-reach
axis alone, which is true and is not the whole question.

**Task 17 (new): the guards `combined_class` and `_change_classes` provide are reproduced, or the
mechanism is refused on a split programme.** Whichever the next round decides, the headline says
*0 on a single-workstream run, 1 on a split one* rather than *0*.

## The synthetic class cannot be fed to `relax` as written, and the price is named

The fifth draft settled the placement as *"a synthetic class fed to `relax`"*. Measured:

```
policy.relax("confirm", "project_preauth")        PolicyError: no change class 'project_preauth'
policy.combined_class(["project_preauth"])        "normal"   — silently discarded
```

**Two opposite failures on the same input**: a `PolicyError` that kills every single-workstream run,
and a silent no-op on a split programme — which is the very axis this record's split-programme
finding is about.

`combined_class` reads `seen = [n if n in BY_CLASS else DEFAULT_CLASS for n in names]`, so an
unregistered name is not an error there; it is a downgrade nobody is told about.

So the name must be **registered in `policy.CLASSES`**, and that has a price this record must pay
rather than assume:

- `CLASSES` moves back onto the **falsified** list. The fifth draft took it off on the ground that
  it *"describes this design rather than being falsified by it"*; a class this record adds is a
  class the paragraph's *"a person's judgement about a type — made once, written down, and
  revocable"* has to cover, and a project table is not made once by a person for a change.
- `combined_class`'s tail is `return "emergency" if "emergency" in seen else "standard"`, so a run
  relaxed by the new class would be **reported as `standard`** on a split programme. That is a
  wrong sentence in the durable record, and it is task 21.

## Risk & rollback

- **The marginal reach is zero cells**, and the contribution is that it is *narrower* than what
  already ships. If that is not worth six text rewrites, twenty tasks and two annotated acceptance
  records, **this record should be refused** — and one seat says plainly that it would refuse it.
  The number is in the first section so that decision can be made there.
- **The strongest argument against it, which its refuser makes:** *narrower than what already ships*
  argues for **replacing** the class route at this cell, not adding a second mechanism beside it.
  The one edit that changes that answer is binding `relax` by the same predicate, which would take
  the marginal reach from zero to **negative two** and make 「merge 永遠留一個人」 true on `main` for
  the first time. **That is a different record and this one does not build it.**
- **The reachable sequence nobody wrote down:** `pm_confirm.rejects_to = "pm_plan"`, so the one cell
  is re-enterable. A person rejects the plan → the model revises it → the standing pre-authorisation
  passes the revision with no person. The class route has the same shape, so this adds no reach —
  but it is the worst-reading sentence about this design and it belongs here.
- **`_permanent_halt` is unchanged and is not a defence this design provides.** It checks
  declarations, not actions.
- **The `--confirm`-opens-a-`halt` defect is now carried.** The first draft named it, scoped it out
  and said it was *"carried out separately"* — and nothing carried it for a day. It is
  **CHG-20260903-27**, shipped, along with the ruling that a blanket `--confirm` cannot open
  `halt_independent` while a person answering the stop can.
- Rollback: revert. Every gate answers cold and the six texts read as they did — noting that a
  text this record makes *incomplete* does not become “true again” on revert, which is the
  distinction the sweep exists to draw.
