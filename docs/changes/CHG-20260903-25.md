delta is **who** may pre-authorise and **for how long** — a project setting rather than a signed,
dated, self-expiring declaration. That is the thing to accept or refuse.

to `1` on a split-workstream run 280 lines below, in a section headed *the headline number is 0

project-level default change class — the obvious cheaper alternative — lowers all five `confirm`
cells including `merge@low` and `pr@high`. The derived predicate lowers one.

`{"kind": "ordinary"}`. This design cannot reach `merge`, which is not the same as securing it. That
requirement needs its own change and it is not this one.

## The rung was copied; the contract it belongs to was not

`relax`'s bound is one half of a pair. The other half is `policy.class_in_force`, which refuses a
class with no `authorised_by` — *"A pre-authorisation nobody signed is a relaxation on nobody's
authority"* — and no `review_by`, and expires it back to `normal` past that date.

The class route to `plan_confirmed@medium` is signed, dated and self-expiring; a project table would
be anonymous and permanent unless both are required. **That is the entire marginal risk of this
design.**

And the two are handled differently: **an expired row degrades to "the gate stops"; only a malformed
one refuses.** A per-change class is typed this run, so refusal is right. A project table is ambient
and long-lived — raising on the review date would brick every run in the project. `class_in_force`
already has exactly this asymmetry; the honest sentence is *copy the contract, including the
asymmetry it already has*, not that no earlier draft said it.

## The synthetic class cannot be fed to `relax` as written, and the price is named

The fifth draft settled the placement as *"a synthetic class fed to `relax`"*. Measured:

```
policy.relax("confirm", "project_preauth")        PolicyError: no change class 'project_preauth'
policy.combined_class(["project_preauth"])        "normal"   — silently discarded
```

**Two opposite failures on the same input**: a `PolicyError` that kills every single-workstream run,
and a silent no-op on a split programme — which is the very axis this record's split-programme
finding is about.

`combined_class` reads `seen = [n if n in BY_CLASS else DEFAULT_CLASS for n in names]`, so an
unregistered name is not an error there; it is a downgrade nobody is told about.

So the name must be **registered in `policy.CLASSES`**, and that has a price this record must pay
rather than assume:

- `CLASSES` moves back onto the **falsified** list. The fifth draft took it off on the ground that
  it *"describes this design rather than being falsified by it"*; a class this record adds is a
  class the paragraph's *"a person's judgement about a type — made once, written down, and
  revocable"* has to cover, and a project table is not made once by a person for a change.
- `combined_class`'s tail is `return "emergency" if "emergency" in seen else "standard"`, so a run
  relaxed by the new class would be **reported as `standard`** on a split programme. That is a
  wrong sentence in the durable record, and it is task 21.
