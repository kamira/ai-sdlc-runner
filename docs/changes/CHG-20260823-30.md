## The worst thing: I closed the complaint, not the finding

The silent dry run is **still producible with keys the closed schema accepts**:

```
plan.check({"ship": {"repo": ".", "chg_id": "CHG-X", "branch": "b", "message": "m",
                     "acc_id": "ACC-9", "acc_body": "evidence"}})   -> ACCEPTED
cli.effects_provider(p)("record_module")                            -> []
```

`record_effects` is called only `if task`. So `acc_id` and `acc_body` without one are read by
nothing: the acceptance record is never written, nothing refuses, and the run reports `finished`.

Every key was in `SHIP_FIELDS` and all four required ones were present. **The closure answered the
misspelling and left the case one conditional deeper** — inside the very block it closed, against a
docstring quoting the doctrine it was breaking.

Now refused, and so is its mirror: a `task` with no `acc_id` has no identity to be written under.

## The chart claimed a check that did not exist

Four contradictions stood in it at once — the legend still calling the plan the open one that
matters, *"two of them are closed"* over three closed chips, *"four are enforced"* over its own
legend saying five — and the footer said it was **pinned by four named tests**.

**None of them read it.** A seat grepped `tests/` and found zero hits.

Claiming a check is worse than having none, because it stops anybody looking.
[`tests/test_schema_atlas.py`](../../tests/test_schema_atlas.py) exists now — eight tests, including
one that refuses the page naming a test that does not read it.

## The test that guessed what it said it counted

`test_the_test_count_the_readme_states_is_the_real_one` subtracted the skips, with a comment saying
they were *"counted, not guessed."*

**They were always guessed.** `pytest --collect-only -q` never emits `SKIPPED`, so the fallback
constant ran on every machine. Both skips here are `curses` importorskips — on CI's Ubuntu they
**execute**, so `pytest -q` prints two more passes than this machine, the README's number was false
there, and the test passed anyway because it subtracted the same constant everywhere.

The README now states a **collected** count, which is machine-independent, and the test compares
collected to collected. How many pass on a given machine is a property of that machine.

## The near-miss: I nearly refused correct plans

My first `decisions` check took only a string. **Twenty-five existing tests caught it** — a decision
is legitimately three forms, and `_choose`'s own docstring names them: a label, a sequence consumed
one per visit, or `"frontier"`.

That is the other failure mode of a closed schema, and it is the worse one: not accepting what it
should refuse, but **refusing what it should accept** — a plan that was correct stops working and the
message calls it malformed. It reached the suite and not a user because the suite already drove all
three forms.
