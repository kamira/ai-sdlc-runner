## The question, and the answer

**Model configuration is two halves, and only one of them is persisted by anything.**

| | What it is | Where it lives | Who writes it |
|---|---|---|---|
| **Registry** | *which models exist* | `models.json` → the `models` table | the operator, via `POST /models` — **and it persists** |
| **Assignment** | *which node and which seat gets which model* | the plan's `node_models` / `seat_models` | **nobody** |

Verified rather than assumed:

```
any POST touching assignments? False
any POST touching node_models? False
does /config/nodes write anything? False
assignments is built once, at cli.py:704, from plan.get(...)
```

`assignments` is read from the plan at startup, held in memory, exposed **read-only**, and there is
no writer anywhere in `src/`.

## Why that is defensible, and why it is still a half-feature

**Defensible**, because `Registry`'s own docstring draws the line — *"the models this project may
use, and nothing about which node uses which"*. An assignment is a property of **this change**, not
of the project. The plan file is its durable home, and it is the file a person version-controls.

**A half-feature**, because through the console you can **add a model and cannot assign it to
anything**. It appears in `by_model` with empty `nodes` and `seats` and stays there until somebody
hand-edits the plan.

Neither page said any of this. `DATABASE.md` had a `models` table and never explained that the other
half lives elsewhere; `MODELS.md` had one table row saying the assignment "is not closed" and nothing
about it never being written.

## The ambiguity I resolved silently, now named

The ruling says:

> 「sqlite 內容不僅限於紀錄，也包含 **model 模型配置**的紀錄儲存」

**「模型配置」 reads two ways**, and I took the narrow one without saying so:

1. **the registry only** — what the `models` table holds;
2. **the registry *and* the assignment** — which needs two more tables and the API routes to fill
   them.

I chose (1) because `Registry` draws that line itself. **That is exactly the move a previous round
of this same design was refused for** — deciding an ambiguity silently instead of naming it — and the
user's question is what caught it. It is now `DATABASE.md` §0.2, as an open decision.
