## Motivation
The resident dashboard redraws on **every keystroke**, and each redraw recomputes expensive I/O:
`DashboardModel.status_panel()` shells out to `git` **3×** (rev-parse / branch / status --porcelain)
and reads `state.json` + `.sdlc-lock.json`, while `verify_panel()` globs and reads every file under
`docs/acceptance/`. So typing runs 3 git subprocesses + several disk reads **per character** — the
real source of any typing lag (not the curses-vs-Ink framework choice; curses already delta-renders).
Cache those results and refresh them only on real events, so keystrokes do zero subprocess/disk I/O.

## Decisions & trade-offs
| Decision | Options | Assumptions | Why this choice |
|----------|---------|-------------|-----------------|
| Where to cache | inside `DashboardModel` vs in the resident layer | snapshot path calls panels once; resident calls per keystroke | Cache in `DashboardModel` with an explicit `refresh()` invalidator — the snapshot path (`render_snapshot`/`runner dashboard`) computes once as today (cache cold → compute), the resident loop reuses the cache. |
| When to refresh | per keystroke vs event-driven vs timer | git dirty/ACC change only on real actions | **Event-driven**: refresh on app start, on `/open`, and after each run completes/halts. (A periodic timer for live dirty-status is a possible later follow-up; not needed to kill the lag.) |
| Framework switch (Ink/Textual) | rewrite vs stay | runner is stdlib-only, zero-dep | **Rejected** — a Node/Ink or Textual rewrite adds a heavy dependency against the runner's design and would not beat caching for a small TUI. |

## Modification Guide
### Goal
Zero `git`/disk I/O per keystroke in the resident dashboard; the expensive panels (status git-lines +
lock/state, verification ACC list) are computed on real events and cached; snapshot behavior unchanged.

### Impact scope
| Affected item | Type | Change | Knock-on |
|---------------|------|--------|----------|
| `src/ai_sdlc_runner/dashboard.py` | logical | `DashboardModel`: memoize the I/O-bound panel bodies (`status_panel` git+lock+state lines, `verify_panel` ACC reads) behind cache fields; add `refresh()` that clears them so the next call recomputes. `status_panel`/`verify_panel` compute-if-cold-then-cache, else return cache. `exec_log_panel`/`agent_panel` stay live (in-memory events, cheap). `ResidentApp`/`run_resident`: call `model.refresh()` on start, on `/open` (`ResidentState.open_project`), and after each run in `_start_run`. Per-keystroke `render_layout` now hits only the cache. | input redraw cost |
| `tests/test_dashboard.py` | logical | Prove I/O is O(events) not O(keystrokes): inject a counting fake `git`/reader (or monkeypatch `_git`) and assert `status_panel` called N times after one `refresh()` triggers the git work **once**, not N; `verify_panel` similarly; `refresh()` invalidates. Snapshot path still renders correctly. | regression |
| `docs/ARCHITECTURE.md` / `README.md` | docs | one line: resident redraw is cache-backed (no per-keystroke git/disk); refresh on open/after-run | — |
| `docs/structure/design.md` | design | note the resident render cache + refresh points | truthful structure |
