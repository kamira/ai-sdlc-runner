## Read this first

`CHG-20260904-13`'s subject was *a guard satisfied by prose about the defect*. It fixed three and
left the same shape in four more, plus one it created.

### The strip knew two comment syntaxes and the page has three

`_console_code()` is applied to an **HTML** file whose first fifteen lines are a `<!-- … -->` block.
Blanking the read and naming the field inside that block left **98 passed** — `CHG-20260904-11`'s
defect and `-13`'s two fixes, restored through the syntax neither knew.

### And it read prose as JavaScript, so one apostrophe disabled it

Scanning a whole HTML file under JS quoting rules means a possessive in *markup* opens a string
that never closes. Measured on the shipped page:

```
                                              `//` surviving the strip
as shipped                                     2 of 70   (both inside string literals: http://)
one apostrophe in prose                       17 of 70
```

Both existing floors anchor past the point where the next apostrophe re-syncs, so neither fired.
Markup is removed first now, and quotes are tracked inside `<script>` only — which is where a quote
means a string.

**And the disclosure about this was false twice.** `ACC-20260904-13` reservation 2 said the scanner
does not know regex literals and that *"nothing in the console uses one"*. `index.html` has carried
`var m = /token=([^&]+)/.exec(location.hash);` since the commit that wrote the console. The failure
direction was backwards too: `/x\/y/` passes through untouched, while a **quote** inside a regex
opens a string that never closes — a false pass, not a false failure. A floor now asserts the
scanner reaches the end of the real page with no string open, which would have caught the sentence
at the time it was written.

### The sibling of L-46, in the same file, left on the raw page

`test_every_report_field_is_rendered_or_written_down` still read `_console()`. Five report fields —
`asks`, `halt_reason`, `halted_at`, `options`, `verdicts` — are not snapshot keys, so they had no
other guard: deleting the only rendering of `options` and leaving a trailing comment left
**98 passed**.

### The console guard banned one spelling of the rule `-24` was withdrawn over

`state.adjudication_here || state.adjudications.at(-1)` satisfied both assertions — the field is
read, and the banned text does not appear — and restores the withdrawn defect exactly: at `merge`
on a default install `_adjudication_for` returns `None`, the fallback fires, and the one-way door is
pre-answered with `lead_review`'s verdict on built work. Measured: **117 passed**. What is refused
now is the box reaching into `state.adjudications` at all.

### The decision rule enumerated, in both directions

`taken & wanted` let a method taking `stop` and calling `self._answering(gate=stop)` intersect to
nothing and pass. Requiring every name `_answering` declares was too strong the other way: `rule`
answers a tie, which has no gate.

The invariant under both does not enumerate: **every stop name a method writes into the durable
record must be one it handed to `_answering` first, and the same value.** `rule` records no gate,
so it owes none. `DECISION_LISTS` is written once now rather than three times — the floor that
exists to notice a new decision method selected methods with the same set, so a method appending to
a fourth list was invisible to it.

### And a guard that asserted a position rather than a grouping

The `reason` guard read *everything below the first tie divider*, so the mirror-image error — the
page saying `reason` is incomplete-only, equally false — passed with **254 tests green**. A field
belongs to whichever group its nearest divider above names; `reason` is carried by two questions,
so it belongs above both.

## Task 9 - the reservation was refutable

`ACC-20260904-13` said reverting `page = _console_code()` was unpinnable while no snapshot key is
prose-only. The defect seat supplied the shape: plant both halves — a key that reaches no front end,
named only in a comment — and monkeypatch, because `_console_code()` resolves `_console` at call
time. No source text is read. It is a test now rather than a reservation.

## Task 10 - the ground every measurement in this session stood on

`site-packages/__editable__.ai_sdlc_runner-*.pth` points at whichever checkout it was installed
from — in practice the **main** one. A bare `pytest` inside a worktree therefore imports
`ai_sdlc_runner` from somewhere else, and a seat measuring a `src/` mutation that way got
`98 passed` where the same mutation with `PYTHONPATH=src` gave `3 failed`.

The repo's own harness sets it and was never exposed. Everything else is. `pytest_configure` now
refuses to run when the imported package is not this tree's, and names both paths.

## Risk & rollback

- Task 10 makes a bare `pytest` a usage error inside a worktree. CI installs editable from its own
  checkout and passes; a person who has not set `PYTHONPATH=src` gets a message instead of a wrong
  answer.
- The strip is two passes now. Both are used only by guards; no product code reads either.
- Rollback: revert. Six guards go back to being satisfied by something other than what they check.
