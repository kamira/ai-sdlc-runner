## The number that nothing could check

A seat once caught the README claiming *"847 passing"* when 857 did, and noted it was **the one
figure `test_documented_numbers` cannot see** — because a suite cannot count itself while running.

It can in a subprocess. `test_the_test_count_the_readme_states_is_the_real_one` runs
`pytest --collect-only -q` and compares.

**It caught a stale number the moment it existed.** I wrote 1083; the suite collected 1086. Then it
caught the second version too: 1086 is the *collected* count, and `pytest -q` prints **1084 passed,
2 skipped** — so a README saying 1086 would have been checkable and still wrong. The test now
compares collected-minus-skipped, which is the number a run actually prints.

Stating a number nothing checks is how the first one drifted. The answer is to check it, not to stop
stating it.
