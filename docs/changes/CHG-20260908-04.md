## What the item said, and what nobody had measured

The item, handed off by a seat in the previous phase and carried through two builds of this record:

> `tests/test_paths.py`'s long-path tests have no `finally` and no `\\?\`, so every run that
> includes them leaves an immortal `pytest-N`.

Two builds were written on that. Both measured `shutil.rmtree` on a plain path, watched it fail with
`WinError 3`, and **attributed the failure to pytest**. Nobody ran pytest's cleanup.

**pytest prefixes the path.** `_pytest/pathlib.py`, installed version 9.1.1:

```python
def rm_rf(path: Path) -> None:
    path = ensure_extended_length_path(path)      # adds \\?\ on Windows
    ...
    shutil.rmtree(str(path), onexc=onerror)
```

`maybe_delete_a_numbered_dir` does the same before its rename. Measured end to end with
`PYTEST_DEBUG_TEMPROOT`, running the two chain-building modules four times with no fixture at all:

```
after run 1   pytest-0
after run 2   pytest-0  pytest-1
after run 3   pytest-0  pytest-1  pytest-2
after run 4             pytest-1  pytest-2  pytest-3
```

`pytest-0` held 84 top-level directories, 474 entries, 17 of them past 259 characters, deepest 391.
pytest removed it — deep chains and all — with no warning.

## Then why are there stranded directories on this machine?

Because they are **locked**, not because they are deep:

```
pytest-6937   .lock present   30 entries   2026-09-07 03:06
pytest-7669   .lock present   49 entries   2026-09-08 19:00
pytest-7884   .lock present  826 entries   2026-09-08 23:43
```

`_pytest.pathlib.ensure_deletable` returns `False` while a lock file exists and is younger than the
cutoff, and `try_cleanup` skips the directory. Every stranded basetemp on this machine carries one,
and `pytest-7884` at 23:43 with 826 entries is a **full suite this session started in the background
and killed** — the operator's own doing, not the suite's.

So the item's premise is false in both halves: the directories are not immortal, and the tests that
build deep chains are not why they are there.

## What was built and is not shipping

Two builds, both refused, and the refusals are worth keeping because they were right about
everything except the thing that mattered:

- **First build**: an autouse fixture in `tests/test_paths.py` calling
  `shutil.rmtree(paths.real(tmp_path), ignore_errors=True)`. Both seats refused: a removal that
  cannot fail keeps every test green while the problem continues. The running seat measured the case
  where it bites — `test_sqlite_opens_at_that_depth` failing before `db.close()`.
- **Second build**: the fixture moved to `tests/conftest.py`, named rather than autouse, warning when
  a survivor reached past 259 characters, with a second module opted in that a sweep had found. The
  reading seat refused three more: the warning measured the **prefixed** path against the plain
  limit and so reported every depth four characters too high, `os.walk` errors were swallowed, and
  the record marked *"every module that builds a chain opts in"* as passing with nothing enforcing
  it. All three were repaired, and a guard was added that goes red when a chain-building module
  drops its mark.

None of it ships, because there is nothing for it to fix.

## Sentences these records made that measurement refuted

Kept rather than deleted, per this ledger's convention. Every one of them was written confidently
and none was measured before a seat measured it:

- ~~*"nobody — not pytest, not Explorer, not `rmdir /s` — could delete"*~~ — `rmdir /s /q` returns
  exit 0 and the directory is gone.
- ~~*"`os.walk` stops at 227 characters"*~~ — plain `os.listdir` succeeds at 250 and first fails at
  256.
- ~~*"the first count reported zero because the walk could not descend"*~~ — plain `os.walk` returns
  74–75 of 79–83; both zeros came from a `/c/…` path Python on Windows does not resolve.
- ~~*"320-character chains"*~~ — the chain stops at the first boundary at or past 320; 345, 359,
  365, 391, 400, 402 were all measured.
- ~~*"11.7s against 1.1s"*~~ — does not reproduce; 0.87–1.38s against 0.66–0.82s.
- ~~*"each holding four of these chains"*~~ — three from `test_paths`, one from the other module.
- ~~*"45 top-level directories, 351 entries"*~~ — 84 and 479 under default retention; the quoted
  figures came from a run with a non-default retention policy.
- ~~*"30 top-level directories survive plain rmtree"*~~ — 74; 30 was where the abort happened in
  listing order, which is not a property of the tree.
- ~~*"what survives reaches N characters"*~~ — N was the prefixed length, four too many.
- ~~*"pytest's own cleanup is what fails"*~~ — the whole premise. It does not.
