## Why

The user, verbatim:

> 若可以的話在dashboard 上顯示使用額度與剩餘額度

## What can be measured (survey)

- `claude -p --output-format json` prints `total_cost_usd` and `usage` (input, output, cache-read,
  cache-creation tokens). It prints **nothing about remaining quota**.
- `codex exec --json` prints `thread.started{thread_id}` and `turn.completed{usage}` on stdout.
  Remaining quota (`rate_limits.primary/secondary`: `used_percent`, `window_minutes`, `resets_at`)
  is written **only** to its local session log, `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-*-<thread_id>.jsonl`.
- Any other backend (a stub, a script, `ollama run`) reports neither.
- The runner today merges a JSON reply's keys into the answer (`cli._Process.ask`) and records no
  usage anywhere.

## What changes

1. **Per-ask usage, read from what the backend printed.** A new `usage.py` reads one ask's reply:
   claude's JSON shape, or codex's JSONL events (plus the rate limits from the session log of
   *that* thread). Anything else is recorded as "not reported", never as zero.
2. **The run report carries it.** `RunReport.usage`: one entry per ask (node, model, kind, cost,
   tokens, remaining windows with reset time and the time of the reading), and a summary (cost and
   tokens per model; the latest reading of each remaining window).
3. **`GET /usage`** returns `{run, asks}`: the summary for the server's current or last run, and the
   per-ask list. Staleness in both is judged when the request is served.
4. **A console panel** shows used (cost, tokens per model) and remaining (percentage, window,
   reset time, "as of"). Where the backend does not report remaining, it says so in words.

## Interpreted, and what it was chosen over

- **"剩餘額度" is shown only where a backend states it.** Today that is codex's rate-limit windows.
  Claude's CLI states no remaining quota, so the panel says "not reported by this backend" rather
  than estimating one. Chosen over an estimate from a plan's price list, which would be a number
  the runner made up (KN-15: unknown is not safe).
- **A reading is dated, and a window past its reset says the reading is stale** instead of showing
  the old percentage as current. Judged when the reading is read (`GET /usage` with the server's
  clock; the console again on each redraw against its own, and an idle page redraws by a timer at the earliest reset ahead), not when the ask ran.
- **The codex log is read for the runner's own thread only**, located by the thread id the runner
  just received, read-only, and only the `rate_limits` field is kept. Chosen over scanning the
  newest session log, which could be another program's session.
- **Claude's cost is an API-equivalent figure** as the CLI prints it; on a subscription it is not
  money spent, and the panel labels it that way.
- `runner setup` now proposes the JSON output flags (`--output-format json`, `--json`) because
  without them no backend reports usage, and the runner unwraps those envelopes to read the answer;
  chosen over requiring a user-written wrapper script, which would make the panel empty for
  everyone using setup's proposal.
