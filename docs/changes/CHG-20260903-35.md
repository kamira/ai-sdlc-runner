## FR-20 — a P0 that is false about `main` and disagrees with another P0 in the same table

`settings.FIELDS` holds **three** names, and the third is not decorative. Measured in
CHG-20260903-28:

```
policy.unverified({kind: ordinary, targets: ['npm ci']}, ())        -> ('npm ci',)  on_trust=True
policy.unverified({kind: ordinary, targets: ['npm ci']}, ('npm',))  -> ()           on_trust=False
```

`engine.py` refuses on that tuple. So the third setting **standingly clears a refusal**, which is
not the seat floor. That record rewrote `settings.py`'s own paragraph for exactly this and did not
reach the requirement table.

And FR-20 disagreed with **FR-13**, three rows above and also P0: *"**Both** the seat count and the
mode are set on a screen and persisted."* Two settings where FR-20 said one. **Two P0 rows in one
table disagreeing about the size of the same surface is worse than either being wrong alone.**

The row now **names** the surface — *"Settings reach `settings.FIELDS` and nothing outside it"* —
rather than counting it, so it follows `FIELDS` instead of drifting from it. The original text and
the measurement are kept beneath it.

## `can_execute` — a bound no mechanism reads, and the rule that catches the next one

`policy.py` says *"`can_execute=False` because planning is not building, and **a planner that could
run commands would be an engineer with a different name**."* Measured, `planner` and `engineer`
receive the identical sandbox at the same grade — the same bwrap argv. `sandbox_for(risk,
can_write)` does not take the flag.

`tests/test_sub_planning.py` pins `caps["can_execute"] is False` — **the dict value**, green whether
or not anything enforces it. That is the class `tools/mutation_check.py`'s own docstring warns
about: *"can the tests I wrote fail?", never "did I write the test for the case that matters?"*

**Not enforced here.** Denying exec needs the mechanism to do it, which neither `bwrap --ro-bind`
nor the seatbelt profile does, and that is its own change. What is fixed is that the module stops
describing a bound it does not draw.

**And the fix is a rule, which immediately found a second flag.**
`test_a_capability_flag_is_either_enforced_or_says_it_is_not` compares `Role`'s `can_*` fields
against `sandbox_for`'s parameters and requires a written declaration for every difference. It went
red on `can_spawn` — which **is** enforced, but by the graph's shape (`sub_plan` is the only
spawner) rather than by any argv. That is now said where a reader looking for the enforcement would
look.

## The one-seat panel — and the report was right about the fact and I was wrong about the fix

`resolve_seats`'s refusal message reads: *"one reviewer is the single point of view the panel exists
to avoid, so this runner does not lower the floor by itself."* And `high_risk_mode` lifts it to
**exactly one reviewer**. Both keys are `settings.FIELDS` entries, so the guard and the thing that
lifts it are two lines of one file.

My first instinct was to make the floor **2** under high-risk mode. **Checked before acting: five
tests drive `review_seats: 1, high_risk_mode: True`**, including `test_panel_diversity.py`, and
`_note_panel_diversity` is deliberately blind below two sessions. One seat is allowed **on
purpose**, and refusing it would have turned five deliberate tests red.

So the finding is not the floor. It is that the consequence was never said:

```
1 seat, split   -> fail          <- `undecided` unreachable: seat_names(1) is the veto-holder
2 seats, split  -> undecided
3 seats, split  -> pass
```

At one seat `adjudicate` reaches two of its three outcomes, and the missing one is the one *"an even
split has not decided anything, and returning `fail` would send the work back on nobody's
judgement"* exists to produce. The exemption now carries its own consequence.

## `seat_models` — a validation loop that walked a key it never checked

```python
for key in ("node_models", "seat_models"):
    for owner, value in (payload.get(key) or {}).items():
        if key == "node_models" and not isinstance(value, (list, tuple)):
            raise PlanError(...)
```

The **whole body** is guarded by `key == "node_models"`, so iterating `seat_models` checked nothing.
The guard is right — `store.seat_models(db)` is `Dict[str, str]` — but `seat_models` then got **no
shape check at all** where `node_models` gets one, and the failure is silent rather than merely
unchecked: `cli.py` does `argv = seat_argv or default`, so an operator who configured the defect
seat and mistyped the value gets the **default backend** with nothing said.

That is the class `cli.py`'s own comment names: *"configuration that looks connected and does not
govern execution."*

## Risk & rollback

- **Task 7 is a tightening on plan loading.** A plan carrying `seat_models: {"defect": ""}` loads
  today and is refused afterwards. Anything relying on it was being dispatched to the default
  backend without knowing.
- **Tasks 1, 3, 4 and 5 change sentences, not behaviour.** `can_execute` is still unenforced and the
  one-seat panel is still permitted; what changes is that neither is described as something it is
  not. **A seat may rule that `can_execute` should have been enforced instead** — that needs the
  sandbox mechanism to deny exec and is a larger change than this record.
- **Task 2's rule is a phrase match on one row shape.** A requirement that counts the surface in
  different words slips past it.
- **The one-seat disclosure is in a docstring**, which an operator does not read. A stronger fix
  would put it in `report.relaxations` beside the seat-floor line that is already written there.
  Not built here.
- Rollback: revert. A P0 row is false again, two capability flags claim bounds nothing draws, the
  one-seat exemption hides its cost, and a mistyped seat assignment dispatches the default.
