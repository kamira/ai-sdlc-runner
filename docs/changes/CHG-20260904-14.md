## Read this first

In a fresh worktree at this sha:

```
pytest tests/test_documented_numbers.py -k example_path

  these example paths are cited by source as evidence and do not exist:
  ['src/ai_sdlc_runner/worktree.py: examples/minimal/greet.py']
```

`git log --all -- examples/minimal/greet.py` is **empty**. The file has never been in the
repository, `.gitignore` carries `examples/*/greet.py`, and `git ls-files examples/minimal/` gives
four files that are not it.

It passes in a full run because **another test manufactures it**. `tests/test_change_classes.py`
runs the real CLI against `examples/minimal/runner.yaml`, whose agent writes `greet.py`, and
`test_change_classes` sorts before `test_documented_numbers`:

```
fresh worktree, that file alone                    1 failed
fresh worktree, test_change_classes.py first       greet.py appears in examples/minimal/
then that file alone                               1 passed
```

No `pytest-randomly` is installed, so the ordering is stable and the pollution is reliable. The
rule's own docstring is *"the instance was cited four times and existed nowhere"*. It is now
satisfied by the suite producing the file it checks for.

## The rule asks the wrong question

`worktree.py` cites `examples/minimal/greet.py` three times, and every one of them is **about it
being a build artefact**:

```
"`examples/minimal/greet.py` is exactly that case"
"where `examples/minimal/greet.py` lives, and a run that produced it and then deleted the ..."
"content - `examples/minimal/greet.py` is one - and a build normally leaves them in your ..."
```

A file whose whole point is that a run produces it is **deliberately not committed**, and the
`.gitignore` line is where that decision is written down. The rule asks `(root / what).exists()`,
which is neither *a reader can open this* nor *this is an artefact* - it is *something put it here*,
and something did.

So the predicate changes from existence to **provenance**:

- **tracked by git** - a reader who clones can open it. That is what a citation offers.
- **ignored by git** - the citation is about an artefact, and the ignore is the repository saying
  so on purpose.
- **neither** - the failure this rule was written for, and the one it caught: a path cited as
  evidence that nobody can produce or find.

`.exists()` leaves the predicate entirely, which is what makes the answer the same whether or not
another test has run first.

## Task 5 - what is not fixed here, and why

The suite writes `examples/minimal/greet.py` into the tracked source tree on every run. Measured:
moving the subprocess's `cwd` from the repo root to the temporary directory changes nothing -
`88 passed`, and the file appears anyway. The agent writes it beside the config it was given, so
this is the example's own behaviour under the shipped runner, not the test's choice of directory.

Changing that means changing what `examples/minimal/` does, which is a different subject. What this
record removes is the **dependence** - the rule is order-independent now, so the pollution can no
longer decide a verdict. That the suite still dirties the working tree is stated rather than
quietly left.

## What a clean checkout says, before and after

```
                                        before            after
pytest -k example_path, fresh worktree   1 failed          1 passed
the same, after test_change_classes      1 passed          1 passed
mutation_check --only provenance         BASELINE RED      baseline ok, all 4 caught
```

The middle row is the finding: two runs of the same command on the same commit gave two verdicts,
and the harness was honest about it — it printed `BASELINE RED` and refused to measure — but only
on a tree where nobody had run the suite yet. The two mutations under that baseline were
unmeasurable on a clean checkout while the records reported the green reading.

## Risk & rollback

- The rule now shells out to `git`. Where `git` cannot answer, it **skips with a message** rather
  than passing, on the same argument `tools/ledger_check.py` makes for an unresolvable ref.
- A path that is tracked *and* ignored cannot happen; tracked wins and the rule says so.
- Rollback: revert. `main` goes back to red on a clean checkout and green in CI by accident.
