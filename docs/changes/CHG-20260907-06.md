# CHG-20260907-06 - a run stopped by a failed effect reported that it had finished

- Project: ai-sdlc-runner
- Branch: claude/chg-20260907-06
- Date: 2026-09-07 (UTC+0)
- **Measured against `origin/main` at `7a40558`**, pinned by sha
- Type: behaviour. One assignment, in the clause of a definition that was never implemented.
- Risk: medium - the state a run reports changes on one path. The exit code does not, deliberately.
- Autonomy: high
- Target ACC: ACC-20260907-06

## The definition and the code, eleven hundred lines apart

```
engine.py:289   STOPPED = "stopped"   #: stopped, and nothing continues it — a permanent halt,
                                      #: or an effect that failed
engine.py:392   state: str = FINISHED
```

`_run_effects`'s `except EffectError` block set `halted_at` and `halt_reason` and left `state` at
its default. Driven, with the fixture `tests/test_cli.py` already uses for a failing effect:

```
halted_at    record_module
halt_reason  effect failed at 'record_module': effect 'tick' ran but its postcondition is still
             not true
state        finished
```

The second clause of the sentence that defines `STOPPED` was never implemented.

## Where `finished` went

Three surfaces read `report.state`, and none of them had another source:

- `cmd_run`'s only state-dependent branch is `SUSPENDED`, so the terminal said nothing at all.
- `server` copies `report.state` into `RunState.state`, so the console showed **finished**.
- `conversation.close(state, at_node=…, why=…)` writes it as the **durable record** of the run.

So a run whose `pr` effects half-landed — branch made, commit written, push done, the pull request
not — reported that it finished, in the terminal, on the console, and in the document that outlives
both.

## It implements a decision already recorded

`CHG-20260827-22` made exactly this call for the other half of the same sentence: a permanent
terminal used to report a normal finish, and it was changed *"because that is exactly the
distinction the state vocabulary exists to draw."* This is the same distinction, for the clause of
the same definition that was left behind.

Checked for reversion:

- `CHG-20260905-01` touched this very `except` block, to preserve `exc.outcome`. It neither chose
  nor discussed `FINISHED` for a failed effect.
- No test pinned `finished` here. `test_the_engine_records_a_halted_nodes_partial_outcome` asserts
  the halted node, the applied effects and the reason — never the state. That is the difference
  between an uncovered defect and a decision.
- `server` already admits `STOPPED` on both recovery paths (`start` at :344, `instruct` at :377),
  so nothing that could recover before is stuck now.

## What deliberately does not change

`cmd_run` still returns `0`. Making it return non-zero for a stopped run is a behaviour change for
anything scripting this command; it is not implied by naming the state correctly, and it is a
separate decision with its own blast radius. Recorded here so the next reader knows it was
considered rather than missed.
