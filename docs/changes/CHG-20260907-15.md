## The finding

`conversation.close` appears in exactly one place — inside `_finish` (`engine.py:2081`) — and every
one of the eight `_finish` call sites in `walk` is on a `return`. So **the closing turn is written
on the return paths and on no exceptional one**: any exception escaping the walk leaves the durable
record open.

Measured on the shipped graph, turns written and whether a `CLOSED` turn exists:

```
a run that finishes                             50   closed
a decision naming a branch that is not offered  36   NOT closed
an effects provider raising                     21   NOT closed
a dispatcher raising                            17   NOT closed
a KeyboardInterrupt in the dispatcher           16   NOT closed
```

Neither entry point covers it either: `cli.cmd_run`'s handler prints `halted:` and returns 10;
`server._walk_once` sets `state.state = STOPPED` and `state.error` and touches no conversation.

The run that most needs reading afterwards is the one that cannot be.

## Three things the repair had to get right, each measured rather than assumed

**`except BaseException`, not `finally`.** `conversations.close`'s own docstring says it is *"not
deduplicated, and that is the difference from an instruction: a walk ending suspended and later
ending finished are two things that happened"*. A `finally` around the loop would therefore write a
**second** closing turn on every normal run.
`test_a_walk_that_finishes_closes_exactly_once` is the guard against that repair.

**`BaseException`, not `Exception`.** A `KeyboardInterrupt` is the interruption a durable record
exists for. The mutation narrowing it to `Exception` is caught.

**`STOPPED`, not `report.state`.** `RunReport.state` defaults to `FINISHED` (`engine.py:388`), so
closing with it would record a crashed run as a clean one — the false green CHG-20260907-06 removed
from the other half of this same sentence. The mutation swapping the word is caught.

`STOPPED`'s definition said *"a permanent halt, or an effect that failed"*; it now names the third
cause it carries. `server._walk_once` had already chosen this word for the same thing.

## A claim I could not reach, and withdrew

A reviewer measured a fourth row — an `EffectError` at `record_module` leaving the record open on a
**return** rather than an exception — and named `engine.py`'s effect-failure
`return _finish(stop, confirmations)` as the cause: the only one of the eight sites that passes
neither `cfg.conversation`, nor `_held()`, nor `_unsandboxed`.

I built the repair, the comment and a test for it. **The test passed with the repair reverted.**
Instrumenting `_finish`'s call sites, every scenario I could drive through a failing effect left
the walk at `engine.py:2396` — the `after` gate — with the conversation passed and the record
closed. The line I had changed was never reached.

So the test is gone, the mutation is gone, and the comment says what was measured: this is the
seven other sites' argument list given to the eighth, **because a difference nobody can explain is
a difference nobody can rely on** — and not, on the evidence I have, a repair to a reachable
defect. The argument list still ships; the story about it does not.

## What the split cost, which I did not measure before choosing it

`walk` is now a wrapper and `_walk` is the body. **Eight places read the walk's source** to assert
structural properties of it — six through `inspect.getsource(engine.walk)` and two through an AST
lookup for `FunctionDef(name="walk")` — and every one of them was reading a twenty-line wrapper
after the split. Seven tests failed, in five files.

They assert properties of the **body**, so they read the body. But I chose the structure to keep
the diff small and did not measure what read `walk` first, which is the check I had been asking of
the reviewers all round. The suite is what caught it.

The same run caught a second one: three of my comments cited `engine.py:<n>` addresses, and this
repository's rule is **name the symbol, not the line** — `CHG-20260904-04` records two such
citations that were already wrong at the commit that wrote them, because a function was inserted
above them in the same change.
