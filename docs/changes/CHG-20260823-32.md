## What changed

### 1. `src/ai_sdlc_runner/paths.py` — one place that knows how long a path this machine takes

The defect had bitten three times and been "fixed" twice by making the path *shorter*
(`attachments.py` cut a hash from 64 characters to 32 for it) or the failure *louder*. Neither is
the fix.

Measured on this machine before writing anything:

```
target depth: 294
makedirs, plain:     FileNotFoundError errno=2 winerror=206
makedirs, extended:  ok
file (303 chars)     plain: FileNotFoundError    extended: ok
sqlite               plain: unable to open database file    extended: ok
200/255-char name: accepted ; 300-char name: OSError errno=22
```

The split the module is built on:

| | fixed by | |
|---|---|---|
| total path length | the `\\?\` prefix on Windows; nothing needed on POSIX | **closed** |
| one component over 255 bytes | **nothing** | **refused by name**, before the write |

A limit that can be lifted is lifted; a limit that cannot is refused with the offending component
named, rather than arriving as `FileNotFoundError` about a directory that demonstrably exists —
which is how this defect disguised itself all three times.

POSIX is not a no-op wrapper: `real()` returns a plain absolute path there, because inventing a
prefix would only make every traceback less readable. What POSIX *does* enforce, and what no prefix
lifts anywhere, is `NAME_MAX` — so the per-component refusal is the part that is genuinely
cross-platform.

Wired through `conversations.py`, `engine.py` and `store.py` — every module that opens a file. The
sqlite connection takes it too: the model store is a database at whatever depth the operator chose.

### 2. `--format html` — the conversation as a waterfall down the flow

A fourth export format. `json` is lossless, `markdown` reads as a transcript, `csv` is the lossy
one; none of them shows the **shape** of a run. The waterfall's stops are the nodes the walk made,
in order, so a node revisited is a second stop rather than a merged one — scenario A comes out as
24 stops for 55 turns with `engineer_build` marked `visit 2`, `visit 3`, `visit 4`.

Three voices are told apart on the page — what the runner asked, what the model answered, what a
person decided — because that distinction is what the store exists to keep, and both other formats
flatten it into one column. Every card carries a one-line summary and opens to the raw record.

Answers carry `ask_id` and no `node_id`, so a first version read each one as its own stop and
produced 53 stops for 55 turns: a list wearing a waterfall's markup. Grouping an answer with the ask
it answers is what makes it a waterfall.

### 3. `examples/tide-spa/` — one brief, five plans, five outcomes

Driven end to end against the real CLI. Each scenario is `plan.json` plus one **named mutation**
rather than a fifth copy of a 14 KB file: a copy shows five nearly identical files and leaves the
reader to diff them.

| | one changed field | exit | asks | built | stopped |
|---|---|---|---|---|---|
| A | — | 0 | 25 | 4 | at `merge`, waiting for a person |
| B | a `deploy` kind inside the build | 0 | 7 | 0 | permanent halt, no way on offered |
| C | `scope`/`objective`/`expected_outputs` → `""` | 0 | 25 | 4 | **nowhere — finding below** |
| D | `operations` → `operationz` | 2 | 0 | 0 | refused at the door |
| E | `ship.acc_id` with no `task` | 2 | 0 | 0 | refused at the door |

The *asks* column is the argument for refusing at load time: D and E cost nothing to find out; B is
a well-formed plan describing work no grade permits, so it is caught where the work would happen —
after seven asks were already spent.

`tests/test_example_tide_spa.py` drives the driver and checks the numbers the README prints, because
a README is the one place in this project where a claim can go stale without anything failing.

## Finding, opened by this change and not fixed by it

**A node spec whose required fields are blank runs the entire flow.** `scope: ""`, `objective: ""`,
`expected_outputs: ""` — present, so the closed schema accepts the shape — completed 24 nodes, 25
asks, four files, exit 0. Nothing refused it and nothing warned.

Cause, in `workorder.py::_check`:

```python
missing = [f for f in required if f not in supplied]
```

That tests whether the *key* is there. `render()` then copies the blank straight into the order it
dispatches. This is the project's dominant defect class — a name standing in for a constraint —
sitting in the work-order builder itself, and it was found by **running** the example rather than by
reading the code.

Recorded here as it behaves, not as it should. `README.md` scenario C, the results table, and
`test_a_blank_spec_is_not_yet_refused_and_the_readme_says_so` all assert the current behaviour, so
the fix cannot land without moving the documentation with it.

### Panel

Both seats independently: **`refuse-blank`**, and independently named the same split.

**Refuse blank (6):** `scope`, `objective`, `instructions`, `done_criteria`,
`acceptance_predicate`, `workdir`. Blank means empty after strip, or a sequence that is empty or
holds only blank strings.

**Allow blank (3):** `input_artifacts`, `expected_outputs`, `idempotence_probes` — all legitimately
`[]` on real nodes. `expected_outputs` is `[]` on 14 of 15 nodes in `examples/plan.json`; a rule
refusing every blank refuses the repository's own example, which is the same coarse check inverted.

Both seats also raised the same adversarial case unprompted: a caller using `scope: ""` to mean "the
whole repository". Both would refuse it, because `""`-meaning-everything and `""`-meaning-nobody-
filled-it-in are indistinguishable to every reader downstream, and the second is this finding.

**Where they disagreed:** codex-seat said both boundaries for all six; fable-seat said `instructions`
must be render-time only, because `engine._order_for` appends `--instruction` text to it and a
plan-level blank can legitimately become non-blank by dispatch.

Settled by the code, not by averaging. `engine.py:512-520` joins supplied instructions onto the
node spec's own, and line 515 reads `own = spec.get("instructions") or ()` — explicitly tolerating a
blank. A plan with `instructions: ""` plus `--instruction` works today, so a load-time check on that
field would refuse a legitimate plan. **Five fields at both boundaries; `instructions` at render
time only.** fable-seat's asymmetry stands on the strength of that line.

Deferred to its own change: the fix inverts scenario C, and the README, results table and test move
with it. That is one change, not a rider on this one.

## Defects found in this change's own work

- `paths.open_(...).write(...)` with no context manager — the handle was never flushed, `_project.json`
  came out **empty**, and `runner conversations` died on `Expecting value: line 1 column 1`. A file
  that exists and is empty is a worse failure than one never created. Found by running the command,
  not by reading the diff. Fixed with `read_text`/`write_text`/`write_bytes`, which close.
- The scenario driver used `text=True`, which decodes subprocess output with the **caller's** locale
  codec. On a cp950 console the driver died with `UnicodeDecodeError` while the run underneath it
  had succeeded. The example must not depend on the caller having set `PYTHONUTF8`.
- Two tests that read vocabulary instead of the claim: one asserted a fixture's two builds were two
  stops when the fixture had them consecutive (correctly one stop — the fixture was wrong, not the
  code); one grepped `scenarios.py` for `text=True` and failed on the comment explaining why it is
  not used. The second now reads the `subprocess.run` keywords out of the syntax tree.
- Heredoc backslash mangling, again, writing `test_paths.py` — `\\?\` came out as `\?\`. This is a
  documented rule of my own and it was broken again; the file was rewritten with the editor.

## Correction (CHG-20260823-38)

**This record overclaimed, three times, and both review seats named it the worst thing in the
batch.** It is corrected here rather than edited above, because a ledger that rewrites itself is
not a ledger.

| said | was true |
|---|---|
| "a path module every writer now goes through" | three modules of eight |
| "every module that opens a file" | `conversations.py`, `engine.py`, `store.py` |
| "every file write now goes through it" | five modules wrote directly |

The five: `attachments.py`, `models.py`, `settings.py`, `server.py`, and two `cli.py` sites
(the ship ledger writes and `export --out`). `store.py` additionally passed `paths.real(file)` to
sqlite, and `real()` does not check — so the component refusal this record claims sqlite received
was not applied to the database's own name.

The sharpest of them is `attachments.py`: the module `paths.py`'s own docstring cites as the
historical victim, still carrying the 32-character hash workaround written for this exact problem,
and still writing directly.

**Also wrong:** "NAME_MAX (255 bytes) … genuinely cross-platform". Windows counts UTF-16 code
units. A 100-character CJK name is 300 bytes and 100 units — legal, and refused with a message
asserting no filesystem would take it.

All of it is fixed in CHG-20260823-38, and `test_every_module_that_writes_goes_through_this_one`
now reads the syntax tree of every module so this claim cannot be made falsely again.
