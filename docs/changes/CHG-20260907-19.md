## The finding

`server.py` spells the loopback boundary twice, four lines apart:

```
LOOPBACK       = ("127.0.0.1", "::1", "localhost")           what the server may bind
LOOPBACK_HOSTS = frozenset({"127.0.0.1", "localhost", "[::1]", "::1"})   what a header may say
```

Measured, they are read by different code for different questions:

```
serve              if host not in LOOPBACK              the bind address
_loopback_host     host.lower() in LOOPBACK_HOSTS       the Host header
_loopback_origin   host in {h.strip("[]") for h in ...} the Origin header
```

Two names is the right shape - `[::1]` is a bracketed form that only means anything in a
header, and is not something to bind. But where they overlap they must agree, and **nothing
required it**. A sweep of the repository found no test naming either constant; every mention
outside `server.py` is a historical record.

## What nothing caught

A legitimate loopback alias added to the bind list alone:

```
LOOPBACK = ("127.0.0.1", "127.0.0.2", "::1", "localhost")
     the whole of tests/test_server.py:   128 passed
```

`127.0.0.2` is loopback on every platform this runs on, and `::ffff:127.0.0.1` is the same
story. The server binds it, the browser sends `Host: 127.0.0.2:8765`, and `_loopback_host`
refuses it as a foreign host - a server that will not answer at the address it is listening
on, with a refusal that blames the request.

## What already held, measured rather than assumed

The other direction is different. Tightening `LOOPBACK_HOSTS` below what is bound was already
caught, by `test_our_own_origins_are_still_accepted`:

```
LOOPBACK_HOSTS without "localhost"
     FAILED test_our_own_origins_are_still_accepted[http://localhost:8765]
```

That test pins four origins as **literals it wrote down**, not as anything read from the
constant. So it catches the values it happens to name and nothing else, and it says nothing
at all about the bind list. Half the property was covered by accident; this record covers the
property.

## What ships

One test in `tests/test_server.py`, and it is one-directional on purpose:

```python
bare = {host.strip("[]") for host in server.LOOPBACK_HOSTS}
unreachable = [addr for addr in server.LOOPBACK
               if addr.lower() not in server.LOOPBACK_HOSTS or addr not in bare]
```

Both header checks, because they differ: `_loopback_host` compares against the set as
written, `_loopback_origin` against the same set with brackets stripped. An address that
passed one and failed the other would be reachable by `Host` and refused by `Origin`.

The reverse is not asserted. `[::1]` is in the header set and not in the bind list, and that
is correct.
