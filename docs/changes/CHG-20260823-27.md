## The process failure, first

fable-seat opened with something I have to record before any finding:

> *"while this review ran, `cli.py` and `store.py` were **modified in the shared worktree,
> uncommitted** … Those edits are not part of CHG-26 and were not reviewed."*

**I edited the tree the seats were reviewing, while they were reviewing it.** The seat handled it
correctly — pinned every claim to the committed commit and refused to review the uncommitted work —
but it should not have had to. A review against a moving tree is a review of nothing, and this
repository's own README says the seats read *"against a frozen tree"*.

It also produced a concrete symptom the seat caught: one of my source-reading tests **failed during
its run**, purely because `inspect.getsource` desynced from a file that changed underneath it. That
is a test failing for a reason unrelated to behaviour — which means it can also **pass** for one.

## The worst thing: round 1's finding, one command over

```python
session_factory(config, seat_models)     # no registry
```

`cmd_run` resolved the store into `RunConfig` and then built a factory that **cannot use it** —
every model-routing branch is guarded by `registry is not None`. Proven:

```
WITHOUT a registry (what cmd_run did):
   seat defect -> ['opus']
WITH the registry (the fix):
   seat defect -> ['claude', '-p']
```

Two consequences, and the second is worse than I understood:

- a stored **seat** assignment made `runner run` **try to execute a program named `opus`**;
- a stored **node panel** was answered three times by the default backend, and then
  **adjudicated as a cross-model majority attributed to models that never ran** — reaching
  `report.adjudications` and the conversation record.

The code's own error message names that exact failure — *"would send the work to the default and
report it as {model}"* — and it was unreachable in `run`, behind the registry guard.
