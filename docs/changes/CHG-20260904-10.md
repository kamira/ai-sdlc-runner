## Read this first

Three instruments, none of which could see the thing it was written to watch.

### L-34 - a guard whose blindness check was satisfied by prose

`_suspension_literals` searched `engine` for `report.suspended = {` and asserted it found at least
one, with the message *"this guard has gone blind"*. `CHG-20260904-07` routed all three shapes
through `engine._suspension`, so no literal exists. The single remaining hit is **the comment `-07`
itself wrote about the literals it removed**:

```
hits for 'report.suspended = {'   1     a comment: "The three `report.suspended = {...}` sites
                                        carried 9, 11 and 13 keys"
the block the guard brace-matches       {...}
keys extracted from it                  0
`assert blocks` (the blindness check)   passes
fields a suspension really carries      15
```

`-07` retired this guard's sibling on a retirement condition that held for **both**, and kept the
one that had gone blind. It is retired here on its own terms - `test_the_suspension_union_is_the
_only_way_a_shape_is_built` already refuses a fourth dict literal, so what the helper looked for
cannot come back unannounced.

This is the inverse of a failure this review has produced five times, where a **rule flagged its own
explanation**. Here an explanation **rescued a dead rule**.

### L-36 - the contract page says the opposite of what the data does

`docs/API.md` section 4, after `-07`:

> **Nine keys are on every suspension** ... Six more are carried only by the question that needs
> them

with `// only when` dividers over six fields. Measured:

```
engine._suspension(node_id=..., gate=..., gate_when=..., verdict=..., risk=...)
  15 keys ; reason == '' ; missing == [] ; 'verdicts' in it == True
```

`git log -- docs/API.md` says `-07` never touched it. The guard `-07` shipped asks only whether
each field is **named** on the page - so all fifteen names were there and it passed for a day. A
client written to that sentence writes `stop.get("reason", "...")` at a gate stop and gets `""`,
which is verbatim the failure `-07` exists to close, relocated from the data into the document.

The sentence has now been false in **both** directions: the original *"every kind of suspension
carries the same keys"* was false until `-07` made it true, and the correction that replaced it
became false the moment `-07` shipped.

### L-41 - the citation ban could not see a docstring's body

The scope was: the line starts with `#`, or the line contains a triple quote. That admits a
docstring's opening and closing lines and **nothing between them**. Planted as the second line of
`graph.Node`'s docstring, the sentence the rule exists to ban passed.

Scoping to prose was necessary and stays - `paths.py` quotes `json`'s own `Expecting value: line 1
column 1`. What changes is that the scope is **stated**: `tokenize` for every comment, `ast` for
every docstring body, and `column` following the number is what tells a parser's position from a
reference into this source.

## Task 6, which this record needed before it could prove task 2 - and which was two places

`tools/mutation_check.py` asks whether the mutated file still imports. `docs/API.md` is not a
module, and the answer was `ModuleNotFoundError: No module named 'API'` - an honest mutation
reported `BROKE`. A page three surfaces are written against is a contract, and a contract that says
the wrong thing about the data is the same defect class as code that does; the registry now says so.

**And the same assumption sat in a second place, which only the full suite found.**
`test_no_shipped_mutation_makes_its_file_unparsable` runs `ast.parse` over every shipped mutation's
file, and reported `unterminated string literal` for the two markdown ones. The narrow group run
was green; the file's own guard was not. Both boundaries are now stated, and a third test asserts
the boundary rather than leaving it to the `contract` group happening to pass:

```
python tools/mutation_check.py --only contract    all 4 caught
pytest tests/test_mutation_check.py               13 passed   <- and it was the suite that said so
```

That is this record's own subject happening to this record: a guard that could not see the thing it
was checking, found by running the wider instrument rather than the narrow one.
