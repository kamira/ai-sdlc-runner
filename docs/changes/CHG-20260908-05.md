## Two defects, and why they ship together

**The race.** `start`, `instruct` and `attach` read the attachment store inside `with self._lock`.
`_walk_once` did not — deliberately, because a walk holds no lock across itself, which is what
`_advance` is built on and what `CHG-20260823-44` pinned. But `Store.all()` opens `manifest.json` to
read it, and `Store.add`, under the lock from `attach`, ends in `os.replace` onto that same file. On
Windows a replace onto a file another thread holds open fails:

```
os.replace onto a file a reader holds open   PermissionError [WinError 5]
the same replace after that reader closed    succeeded
```

So the lock serialised writers against writers and left the walk's reader racing the writer. There
was exactly one such reader — `server.py:916` **at `77b5c14`, where this was measured**, and
`server.py:931` in the tree that ships — and `start` (499), `instruct` (527) and `attach` (549)
were all already inside the lock.

**The test that could not report it.** `test_the_gate_never_rests_with_something_still_flagged`
joins six worker threads with `join(timeout=20)` and then asserts on `runner._walking` and
`runner._walk_again`. It never asserted on the workers. `poke` swallowed `ServerError` and nothing
else, so a thread dying of anything different became a `PytestUnhandledThreadExceptionWarning` — a
warning, and this repository sets no `filterwarnings`. Measured on `77b5c14`: **eight ordinary runs,
one had a thread die** of the `PermissionError` above, and that run reported `1 passed, 1 warning`.

They ship together because repairing the test alone makes it fail intermittently until the race is
fixed, which is knowingly shipping an intermittent test. Both seats said so independently.

## What ships

**The read moves inside the lock, and nothing else does.**

```python
if self._store is not None:
    with self._lock:
        order_paths = tuple(self._store.order_paths())
else:
    order_paths = ()
```

`self._lock` is an `RLock` and `_walk_once` is called from `_advance` outside it, so this nests
nothing.

**The workers are accounted for.** `poke` records any non-`ServerError` exception and re-raises;
after the joins, the test asserts no thread is still alive and no failure was recorded, **before**
it reads the flags — because a flag is readable while a thread is not finished.

## The regression signals, and how each was measured

**The race is driven, not waited for.** One run in eight is no use as a signal. The new test parks
the walk *inside* its manifest read, holding a real handle, while an attachment is posted from
another thread:

```
                    three runs each
the lock reverted   1 failed  1.20s / 1.62s / 0.61s   the writer always reaches the replace
the lock as it ships 1 passed 6.32s / 6.29s / 5.72s   the signal never comes; it is blocked

a seat, on the version with the sleep, on its own machine and under load:
  reverted, idle      6 of 6 red, 0.81-1.06s
  shipped, idle       3 of 3 green
  16 CPU burners      the writer took 1.05-2.43s to reach the replace, and the 0.3s sleep let
                      one run in five pass green with the lock reverted
```

The green side costs a five-second timeout, and that is the point: the wait ends because the writer
**could not** reach `os.replace`, not because a sleep elapsed. **A seat refused the first version of
this test for exactly that**: it slept 0.3s and released the handle, so on a machine where the
writer was slower than 300ms the handle closed first, the reverted code succeeded, and the test
passed guarding nothing. The window was load-bearing and unsynchronised. It is an event now, set by
the writer immediately before the replace.

**The accounting was measured by injection**, because a mutation cannot stage it — see below:

```
a worker injected to die, accounting present   1 failed
the same, accounting removed                   1 passed
                                               the same `1 warning` in both
```

## Three hollow tests written on the way to this one

Each was green and guarded nothing, and each is worth more written down than quietly fixed:

- **The anchor named a test that does not exist.** The hammer test is
  `test_the_gate_never_rests_with_something_still_flagged`; a patch keyed on a remembered name and
  aborted. Cheap, because the script asserted its anchor — **and then the same wrong name went into
  `server.py`'s shipped comment and stayed there**, through a full suite, a mutation run and this
  record's own paragraph about anchors naming tests that do not exist. A seat found it. The lesson
  the paragraph states is the one the paragraph failed to apply four lines from where it is
  written.
- **The hook was on the wrong function.** `Store.all` is called by `start`, `instruct` and `attach`
  as well, every one of them under the lock. A fixture patching `all` parked on `instruct`'s read
  and the test failed on a stale version — red for the wrong reason, which is a fixture measuring
  the wrong moment. The hook is `order_paths`, which only the walk calls.
- **The barrier held nothing open.** The first working version parked *after* the read had
  completed, so no handle was open across it, and **the test passed with the lock reverted**. A
  guard that cannot fail, written into the change that exists because of one. It holds a real
  handle now.

## What this does not do

- **It does not make the walk hold a lock.** Only the read is inside; `self._walk(cfg)` is where it
  was.
- **It does not touch the version check.** The new test's writer reloads on a stale version the way
  a client does, and records anything else — the staleness is the API working.
- **It does not address `tests/test_server.py:2659`**, a timed-out join whose expiry would silently
  reintroduce a flake in another test. It is a wait whose result is unasserted, the same class, and
  it is not a false green; it is named in `ACC-20260908-05` as still open.
