## What this design actually is, now

Four rounds of review have taken it apart. What is left is small enough to state in three lines, and
the honest measurement is that **it adds no reach at all**:

```
cells a project may pre-authorise standingly : 1     plan_confirmed @ medium
cells already reachable on `main` by a class : 5     including that one
marginal reach over `main`                   : 0
```

Every `confirm` cell is already lowerable today by a `standard` or `emergency` class. So the whole
delta is **who** may pre-authorise and **for how long** — a project setting rather than a per-run
flag or a signed, dated, self-expiring class. That is the thing to accept or refuse, and the record
says it in the first section rather than discovering it in acceptance.

**And 「merge 永遠留一個人」 is already false on `main`.** Measured: `risk: low` plus a signed
`standard` class makes `merge` `auto`, and `_permanent_halt` passes because the shipped example
plans declare merge `{"kind": "ordinary"}`. Draft four's exemption read as if it secured that
requirement. It secures it against **this** mechanism and nothing else, and the requirement needs
its own change.

## The two things, and only one of them touches a person

| | question | removes a person? |
|---|---|---|
| **`ANSWERED_FIRST`** | who answers **first** | **never** |
| **the standing pre-authorisation** | is this stop already cleared | yes — at one cell |

## ① `ANSWERED_FIRST` — one bit, in `policy`; the arrangement stays in `graph`

Draft four returned four answerers — `seat_panel`, `graded_panel`, `model_panel`, `single` — from a
resolver in `policy.py` taking a `graph.Node`. Three findings killed it:

- **It reverses the only dependency edge this codebase has.** `policy.py` imports nothing from the
  package; `graph.py` imports policy *inside a function* to keep the edge one-directional. A
  resolver annotated `graph.Node` beside `GATES` reverses that with a type hint.
- **Three of the four words are `node.mode` verbatim**, returned to a caller that had to hold the
  node to make the call. `routed_to("deploy") → "release"` crosses two vocabularies; this crossed
  none.
- **`graded` is already spent in `policy.py`** — it is `relax`'s first parameter and `verdict`'s
  local, meaning *the verdict `GATES` grades*. `graded_panel` beside it is the `voices` collision
  one identifier apart.

So the axis decomposes, and each half goes where it already lives:

```python
#: Whether a stop is answered first by a person or by the node's own voices. Data, beside `GATES`.
#: Partial: a gate absent from this table is answered by the operator, and editing the table can
#: never delete that fallback — `DEFAULT_RECIPIENT`'s argument, and `HALT_ROUTING`'s shape.
ANSWERED_FIRST: Dict[str, str] = {}          # gate -> "node"
DEFAULT_ANSWERER = "operator"

def answering(gate: str, table=None) -> Tuple[str, str]:   # (who, source); str in, str out
```

`str` in, `str` out, keyed by the same thing its argument is — `routed_to`'s shape exactly. Draft
four's table was keyed by *gate* while its resolver took a *node*, and six of ten gates have a node
id different from the gate name; both its worked examples were drawn from the four where they
coincide.

**Which arrangement answers** is read in `engine`, which already imports both modules and already
selects on it: `if node.grades_risk: adjudicate_grade(...) else: adjudicate(..., voices="models")`.
No new vocabulary, and `lead_review` keeps `conformance`'s veto because nothing renames its mode.

## ② The pre-answer is the run's own adjudication record, not a new object

`walk` already writes exactly this, at four sites, identically:

```python
report.adjudications.append({"node_id": node.id, **outcome, "verdicts": dict(verdicts)})
```

**The idiom is to spread the adjudicator's own output**, not to enumerate a shared subset. Draft
four enumerated `{answered_first, outcome, vetoed, reason, verdicts}` — which at `lead_assess`
carries `vetoed`, a key `adjudicate_grade` never returns and which has no meaning for a panel with
no veto, and **drops `grade` and `proposed`**, the only keys carrying what that panel decided.

`CHG-20260901-18` is titled *"the grade a panel decides reached nothing that names it."* Draft four
reproduced it in the design that cites it.

So: the pre-answer is a **reference to the run's `adjudications` entry for that node**, spread the
same way. And the render is per-answerer — `.voices` for the two binary panels; `grade` with
`proposed` for the graded one, three-valued in `policy.RISKS` order. Draft four gave four answerers
one binary renderer, which is `adjudicate_grade`'s own refutation (*"It is **binary**, and a grade
is one of three"*) restated in CSS.

### On a default install there is no pre-answer at any gate that stops

Measured, `node_models = {}`:

```
gate                   node             adjudication produced?
lead_review            lead_review      YES  (SEAT_PANEL always opens SEAT_FLOOR seats)
every other stopping gate               none
```

`walk` enters the panel path only on `node.mode == MODEL_PANEL and len(configured) > 1`, so the five
model panels take the single-ask path and produce no `outcome`, `reason` or `verdicts`. The three
`single` gates never adjudicate by design.

**This is not an open question and it is not a labelling problem.** `CHG-20260901-18` D-2 already
ruled on this shape four commits ago, in a change this record cites: its defect was code living
inside `if node.mode == MODEL_PANEL and len(configured) > 1`, and its fix rule was *"Keyed on the
answer, never on the mode."* Draft four demoted the same gap to an open question. It is a
**prerequisite task** here: a pre-answer is written where an adjudication exists, and where none
exists the gate says so rather than rendering one voice inside a panel-shaped block.

## ③ The pre-authorisation lives in `engine._gate`, not in `policy.verdict`

`_gate` already implements a per-gate, targeted-or-blanket, **counted and recorded**
pre-authorisation — `--confirm` — with its own docstring: *"A gate the operator has already
confirmed is **recorded** rather than silently skipped: an approval that leaves no trace is one
nobody can audit afterwards."* And `relax` names it: *"`confirm` can be pre-authorised with
`--confirm` and a halt cannot."*

Putting the lowering in `verdict` makes the verdict `auto`, so `_gate` returns at its first line:
**no `report.confirmations`, no `conversation.decision`, no record that a stop existed.** Draft
four's task 16 asks to measure divergence from `conversations.decision` and latency from turn
timestamps — and at the one cell the mechanism applies to, there would be no clearance to measure.
**Its own tasks cancelled each other.**

Expressed as a **standing confirmation consumed in `_gate`**, in `--confirm`'s vocabulary and
through its recording path:

| | draft four | this draft |
|---|---|---|
| `policy.py` takes project input | yes — 3 texts made false | **no — those 3 survive** |
| the stop is enumerable afterwards | no | yes, `report.verdicts` still says `confirm` |
| a three-way audit is needed | task 11 | **evaporates** |
| where in the chain | task 12, and its answer was **inverted** | spent after the verdict, for free |
| the rung is enforced by | a new function | `_gate` runs only when `policy.stops(...)` |
| targeted beats blanket | unstated | `_gate`'s existing rule |
| task 16 is measurable | **no** | yes |

**The chain order draft four proposed was backwards**, and this placement removes the question.
Measured by the defect seat: applying a lowering *first* rewrites `graded` before the rank
comparison, so a change declaring exactly what the table already says is recorded as `tightened` —
which then fires CHG-20260902-19's branch and prints a sentence about a non-event. In `verdict` the
**most** specific input applies first and the **least** specific applies last, guarded. Least
specific ⇒ last. The premise was right and the conclusion inverted.

## ④ The exemptions are derived. There are none to list.

Draft four bounded the lowering by rung and still named three exempt gates. Measured, all four
exclusions fall out of facts already on the node:

```
confirm ∧ ¬grades_risk ∧ ¬settles_risk ∧ rejects_to is not None
```

| cell | excluded by |
|---|---|
| `feasibility_confirmed` @ medium | `grades_risk` |
| `before_dispatch` @ medium | `settles_risk` |
| `pr` @ high | `rejects_to is None` |
| `merge` @ low | `rejects_to is None` |
| **`plan_confirmed` @ medium** | **nothing — this is the one cell** |

`rejects_to is None` selects exactly `{pr, merge}` among the ten gated nodes, and `graph.py`'s own
comment is the argument: *"Rejecting `merge` means do not merge — there is no node for that … a
console must not offer a control the graph cannot honour."* **A gate a person can only approve and
never refuse is a gate where removing the person removes the only outcome that was available.**

So 「merge 永遠留一個人」 holds **structurally**, against this mechanism, with no name written down —
and `pr@high`, which draft four called *"the sharper of the two"*, falls out by the same property
rather than by nerve. This is `CHG-20260902-19` ③'s idiom — *"Membership comes from the graph, not
a list"* — applied to the set draft four still hand-listed.

### And the reach is pinned, because a rung's reach is not structural

The predicate is structural; **the set it selects is a property of `GATES`, which is data.** And it
fails in the direction nobody watches: editing a cell from `halt` to `confirm` — a **tightening** —
silently adds a lowerable cell, with no name to update.

Measured, `GATES` is pinned only in fragments (three cells in `test_policy.py`); `lead_review` and
`qa_verify` are pinned nowhere. So the lowerable set is pinned by value, and a `GATES` edit that
widens it turns red and forces its author to say whether the new cell is lowerable. That is the
two-way drift guard `plan.FIELDS` and `SHIP_FIELDS` were given in `CHG-20260902-20`.

## ⑤ The rung was copied; the contract it belongs to was not

`relax`'s bound is one half of a pair. The other half is `policy.class_in_force`, which refuses a
class with no `authorised_by` — *"A pre-authorisation nobody signed is a relaxation on nobody's
authority"* — and no `review_by`, and expires it back to `normal` past that date.

Draft four said the lowering used *"the same rung `relax` is bounded to, for the same reason"* and
gave it **neither signature nor expiry**. Measured, the class route to `plan_confirmed@medium` is
signed, dated and self-expiring; the proposed route to the same cell was anonymous and permanent.
**That is the entire marginal risk of this design**, and it is closed by requiring both fields with
the same expiry fallback.

Related, and also inherited: `conversations.emergency_runs()` derives a review queue from the
`CLOSED` turn's `change_class`. A standing pre-authorisation produces no class, so it appears in no
queue and no review is owed. `ACC-20260827-20` guard 5 was *"emergency runs are marked and queued
for review"*; this creates instances of the same act. It is a task, not a footnote.

## Open questions for the panel — one

Draft four had five and four of them were decisions. Answered here:

- *a tied pre-answer's wire* — **not a third shape.** A tie at a gate is already **two stops in
  sequence**, measured: the gate stop, then the undecided stop with `verdicts` and `reason`.
  `_require_suspension`'s binary is what keeps the two questions apart, and
  `test_ruling.py` says why: *"filing a ruling under `confirmations` would make the report say a
  gate was confirmed when nobody confirmed anything."* And a tied **grade** sets `STOPPED` before
  `_gate("after")` runs, so it is unreachable at `feasibility_confirmed` by construction.
- *FR-24 at the `single` gates* and *the default install has no panel* — the same task, not
  questions.
- *`serve` has no `--change-class`* — **a defect on `main`**, carried out of this review the way
  twenty-three others were, not left here.

**The one that is real:** `lead_review` is the only `after` gate whose pre-answer is not free.
`_adjudicate` runs *after* `_gate("after")` and calls `_send_back`, which mutates the report — so
pre-answering it means moving adjudication ahead of the gate. And measured, that is **not a
reordering**: today the stop is byte-identical whether the panel unanimously passed or unanimously
failed, so putting the outcome in front of the person changes what approving `lead_review` means.

## Risk & rollback

- **The marginal reach is zero cells.** Everything this can pre-authorise, a change class can
  already lower today. What is new is that it is a **project setting** rather than a signed, dated,
  expiring declaration — which is why task 14 is not optional.
- **Two gates gain a dispatch**, `pr` and `merge`. The other seven `after` gates gain none.
- **A pre-answer is a recommendation a person may follow without reading.** Task 19 makes the
  absence of reading visible — divergence and latency, both from data already written. Nothing makes
  the presence provable.
- **`_permanent_halt` is unchanged and is not a defence this design provides.** It checks
  declarations, not actions; a plan declaring merge `{"kind": "ordinary"}` passes, and the shipped
  examples say exactly that.
- **「merge 永遠留一個人」 needs its own change.** It is already false on `main` at `low` with a class.
  This design cannot reach `merge`, which is not the same as securing it.
- Rollback: revert. Every gate answers cold and stops, and the eleven texts are true again.
