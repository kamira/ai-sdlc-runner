# CHG-20260828-04 — worktree isolation broke an agent that reads the filesystem

- Project: ai-sdlc-runner
- Branch: claude/chg-20260828-04-artifacts-carry-forward
- Date: 2026-08-28 (UTC+0)
- Type: a regression fix, on behaviour shipped hours earlier
- Proposed by: running `examples/weather-spa` while taking the wall-clock measurement task 6 asks for
- Risk: **high** — it is a live defect on `main`: a shipped example does not complete
- Autonomy: high
- Related: CHG-20260827-21 (step one, which shipped this), CHG-20260823-50 (the cycling defect this
  reproduces from a new cause)

## The gap

`examples/weather-spa` builds four modules and, under the isolation shipped by CHG-20260827-21,
never gets past the first:

```
halted: walk exceeded 200 steps. Most-visited: engineer_build ×39,
        last answered {"module": "markup", "wrote": "index.html"}
```

Two facts meet:

1. **The agent decides what to build by looking at the filesystem.** It writes into `site/` and
   picks the first module whose file does not match the brief — its own comment says so, and says
   the runner's cycling complaint is "exactly the right complaint about exactly this bug".
2. **`site/` is gitignored** (`.gitignore:191`, `examples/*/site/`).

Under isolation, each tree is cut from a **commit**; an ignored file is never in a commit; and the
artifacts were carried into the working tree only at the **end** of the run. So every tree showed
the agent an empty `site/`, it rebuilt `markup`, nothing tracked changed, the tip never advanced,
and the step guard stopped the run.

This is CHG-20260823-50's defect — the module loop not advancing — reintroduced by a completely
different cause.

## Two causes, and the second was in the first fix

**Artifacts did not propagate between modules.** The commit carries the source; the artifacts are
deliberately not in it, so they have to be carried by hand. They now are: each new tree gets every
earlier module's artifacts copied in, oldest first, so a tree looks like the working tree would have
looked at that point — committed source plus everything built so far.

**`git status --ignored` collapses an ignored directory to one entry.** It reports
`examples/weather-spa/site/`, not the files inside it. The first fix checked `is_file()` on that
entry and therefore copied **nothing at all** for the case it was written for. The check existed and
carried a comment claiming *"a directory entry; its files are listed separately"* — which is false,
and was never verified.

Both the carry-forward and the final carry now go through one `_copy_artifact`, so they cannot
disagree about what an artifact is.

## Why this reached `main`

**No test drove a multi-module build through the real command.**

* `test_example_weather_spa.py` drives the console and the server; it contains zero CLI runs.
* `examples/minimal` — the example every other end-to-end test uses — has **one** module, and one
  module never exercises the carry-forward at all.
* `test_worktree_isolation.py` tested two modules through the `Trees` API, where the artifacts were
  written by the test rather than by an agent that reads them back.

Every one of those is a real test. Together they left the one shape that matters — *several modules,
built by an agent that reads what the last one wrote* — uncovered.

## And a second defect the same run exposed

A halted run keeps its trees — the tree is the evidence — and ACC-20260827-21 disclosed that
*"nothing prunes them"* as a reservation. Taking the measurement showed what that costs.

After a session of halting runs this repository held **156** worktree registrations. Every
`git status` walks all of them: an ordinary status took minutes, and `git worktree list` did not
return at all. The full suite went from about seven minutes to **twenty-two**.

The evidence an operator wants is the **files**. The git registration is not evidence, and it is
the part that grows. A kept tree is now **unregistered and left on disk**: the files remain to be
read, and the repository's metadata does not grow. `git worktree remove` would delete the
directory, which is the opposite of what a kept tree is for, and `git worktree prune` only forgets
directories that are already gone — so the registration is removed directly, which is exactly what
prune does once a tree has vanished.

Losing `git diff` inside a temp directory is a far smaller cost than a repository nobody can use.

## Risk & rollback

- The fix only ever **adds** files to a tree that would otherwise be missing them. It cannot remove
  or overwrite committed source, and a later module's artifact winning over an earlier one's is the
  rule the commits already follow.
- Rollback re-breaks `weather-spa`, so it is not a real option; the honest rollback is reverting
  CHG-20260827-21 entirely.

## Status

**Accepted** — see [ACC-20260828-04](../acceptance/ACC-20260828-04.md).

### Not claimed

**That every filesystem-reading agent now works.** An agent that reads something outside the
worktree — a database, a cache, a directory above the repository — still sees whatever is there, and
isolation neither helps nor hinders it. This fix is about files git was told to ignore *inside* the
tree.

**That the artifact set is small.** Everything ignored-and-present is carried between trees,
including whatever a build leaves lying around. Nothing prunes it, and a build that writes a large
ignored directory pays for it once per module.
