# CHG-20260828-04 — the two sandbox mechanisms are asserted separately, so nothing compares them

- Project: ai-sdlc-runner
- Branch: claude/chg-20260828-04-05-mechanism-conformance
- Date: 2026-08-28 (UTC+0)
- Type: a contract that exists in prose, made into a suite every implementation must pass
- Proposed by: a code-level comparison against langchain-ai/langgraph, which ships its checkpointer
  contract as an installable conformance suite (`langgraph-checkpoint-conformance`) rather than as a
  paragraph each backend is trusted to have read
- Risk: **medium** — nothing in `src/` changes. What changes is which divergences can reach `main`.
- Autonomy: high
- Related: CHG-20260827-23 (the mechanisms), CHG-20260828-02 (the same argument about guards)

## The gap, reproduced

`sandbox.py` builds two command lines from one policy. Each is asserted on its own — the bwrap tests
check bwrap's argv, the seatbelt tests check seatbelt's profile — and **nothing asserts that the two
agree**. They do not:

| | `_bwrap` | `_seatbelt` |
|---|---|---|
| `/tmp` at `write: none` | `--tmpfs /tmp` — a fresh, isolated tmpfs | `(allow file-write* (subpath "/tmp"))` — the **real** `/tmp` |

Both are unconditional. So a `high` grade, whose policy row says `write: none`, still hands the
process a writable `/tmp` on both — and on macOS that is the machine's own `/tmp`, shared with
everything else running. The table says one thing and two implementations say two others.

This is not a bug in either function. It is the absence of a place where "these must agree" is
written down as something that runs.

## What LangGraph does instead

`langgraph-checkpoint-conformance` is a package. A backend imports it and runs it, and the suite
"validates that a `BaseCheckpointSaver` subclass correctly implements the checkpoint storage
contract — blob round-trips, metadata preservation, namespace isolation, incremental channel
updates". Postgres and SQLite are held to the same assertions by construction rather than by two
sets of tests that happen to have been written from the same paragraph.

The shape transfers exactly: `MECHANISMS` is a closed tuple of implementations of one policy, which
is the situation that suite exists for.

## Scope

`MECHANISMS` first, because a divergence is already there. `probes.py` has the same shape — every
probe claims to *"describe the postcondition, not the action"*, a contract currently held by review
rather than by a test — and is the obvious second subject. This record proposes the first and names
the second rather than doing both under one title.

### Not claimed

**That a conformance suite makes the mechanisms equivalent.** bwrap and seatbelt bound different
things and always will. What the suite pins is the set of properties the policy table claims, which
is a smaller set than "these behave the same".

**That `probes.py` is covered.** It is named here and not done here.
