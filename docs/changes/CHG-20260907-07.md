## A rule that had never run, and a test named after it

```python
if BY_ID[node.follows].mode == FOLLOWS:      # fires first
    raise GraphError(f"node {node.id!r} follows {node.follows!r}, which follows something else …")
if node.follows == node.id:                  # unreachable
    raise GraphError(f"node {node.id!r} follows itself")
```

A node following itself *is* a chain of follows, so the first rule always fired and the second
never did. Driven:

```
node 'engineer_selfverify' follows 'engineer_selfverify', which follows something else
```

— pointing at itself while saying "something else".

And `test_a_node_cannot_follow_itself` asserted
`match="follows itself|follows something else"`. The alternation let it pass on the other rule's
wrong sentence, so the thing its name claims was never tested. Someone met this and papered over it
instead of reordering.

The two checks are now in the other order: the dead rule is live, the misleading message is gone,
and the test matches `"follows itself"` alone. `test_a_follows_chain_is_refused` is unaffected —
`fix_pass` follows another node, not itself.

## What changes

- `graph.py`: those two checks swap places. Nothing else in `src/`.
- `tests/test_graph_validation.py`, new: fifteen reverse tests, one per rule. These are graph
  invariants, not execution-mode rules, and `test_execution_mode.py`'s scope is deliberately narrow.
- `_validate_with` here swaps **both** `NODES` and `BY_ID`. `test_risk_adjudicated._validate_one`
  swaps only the first — enough for its field-only changes, and wrong for anything about ids,
  reachability or follows, because `validate` compares the two lengths and then traverses `BY_ID`.
- Sixteen mutations in `graph-validation`, one per pinned rule.

## Five of these tests were hollow, and only the mutations said so

All fifteen passed on the first write. `--only graph-validation` reported **5 of 16 NOT CAUGHT**.
None was a missing test; each was a `match=` loose enough for a different rule to satisfy:

| test | what its pattern also matched |
|---|---|
| decision branch count | `"branch"` — the panel rule's *"whose 'fail' names no branch of its […]"* |
| step successor | `"next\|successor"` — the node id **`next_module`**, inside the reachability rule's list |
| role exists | `"role"` — the gate and mode messages beside it |
| rejection needs a gate | `"gate\|reject"` — very nearly every message this function raises |
| self-follow | nothing; the entry named `test_graph_validation.py` and that test is in `test_execution_mode.py` |

The second is the one to remember: **the pattern matched a node's name** in an unrelated list.

This is the same defect as the alternation removed above, committed five times in the change that
removes it. Fifteen green tests, a plan reviewed by two engines, and only the mutation run could
see it. Each pattern is now a phrase only its own rule produces.

## Not in this change

The **conformance seat holds a veto** on the documented contract *"no node claims a gate phase
without a gate"*: `validate` refuses only `gate_when == "after" and not gate`, while an ungated
node carrying the default `"before"` also has a phase and no gate. Its own message —
*"has a gate phase but no gate"* — states the contract in full while the condition implements half.

Three **gated** nodes rely on that default and tests and records preserve it, so the repair is
either a `None` phase on `Node` (touching the public shape and its server, API and schema readers)
or narrowing the documentation to the enforced rule. That is a decision about a published contract
and belongs in its own record; `test_an_after_phase_may_not_name_no_gate` pins the enforced half
and says which half it is — and that test was **removed in CHG-20260907-11**, the record this
paragraph anticipated, which made the type optional and replaced it with
`test_a_phase_without_a_gate_is_refused` and `test_a_gate_without_a_phase_is_refused`.
