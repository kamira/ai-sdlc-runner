## What both seats found

`codex-seat`: the allowlist matches on a **prefix**, so `git` being listed made
`git push origin --delete main`, `git branch -D main`, `git tag -d`, `git stash clear`, `make deploy`
and `npm run release` all ordinary. Every one ran to `done` under the **default** safe setting with
`on_trust` empty.

`fable-seat` found the same class and went further:

```
cat /dev/urandom > /dev/sda      # `cat` is listed; the prefix never sees the redirection
find . -name '*.log' -delete     # `find … -name` is listed; the `-delete` never gets a vote
git restore .                    # discards uncommitted work
cp /dev/null customers.db        # truncates a file
../../../etc/shadow              # the bare-path rule allowed traversal
```

**And it measured the other direction: 13 of its 20 real development commands — 65% — were stopped.**
`python scripts/build_docs.py`, `npm start`, `pip freeze`, `docker run`, `node`, `uvicorn`,
`pre-commit`, `go generate`.

## The diagnosis, which is different from the last two

The recogniser was **too permissive and too restrictive at the same time**. That is not a mistuning
to be corrected by editing lists — it says the shape is wrong. A runner cannot classify an arbitrary
shell command string, and two rounds of trying produced a check that was both unsafe and unusable.

So it stops trying. `policy.recognise` now answers only what it can actually know:

| Question | How |
|---|---|
| does this match a **known-dangerous** pattern? | the red rules — imperfect, and every addition is safe |
| is it a **plain repo path** or **read-only version control**? | decidable: no traversal, no metacharacters, no writes |
| has **the operator vouched for the command**? | `ordinary_commands` in settings — they know their toolchain and this runner does not |

Everything else is `unrecognised`, which is a true statement about this runner's knowledge rather
than a verdict about the target. It stops by default and is recorded when allowed through.

Three things make that hold:

- **Shell composition disqualifies.** `>`, `|`, `;`, `&`, backticks, `$(`, and `..` as a path
  segment. `cat` is harmless and `cat x > /dev/sda` is not, and the difference is a character a
  prefix never saw.
- **Vouching is for the tool, never the command line.** `policy._SUSPECT` still refuses
  `npm run release` from an operator who vouched for `npm` — otherwise this is the identical prefix
  mistake one level out, which is exactly how round 6 happened.
- **Settings refuse a multi-word entry**, for the same reason.

### Measured

| | result |
|---|---|

command answered three times: sessions independent, models not, and nothing in the report says which
it was. The requirement asks for 多模型互審 and the mechanism exists, but a panel that silently
consists of one model is the kind of false assurance this whole design is against. Named here, not
fixed here.
