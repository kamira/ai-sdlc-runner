## One shape

`policy.verdict` and `plan.check` are the two doors a verdict's height passes through. Each carries a
rule in its own text, and each of the three defects here is that rule **not applied as written** —
twice silently, once in the function whose comment says it cannot happen.

## ① A class undid a tightening the change asked for itself

`policy.verdict`, verbatim:

> The instance's own word is the more specific of the two, so relaxing is applied to what is left
> standing rather than to the table — **a `standard` class cannot undo a tightening the change asked
> for itself.**

The code did the opposite, because *"what is left standing"* is the tightened value:

```python
relaxed, why = relax(str(result["verdict"]), change_class)   # <- the value autonomy just set
```

Measured on `main`:

```
autonomy=confirm  change_class=None       -> confirm   tightened=True
autonomy=confirm  change_class=standard   -> auto      tightened=True     <- undone
autonomy=confirm  change_class=emergency  -> auto      tightened=True
```

A change that declared itself more dangerous than its grade was handed back its grade. `source`
printed both halves — *"tightened by the change's Autonomy field; relaxed from confirm by the
'standard' class"* — so **the report was honest while the verdict was not**, which is the harder
version of this defect to find.

### The guarantee already had a test, and the test picked the cell where it holds

`test_a_class_cannot_undo_a_tightening_the_change_asked_for_itself` has been green since
CHG-20260827-20. It uses `self_verify` at `low` — graded `auto` — with `autonomy=halt`:

```
relax('halt',    'standard') -> halt      <- relax cannot touch a halt, whatever the code does
relax('confirm', 'standard') -> auto      <- the rung with teeth, and the one nothing tested
```

So a test named for exactly this guarantee could not have failed for it. Not a vacuous test — the
case it covers is real — but a **named** guarantee tested only where it holds, which is the shape
this repository has logged before under a different heading. The new test says so in its own
docstring and picks the other cell.

### The fix, and what it reports

A tightening is skipped rather than re-relaxed. And a class that *would* have relaxed and did not
says so, for the reason `verdict` already gives about refusing a loosening: a refusal the node never
sees is a refusal that may as well not have happened.

## ② `autonomy` honoured one tightening in four, and reported one refusal in five

Found while measuring ①. The branch read:

```python
if graded == AUTO and want in STOPPING:        ...tightened
elif want == AUTO and graded in STOPPING:      ...refused, and reported
```

So a change declaring `halt` at a gate graded `confirm` matched **neither** branch: its word was
discarded, `tightened` stayed `False`, nothing was reported — and then ① relaxed the result to
`auto`. Measured on `main`:

| graded ⧵ asks for | `auto` | `confirm` | `halt` | `halt_independent` |
|---|---|---|---|---|
| `auto` | auto | confirm\* | halt\* | halt_independent\* |
| `confirm` | confirm | confirm | **confirm** | **confirm** |
| `halt` | halt | **halt** | halt | **halt** |
| `halt_independent` | halt_independent | **halt_independent** | **halt_independent** | halt_independent |

`*` = `tightened`. **Bold** = the request was neither honoured nor reported. The docstring promises
both: *"a change may declare itself more dangerous than its grade suggests, never less. Asking to
loosen is not honoured **and is reported**."*

### The order this reads by is `relax`'s, not a new one

`relax` allows `confirm → auto` and nothing else. That says `auto` is looser than `confirm`, and
`confirm` looser than either halt — because `confirm` can be pre-authorised with `--confirm` and a
halt cannot. So:

- **`auto < confirm < {halt, halt_independent}`** — every tightening along it is honoured.
- **`halt` and `halt_independent` stay unranked against each other.** `engine.py` says *"no ordering
  between `confirm`, `halt` and `halt_independent` is needed anywhere"*, and inventing one here
  would be a design change wearing a bug fix's clothes. A request that crosses between them is not
  honoured — and is **reported**, because a change that asked for something and got something else
  is exactly what this branch exists to say.

## ③ A plan could set the height of a gate standing over the whole change

`_grade_in_force` states the rule:

> a node in a workstream reads that workstream's grade. A node in none — `pr`, `merge`, `close_out`,
> and everything before the split — reads the **strictest** of them: a programme is as risky as its
> riskiest part **at the point where all of it merges**.

`plan.check` validated only that the workstream *name* was declared. **The node id was never checked
at all** — not against the flow, and not against the region a workstream grade is about. Measured:

```
run settled at high; the plan puts qa_accept in a workstream declared low
  _grade_in_force(qa_accept) -> low
  acceptance resolves        -> auto
```

`acceptance` at `high` is the **only** `halt_independent` cell in the entire table, and `README.md`
says of that grade: *"That grade **always stops for a person**."* A plan — written by the PM, and a
model — could delete it with two keys.

### Membership comes from the graph, not a list

`graph.module_cycle()` is the same function `engine._workspace` reads, for the reason its docstring
gives: *"so a node added to the loop later is inside the isolation instead of quietly outside it."*
The assignable set is therefore `{engineer_build, engineer_selfverify, fix_pass, lead_task_review,
re_review}`, derived, and `qa_accept`, `lead_review`, `qa_verify`, `pr` and `merge` are refused at
the door with the reason. A node id the flow does not have is refused too — that was the second half
of the same gap.

## Risk & rollback

- **① and ② make some runs stop where they did not.** A change that declared `autonomy` and carries
  a relaxing class now keeps its own word; a change declaring `halt` over a `confirm` gate now gets
  `halt`. Both are the documented behaviour and neither has ever happened.
- **② adds text to `source` on requests that were previously silent.** `source` is carried in the
  work order's closed verdict shape, so every model now sees a sentence about a request that was
  dropped. That is the point, and it is more text than these orders used to carry.
- **③ refuses plans that `main` accepts.** A plan assigning a workstream to `pr`, `merge`,
  `qa_verify`, `lead_review` or `qa_accept` now fails at the door. None of the shipped examples does
  — measured — but a project that wrote one was getting a grade it did not mean, and will now be
  told rather than silently corrected.
- **③ is a refusal, not a clamp.** Refusing at the door rather than quietly reading the strictest
  grade instead, because a plan that says something this runner will not honour should hear so — the
  argument `plan.py`'s own module docstring makes about `ship`.
- **`halt` ↔ `halt_independent` is still not honoured.** A change asking to move between them gets
  the table's word plus a sentence. If that ordering is ever wanted it is a design change and this
  is not it.
- Rollback: revert. Each of the three is independent, though ② was found by fixing ① and the two
  compound in the same cell.
