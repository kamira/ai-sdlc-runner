## Two defects in shipped code

### The payload could overwrite the envelope

```python
return {"seq": self.seq, "kind": self.kind, "at": self.at, **self.body}
```

The body spread **last**, so a body key replaced the turn's identity:

```
body overwrote envelope -> {'seq': 999, 'at': 'not-a-time', 'kind': 'note'}
```

`kind` survived only because Python raises `TypeError` on the keyword collision — **luck, not
schema**. A log whose payload can rewrite its own envelope cannot be ordered, deduplicated or dated,
which is the whole of what a log is for.

Fixed by spreading the body **first** and refusing the collision. The refusal is raised in
`Conversation.turn`, **ahead of `_guarded`** — a body naming its own envelope is a bug in the
caller, not a disk that filled up, and `_guarded` exists to keep archival failures out of a run. Left
inside it, a programming error would have been swallowed into `write_errors` and the run would have
carried on with a turn it never stored.

### A typo in the registry envelope deleted every model, silently

```
accepted with junk envelope -> Registry(models=())
```

That was `{"models": [], "modelz": [...]}`. `_model_from` closes an **entry**; `load()` read
`payload["models"]` and ignored every other top-level key. Misspell `models` and your whole registry
loads as empty, with no message — the same defect the module refuses one level down, in the same
file. Now the envelope is closed too, and the refusal quotes the reason.

## The root cause, which both seats found independently

**Nothing pinned the page.** `test_documented_numbers.py` holds the README's counts, flags and
examples to the code. The schema catalogue had no test at all, and drifted three ways in a day.

[`tests/test_schemas.py`](../../tests/test_schemas.py) — 17 tests. Each drift was **reintroduced and
the suite shown failing on it**:

```
CAUGHT  the closed count
CAUGHT  the attachment id
CAUGHT  opened_at back in the DDL
```

The closed-count test does not read a label — it **exercises** each schema with an unknown field and
counts the ones that refuse.

### The first version of that test missed one of the three

It asserted that `"64"` and `"stored_name"` appeared somewhere in entry 12. With the false line put
back, it **passed** — the corrective prose underneath still contained both words. A check that looks
for vocabulary rather than for what is being said is this repository's most frequent defect, written
into the test built to prevent it. It now reads the `id` line out of the example block and pins the
claim.
