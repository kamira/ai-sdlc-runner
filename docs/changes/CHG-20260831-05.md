CHG-20260831-04 recorded task 13 as *"The other three load doors name their file"* and its Risk
section said *"all four doors that can hit that now name the file"*. Measured — four sites can raise

| site | handler | changed this round |

| `cmd_run`, store (`cli.py:891`) | yes | yes |

| `build_factory`, per walk (`cli.py:1367`) | **none** | no |

Three have a handler; two were changed. The same record's *Not claimed* section and its acceptance's
reservation 3 both say the fourth has none — so the record contradicted itself and its own
acceptance on one page, and the sentence an operator reads for rollback was the wrong one.

## Veto 3: a bound in characters that was not one

ACC-20260831-04 reservation 2 disclosed the known-open bystander hole as *"one paragraph, at most

## The rename happened and the body did not

The defect seat's finding, and the sharpest of the round. CHG-20260831-03 said the disclosure
*"calls the rule"* instead of restating it; CHG-20260831-04's test docstring said *"It calls it
now."* Measured: `graded_by_guess`'s body is byte-identical to the function it was renamed from,

`reach_of` calls `graded_by_guess` now. One judgement, one place.

## Refusals that still did not lead where they said

Three more, and one of them is the fix for the last one:

1. **The store handler's assignment warning names two tables that do not exist.** It said to delete
   *"`seat_models` and `node_models` rows"*; the tables are `seat_assignments` and
   `node_assignments` — `seat_models` and `node_models` are function names in `store.py`. Following
   it gives `no such table`. The substance of the warning reproduces (foreign keys are off in every
   editor but this one, the orphan survives, and the console then starts clean and says nothing);
   only the names were wrong. The test now reads the table names *out of sqlite* and requires both
   to appear.
2. **The ghost-test lint accepts exactly one phrasing.** `deleted in`, `dropped in`, `renamed in`,
   `removed by` and — worst — `removed in [CHG-…](../changes/CHG-….md)`, the markdown-link form, in
   a ledger written in markdown, were all refused, because `]` is not a digit. Four verbs and the
   link form now, eight new rows in the table.
3. **The in-flight guard told the operator not to do the one thing that works.** It says *"restore
   from the record by hand rather than deleting it"*; `--recover`'s own new refusal says *"Delete it
   once the tree is reconciled."* For an empty record there is nothing to restore. The guard's
   message now sends people to `--recover` first, says what to do when it refuses, and says that
   deleting is the last step rather than the forbidden one.

And `serve --assignment-store none` — the escape the `run` refusal advertises — created a sqlite
database in the working directory **literally named `none`**, printed `models 0 registered`, and
started. Somebody following that instruction detached from every model and assignment they had,
silently, on the one command the refusal is about. `serve` refuses it now, and the advertisement
says where it works.

## Two more places a guarantee was claimed and not held

- **`recover()` tracebacked on valid JSON that is not an object.** `[]`, `null`, a bare string:
  `record["path"]` raises `TypeError`, which was not in the except tuple — in the branch whose
  refusal tells an operator to open the file and edit it by hand. `_owner`, twenty lines below,
  already caught `AttributeError` for exactly this shape.
- **The void rule could be silently disarmed.** `tools/ledger_check.py`'s comment claimed the two
  tuples were pinned *"in both directions"*. Dropping `voided` from `ACC_NEVER_TRUE` left the file
  green and a `**Voided.**` acceptance silently closed its change. Whether a word *means* never-true
  cannot be compared between tuples; it is pinned one spelling at a time, behaviourally, now.
