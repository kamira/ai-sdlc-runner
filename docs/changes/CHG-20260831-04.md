## The remedy deleted the file it called the only copy

The worst finding of the round, and it is four rounds old.

The in-flight guard tells whoever trips it: *"it holds the original text, and is the only copy …
`python3 tools/mutation_check.py --recover` puts it back when the recorded owner is gone; if it
refuses, restore from the record by hand rather than deleting it."*

Measured on a truncated record and on an empty one — the two shapes the previous round's own comment
calls *"what a kill mid-write leaves"* and *"the leftover this guard exists for"*:

```
$ python tools/mutation_check.py --recover
$ echo $?
0
$ ls tools/.mutation-in-flight.json
ls: cannot access: No such file or directory
```

Silent, exit 0, record gone. `recover()` hit `except (OSError, ValueError, KeyError):`, unlinked the
file and returned a string the `--recover` path never printed.

The rule was already written twenty lines below, about the edited-file case: *"a refusal that also
throws away the original strands the file for good."* These are the two shapes that most needed it.

**And a test was asserting the destructive behaviour.** `test_an_unreadable_record_is_discarded_and_
said_so` ended with `assert not sentinel.exists(), "an unparseable record must not block every later
run"` — a convenience argument, and the argument for discarding the only copy of an original. That
is why this survived four rounds of review of this exact file.
