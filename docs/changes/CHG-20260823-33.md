## Why three and not one

Each is silent about what the others show, so none of them substitutes for another.

| | answers | silent about |
|---|---|---|
| terminal capture | what was run, and what came back | why any of it was run |
| run replay | what the runner did, node by node, and how long each took | the commands that reproduced it |
| worklog | what was decided, on what evidence, what was rejected | whether any of it is true |

A terminal capture shows a test failing but not why that test existed. A replay shows a node halting
but not the six commands it took to get there. A worklog claims both and proves neither.

## 1 · `tools/session_record.py` + `tools/render_cast.py`

```bash
python3 tools/session_record.py --cast-dir docs/recordings/chg-34 -- python3 -m pytest tests/ -q
python3 tools/render_cast.py docs/recordings/chg-34 -o docs/recordings/chg-34.html
```

Casts are asciinema v2 — a format that already exists and can be read by tools that know nothing
about this repository. The player is ours, because an external one is a network fetch and a
recording that needs the network to replay is not a recording you can keep. The rendered page
fetches nothing but a font, and a test asserts it.

**One cast per command**, not one per session: a single growing file needs a lock the moment
anything runs concurrently, and a half-written trailing event from a killed process corrupts the
whole session rather than one command.

**The child is forced unbuffered**, and this is a real trade worth naming — it changes the child's
behaviour. The alternative is worse. Python line-buffers to a terminal and block-buffers to a pipe,
and a recorder is always a pipe, so a script printing steadily for two minutes records as one event
at the end with every timing gone. Measured on the same driver: **2 events buffered, 10 unbuffered.**

**Waiting is compressed and named.** A gap over `IDLE_CAP` (2s) plays as 2s with its real duration
shown. At true speed nobody watches it; cut silently, a review cannot tell a slow failure from a
fast one.

## 2 · `--format playback` — the fifth export format

The left rail is the flow, one entry per stop, lighting up as the replay reaches it. The stage
accumulates turns with the three voices marked apart.

**It shares `_stops()` with `html`.** Two renderings of one run that disagree about where a stop
begins make both untrustworthy, and the drift is invisible from either page alone. A test asserts
the rail length, the stop count and the waterfall's markup all agree.

**The clock is legible rather than literal, and the page says which.** A turn plays for at least
`MIN_BEAT` (0.35s); a pause over `IDLE_CAP` plays as 2s with its real length named. A turn whose
`at` will not parse gets a beat, never an invented duration — `_seconds` returns `None` rather than
"now", because a replay whose whole claim is that the timings are real must not manufacture one.

## 3 · `docs/RECORDING.md` and `docs/worklog/CHG-*.md`

What each recording answers and what it cannot; and the worklog convention — the panel's verdicts in
full, where the seats disagreed and what settled it, what was abandoned and why. Explicitly *not* a
prose retelling of the commands: those are in the cast, timestamped, and a second version of them
can disagree with the first.

## Defects found in this change's own work

- **The first replay was 3 seconds long for 55 turns.** Strictly accurate — the stand-in agent
  answers in milliseconds — and completely unwatchable. Found by opening it. `MIN_BEAT` compresses
  the ratio instead of erasing it, and a test pins that a slow turn still reads as slower.
- **An injection vector in the replay.** Turn bodies are embedded as JSON inside `<script>`. I
  reused the waterfall's markup-escaping mental model without checking where this text lands: in
  script context a literal `</script>` inside an answer ends the block early and the rest parses as
  page content. A model writes that sequence the moment it is asked about HTML — as this repo's own
  tide example does. Fixed at the JSON level (`<`, `>`, `U+2028`, `U+2029`) rather than by matching
  sequences, because a fix that enumerates dangerous strings depends on the enumeration being
  complete.
  - The test that *found* it used `<img src=x onerror=…>`, which is inert inside a JS string — right
    bug, wrong demonstration. A second test now uses the vector that actually breaks out.
- **Heredoc backslash mangling, twice more**, one of them producing a test that contradicted itself
  one line later while the code under test was correct throughout. A documented rule of my own,
  broken again.
- **A test that read a comment instead of the code** — grepped `scenarios.py` for `text=True` and
  failed on the comment explaining why it is not used. Rewritten to read the `subprocess.run`
  keywords out of the syntax tree. Third instance of this class this session.

### Not claimed

**That a recording proves the work is correct.** It shows what ran and what came back. A green suite
recorded is still a green suite; the recording buys reviewability, not correctness.

**That the terminal capture is complete.** It records what commands emitted — not input (there is no
pty), and only the steps wrapped in it. A step run outside the recorder is absent from it *without
leaving a hole*. That is the honest limit of the design, and the reason the worklog exists beside it
rather than instead of it.

**That the playback timings are literal.** They are compressed at both ends, and the page says so in
its own header rather than in this document.

## Correction (CHG-20260823-38)

This record says the script-context injection was **"Fixed at the JSON level (`<`, `>`, `U+2028`,
`U+2029`) rather than by matching sequences."**

True of `conversations.py`. **False of `tools/render_cast.py`, shipped in this same change**, which
went on embedding raw `json.dumps(steps)` into a `<script>` block with the `command`, `title` and
`note` unescaped. Both review seats found it independently; reproduced with a recorded command
containing `</script><img src=x onerror=…>`, which produced four closing `</script>` strings where
there should be one.

Reachable without an attacker: `session_record.py` records argv into the header, so recording any
command that merely *mentions* the string poisons the page.

Fixed in CHG-20260823-38. The two escapers are now compared against each other by a test, because
one rule living in two files is how one of the copies stopped being applied.
