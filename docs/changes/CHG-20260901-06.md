## What happened

Eighteenth round, four seats, four worktrees. **37 findings** — conformance 10, defect 5, risk 7,
idiom 15, which sums to 37. Several are the same defect reached independently by more than one seat;
the total is the sum of the seat reports and is not deduplicated. Every seat failed it. **Five
vetoes**, all from the conformance seat.

The headline is not a defect in the last fix. It is that **the thing being fixed should not
exist**.

## The rename excuse

`renamed to X in CHG-…` was accepted as an excuse for a test name that no longer resolves, because
it gives the reader somewhere to go. It has now produced the largest finding in each of the five
rounds that touched it:

| round | what the rename excuse did |
|---|---|
| CHG-20260901-02 | widened to any new name — `` renamed to `x` `` excused a ghost |
| CHG-20260901-03 | the new name had to resolve; the check vouched for **someone else's** rename |
| CHG-20260901-04 | scoping added, and it measured **clause order**, not scope |
| CHG-20260901-05 | a capital `R` turned the whole gate off; a wrap refused a true sentence |
| this one | a punctuation blacklist that `but`, `and`, `while` and an em dash walk through |

Every fix was inside the previous fix. This round's defect seat showed the current one open in four
natural spellings; the risk seat then measured what closing it properly costs — **83%** of
backticked test-name mentions in this ledger have a `,`, another backtick, a `.`, a `:` or a `;`
within the next 60 characters, and a strict rule refuses ten true sentences where the record
disclosed one, including `i.e.`, `e.g.` and `…`, which is verbatim the defect CHG-20260831-07
removed from `_SPAN`.

So: strict refuses the house style, loose excuses ghosts. What settles it is the third measurement.

```
check_named_tests_exist over this repository
  as shipped                                    0 problems
  with the rename alternative removed entirely  0 problems
```

**Not one of the 275 records relies on a rename excuse.** The only two records containing the
phrase at all are the two written *about* this rule. Five rounds of defects, and the feature they
were in has never once been used.

It is gone. A rename **is** a removal of the old name, so `removed in CHG-…` says it truthfully and
is four words longer; the record may still say what the test became, as prose the reader benefits
from rather than a clause the checker reasons about. Re-accepting renames turns **10** rows of
`GHOST_EXCUSES` red — the largest figure in the bounds table, and the one that says what the
narrowing bought.

With it go `_renamed_to`, `_ATTACHED`, `_CONNECTIVES`, `_REMOVED_NO_RENAME`, `_removed_by`, the
third scan pattern and the whole attribution gate. The refusal message now spells out the words
that work, because "say it was removed" was answered for four rounds by a phrasing that no longer
counts.

## The refusal still offered to overwrite somebody's edit

`recoverable` gained `mutated` last round and still never looked at the **file**. A record whose
only fault was `owner` — the exact hand edit the message invites with *"do not invent a pid"* — got
a restore instruction over a file that no longer held the mutated text:

| record | over a file holding an unrelated edit |
|---|---|
| complete | *"it matches neither … so somebody has edited it since"* — untouched |
| `mutated` removed | refused (last round's fix) |
| `owner` missing, or a string, list, float or bool | **"put the `original` back by hand"** |

The branch with *more* information gave the more destructive advice. It reads the file now, the
same way the automated fork does, and says what actually stopped it rather than naming fields.

## A capital `D` turned a guard off, in the change titled "a capital R turned the gate off"

The rule-3 pin is `if "delete" in said`. Last round rewrote the non-recoverable branch to begin a
sentence *"**D**elete this record once the tree is reconciled"* — so three shapes stopped being
checked by a guard whose entire subject is a message that says delete. It is `.lower()` now, and
the exemption is stated rather than lexical: a branch may say delete with no restore only when it
has said there is nothing to restore from.

## And two claims that falsified themselves

- **`git log -S"_REMOVED_NO_RENAME"` returns one commit** — which writing the sentence made false,
  because the sentence adds an occurrence of the string. The census defect, in the correction for
  the census defect. Restated as two named commits and what each contains.
- **A removal note for a test that never existed.** The note named an intermediate name this
  change passed through between two renames; the test actually deleted had no note at all. The lint
  accepted it because a removal note excuses whatever name it is attached to.

## Risk & rollback

- **`ledger_check` refuses every rename spelling it accepted**, and accepts everything it accepted
  before by way of `removed in CHG-…`. Over the real ledger nothing reclassifies: 0 problems before
  and after, 138 changes green.
- **The refusal is longer**, and names the accepted words. That is the point: the old one offered a
  remedy the author had already followed.
- **`--recover` refuses one more state**: a record whose only fault is `owner`, over a file that has
  been edited since. It used to advise overwriting it.
- **`_alive_posix` answers `True` for a pid outside `pid_t`** instead of raising. Refusing is the
  safe answer and matches every other "cannot tell" in the module.
- Rollback: revert. The rename excuse comes back with five rounds of open defects, the refusal
  offers to overwrite an edited file, and a capital `D` turns a guard off.
