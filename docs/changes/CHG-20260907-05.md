## The request and the check disagreed, twenty lines apart

`intake.option_request` is the text this runner actually sends a model when an aspect has been
asked for three times and not supplied:

```
Propose at least 3 concrete, different options a person could pick between.
Do not pick one. Each option: what it is, and what it costs.
```

`intake.read_options`, which reads the answer to exactly that question, counted the length of the
list:

```
read_options({"options": ["a", "a", "a"]}, "ui")   ->  ['a', 'a', 'a']
read_options({"options": ["a", "A", "a "]}, "ui")  ->  ['a', 'A', 'a']
```

So three copies of one label answered a question that asked for three different ones. The check's
own docstring says why it exists — *"two is a false choice and one is a decision wearing a question
mark"* — and one label repeated three times is precisely the second of those, wearing the question
mark three times.

This is not a record disagreeing with code. **It is one module's request disagreeing with the same
module's check**, and the word that was never implemented — *different* — is in the sentence the
runner sends.

## What changes

`read_options` counts distinct options, by exact string, after the strip `_strings` already does.

The refusal message changes too, and it had to: it said `got {len(options)}`, so refusing three
identical labels would have read *"asked for at least 3 and got 3"* — a sentence that contradicts
itself while enforcing a rule. It now reports both numbers:

```
asked for at least 3 different options for 'ui' and got 1 from 3 offered.
```

## Not case-folded, deliberately

`["Fast", "fast", "Slow"]` is accepted. `Fast` and `fast` are two labels a person can tell apart,
and they may be two real things — identifiers, flags, filenames on a store that distinguishes them.
Case-folding to catch a model repeating itself in a different case would refuse more than it
caught, and it would still miss a model repeating itself in different words. Exact string is the
boundary that needs no new policy.

## What it does not revert

`MIN_OPTIONS` and the three-option rule are untouched; only what counts as one option changes.
Nothing in `docs/` or `tests/` passed duplicate options: every existing case is `["a", "b", "c"]`
or similar. `codex` cited `CHG-20260823-13` as saying *"at least three concrete, different
options"*; measured, that phrase does not appear in that record (`grep`: 0). It appears in
`intake.py` itself, in the request — which makes the case stronger rather than weaker, and is why
this record quotes the code and not the ledger.
