## M-1 — `runner run` could never reach the escalation `intake.py` promises

`intake.py`'s module docstring:

> After the third time a given aspect has been asked for and not supplied, the runner stops asking
> and **proposes at least three options** for it.

`cmd_serve` passes `intake_history=`. **`cmd_run` never did**, so `cfg.intake_history` was `()` on
every invocation and `intake.times_asked` was hard-wired to 0. Measured by the seat, five real
invocations with the seats reporting `missing: ["flow"]`:

```
runner run    invocation 1..5:  options={}   reason: "... (asked once)"
runner serve  stop 1..3: options []          stop 4: the engine asks for options
```

Not a smaller number — **the escalation could not fire on the command line at any count**, and
`stop_reason` rendered *"asked once"* on the fifth re-run, because
`{1: "asked once", 2: "asked twice"}.get(seen, ...)` is a ladder only one of the two commands could
climb.

### The fix, and where the count lives

`serve` keeps the count in `RunState`, which is one process. `run` had nowhere to keep it, so this
gives it one: **the ask journal** — already this command's memory across invocations, the directory
`--ask-journal` names and `--resume` reads.

- `AskJournal.record_intake_stop(missing)` / `.intake_stops()`, a file per stop rather than one file
  rewritten, so two runs sharing a journal cannot lose each other's count to a last-writer.
- `entries()` excludes them by name. A stop carries no `ask_id`, no `status` and no `order`; a
  `pending()` that swept one up would report it as a question nobody answered.
- `cmd_run` reads before the walk and records after it, from `report.suspended`, so the engine still
  takes its whole world through `RunConfig` and gives it back through the report.

```
invocation 1: times_asked=0  needs_options=False
invocation 2: times_asked=1  needs_options=False
invocation 3: times_asked=2  needs_options=False
invocation 4: times_asked=3  needs_options=True     <- ASK_LIMIT
```

## M-2 — a requirement naming an undefined aspect killed the run with a traceback

`intake.IntakeError` is a bare `Exception`. `cmd_run` caught `EngineError`, `PolicyError`,
`CliError`, `SandboxError` and `WorktreeError`. Measured by the seat, a real CLI run whose seat
answered `intake_review` with `{"missing": ["database"]}`:

```
exit code: 1
stdout: (empty)
stderr:  Traceback ... ai_sdlc_runner.intake.IntakeError: seat 'conformance' says 'database' is
         missing, which is not one of the aspects this runner asks about
```

`intake.collect` refuses it with a sentence written for a person — *"a seat reporting `database`
missing has answered a question this runner did not ask, and quietly dropping it would lose a real
observation while looking like agreement"* — and that sentence reached stderr wrapped in a stack,
with **exit 1** rather than 10, the one halt code this CLI returns.

Two further consequences of the skipped branch, and they are the reason this is not cosmetic:
`_report_pending(journal)` never ran, and neither did `_close_trees(trees, args, keep=True)` — so a
`--worktree` run **leaked its trees** on the one path whose own comment reads *"A halted run KEEPS
its trees: the tree is where the evidence is."* `serve` catches `Exception` broadly and rendered it;
`run` did not.

## M-3 — the guard shipped two changes ago looked one way

`test_both_ways_to_start_a_run_take_the_same_governance` (CHG-20260901-16, task 3) compares the two
`engine.RunConfig` call sites. Its own docstring says *"the defect is the drift and not the field"*.
It computed one set:

```python
missing = built["cmd_run"] - built["cmd_serve"]
```

The reverse was never computed, and it is where M-1 was hiding. Run in the other direction, with the
same exemption discipline:

```
shipped guard, as written    : PASS
same guard, other direction  : FAIL
    `serve` passes ['artifacts', 'instructions', 'intake_history', 'rejections']
    that `run` does not; unexplained: ['intake_history']
```

Three have honest reasons — `run` has no `--attach`, no `--instruction`, no `--reject`; the console
collects those from a browser. `intake_history` had none: **it is not a console concept, it is the
runner's own counter.** The guard is bidirectional now, with a named, argued exemption set on each
side.

That a guard written to catch drift, in the change that found four drift defects, could not see the
drift in the other direction is the finding, not the fix.

## What is **not** fixed here, and why

The seat also reported **M-3′**: `serve --undeclared allow` waives the permanent-halt declaration
check on every node and the console cannot say so — `report.relaxations` is absent from
`RunState.snapshot()`, along with **sixteen** other report fields.

Verified independently, and **left open, deliberately.** It is not a new defect: it is the exact gap
CHG-20260901-15's task 18 exists to close, measured again from another angle, and closing it here
would ship the console half of a design that is under review and has been failed by four seats
twice. What this change does instead is record the number so the design's task cannot be scoped
from an estimate:

```
RunReport fields                     : 28
absent from RunState.snapshot()      : 16
  asks · change_class · effects · halts · on_trust · options · panel_rounds · relaxations ·
  relaxations_by_class · resumed · risk_agreed · risk_proposed · risk_settled ·
  single_model_panels · store_errors · verdicts
```

Sixteen, not eighteen. A plain name comparison says eighteen and is wrong: `halted_at` and
`halt_reason` **do** reach the console, under the keys `at` and `reason`. Recorded because the naive
number is the one a reader would reproduce, and a task scoped against it would be scoped against two
fields that are already there.

Two of the sixteen carry a promise in their own docstring or in a P0 requirement:
`single_model_panels`, which FR-24 requires be recorded **and printed**, and `halts`, which
CHG-20260901-16 wired into `as_dict()` four commits ago — where, as the seat also measured,
`as_dict()` has **no caller in `src/` at all**. That is worth stating plainly against this session's
own work: D4 made those six fields emittable and did not make them reach a reader.

The seat's **M-4** is a stale comment, not a defect: `engine.py:940` says `_dispatch_from` is
*"seeded by the run"*, `dispatch_seed` has no caller, and `README.md:197-201` already states the
truth. Recorded here rather than fixed, because correcting a docstring the README already corrects
is not worth a behaviour-free `src/` change in a defect record.

## Risk & rollback

- **M-1 changes what a repeated `runner run` does.** A project that has re-run the same incomplete
  requirement three times will now be offered options instead of being asked a fourth time. That is
  the documented behaviour and it has never happened on this command before.
- **The journal gains files that are not asks.** Anything reading `--ask-journal` by globbing
  `*.json` and assuming an ask shape will now see `intake-stop-NNN.json`. Nothing in this repository
  does — `entries()` is the only reader and it filters — but the directory is an operator-visible
  surface and its contents changed.
- **M-2 changes an exit code from 1 to 10** on one path. A CI job treating any non-zero as failure
  is unaffected; one distinguishing 1 from 10 will now see a halt where it saw a crash, which is the
  correct reading.
- **M-3 makes a green test able to fail.** It was passing on half the property it claimed.
- Rollback: revert. Each of the three is independent.
