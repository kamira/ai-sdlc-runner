## The sentence both seats killed

> *"The `AskJournal` already writes every ask down… The store is therefore **derived**, not a second
> source of truth."*

Fourteen lines above it, the same brief defined a conversation as asks **and operator decisions** —
*"a person answering is as much a turn as a model answering, and a store that keeps only the model
side has thrown away half of what a reader would come to it for."* Then it chose a source that has
never held one. `journal.record` and `journal.answered` are the journal's only two writers;
confirmations, rejections and rulings reach only the in-memory `RunReport`.

The design could not produce the document the design defined, and I did not notice while writing
both halves fourteen lines apart.

Two things I then confirmed by **running** them rather than reading them:

```
two fresh runs, one journal directory  ->  entries: 1
what survives                          ->  {"brief": "SECOND RUN"}
run_id 1 == run_id 2                   ->  True

sorted('%03d-x' % n for n in (99,100,101,999,1000))
['099-x', '100-x', '1000-x', '101-x', '999-x']
```

The journal is keyed by position and `record` overwrites, so the first conversation is not stale in
the store — it is **gone from the source**. And `entries()` sorts filenames, so the 1000th ask sorts
between the 100th and the 101st; a store presenting "the ordered sequence of turns" would have
inherited that for free, at a scale where a demo looks fine.

So the store is a **first-class append-only log**, written as turns happen. The journal stays what a
resume reads. They record different facts and cannot drift, which was the original objection to
having both.

## What each seat found, and what it changed

| Finding | Seat | What it changed |
|---|---|---|
| The journal holds no operator turn, and overwrites the model turns | **both** | the whole architecture — a log, not a derivation |
| A loopback host does not constrain `MongoClient`: topology discovery connects to members it learns of **from the server** | **both** | four URI rules **plus** `directConnection=true` forced on the client — the one that binds the driver rather than the string |
| `run_id` is the journal directory: two runs collide, and a Windows path is not a filename | **both** | a minted `conversation_id`, marked beside the journal so a resume re-attaches |
| `--project` defaulting to the plan's parent directory files everything under *"examples"* | **both** | required, no default, and hashed before it touches the filesystem |
| CSV formula injection — `=HYPERLINK(…)` in model-produced text | fable | every cell defused |
| Excel truncates silently at 32,767 characters | fable | data whole, an `over_spreadsheet_cell_limit` column |
| ``` inside an answer ends a markdown fence early | fable | fence length computed from the content |
| A relaxation has nowhere to record at `export` time — there is no `RunReport` | fable | recorded in the document |
| *"must not be silent"* named no mechanism | fable | `RunReport.store_errors`, a `note` turn, and stderr |
| The three backends guarantee nothing in common | codex | five guarantees stated, including **no concurrent writers** |
| `<root>/<project>/<run>.json` repeats a hazard `attachments.py` records | codex | both path components are 32-hex |
| A model's identity is not in any durable record | codex | the `ask` turn carries it |
| `file` is the default and is not a NoSQL DB | fable | said, not argued around |
| CSV cannot carry an in-band "this is lossy" note | fable | the notice is the column names |

## One the seats could not find, because the code did not exist yet

The Mongo rule shipped in my first draft with the **same hole CI caught in `server.py` two changes
ago**: `urlsplit("mongodb://[::1].evil.example")` returns host `::1` and drops the rest, so the
loopback set accepted a domain an attacker registers. A test written for that finding, pointed at
this function, failed on the first run. The host must now **round-trip**, not merely parse.

I had written the correct check once, in another file, two days earlier.

## Risk & rollback

- **Nothing changes without `--project`.** `RunConfig.conversation` defaults to `None` and every
  existing caller passes nothing; the 857 tests that predate this change still pass unmodified apart
  from two that assert on the literal text of a `_finish` call.
- The store is a **new copy of sensitive material**. It is as sensitive as the journal already on
  disk beside it and no better protected, which the README now says rather than implies.
- Rollback: revert. The store is additive and nothing reads it during a run.

### Not claimed

**That the tinydb and mongo backends have been run.** Neither package is installed here, so what is
tested is the refusal — which is the path an operator without them actually hits. The backends' own
tests skip, and `pytest -rs` in CI prints the skip rather than letting it read as a pass.

**That `directConnection=true` was observed stopping a discovery.** That needs a replica set with a
remote member, which this machine does not have. fable-seat flagged the same limit on its own
finding. What is tested is that the flag is forced onto every URI and that `directConnection=false`
is refused.

**That the store is protected.** It is not. It is as readable as the journal beside it.
