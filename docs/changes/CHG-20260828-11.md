# CHG-20260828-11 — two planners spacing a signature differently stopped the run

- Project: ai-sdlc-runner
- Branch: claude/chg-20260828-11-signature-spacing
- Date: 2026-08-28 (UTC+0)
- Type: a false stop removed, without acquiring a type language
- Proposed by: reservation 2 of ACC-20260827-22
- Risk: **medium** — it makes `reconcile` refuse **less** often, and `reconcile` is a gate on the
  plans
- Autonomy: high
- Related: CHG-20260827-22 (sub-planning and the reconciliation node)

## The gap

`ACC-20260827-22`, reservation 2:

> **The signature is an opaque string.** `(id) -> User` and `(id)->User` are a conflict. That is
> deliberate — normalising would mean parsing a type language this runner does not have — but it
> means a formatting difference stops a run. The halt names both strings, so the fix is visible, but
> it is a false stop and it is not measured here.

Two planners describing the same interface, one of whom put spaces around an arrow, send the run
back to `pm_plan` and then to `halt_unreconciled`. Nothing is wrong with either plan.

A false stop is how a check gets switched off — this repository's own recorded concern about the red
lines, and the reason `--sandbox` refuses only when somebody asked for it.

## The reservation conflated two things

*"Normalising would mean parsing a type language"* is true of **semantic** normalising — deciding
that `List[int]` and `list[int]` are the same needs to know the language. It is **not** true of
whitespace, and the two were run together, which is why the gap stayed open.

## The rule

**Whitespace touching punctuation is formatting; whitespace between two word characters is not.**

```
(id) -> User    ==  (id)->User        the case the reservation named
Dict[str, int]  ==  Dict[str,int]
int x           !=  intx              a space between words carries meaning
(a) -> b        !=  (a) -> c          a real disagreement is still a conflict
```

Stated as a rule rather than a regex because the regex is the easy part. The first attempt was
*strip all whitespace*, which merges `int x` with `intx` — two different declarations in every
notation this could plausibly hold. It is pinned by its own mutation, so the cheap wrong rule cannot
come back.

**Comparison only.** The reported strings stay exactly as each workstream wrote them: when two
planners genuinely disagree the operator needs to see what each of them said, and a halt quoting a
normalised form would send them looking for text that is in neither plan.

## Risk & rollback

- This makes `reconcile` refuse **less** often, which is the direction that needs the argument. The
  argument is that the two declarations it now accepts are the *same declaration*, and stopping on
  them stopped nothing real.
- It cannot accept a disagreement in any character that is not whitespace.
- Rollback: revert. The false stop returns.

## Status

**Accepted** — see [ACC-20260828-11](../acceptance/ACC-20260828-11.md).

### Not claimed

**That semantic differences are handled.** `List[int]` and `list[int]` are still a conflict, and
`(id) -> User` against `(uid) -> User` is a conflict that looks like a typo. Both need a type
language this runner does not have, and the reservation was right about that half.

**That the false stop was measured.** The reservation said it was not measured, and it still is not:
nothing counts how often two planners would have spaced a signature differently. The case is
reasoned from what two people writing the same interface do, not observed.
