## Veto 1: "cannot tell" was answered "mine"

CHG-20260831-02 made the in-flight guard judge ownership **per path**, correcting a fix that had
made the mutation harness constant. The new filter was:

```python
present = [p for p in present if owned is None or mutation_recovery._owner(p) != owned]
```

`_owner` returns `None` for a record it cannot read — no `owner` key, `owner: null`, truncated JSON,
a zero-byte file — and `owned` is `None` whenever `MUTATION_RUN` is unset, **which is the CI path**
(`.github/workflows/ci.yml:53`). So `None != None` is False and the record was dropped before
`assert not present` ever looked at it.

The defect and risk seats measured the same regression independently, and the idiom seat then drove
the real test function from both sides of the range on one fixture:

| record on disk | `MUTATION_RUN` | at `3b146f1` | at `2510e08` |
|---|---|---|---|
| `{…, "owner": 999999}` | unset | fails | fails |
| no `owner` key | unset | fails | **passes** |
| `"owner": null` | unset | fails | **passes** |
| truncated JSON | unset | fails | **passes** |
| zero-byte file | unset | fails | **passes** |

The truncated record is the one a kill mid-write leaves — the exact leftover the guard's own
docstring exists for. And the harness could not reach the broken column by construction: a mutation
run always sets `MUTATION_RUN` to a pid, so `--only stranded` was 12/12 with the hole open.

**Unreadable is not owned.** Only a record that exists *and* names the announced pid is excused.

## And the skip was about a variable, not a record

`if not present and announced:` — once the filter emptied `present`, the skip fired on the
**variable**. With `MUTATION_RUN=1` exported and nothing on disk, the guard skipped, reporting that
run "owns the record" over a tree that held none. One stray export, or the name appearing in any CI
environment, turned the stranded-tree detector into a permanent abstention.

A skip now requires a record that was actually excused.

## The ledger's matching, again — and this time it was English

The round above recorded *"every boundary rule so far was right about English"*. Here it is the
inverse, and undisclosed:

| status | was | is |
|---|---|---|
| `not done` | **DONE** | not finished |
| `not yet complete` | **DONE** | not finished |
| `not merged`, `not accepted`, `not shipped`, … | **DONE** | not finished |

English negates with a **space**, so the ASCII boundary rule fires between `not` and `done` and
there was no vocabulary entry for `_standing` to nest the `done` inside. ~~Nine of the ten~~
**All ten** English `DONE` words, across both prefixes — twenty phrases. The nine-of-ten figure
came from the round-8 risk seat and I repeated it in three places without measuring it;
corrected in CHG-20260831-04 (idiom seat). The negated forms are **generated from `DONE`** rather than typed, so a word added
there cannot acquire the defect by being written into one tuple and not the other.

The third vocabulary scan — `AWAITING_DECISION` — was still the raw `w in status` construction, in
the same function as the docstring that names that construction as the bug. It tripped on nothing in
the real ledger: exposure, not a live defect, and the next word added would have inherited it.

## What I found by reverting my own fix

The first draft of the tests written to close veto 1 **could not tell a failure from a skip**. Both
halves of the guard fix were reverted and the suite reported `31 passed, 4 skipped` and `34 passed,

silently. `_guard_must_fail` treats a skip as a failure; both reverts now go red.

No seat found this. Reverting the fix to test the test did.

## Risk & rollback

- **The guard is stricter, and that is the point.** A record it cannot read now fails the suite
  rather than being excused. On a tree holding a genuinely orphaned half-written record, `pytest`
  goes red until a person reconciles it — which is the behaviour `recover()`'s own refusal
  prescribes.
- **`ledger_check` classifies more statuses as unfinished.** Every existing status and verdict in
  the ledger classifies as before — checked, ~~128~~ **129** changes (this record is in the ledger it counted;
  corrected in CHG-20260831-04), `check(repo) == []`. What changed is that
  ~~nine~~ **ten** English negations that read as *finished* no longer do — the same miscount as
  the one struck eighty lines above, surviving in this record's own Risk section. There were
  four sites, not three. Corrected in CHG-20260831-05 (VETO).
- **`models.py` refuses less than it did last round, and still more than two rounds ago.** A bare
  username with no credential shape passes again; a password, a token-shaped username, a fragment
  key and a query key are all refused.
- **The retroactive-load refusal stands.** A model stored before CHG-20260831-02 with a credential
  in its userinfo makes `store.load_registry` raise on **load**, taking every other model with it.
  The handler catches it and the message names the sqlite file to edit. There is no migration.
- Rollback: revert. Four of five record shapes stop failing the guard, the skip goes back to firing
  on a variable, and the disclosure resumes naming IPv6 models it did not grade.
