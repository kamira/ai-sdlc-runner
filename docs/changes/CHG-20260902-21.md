## The shape, for the twentieth to twenty-third time

Each of these is a **declaration that does not reach the thing it declares about** — and three of
the four are in the file that makes the declaration.

## L-20 — three of the eight `rejects_to` edges deliver a reason to a node that is asked nothing

`_order_for`'s own comment presents this as closed: *"Eight nodes carry `rejects_to`; every one of
those loops asked the same question and got the same answer, which is not 'unbounded' but
**non-convergent**"* (CHG-20260901-12). `sent_back` is keyed by node id and consumed where a node is
asked — and `sent_back.pop(node.id, None)` ran **before** `if node.role:`, so at a node with no role
the message was popped and dropped.

Measured:

```
node                 rejects_to          target role   reads the reason?
pm_confirm           pm_plan             pm            yes
lead_assess          pm_plan             pm            yes
pm_signoff           pm_plan             pm            yes
engineer_selfverify  engineer_build      engineer      yes
lead_task_review     fix_pass            engineer      yes
lead_review          review_failed       None          NO
qa_verify            next_module         None          NO
qa_accept            acceptance_failed   None          NO
```

The three dead edges are exactly the **whole-change** refusals — the three most expensive loops in
the graph. The seat measured a refusal at `qa_verify` reaching **0 of the 5** work orders on the lap
that followed, while `report.rejections` said *"the run goes to next_module"*.

### The fix: forwarded, not spent

A message is popped only by a node that can be told, and re-keyed onward at the point the run
decides where it is going. Traced, all three land on `engineer_build` — the node doing the rework:

```
lead_review  -> review_failed -> change_retry -> next_module -> engineer_build
qa_verify    -> next_module                                  -> engineer_build
qa_accept    -> acceptance_failed -> change_retry -> next_module -> engineer_build
```

Re-keyed rather than broadcast: it stays one message for one node, and it keeps moving only while
nothing can consume it. A node **with** a role popped it already, so this cannot re-deliver
something already read.

## L-20b — `_adjudicate` called `_send_back` and threw the result away

Same function, two callers. `walk`'s model-panel branch does `rework = _send_back(...)`;
`_adjudicate` did `_send_back(...)`. `_send_back`'s own comment:

> **Returned, not only recorded.** … the rework was never told what it was reworking, and a `fail`
> that loops back produced the same answer next lap.

So `graph.review_failed`'s note — *"back into the module loop; **the panel's reasons travel with the
run**"* — was false for every seat panel in the flow, and the seat measured the rework lap's work
orders coming back byte-identical.

`_adjudicate` returns `(branch, rework)` now. One production caller.

## L-21 — a probe read "git cannot answer" as "the branch is not there"

`probes.py` states the rule twice — *"An unanswerable probe is **never** read as 'not done': that
would re-run an effect that may have succeeded"*, and `ProbeError`'s *"collapsing them makes the
engine re-run an effect that may already have landed."* Its three sibling git probes raise.
`branch_exists_locally` was one line:

```python
return proc.returncode == 0
```

It is the `branch` effect's probe in `ship.effects_for`, so a false `False` re-runs
`git checkout -b <branch>`.

### The fix, and the measurement that changed it

The first version of this fix raised on anything but 0 and 1. Measured, that was wrong:
`git rev-parse --verify` exits **128 for both** *"no such branch"* and *"not a git repository"* — so
that probe cannot tell the two apart **at any exit code**, and the fix would have refused to answer
a question it could answer. `git show-ref --verify` gives three codes for three states:

```
0    the branch is there
1    the branch is not there          <- an answer
128  git could not be asked           <- not an answer
```

Recorded because the first attempt looked right and was measured wrong before it shipped.

## L-22 — the gates a change class dissolved never reached the durable record

`RunReport.relaxations_by_class`: *"Gates this run passed **because** of the class, each named. A
relaxation nobody can enumerate afterwards is a relaxation nobody can audit."*
`conversations.relaxation`: *"Recorded **in the document**, not only in the run report."*

`_finish` iterated `report.relaxations` alone. Measured by the seat on a `standard`-classed run:

```
relaxations_by_class: ["merge: merge at risk low would have been 'confirm' and passed
                       on the 'standard' class"]
durable store        : 14 relaxation turns, all "<node> ran undeclared" / "below the floor"
is the merge note in the durable conversation?  False
```

The gate that was dissolved is **`merge`** — the one-way door. The durable record said a `standard`
class governed the run and never said which gate it opened, while carrying fourteen turns of
`--undeclared` noise beside it.

## L-23 — the single-backend disclosure named a flag that cannot reach the panel it flagged

`_note_panel_diversity` is called from four sites — the model-panel branch twice, the survey, and
the seat panel — and said *"Use `--seat-model SEAT=COMMAND`"* at all of them. A `MODEL_PANEL` node
opens **no seats**: `cli.session_factory` resolves a seat command through `seat_models.get(seat)`,
and the model-panel path passes `seat=None`.

So FR-24's false-assurance detector was telling an operator to use a flag that does not go there.
The remedy is read off the node's mode now — a model panel is pointed at `node_models`, which is
where its voices actually come from.

## Risk & rollback

- **A rework lap now carries a reason it did not carry.** Three loops that produced byte-identical
  work orders will now produce different ones. That is the fix, and it changes what every model on
  those laps is asked.
- **L-21 turns a silent re-run into a refusal.** A `ship` run in a directory git cannot read now
  raises where it used to create a branch. Anything relying on the probe's `False` in a broken
  repository was relying on a re-run.
- **The durable conversation gains turns** on any classed run. `runner export` output grows, and a
  reader diffing exports across this change sees new relaxation lines for runs that behaved
  identically.
- **The diversity message changed wording** at every site, not only the model-panel ones — "seat"
  became "voice", because the function is called from four places and only two of them have seats.
  Anything matching that string exactly will stop matching.
- **`_adjudicate`'s signature changed** from `str` to `(str, Optional[dict])`. One production caller
  and one test.
- Rollback: revert. Each of the four is independent.
