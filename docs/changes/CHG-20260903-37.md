## `docs/API.md` on `survey`, wrong in three ways at once

```
ships   {"problems": {"<seat>": […]}, "missing": […], "safety": {"<seat>": […]}, "complete": false}

§3      "safety": […]                          an array
§3      complete                               absent
§4      "safety": { "<aspect>": [ … ] }        keyed by aspect
```

`intake.collect` writes `survey.safety[seat] = unsafe`, and `engine` carries it through unchanged.
There are six aspects and four seats; the key spaces do not even overlap.

## The two pages that disagree about six tables

`SCHEMAS.md` row 14 said **"3 of 5 tables built"**. `DATABASE.md` says **"6 of 6"**. `store._EXPECTED`
enumerates six and `store.py` carries six `CREATE TABLE IF NOT EXISTS`.

The sharp part is that `SCHEMAS.md`'s own opening paragraph says:

> *"A catalogue of closedness that miscounts its own subject is the thing it warns about, so the
> count is now checked by `tests/test_schemas.py` rather than asserted here."*

That guard covers the **closed-schema** count, which is right. The **table** count sat in the same
table, asserted and checked by nothing.

And `DATABASE.md` contradicts itself inside one paragraph: it names all six as *"live in
`store.py`"* and then, three lines later, calls `conversations` and `turns` *"designed here and
created by no code"*. Both are in `_EXPECTED` and both are among the six `CREATE`s.

## The fix surfaced a defect in the guard that caught it

Correcting `SCHEMAS.md` to `6 of 6` turned `test_the_page_says_which_tables_are_built_and_which_are_not`
red with:

```
the page must say how many of the 7 tables exist; 6 do
```

**Seven.** The guard derives its `designed` set with `CREATE TABLE (\w+)` over the whole page, and
the real DDL form is `CREATE TABLE IF NOT EXISTS <name>` — so the moment this record's own
annotation quoted `store.py` verbatim, the pattern captured **`IF`** as a seventh table, declared it
designed-and-unbuilt, and demanded the page say so.

**That guard is right about the property and was wrong about where to look.** It is derived rather
than frozen — its own comment says an earlier version accepted a hard-coded *"three of five"* and
that *"the frozen half made the computed half optional"* — which is exactly why it caught this
change at all. A documentation page that cannot mention the syntax it documents is the guard's
defect, not the page's.

Anchored to the start of a line now: DDL is, prose about DDL is not. With that, `designed` is six,
`built` is six, and `SCHEMAS.md`'s corrected `6 of 6` stands.

**Neither seat found this.** It exists because a documentation fix ran into a derived check, which
is the argument for deriving them.

## Risk & rollback

- **Nothing here changes behaviour.** Every fix is a sentence, a shape or a path. What changes is
  what a caller writes against `docs/API.md` and what a reader believes about the graph and the
  store.
- **Task 4's rule fired on three paths and two were its own fault**: a test docstring quoting the
  old path (this record's), and a directory fragment that is prose rather than a path. Both are
  narrowings of the rule, in the test, with the reason — **not** changes to the code to satisfy it.
- **Task 3's rule compares keys, not shapes.** A key documented with the wrong *type* still passes
  it; §3's `"safety": […]` is caught here by an explicit assertion rather than by the rule.
- **`docs/API.md` is a contract for callers outside this repository.** Correcting it is right and it
  may still surprise anyone who wrote against the wrong shape — they were writing against something
  that never matched.
- Rollback: revert. A caller keys safety findings by aspect and matches nothing, a shipped refusal
  cites a file that does not exist, and two pages disagree about six tables.
