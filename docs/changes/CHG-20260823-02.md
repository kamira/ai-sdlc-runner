## What the verifiers found

Two independent seats, asked separately. `codex-seat` returned **Fail**; `fable-seat` returned
**Pass with reservations** — and **both, independently, named the same worst finding.** That
agreement is what settles it: this is not one reviewer being severe.

`fable-seat` also mutation-tested the previous round's fixes — cutting the wire on `adjudicate`,
`answer_decides`, `_permanent_halt`, `_run_effects` and `confirmed` in turn, and confirming each cut
turned tests red (42 red for one of them). Those fixes are real. The findings below are what is
left.

The finding that justifies the Fail on its own:

> FR-12 宣稱六類永久紅線「never automated」,但比對只是可輕易改寫的 substring blacklist;
> 我用六個自然句子逐類繞過,全部會被派工。這是 P0 安全保證失效。

Six ordinary English sentences, one per red line, every one dispatched:

| Red line | The sentence that walked through it |
|---|---|
| production deploy | `promote the new build into the live environment` |
| data migration | `rewrite all customer rows to the new format` |
| hard delete | `erase every customer record permanently` |
| moving money | `wire USD 500 to the vendor` |
| secrets / access | `grant Alice administrator privileges` |
| publishing | `make the embargoed article visible to everyone` |

`fable-seat` produced six *different* sentences that also walked through — "push the new build to
prod", "wipe the users table", "rotate the signing key", "make the repo public" — which is the
proof that the list was never one word short.

Reproduced before changing anything: all twelve returned `None`.

And a second hole under the same rule, from `fable-seat`: **the check only ever read what a plan
volunteered.** A plan that simply omitted `operations` was checked against nothing at all. The red
lines could be walked past by saying *less*, not by saying something false.

**Adding those six phrasings would have fixed nothing.** The next six sentences are free, and free
again after that. A blacklist stops the phrasings somebody thought of; the ones nobody thought of are
the ones that reach production. The defect is not the word list's contents — it is that a word list
was load-bearing at all, and that its default branch was *proceed*.

The test that was supposed to cover this fed each rule's own description back into its own word list.
A tautology, and it passed.

### Risk & rollback

- Risk: **high**. Task 1 changes the shape of `operations` in every plan: a bare string is now
  refused. That is a breaking change on purpose — the old shape could not be classified without
  guessing, and the guess is the defect.
- Named failure mode: **false stops.** The backstop word lists were widened to catch all six verifier
  sentences, so ordinary work will sometimes trip one and have to be declared. That direction is the
  cheap one: a false stop costs a question.
- Second: the declaration is only as good as the planner's honesty. A red line declared `ordinary`
  still stops if its own description gives it away, but a red line declared `ordinary` **and**
  described blandly will pass. This is a real, named limit — see Status.
- Rollback: `git revert`.

### What I could not close, and am not pretending to

**The declaration is only as strong as the planner.** An operation declared `ordinary` and described
in words that give nothing away will be dispatched. The backstop catches carelessness, not intent.
What this change buys is that the *default* is now a refusal rather than a pass, so the failure needs
a wrong declaration rather than merely an unusual phrasing.

A stronger design exists — derive the kind from what the operation will actually touch (paths,
commands, endpoints) rather than from anything the planner says about it. That is a different change
and I am not smuggling it in here.
