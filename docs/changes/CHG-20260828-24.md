- Type: a guard that was a no-op wearing the name of the thing it did not do
- Proposed by: measuring `store.py`'s coverage — the module was next in the survey, and this fell

## What this started as

`store.py` was the next module with no mutation record. The same probe as CHG-20260828-23: ten
guarantees, one mutation at a time.

**Nine of ten pinned.** The tenth — *"the extended-length prefix does not reach the operator"* —
came back unpinned, and writing the test for it found the guarantee is not delivered at all.

## The defect

`store.connect` refuses a file it cannot open, and quotes the driver's reason through `paths.plain`:

```python
raise StoreError(
    f"{file} could not be opened as a store: {paths.plain(str(exc))}. …")
```

with a comment saying exactly why:

> `paths.plain` on the message: the path we handed the OS carries the extended-length prefix, and
> an error reading `\\?\C:\…` sends whoever is debugging it looking for a network share that does
> not exist.

`paths.plain` strips the prefix **from the start of a string** — right for a path, which is what it
was written for. An OS error is not a path; it is a sentence with a path inside it:

```
unable to open database file \\?\C:\Users\…\config.sqlite
```

The prefix is mid-sentence, so `plain` returns the message unchanged. **The call did nothing, and
had a comment explaining what it did.**

`conversations.py:1108` does the same thing, for the same reason, with the same result. Fixing one
and leaving the other would be fixing the example rather than the class.

## The change

`paths.plain_in(text)` — the same stripping, wherever the prefix appears. `plain` is untouched and
now says in its docstring what it is *not* for.

UNC is replaced first, because `\\?\UNC\server\share` starts with `\\?\` too and stripping the
shorter prefix first leaves `UNC\server\share`, which is not a path anybody can use. That ordering
is a guarantee, so it has its own test and its own mutation.

## The test that would have passed either way

The first version opened a junk file and asserted the prefix was absent from the refusal. It passed
— and it would have passed with the guard deleted, because SQLite's message for that case is
`file is not a database`, which contains no path at all.

**A test asserting the absence of something that is never present.** Written into the change whose
subject is a guard that does nothing, while the previous change was about tests that assert around
a guard rather than driving it. The test now makes the driver produce the message the guard exists
for.

## Risk & rollback

- `plain_in` is additive; `plain` is unchanged, so nothing that formats a path moves.
- The two messages get longer by nothing and shorter by a prefix. No caller parses them.
- Rollback: point both sites back at `plain`. The messages go back to carrying `\\?\`.

## Status

**Accepted** — see [ACC-20260828-24](../acceptance/ACC-20260828-24.md).

### Not claimed

**That these are the only two.** They are the only two call sites that run an OS error through
`plain` today. Any message that interpolates `{exc}` raw — and `cli.py` has several — was never
promising to strip anything, so it is not this defect; whether it should be is a different question.

**That the operator ever saw it.** For it to bite, SQLite has to quote the path back, which happens
on some failures and not the one the existing test uses. The guarantee was stated, was believed, and
was not delivered; how often it mattered is not measured here.
