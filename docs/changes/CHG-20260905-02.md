## Read this first

These are separate from `CHG-20260905-01` on purpose. That change alters what the engine does on a
failing path and could conceivably need reverting. These are sentences that are false or
unreachable, and reverting the behaviour change should not take true sentences down with it.

The four have one shape between them: **a statement placed where nothing keeps it honest.**

## 1. `D6.2` has exactly one way in, and its siblings have none

`src/` cites `D6.2` in four places - `effects.py` twice, `probes.py`, `ship.py` - and
`docs/knowledge/knowledge.md` KN-6 cites it without defining it. Its home is
`docs/changes/CHG-20260822-04.md`, section `### D6`, **item 2 of an unlabelled ordered list**. The id
is never written as a heading or a label there. One line binds it, in the same file's Global
constraints:

```
- **No effect without a probeable postcondition** (D6.2). If an operation cannot be probed, it…
```

Delete that line and every `D6.2` in `src/` becomes unresolvable. `D6.1`, `D6.3`, `D6.4` and `D6.5`
have **no back-reference at all** - measured, `grep -c "D6\.[345]"` on that file returns 0 - and are
resolvable only by counting list items, which is exactly what `effects.py`'s docstring asks a reader
to do when it cites `D6.3` and `D6.4/D6.5`.

**Repair:** label the five list items explicitly, so the id a reader arrives with matches something
they can see. The Global-constraints line stays; it is now one of two ways in rather than the only
one.

## 2. "Unanswerable raises rather than returning False" is written where nothing enforces it

The sentence is true and it matters - *"I could not reach the remote" and "the branch is not there"
are different facts, and merging them makes a resume push twice*. It is written twice, and both
times as a property of the **`Effect` dataclass's `probe` field**:

| where | text |
|---|---|
| `docs/structure/data.md`, "The effect" table | `` `probe` `` \| callable \| Reads the postcondition from the world. **Unanswerable raises rather than returning False** |
| `docs/structure/design.md`, the `Probe` bullet | `` () -> bool ``, reading the world. Unanswerable **raises** rather than returning `False` |

`effects.py` enforces none of it. It holds in `probes.py`, by convention, because every probe
written there does it. A reader who takes the `data.md` row at face value writes a probe that
returns `False` when it cannot reach the remote and finds nothing objecting.

**Repair:** the sentence keeps saying what it says, and moves to where it is true - a statement about
the probes in `probes.py`, marked as a convention those probes hold to rather than a property the
type checks. Both places say which it is.

## 3. The absolute in `data.md` is not absolute

> "An operation is admitted as an effect **only if it leaves a probeable postcondition** - there is
> deliberately no way to construct one without a probe."

Measured against the class: the ordinary routes are all closed - the constructor,
`dataclasses.replace` (`__post_init__` re-runs), assignment (the class is frozen). Deliberate
bypasses are not: `object.__setattr__`, a subclass overriding `__post_init__`, and unpickling an
`object.__new__` instance all produce a probeless `Effect`. None is reachable from either importer -
`engine.py` and `ship.py` construct normally, and nothing in `src/` uses any of them - so this is an
overclaim, not a live hole.

The live part is different and is what the sentence hides: what `__post_init__` checks is that a
probe **exists and is callable**, not that it is probeable. `Effect(probe=lambda: True)` - a probe
that reads nothing at all, which is what the module docstring calls *reintroducing exactly the
receipts this design refuses* - passes the front door with no bypass.

**Repair:** say what is enforced and say that D6.2 itself is settled in review. `effects.py`'s own
version of this sentence was already corrected by `CHG-20260905-01`; this is the copy in `data.md`.

## 5. `data.md` describes three of the four fields `effects` carries

> `` `effects` `` | dict[str, object] | Per node: applied, already met, and anything found true out
> of causal order

`as_dict()` always writes **four** keys, and the missing one is `frontier` - the field that says
where a resume started. The row is also silent about something a reader will get wrong: an
out-of-order effect appears in **both** lists. Measured:

```
already_met: ['chg', 'push']    out_of_order: ['push']
```

So `len(already_met) + len(applied)` is not the number of effects in the sequence, and anyone
counting that way over-counts by exactly the out-of-order ones.

**Repair:** name the fourth field and state the overlap.
