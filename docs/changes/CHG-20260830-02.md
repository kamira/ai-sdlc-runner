## What `models.py` decides

`reach` is what says whether a dispatch stays on this machine, stays on this network, or leaves it.
It is **computed, never declared**, and the docstring gives the reason: *"a model labelled
`internal` pointing at a public host is a configuration that reads as safe and is not."*
`validate` then decides whether a key can end up in a file.

Twelve guarantees, measured with the harness against `tests/test_models.py`:

| | |
|---|---|
| reach is computed rather than declared | pinned |
| an unresolvable name is external, not internal | pinned |
| a private address is internal | pinned |
| loopback is local | pinned |
| a secret in the query string is refused | pinned |
| the scan reads the **key**, not the value | pinned |
| `key_env` holds a variable name, not a key | pinned |
| a public endpoint with no key named is refused | pinned |
| an unspoken scheme is refused | pinned |
| an api model carrying a command is refused | pinned |
| two models sharing an id is refused | pinned |
| **an api model with no host gets a reach guessed for it** | **not pinned** |

Eleven of twelve. The best ratio of the four modules measured, and the one hole is on the same
axis as everything else in the file.

## The hole

`reach_of` refuses when it cannot find a host:

```python
raise ModelError("an api model needs an endpoint before its reach can be known")
```

Replacing that with `return EXTERNAL` left every test green.

**`external` is the safe-looking wrong answer.** It is the grade that makes `validate` demand a key
— and then wave the entry through. So an endpoint of `https://`, with a `key_env` set, would have
been registered as a real public model that resolves to nothing. Confirmed by construction: with the
guard in place `validate` refuses; with it removed the model is accepted with `reach == external`.

It is reachable from ordinary input, not just from a crafted one — `https://`, `not a url`,
`file:///x` and `://nohost` all arrive with no hostname, and the second is what an operator types.

The refusal is now pinned three ways: the four inputs, an end-to-end pass through `validate`
(because `reach` is a property, and a guard that fires inside `reach_of` while `validate` swallows
it is a refusal nobody meets), and the opposite direction — a `cli` model still needs no endpoint,
so the rule cannot spread to every local model in the project's own examples.

### Not claimed

**That reach is right, only that it is computed and refuses what it cannot answer.** Whether
`.local`, `.internal`, `.lan` and `.home.arpa` are the right suffixes, and whether a single-label
name is always internal, are judgements this pins rather than checks. A network where `gpu-box`
resolves publicly would be graded wrongly and nothing here would say so.

**That the registry's other halves were surveyed.** `load`, `save` and `_model_from` have their own
refusals — a bad envelope, an unknown key, invalid JSON — and only the id-collision one is in this
group.
