## The finding

CHG-20260823-44 cites `test_an_action_arriving_as_the_walk_decides_to_stop_is_not_stranded` and
`test_the_gate_never_rests_with_something_still_flagged` as catching the lost-wakeup window.
Reintroducing the window shows both **pass**; only the structural
`test_the_release_and_the_decision_are_one_critical_section` fails.

The fix is not to add a behavioural test. A race window that narrow is not reliably reachable from
one, and pretending otherwise is how the wrong test gets trusted. The honest position - recorded in
ACC-20260823-44 - is that **for this defect the structural test is the load-bearing one**.

What is missing is that the tests do not say so. A reader meeting them assumes the behavioural pair
covers the window.

## What changes

Each of the three tests states what it does and does not cover, so the next person to touch the
coalescing gate knows which one is holding the property.
