## Read this first

`_walk_once` counts an intake stop:

```python
stop = report.suspended or {}
if stop.get("incomplete"):
    self.state.intake_history.append({"missing": list(stop.get("missing") or ())})
```

It counted **any** walk that ended incomplete, whatever caused it. `attach()` walks — *"Same reason
as instruct: an attachment reaches every work order"* — so:

```
what the operator did          asks recorded   the console said
  typed one instruction              1          asked once
  attached an unrelated file         2          asked twice      <- nobody asked
  attached another                   3          -> intake.ASK_LIMIT
```

At the limit `intake.needs_options` fires and the run **leaves the ask-again path** for the
produce-options path. That is a behaviour change, not a label: the runner gives up on a person who
was asked once and answered by nobody, because they attached two files.

## Scope: my first framing said six methods, and three of them cannot reach it

I wrote the fix against *"six methods reach `_advance`"*. Measured:

```
start · instruct · attach     no `_require_suspension`   ->  can walk from an incomplete stop
approve · reject · rule       `_require_suspension`      ->  refused there by CHG-20260903-23
```

`_require_suspension` raises *"this run is waiting for a requirement that is not complete … Answer
it with POST /run/instruct."* So the wrong path is **`attach`**, alone. The seat's reproduction used
attachments and was exact; the generalisation was mine and it was wrong. A third guard pins the
three that are already refused, so the comment cannot drift back to claiming a reach it does not
have.

## What counts as an ask

The requirement itself growing — a new instruction — because that is what `intake_review` reads and
what *"asked for and not supplied"* is about. An attachment reaches work orders as an artifact; it
is not somebody supplying the aspect.
