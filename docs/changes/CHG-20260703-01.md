## Motivation
The local skill store shipped v1.0.0 / v1.1.0 while the current published skill is v1.12.1
(github.com/kamira/ai-skills). Running against current triggers a migrate-required mismatch. Make
**v1.12.1 the runner's current baseline** so the store, the expected contract version, and the docs
all agree with the current skill — eliminating the mismatch for new projects.

## Decisions & trade-offs
| Decision | Options | Assumptions | Why this choice |
|----------|---------|-------------|-----------------|
| How to vendor v1.12.1 | git tag archive vs main-HEAD archive | v1.12.1 has **no git tag** (version lives in SKILL.md frontmatter) | Offline `git archive` of the clone's main HEAD `605425e` (labelled "ai-sdlc v1.12.1") into `skills/v1.12.1/` — same offline-extraction method as CHG-05, no fork |
| Keep old store versions | replace vs keep | existing per-project locks may point at 1.0/1.1 | **Keep** v1.0.0 / v1.1.0 — backward compatible; store is multi-version by design |
| Config expected version | leave 1.0.0 vs bump | first-run lock uses config_expected | Bump `contract_version` → `1.12.1` so **new** projects lock at current; existing locks unaffected |
