# CHG-20260906-07 - a seat says this should not be done, and the run walks past it

- Project: ai-sdlc-runner
- Branch: claude/chg-20260906-07

- Type: behaviour. A fourth suspension shape, on a governance decision the operator made today.
- Risk: medium - the walk stops where it did not stop before, on a condition no run could
  previously reach a person with. Nothing existing changes shape: the fourth boolean is false on

- Autonomy: high
- Target ACC: ACC-20260906-07

## The finding, and that it was unanimous

Round thirteen put `intake.py` in front of four seats — conformance and idiom on `codex`, defect
and risk on `fable`, each an independent session that saw none of the others. All four found the
same thing, and I drove it end to end myself:

```
survey.safety   {'conformance': [...], 'defect': [...], 'risk': [...]}
survey.complete True
halted_at       done       reached merge?  True
```

Three seats each answered `{"unsafe": ["this deletes production data"], "missing": []}`. The run
walked all seventeen nodes to `merge`.

`Survey.complete` reads only `missing`, and `engine.py` entered the intake suspension only when
that was false. So the one answer a seat has for *"this should not be done"* was the one answer
that stopped nothing.

Where the words went:

```
                 terminal   snapshot   console
safety              0          0        [object Object] on a finished run
```

`cli.py` contained the string `safety` exactly once — a comment about `attachments.py`. The
console renders the findings properly, in red, but only inside the block that draws an
**incomplete** stop. So the findings were legible only when a *different* field was non-empty.

## Why this needed a person to decide, and what they decided

Three of the four seats declined to propose the fix, for the same reason: the repository had never
said what an unsafe answer should *do*. `CHG-20260823-13` task 4 decided only that unsafe is kept
apart from ordinary problems. The conformance seat put it plainly — *"the correct repair begins in
governance"* — and held its veto open rather than guess.

The operator decided, in their own words:

> When a seat reports something unsafe, the run must **present it to a person** — a short, plain
> list, each item saying which seat said it and the reason — **and the person decides** whether to
> continue.

And, on the second question the design raised:

> A run carrying `--proceed-unsafe` for the first time is an **error**.

## Two designs, and why this is one of them and not the average of two

Both engines were asked for the smallest shape, in independent sessions. They disagreed on the
central mechanism.

`codex` proposed a dynamic `intake_safety` gate in `policy.GATES`, at `halt_independent`, answered
by a targeted `Approval`. It stated that this reverts nothing.

`fable` measured that it cannot be built:

| wall | what it says |
|---|---|
| `test_nothing_is_defined_that_the_flow_never_uses` | `set(graph.gates_used()) == set(policy.GATES)` — a policy gate must be on a node |
| `test_the_survey_node_has_no_gate` | `graph.BY_ID["intake_review"].gate is None`, and CHG-20260823-13 task 1's done-when |
| `test_documented_numbers` | any document saying "N gates" must match `policy.GATES` |
| `engine.py:2085` | an `Approval` whose gate is not in `policy.GATES` is refused |

I read all four myself. They hold. `codex` answered that its gate is *dynamic* rather than
unconditional — but the first wall is about membership of `policy.GATES`, which conditionality does
not affect. The second wall's docstring is the sharper objection, and it is an argument against the
shape rather than a rule about it:

> *A gate that fires on a **complete** requirement would be asking a person to approve the absence
> of a problem.*

The difference in evidence is worth recording. `fable` ran the full suite and reproduced the defect
on three surfaces; `codex`'s sandbox refused to execute Python and it said so plainly and reviewed
by reading. On a question about which guards fire, the engine that could run them was right.

**This change is `fable`'s shape.** The flag's acceptance rule is the operator's. The journal
marker is `codex`'s, and it is the one piece of its design that survives — `fable`'s shape has no
way to tell a first run from a second, and needs one.

## What changes

A fourth **question**, not a fourth kind of incomplete.

- `SUSPENSION_FIELDS` gains `unsafe`. Still **one** `_suspension` call at this node, so
  `test_every_suspension_shape_carries_the_same_keys` still counts three.
- `Survey.complete`, `collect`, `problems` and `all_problems` are untouched.
- `intake.shown_digest(safety)` names *what was put in front of a person*. Not a run id and not a
  brief hash: the risk seat measured that the journal's files carry neither, so a shared journal
  directory lets one brief's history answer for another's. Digesting the findings sidesteps it.
- `AskJournal.record_unsafe_shown` writes `unsafe-shown-<digest>.json` — **named by content, not by
  count**, because the defect seat measured `record_intake_stop`'s `len(existing)` naming losing a
  file when an earlier one is deleted. Showing the same findings twice writes the same file.
- The journal's non-ask prefixes became a tuple. `entries()` excluded one prefix by name, and a
  second kind of file would have been swept into `pending()` and `answers()` as a malformed ask —
  which is the failure its own docstring describes.
- `cli.py`: `--proceed-unsafe`, refused **before the walk** when nothing has been shown; a fourth
  branch, because without one this stop falls to the gate `else` and offers `--resume --confirm
  None` at the very node CHG-20260904-02 fixed that for; and the findings printed after whichever
  branch ran, since two shapes carry them.
- `server.py`: `POST /run/proceed`, through the same `_require_suspension` every other answer uses.
  No journal marker there — the route is reachable only while the run is suspended *showing* the
  findings, so being shown them is the route's precondition.
- `console`: a fourth branch **with a button**, where the incomplete stop deliberately has none.
  That stop is answered by saying more; this one by deciding.

## One thing fixed because this change tripped over it

`SUSPENSION_FIELDS["safety"]` was `()` — the only dict-valued field on that line whose empty was a
tuple, so `_suspension` rendered it `[]` on every shape that does not set it, while its type is
`Dict[str, List[str]]` and `docs/API.md` documented `{}`. Printing the findings on every shape hit
it immediately: `.items()` on a list.

Nothing asserted the wrong value (`grep`: 0), so it had drifted unnoticed because
`test_api_schema` checks that each key is *named* on the page, never what its value is. The same
subject-is-presence shape this whole round has been about.

## What the rest of the suite then asked for

The five mutations were green before any of this. None of it was found by them.

- **`cmd_serve` writes `unsafe_shown=()` and `proceed_unsafe=""` out.** They are true at the moment
  it starts; `_walk_once` sets both per walk. `test_both_ways_to_start_a_run_take_the_same_governance`
  offers an exemption list for a field one command genuinely cannot supply, and `cmd_serve` could
  have taken an entry — but that list is empty on purpose. Two entries left it when CHG-20260903-22
  closed the gap that justified them, and its comment says *"an exemption that outlives its reason
  is a permission nobody re-reads"*. Two empty arguments are cheaper than reopening it.
- **Two `docs/API.md` mutation anchors were re-anchored**, not retired: this change rewrote the
  sentences they name and both guarantees still hold.
- **`approval-lifetime`'s anchor was lengthened by one line.** Retiring a decision about unsafe
  findings reuses `retired_approvals`, and its dedupe-and-append is character-for-character the
  approval one. Extracting a shared helper was the wrong repair — that mutation's replacement text
  refers to `approval`, a local the helper would not have.
- **`docs/schema-atlas.html`**: 18 HTTP routes -> 19.

## Not in this change

- `String(state.survey[k])` rendering `[object Object]` on a finished run. A separate defect with
  its own record; mixing a rendering repair into a governance change makes both unreadable.
- Any `policy.GATES` entry, for the four reasons above.
- A refuse button: `intake_review` has no `rejects_to`, and inventing one would be what
  `Rejection`'s docstring calls pretending a refusal is a step.
