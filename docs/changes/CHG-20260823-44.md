## The window

CHG-43's gate cleared `_walking` in a `finally`, under a **second** acquisition of the lock:

```python
with self._lock:
    if not self._walk_again:
        return snapshot          # <- releases the lock, _walking still True
    self._walk_again = False
finally:
    with self._lock:
        self._walking = False    # <- a different critical section
```

Between the `return` releasing the lock and the `finally` re-acquiring it, another caller can:

1. take the lock,
2. see `_walking` still true,
3. set `_walk_again = True` and return `running`,

and then have the flag cleared out from under them by a walk that had already decided to stop.

Their attachment is not walked. It sits flagged until some unrelated future caller starts a walk —
which then walks **twice**, once for itself and once for the stranded flag.

A lost wakeup, in the gate written specifically so that an action arriving mid-walk is never
dropped.

## The fix

`_walking = False` moves into the same critical section as the check that found nothing waiting.
Deciding to stop and announcing you have stopped are now one indivisible step. The exception path
gets its own explicit handler, which also clears `_walk_again` — a flag with no walk behind it is
the thing being fixed.

## How it was found, and what that says about the tests

By reading the code before sending it to the panel, not by the panel and not by a test.

The two behavioural tests in CHG-43 — *"the action that arrives during a walk is never dropped"* —
**pass against the broken gate**. They can only catch this window when the interleaving happens to
occur, and it did not. That is stated in their docstrings rather than implied.

What makes the window *impossible* rather than *unlikely* is structural, so one test is structural:
it asserts `_walking = False` and the `_walk_again` check sit inside the same `with self._lock`.
That test **fails against the unfixed gate**, which is the only reason to trust it.

Two behavioural tests are added as well:

- one forces the second attachment to arrive while a walk is genuinely inside, by blocking the
  gate's *second* iteration — three walks for two mid-walk attachments, and it would be two if the
  flag were stranded;
- one hammers six threads posting twelve attachments each and asserts the resting state is
  coherent: `_walk_again` false whenever `_walking` is false.

### Not claimed

**That the behavioural tests would have caught this.** They do not. They pass against the broken
gate, and they are kept because they cover what the structural test cannot — that the coalescing
actually walks the thing that arrived. The structural test is what closes this particular window,
and a structural test is a weaker instrument that happens to be the right one here.

**That there are no other windows.** This is the one I found by reading. The gate is small enough to
read, which is most of why it was findable.
