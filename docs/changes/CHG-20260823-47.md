## What was actually wrong

### 1. The scan lost which project a file was in — the same silent omission it was written to prevent

`_walk_store` returned **bare filenames**, flattened across every project directory, into a set.
Two projects each holding an unreadable `shared.jsonl` produced **one** refusal; the other file
vanished, and the report was clean.

That is CHG-42's defect, reintroduced by CHG-45's fix for it. The test shipped alongside it used
**one project**, so the flattening it introduced was never once exercised.

### 2. A broken target was reported as broken source conversations, three times over

`except Exception` per conversation is the right instrument for source dirt and the wrong one for
everything else. A target out of disk was named as damage to conversation A, then B, then C — and
the loop kept writing to a target it had already been told was broken. At four hundred
conversations that is four hundred writes and four hundred false accusations.

`TargetError` now separates the two. **`OSError` out of a write is caught as a target failure too,
whoever raised it** — making the classification depend on every backend remembering to translate
its own errors would be a name standing in for a constraint, which is this log's most-repeated
defect class.

### 3. Importing the same store twice accused the operator of tampering

`import_conversation` coerces `at` to a string and `seq` to an int. The collision check compared
**raw** source turns against **normalised** stored ones. So a legacy turn with no `at` — or a `seq`
written as `"7"` — imported cleanly, and then **every later run refused it** with:

> Same id, different conversation — this runner will not choose between them.

That sentence is false, and the advice attached to it is to remove the target copy. A false
accusation that invites a deletion is worse than a crash.

Both sides go through `_for_comparison` now, and the round trip is tested for **both** backends.

### 4. One stray file stopped the entire store from importing

A file sitting directly under the store root raised `NotADirectoryError` out of
`FileBackend.conversations()`. The importer caught it as *"(the store) could not be listed"* and
returned: **not one conversation imported**, and the report did not say which file.

### 5. `cp A/x.jsonl B/` was reported as "skipped, already here, whole"

CHG-46 claimed a source with two files claiming one id was "still caught". It was not. The collision
read used the project id from the **header**, so `source.read(pid_from_header, cid)` re-opened the
**original** file and compared it with itself. The copy was never read, and the same id appeared in
both `imported` and `skipped`.

A file whose header names a different project than the directory it sits in is refused by name.

### 6. A third level was skipped without a word

The walk assumed exactly `<root>/<project>/<file>`. A subdirectory inside a project — a whole
subtree of conversations — was skipped in silence and the import was reported clean.

### 7. A conversation id reached the terminal with its escapes intact

Verified by running: an id of `evil\x1b]0;pwned\x07\x1b[31mRED\x1b[0m` in a legacy store retitles the
operator's terminal window when the import names it, and recolours everything printed after. A store
this runner did not write holds whatever it holds. `cli._printable` shows control characters as
escapes and leaves everything printable — CJK project names included — exactly as it is.

### 8. A second file in the same project claiming one id was called "already here"

Not found by a seat — found by reading this change's own fix before sending it.

`source.read(pid, cid)` resolves to `<pid>/<cid>.jsonl`. Fixing defect 5 made `pid` provably agree
with the header and left `cid` unchecked, so a file named anything else whose header claimed an id
caused a **different file** to be read and reported under this one's name. Two files in one project
claiming one id: the second compared against the first, found equal, reported "already here".

That is defect 5 exactly, one axis over — which is this log's whole pattern, appearing this time
inside the fix for it, four hours old. Both the directory and the filename must agree with the
header now, so `source.read` provably opens the file the inventory record describes.

## What replaced it

One `_inventory(root)` walk, producing one record per file: `{project, name, cid, why}`, with
exactly one of `cid` and `why` set. Everything is driven from that list. No set subtraction, no
flattening, no reading a file twice, and a refusal names `<project>/<file>` — the thing an operator
can actually go and look at.

## The test that accepted the failure it forbade

`test_a_directory_named_like_a_conversation_does_not_stop_the_import` asserted:

```python
assert good.id in report["imported"] or report["refused"]
```

When the directory **did** stop the import, `imported` was empty and `refused` held one entry saying
the store could not be listed — so the second operand was truthy and the test went green on the
exact abort its own name forbids. It shipped, and it was marked done. Both halves are required
separately now.

### Not claimed

**That the fourth attempt has no fourth-round defect.** Three rounds running, the fix has carried
the defect class of the thing it fixed, and each was found by a seat rather than by the suite. This
round it happened again and was caught **within this change** — defect 8 above is defect 5 one axis
over, introduced by the fix for defect 5. It was found by reading, not by the suite, and not by the
mutation table either. That table is the first thing in four rounds that tests the *tests*; it is
not proof that the shapes chosen for it are the shapes that matter.

**That the inventory covers every filesystem.** Symlink loops, junctions and reparse points are not
handled specially. A loop is bounded — the walk descends exactly two levels and reports the third —
but a symlink pointing outside the store is followed and no test says otherwise.

**That `_printable` makes output safe.** It defuses C0 and C1 control characters. Right-to-left
overrides, zero-width joiners and homoglyphs are printable and pass through unchanged; an id can
still be made to *look* like another id.

**That the index sees concurrent writers.** The target's ids are read once. Anything else writing to
that database during a long import is invisible to the check, and a conversation added mid-import
would be found by the backend's own uniqueness constraint rather than by a named refusal.
