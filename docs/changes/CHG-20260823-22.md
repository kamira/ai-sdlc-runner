## What was missing

The schema review found nine shapes absent from the catalogue. **The largest was the server's HTTP
API** — fifteen routes crossing a process boundary to a browser, with request and response shapes
nobody had written down anywhere.

The database schema existed only as a DDL fragment inside a design record that had been through three
review rounds, with its corrections scattered across four documents.

## [`docs/API.md`](../API.md)

Fifteen routes: eight `GET`, seven `POST`. Read out of `server.py` rather than from memory.

What the page carries that a route list would not:

- **The guard's order.** `Host` → `Origin` → `X-Operator-Token`, and *why* that order: a non-loopback
  `Host` on a loopback socket is DNS rebinding, and that request must not get as far as being
  understood. The test asserts the order in both the page and the code.
- **The two token exemptions**, each with its reason — the shell page cannot present a token before
  it has loaded the page that stores one, and `EventSource` has no API for setting headers.
- **`409` is the interesting status code.** Not a REST conflict: this server saying *"I understood
  you and I am not doing that"*, with the reason in a sentence.
- **Gate and tie are not interchangeable.** `/run/gate` and `/run/decide` each check
  `suspended.undecided` and refuse the other's case, because a gate asks whether the run may proceed
  and a tie asks which way.
- **One shape for the snapshot**, returned by `GET /run`, by every SSE frame, and by every POST
  except `/models` — so a caller never has to know which of the three it is holding.
- **What the API does not have**: no versioning, no pagination, no `DELETE` or `PUT`, one operator.

## [`docs/DATABASE.md`](../DATABASE.md)

Three tables, one index — and a longer section on **columns that are not there**, each with the
finding that removed it. `reach`, `leaves_this_machine`, `opened_at`, `updated_at`. A schema without
its reasons gets "simplified" back into the defect it was avoiding.

It also states, in one place for the first time:

- which pragmas are **file-level** and which **reset on every connection**, measured rather than
  asserted — the distinction three review rounds got backwards;
- what `synchronous = NORMAL` actually buys (process crash safe; power loss may roll back the last
  transactions);
- why there is **no `CHECK` constraint** on `transport` or `kind`: it would be coarser than
  `models.validate`, and two validators that disagree is worse than one that is authoritative;
- **the five queries the schema has to serve**, in full — which is why no `json_extract` appears
  anywhere and Python 3.9's bundled SQLite never has to be asked whether it has JSON1;
- **five things still open**, including the one nobody has answered: a resumed run whose store read
  fails resets `seq` to 0, and against a primary key every turn of that run is refused and swallowed.

## The tests, which is the part that matters

The schema catalogue drifted three checkable ways within a day of being written, because nothing
pinned it. These two pages get their tests **in the same change**, not after the drift.

| Test file | Pins |
|---|---|
| `test_api_schema.py` (17) | every route the server answers is documented and none is invented; the snapshot's and suspension's keys; the twelve `Node` fields `/flow` sends and the two it withholds; every status code; both token exemptions and no third; the guard's order in page **and** code; that no `DELETE`/`PUT` exists |
| `test_database_schema.py` (14) | **executes the page's SQL verbatim** and then tries to violate it |

`test_database_schema.py` is the interesting one. The schema is unbuilt, so there is nothing to
compare against — but the question that matters about a DDL nobody has run is *does it run, and do
its constraints refuse?* So it does both:

```
duplicate seq -> refused: UNIQUE constraint failed: turns.conversation_id, turns.seq
orphan turn   -> refused: FOREIGN KEY constraint failed
```

The second only passes because the page sets `PRAGMA foreign_keys = ON`. Drop that line and the test
fails — which is exactly the defect a seat found in the first draft, where `REFERENCES` was
decorative.

Four columns removed across three review rounds each get a test that fails if they come back.

### Not claimed

**That the database schema works.** It is proposed and unbuilt. What is verified is that its SQL
executes and its two constraints refuse; nothing about WAL under Python 3.9 on Windows, the
killed-process case, or two writers has been tested, and every previous seat said so.

**That the API page is complete for a browser.** The SSE frame *shape* is documented; the token
fragment flow and the console's own behaviour are not driven by any test here.
