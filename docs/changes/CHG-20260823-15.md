## What was wrong

I checked the README I had just written against `--help` output and a dump of the graph, rather than
against my memory of writing it. Three real errors, and one thing I got wrong about being wrong.

### 1 · The flow diagram omitted the failure paths

`review_failed` and `acceptance_failed` were not drawn. Both return to `next_module`; both are how a
run recovers from a panel or an acceptance saying no.

**This is precisely the defect an independent seat found in this project's own mock-up** —
*"claimed 23 nodes, drew 18, and every omission was a failure path, which is what a console is
for"* — reproduced by me in the README three changes later, in a document that quotes the finding.

The diagram now draws all 24 nodes, marks gates with `◆` and terminals with `■`, and labels every
branch with the label the graph actually uses.

### 2 · `--config` came after the subcommand

```bash
runner serve --plan plan.json --port 8765          # was
runner --config runner.yaml serve --plan …          # now
```

`--config` is **global** and must precede the subcommand. The failure is not a usage error, which
would at least be visible: without `--config` there is no `agent_command`, every ask goes to
`_Stub`, and **the run completes having asked nobody** — which looks like success. The README also
now shows what `runner.yaml` contains, which it never did.

### 3 · `feedback` branches on `more`/`done`

Not on the node names the diagram implied.

### 4 · And one claim of mine that was wrong

I said `--seats N` did not exist and that the flag was `--review-seats`. **`--seats` is a real
alias** — declared on the same line as `--review-seats`. I had read `argparse`'s `--help` output,
which prints only the first option string per action, and concluded the alias was fictional.

The README now uses `--review-seats` because it is the canonical name, but the original was not
broken and this record should not imply it was. Recorded because a correction that misdescribes what
it corrected is its own small version of the problem this repository keeps writing down.

## The two tests

Prose is not run, so nothing checked any of the above. Both new tests were written **after** the
defect they would have caught, and both were verified to fail on it:

| Test | Refuses | Verified by |
|---|---|---|
| `test_every_cli_flag_the_readme_names_actually_exists` | a flag in the README that `argparse` does not accept — walking the real parser and its subparsers, so aliases count | injecting `--seatz` → fails with the flag named |
| `test_the_readme_puts_global_flags_before_the_subcommand` | an example that would not parse, or worse, would silently run against a stub | moving `--config` after `serve` → fails with the line quoted |

They join `test_documented_numbers`, which already recomputes every figure from the graph. The set is
now: the README's **numbers** cannot drift, its **flags** cannot drift, and its **examples** cannot
be unparseable.
