## The defect log

[`docs/defect-log.md`](../defect-log.md) — every problem hit building the console and its governance,
with the output captured at the moment each was found.

Grouped **by how each was found** rather than by task, because that is the more useful fact and it
was not obvious in advance:

| Where it came from | Count |
|---|---|
| An independent seat, reading a record or the code | 13 |
| Only by running it on a real project | 9 |
| The test suite, unprompted | 4 |
| My own process failures | 6 |

Two things that grouping makes visible, and neither would show in a per-task list:

**The seats found thirteen defects in things that did not exist yet.** No test could have caught any
of them, because there was nothing to run — including the two that would have turned whole tasks into
no-ops that went green.

**The nine that only running it found had all been shipping**, invisible to a suite passing 800+ at
the time, and the pattern in every one is the same: *a one-module, one-instruction, one-server demo
had the same bug and looked fine.* Scale and repetition made them visible, not cleverness.

It says plainly that **there are no screenshots** and why: the browser pane would not composite for
most of the work, and two of twenty-nine defects were visible on a screen at all. What is quoted is
the captured output, which is the stronger evidence for the other twenty-seven.

## The README

Rewritten from ~230 lines to a document that answers the three questions somebody actually arrives
with: *what is this*, *what does it do at each step*, and *how do I run it*.

Added: the flow as an ASCII diagram with gates marked; the risk table showing where a run stops at
each grade; the six never-automated kinds; the seats and their questions; **the seven execution
modes** and what several models mean at each; the intake stage and its six aspects; the console and
what "local only" actually means (three refusals, not a bind address); the plan format with its
closed schema; and a **practice** section describing how the repository governs itself.

Every figure in it is recomputed by `test_documented_numbers`, so the README cannot drift from the
code without CI saying so — which is not a promise, it is the reason the figures are there at all.
