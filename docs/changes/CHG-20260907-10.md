## The finding (defect seat, L-7)

`graph.py` keeps two views of one graph: `NODES` and `BY_ID = {n.id: n for n in NODES}`, built once
at import. `validate` opened with

```python
if len(BY_ID) != len(NODES):
    raise GraphError("duplicate node id")
```

which is a **length** check. Equal lengths is not the same graph. `validate` then reads its
per-node rules off `NODES` while reachability, the `follows` rule and `_reaches` all go through
`BY_ID` — and `engine.walk` fetches the node it actually executes from `BY_ID` (`engine.py:2329`).

Measured: rebinding `NODES` alone so that `merge` routes back to `intake`,

```
validate()          PASSED
BY_ID['merge'].next close_out   <- what the run executes
NODES  merge.next   intake      <- what was validated
```

`validate` certified a graph that finishes, and the run would have followed one that loops for
ever. Swapping **both** views instead refuses it for a reason about the graph — three nodes stop
being reachable.

## Why this is not a test-only concern

I put it to both reviewers as "the rule protects tests only; is that worth shipping". One refused
the framing with a citation: `policy.py:184-185` says the checks run on every run *"including one
whose graph a caller has altered in memory"*. An in-memory-altered graph is a **supported
surface**, and this is the population the rule guards. The finding stands on that, not on the test
helper that happened to reveal it.

## A correction to an earlier draft

An earlier draft of this record said the two tests using `_validate_one` "pass today for a reason
other than the one their names claim". **That is wrong and is not in this record.** Measured under
the half-swap and under a full swap, the error messages are byte-identical and are the ones the
tests assert on. They pass for the right reason. The identity rule makes them fail for a *new*
reason — the helper — which is why the helper is repaired here.

## The third view, found by both reviewers independently

Neither was asked about it in those terms. `engine._MODULE_CYCLE` was
`frozenset(graph.module_cycle())`, captured at engine import, and read by `_workspace` to decide
which tree a node's work happens in. Measured, with a node inserted into the module loop in memory:

```
validate()                      ACCEPTED
graph.module_cycle() has it     True
engine._MODULE_CYCLE has it     False
_workspace(engineer_lint, 1)    ''            <- the shared tree
_workspace(engineer_selfverify) 'module-001'
```

A node the graph puts inside the module loop, and the engine puts outside it. One pass through the
loop builds one module and CHG-20260827-21 gives that pass its own tree; the snapshot handed the
new node the shared one, quietly.

This was already on record. `_whole_change_rejected`'s docstring (CHG-20260907-08) named
`_MODULE_CYCLE` as the counter-example it was avoiding, and `plan.py:202` had been asking per call
all along. **The previous change fixed the sibling and left the original standing as an
illustration.** It is asked per call now, and the docstring keeps the reason without the example.

## What ships

1. A **separate** `if` after the length check, naming the node. Separate because the two are
   different faults and "duplicate node id" sends a reader after the wrong repair — and because
   `tools/mutation_check.py:158` anchors on the length line verbatim, so folding the rule into it
   would turn a CAUGHT mutation into `ANCHOR GONE`.
2. `_workspace` asks `graph.module_cycle()` per call; `_MODULE_CYCLE` is gone.
3. `test_risk_adjudicated._validate_one` swaps both views.

### What was measured and rejected

**Rebuilding `BY_ID` inside `validate` instead of refusing.** It looks like the better repair —
remove the failure mode rather than report it — and it is not. `engine.walk`, `plan.py`,
`server.py` and `store.py` all read the module-level `BY_ID` *after* validation, so a local index
would certify the view nobody executes; and a validator that writes shared module state on every
call would silently undo a deliberate rebinding. Refuse, do not repair.

**`MappingProxyType` on `BY_ID`.** The disagreement is produced by rebinding a module attribute,
which a proxy does not prevent. `Node` is already a frozen dataclass, so in-place mutation is
impossible anyway. It would cost `TypeError: cannot pickle 'mappingproxy' object` against a
mechanism that does not exist.

## Left to its own change, deliberately

Three test modules carry an implementation of "swap the graph, validate, restore":
`test_graph_validation.py:37` and `test_execution_mode.py:41` are **byte-identical**, and
`test_risk_adjudicated.py:150` is the half-swap repaired here. Both reviewers recommend one
callable fixture in `tests/conftest.py`, and I agree — but it is a ~40-signature edit across three
files, and folding a mechanical refactor of that size into a rule change makes both harder to
review. It is recorded here so it is a decision rather than an oversight.

it the new rule would have been `NOT CAUGHT` on the day it shipped.
