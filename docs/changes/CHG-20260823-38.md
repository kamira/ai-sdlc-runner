## 1 · `paths.py` was not the choke point it claimed

CHG-32 said it three times — "a path module every writer now goes through", "every module that opens
a file", "every file write now goes through it" — and wired **three modules of eight**.

Bypassing: `attachments.py`, `models.py`, `settings.py`, `server.py`, and two `cli.py` sites (the
ship ledger writes, and `export --out`). Every one of them is an **operator-chosen path**, which is
the only kind that gets deep enough to matter.

The sharpest: `attachments.py` is the module `paths.py`'s own docstring cites as the historical
victim — *"shortened a hash from 64 characters to 32 for it"* — and it still carries that workaround
and still wrote directly.

`store.py` had a subtler version: it passed `paths.real(file)` to sqlite, and `real()` is a spelling
function that does not check. So the component refusal CHG-32 claims sqlite received was applied to
the directory and not to the database's own name.

All eight now route through it, and `test_every_module_that_writes_goes_through_this_one` walks every
module's **syntax tree** looking for `write_text`, `write_bytes`, `mkdir`, `os.makedirs`, `os.chmod`,
`os.unlink`, `io.open` outside `paths.` — so this claim cannot be made falsely again, and a comment
mentioning those names cannot satisfy it.

## 2 · `NAME_MAX` was measured in the wrong unit, and refused legal names

```
chars: 100 | utf-8 bytes: 300 | utf-16 units: 100
the filesystem ACCEPTED it -> True
paths.check REFUSED it: …is 300 bytes as a single path component, and no filesystem here takes more…
```

Windows counts **UTF-16 code units**; ext4 and APFS count UTF-8 bytes. Counting bytes everywhere
refused a 100-character CJK name that the filesystem takes, with a message asserting no filesystem
would.

**A false refusal is worse than the failure it replaced.** The original defect was a confusing error
about a real limit; this was a confident error about a limit that does not exist. And it fell only on
non-Latin names — a Latin name reaches 255 bytes and 255 characters together, so nothing in the
original test set could have caught it. This repository is operated in Chinese.

The seats **split** on this one. fable-seat called the refusal "genuinely cross-platform";
codex-seat called it wrong. Settled by measurement rather than by averaging: the filesystem accepted
the name, so codex-seat was right and fable-seat had not tested that case.

`measure()` now returns the count **and its unit**, and the refusal names the unit it used.

### The test that let it through

```python
def test_the_limit_is_counted_in_bytes_not_characters(...):
    """`NAME_MAX` is 255 **bytes**…"""
```

It asserted that the limit was counted in bytes — which is exactly what the code did. It passed
while the code was wrong, because it read my own vocabulary back to me. Third instance of that class
this session and the first to ship.

Replaced by `test_the_check_agrees_with_what_the_filesystem_actually_does`: nine names, Latin, CJK
and astral, each created on the real filesystem, asserting `check` agrees **in both directions**.
Over-refusing is the failure mode a limit like this really has.

## 3 · The injection CHG-33 said it had closed, in the file it shipped alongside

CHG-33: *"Fixed at the JSON level (`<`, `>`, `U+2028`, `U+2029`) rather than by matching sequences."*

True of `conversations.py`. False of `tools/render_cast.py`, shipped in the same change, which went
on embedding raw `json.dumps(steps)` into a `<script>` with `command`, `title` and `note`
unescaped. Reproduced:

```
closing </script> after the payload: 4 (1 is correct)
raw breakout present: True
```

No attacker needed: `session_record.py` records argv into the header, so recording a command that
merely *mentions* `</script>` poisons the page.

Both seats found this independently. The escapers are now compared against each other by a test —
one rule in two files is how one of the copies stopped being applied.

## 4 · Two smaller findings

- `paths.real()` returned an already-prefixed **relative** path unchanged. The prefix turns off the
  resolution that would have made it absolute, so that handed the OS a path it cannot use and called
  it done. Now stripped, resolved, re-prefixed.
- `session_record.py`'s docstring says output is passed through "unchanged", which is not literally
  true for malformed UTF-8 at EOF. Noted, not changed — the behaviour is right and the sentence is
  the thing that is slightly wrong.

### Not claimed

**That the batch is now sound.** Both seats reviewed `91a4148`. This is my answer to what they found,
and answers have been wrong here before — three consecutive rounds earlier in this project found that
the fix contained the same defect class as the thing it fixed.

**That `attachments.py`'s 32-character hash workaround is removed.** It is not. It now writes through
`paths.py`, so the workaround is no longer load-bearing, but shortening the hash back would rename
every stored attachment and that is a migration, not a rider on this change.

**That the syntax-tree audit catches every possible write.** It catches the call shapes this project
uses. A write through `shutil`, `os.replace`, or a name bound at runtime would pass it.
