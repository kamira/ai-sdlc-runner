## Read this first

The intake panel renders two numbers. The `<p>` is `reason`, which `intake.stop_reason` writes
**per aspect**. The row below it read `intake_asks`, which was `len(intake_history)` — **every**
intake stop, whatever was missing.

Measured through the real `Runner`, an intake seat reporting `flow, architecture, architecture,
architecture`:

```
walk  missing        the <p> said     the counter said
  1   flow           asked once       1
  2   architecture   asked once       2      <- disagree
  3   architecture   asked twice      3      <- disagree
  4   architecture   asked twice      3      <- disagree
```

From the second aspect onward the operator reads *"the architecture … (asked once)"* and directly
beneath it *"architecture — asked 2 times."*

## And the count here is **not** the shared name

`CHG-20260903-42` created `intake.asks_including_this_one` precisely because two readers disagreed.
Routing this through it would be wrong:

```
the engine checks BEFORE the stop is written   ->  asks_including_this_one   (tally + 1)
the snapshot is read AFTER it is appended      ->  times_asked               (the tally)
```

**The same question has two correct answers at two moments.** That is why a single shared function
gives the wrong one here, and it is stated in the snapshot's own comment so the next tidy-up does
not "unify" it back into a defect. A test pins it.
