- Related: CHG-20260901-07 (①, the node immediately after this one), -08 (②), -09 (④)

## Status

**Under review** — design only. Nothing is built.

## Three claims, and two of them already hold

| the requirement says | state |
|---|---|
| 需求交由審議席 — the requirement goes to the review seats | **holds** — `intake_review`, `mode=SURVEY`, `role="seat"` |
| 確認是否有漏 / 功能性哪裡有缺 — they say what is missing | **holds** — union of `problems` and `missing`, six closed aspects |
| 整理出清單供使用者確認 — a list, for the user to **confirm** | **absent** |

What comes out of the survey today is `intake.stop_reason`, whose own docstring calls it *"one plain
sentence for a person, naming what is missing and how often it has been asked"*. A sentence is not a
list, and the run stops for the user to **supply** what is missing — never to **agree** that the
list is right.

The difference is not cosmetic. Supplying answers a question the seats asked. Confirming answers a
question nobody has asked yet: *is this the whole of what is wrong?* A user who reads the list and
says "you have also missed X" is giving the run something no seat produced, and today there is
nowhere for that to land.

## The obstacle this change has to argue past

`intake_review` carries a deliberate **NO GATE**, in its own note:

> what stops a run here is the requirement being incomplete, not a risk grade — a gate that fires on
> a complete requirement would be asking a person to approve the absence of a problem, and one that
> never fires is decoration

That argument is sound about the question it was answering. It is not an argument against this one,
and the difference is what the design turns on:

- The rejected gate would have asked *"do you approve that nothing is wrong?"* — a question with one
  possible answer, which is why it would be decoration.
- This gate asks *"is this list of what is wrong complete, and do you accept it?"* — a question a
  person can answer **no** to, and the `no` is worth more than the `yes`.

A gate is decoration when it cannot fire. This one fires whenever the user adds something the seats
missed, and this repository has spent eighteen rounds establishing that the seats miss things.

## The design

One new node, because the survey already does the surveying. What it lacks is the confirmation.

```
intake_review  →  intake_confirm  →  mechanism  →  mechanism_confirm  →  pm_plan
                     │                  (CHG-20260901-07)
                     └─ no ─→ intake_review   (re-survey with what the user added)
```

| | `intake_confirm` |
|---|---|
| kind | `DECISION` |
| role | `pm` |
| mode | `MODEL_PANEL` |
| gate | `findings_confirmed`, `gate_when="after"` |
| `answer_decides` | `True` |
| `rejects_to` | `intake_review` |
| branches | `{"yes": "mechanism", "no": "intake_review"}` |

`gate_when="after"` for `pm_confirm`'s stated reason: the thing a person is being asked to confirm
**is** the list, and stopping in front of it hands them an empty page.

    "findings_confirmed": {"low": AUTO, "medium": CONFIRM, "high": HALT}

Resolves at `high` in practice for the same reason CHG-20260901-07 records: `RunConfig.risk`
defaults to `"high"` and nothing has been graded this early.

### The list is a shape, not a paragraph

`Survey` already holds the two things the list is made of — `problems` (union) and `missing` (union
of aspect ids). The list is those, rendered so a person can answer them one at a time:

| column | source | why |
|---|---|---|
| what is missing | `missing`, expanded through `BY_ASPECT` | the six aspects are already closed and described |
| what is wrong | `problems`, with the seat that raised it | a problem one seat saw is still a problem — it must not be anonymised into a total |
| asked before | `intake_history` | "asked three times" is already counted, and the count is what earns the options |

Rendering it is an **effect** of `intake_review`, not a node: the survey and the writing-down of the
survey are one kind of work, the way `record_module` ticks, commits and updates the worklog in one
node.

## Open questions for the panel

1. **Does `no` re-survey, or go straight back to the user?** Routing to `intake_review` re-asks the
   seats with the user's addition in hand, which is the point — but it is also an unbounded loop.
   Nothing here bounds it the way `re_review` bounds a fix pass, and a user who keeps adding items
   would cycle to `max_steps`.
2. **Does the user's addition become a seventh aspect, or a problem?** The six aspects are a closed
   list, and `intake` already raises rather than shrugs at an aspect it does not know. A user saying
   "you missed the migration path" is naming something outside the six — so either the list is no
   longer closed, or user additions live in `problems` and are shaped differently from seat findings.
3. **Is `role="pm"` right, or should this node have no role at all?** `reconcile` has none: two
   declarations that disagree is a *fact*, not a matter for a vote. Whether a list is complete is
   arguably also a fact — the user knows, and no panel improves on it. If so this is a `RUNNER` node
   with a gate, which nothing in this flow currently is.
4. **The interaction with CHG-20260901-07 is a stop, then another stop.** Two halts in a row before
   anything is planned, on a default-grade run. That may be exactly right for a new project and
   actively hostile for a one-line fix — and neither this record nor -07 proposes a way to tell
   those apart, because the grade that would tell them apart is set five nodes later.
5. **Whether "asked before" belongs in the list at all.** It is true and it is pressure. A list that
   reminds the user they have been asked three times is reporting a fact about the run, not about
   the requirement.

## Risk & rollback

- **This puts a gate on the node this flow documented as gateless.** The argument above is that it
  is a different gate answering a different question; if the panel does not accept that, the design
  is wrong and not merely unfinished.
- **Two stops before planning**, with CHG-20260901-07. See open question 4 — that is the one an
  operator will feel on every small change.
- Rollback: revert. The survey goes back to stopping with a sentence.
