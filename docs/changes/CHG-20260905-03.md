## Read this first

`policy.derive` reads *targets* - the commands, paths and URLs an operation will act on - and returns
every permanent-halt kind they are. Unlike `permanent_halt` it does not read prose, and that is why
it is allowed to overrule a declaration: `rm -rf` in a command is not a phrasing choice, and neither
is a path under `secrets/`.

Its boundary characters are written for POSIX. `/` is a separator; `\` is not:

```
r"(^|[\s/@:.])prod(uction)?([\s/.:]|$)"
r"(^|/)(secrets?|creds?)/"
r"(^|/)migrations?/"
```

This repository is Windows-first. `MAX_PATH` has its own module (`paths.py`), a whole docstring in
`attachments.py`, and its own test parametrisations. Every path this runner handles on the operator's
own machine is spelled with `\`.

## Measured

Nine path shapes, each in both spellings. Written through a file rather than a shell, because two
earlier attempts at this measurement had `\t` and `\a` silently turned into a tab and a bell by an
intervening layer - which is its own lesson about measuring escapes.

```
target (posix spelling)        posix          windows
prod/manifest.yaml             ('deploy',)    ()             <- diverges
deploy/production/app.exe      ('deploy',)    ()             <- diverges
db/migrations/007.sql          ('migration',) ()             <- diverges
secrets/token.txt              ('access',)    ()             <- diverges
creds/aws.json                 ('access',)    ()             <- diverges
.ssh/id_rsa                    ('access',)    ()             <- diverges
config/.env.production         ('deploy', 'access') ('deploy',)    <- diverges
var/secrets/api.key            ('access',)    ('access',)
app/db/migrations/init.sql     ('migration',) ()             <- diverges

diverged on 8 of 9
```

`var/secrets/api.key` survives by accident: a second rule that does not use a `/` boundary catches it.
`config/.env.production` loses one of its two kinds, which the function's own docstring calls out as
the thing it must not do - *"picking one and reporting it alone names the operation wrongly while
still stopping it, which is the kind of half-truth that erodes trust in a stop."*

On the function an operation actually goes through:

```
classify()   prod/manifest.yaml         -> 'production deploy or release'
             prod\manifest.yaml         -> None
             secrets/token.txt          -> 'changing secrets, credentials, access control or permissions'
             secrets\token.txt          -> None
             db/migrations/007.sql      -> 'data migration or irreversible schema change'
             db\migrations\007.sql      -> None
```

The prose backstop does not catch it either - `policy.permanent_halt` returns `None` for both
Windows spellings. Its word lists are multi-word English phrases and a path has no spaces. So on
Windows there is no second line.

## What this made vacuous

The conformance seat found the consequence from the other end, in the module the round was actually
about. `attachments.py`'s three headline safety tests are green **against the design they exist to
defend**, on Windows:

```
mutant: engine._TARGET_FIELDS = ("expected_outputs", "workdir")
        - the input_artifacts exemption the module docstring calls "worse than the bug"

pytest tests/test_attachments.py            -> 31 passed
pytest <the three safety tests>             ->  7 passed
pytest tests/test_false_stops.py            -> FAILED (the property is guarded, elsewhere)
```

and the five parameters of `test_a_filename_that_would_have_tripped_the_scanner_does_not`:

```
production.md      posix->('deploy',)  windows->()
prod.md            posix->('deploy',)  windows->()
deploy-to-prod.md  posix->()           windows->()      <- trips nothing on either platform
prod spec.pdf      posix->('deploy',)  windows->()
PRODUCTION.PDF     posix->('deploy',)  windows->()
```

CI runs `ubuntu-latest` and `windows-latest`, so the property is defended in CI. A developer running
the suite on their own Windows machine is not told any of this.

## What changes

`policy.derive` matches against the raw haystack **and** against a separator-normalised copy, and
returns the **union** of the kinds either finds.

The union, rather than normalising in place, is the whole point. This module's own rule is that each
layer *may only ever add a stop* (`classify`'s docstring says so in those words). Replacing the
haystack would put every existing detection at the mercy of the normalisation: any rule that depends
on a literal `\` - now or later - would silently stop matching, and a permanent-halt recogniser that
can lose a detection through a refactor is worse than one that reads a single separator. Taking the
union makes that class of regression unreachable by construction: a normalisation bug can add a false
stop, which is loud, and cannot subtract a true one, which is silent.

`permanent_halt` is deliberately **not** changed. It reads prose, its lists are multi-word phrases,
and it was measured returning `None` for these targets in both spellings - it is not a path reader
and making it one is a different change with a different argument.

## The cost, stated

Adding stops is not free. After this change, a Windows path with a `prod` segment halts where it did
not before. That is the correct answer - it is the same answer the POSIX spelling already gets - but
it will surface somewhere it has been silently passing.

One place it surfaces is known and is being fixed in the same round rather than discovered later:
`attachments.py`'s store directory is operator-chosen and travels on `input_artifacts`, so
`--attachments` under a directory named for a red line halts every node of every run. That was
already true on Linux. `CHG-20260905-04` adds the startup refusal that turns it into a message at
launch instead of an unrelaxable halt on the first node.

## Re-measured before proposing

The risk seat checked, and I re-checked, whether this reverts `CHG-20260903-30`. It does not. That
record refused adding `\` to the **sandbox literal blocklist**, because `os.path.abspath`
legitimately produces backslashes and blocking the character would refuse a legal path. Refusal and
detection are opposite trades: refusing on a character costs a legal path, detecting on it costs
nothing but a stop that should already have happened.

## Tests

- `test_a_target_is_read_the_same_way_in_both_spellings` - the property, over every path shape, both
  separators, driven through `derive`.
- `test_the_windows_spelling_of_a_production_path_is_classified` - through `classify`, which is what
  an operation actually goes through.
- `test_reading_both_spellings_can_only_add_kinds` - the union's own guarantee: whatever the raw
  haystack finds is still found. This is what makes the union structural rather than incidental.
  `test_normalising_can_only_add_kinds` was **removed in CHG-20260905-03** before it was ever
  registered - this is that record, and the name above replaces it.
- `test_the_prose_check_is_not_a_path_reader` - the scope line: `permanent_halt` is unchanged and is
  asserted unchanged. Written first as
  `test_a_backslash_in_a_command_is_not_read_as_a_path_separator_by_the_prose_check`, which was
  **removed in CHG-20260905-03** before it was ever registered - this is that record.
- `test_every_shape_here_is_a_red_line_in_at_least_one_spelling` - the floor. Without it the
  agreement test passes the moment `derive` stops recognising anything, because `() == ()` for nine
  shapes reads exactly like agreement.

A first draft of the union test carried `assert set(policy.derive([probe])) >= set()`, which is true
of every possible value. It was removed before registration rather than left in: a vacuously true
assertion inside a test named for a guarantee is the shape this repository has spent two rounds
finding.
