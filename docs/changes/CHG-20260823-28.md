# CHG-20260823-28 — The plan file, closed

- Project: ai-sdlc-runner
- Branch: claude/chg-20260823-28-close-plan
- Date: 2026-08-25 (UTC+0)
- Type: feature — the last open schema, closed, plus the pages that described it as open
- Proposed by: the user — *「把 plan 檔關起來」*
- Risk: **medium** — a behaviour change. A plan with an unknown key now stops the run instead of
  being ignored. That is the point, and it can break a plan somebody is using.
- Autonomy: high
- Related: every review round from CHG-20260823-21 onward named this

## The finding six reviews made

The plan is the **outermost** schema — every other shape rides inside it — and it was the only entry
point with no validation at all. Read key by key with `plan.get(...)`, unknown keys silently
accepted and doing nothing.

The case that decided it, from a seat:

> a plan whose `ship` key is misspelled runs **with no side effects and reports `finished`** — a dry
> run wearing a shipped run's report, produced by one typo nothing refuses.

`settings.py` and `models.py` enforce closedness for files far less consequential, and both give the
same reason the plan did not:

> a setting that looks configured and does nothing is worse than one that was rejected

## Closed at two levels

The top level **and** the `ship` block, because `ship` is where the silent dry run lived. Closing the
outside and leaving that open would have answered the complaint rather than the finding.

```
the plan sets ['operationz'], which this runner does not read. Ignoring them would let a
setting look configured and do nothing — and the case that decides it is `ship`: a misspelt
one makes a run perform no side effects and report `finished`.
```

`ship`'s four indexed keys — `repo`, `chg_id`, `branch`, `message` — are **required**, because
leaving one out was a `KeyError` partway through a run rather than a refusal before it started.

## Types, not only keys

A key of the right name holding the wrong shape is the same defect one step in:

```
the plan has 'node_specs' as list, and this runner reads it as an object.
A key of the right name holding the wrong shape reads as configured and supplies nothing.
```

And `node_models` refuses a bare string where a list belongs — the order of a node's list is
load-bearing, so a string is not a one-item list.

## What it deliberately does not check

Said rather than left to be discovered:

- **the interior of a node spec** — `workorder._check` does that, closed, at render time. Two
  validators for one shape is worse than one that is authoritative;
- **that a node id exists** — a plan may legitimately name nodes for a graph it has not been run
  against yet.

## Two lists that must not drift

A closed schema built from memory fails the other way: a key the code reads and the schema lacks
would refuse a plan that is **correct**. So a test walks `cli.py` for every `plan.get("…")` and
every `settings[…]` in `effects_provider`, and asserts both are covered.

## Driven, not asserted

```
the example still runs   -> visited 20 nodes, 17 asks, state: finished
a typo stops at the door -> error: typo.json sets ['operationz'] …
```

Two of the tests run the whole CLI in a subprocess, because the refusal has to hold at the door an
operator actually walks through, not at a function they never call.

### And a test of mine checked the wrong thing again

The CLI test asserted the output did not contain `"finished"` — and matched it inside **my own
refusal message**, which explains the defect it prevents. Checking vocabulary rather than the claim,
in the test written for a defect that is exactly that. It now checks for the report's `state:` line.

## The count test earned its keep

`test_the_closed_count_is_the_number_of_schemas_that_are_actually_closed` **exercises** each schema
with an unknown field rather than reading a label. I changed the page to say five and it failed at
four — correctly, because the plan was not yet in what it drives.

### Not claimed

**That the plan is now fully validated.** It refuses what it can name. The interior of a node spec,
the existence of a node id, and whether an operation's `targets` are reachable are all checked
elsewhere or not at all.

**That no plan in the wild breaks.** Any plan with a stray key stops now. That is the change.
