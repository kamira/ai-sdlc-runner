## The ratio, and the shape behind it

Seven guarantees; **three pinned**. The worst of the five modules measured — and the four holes are
not scattered:

| guarantee | before |
|---|---|
| the intent is recorded before the effects it describes | pinned |
| the PR step asks whether a PR is already open | pinned |
| the push step asks whether the branch is already on the remote | pinned |
| **a git command that returned non-zero raises** | **not pinned** |
| **a commit over a dirty tree is not finished** | **not pinned** |
| **an effect with no writer refuses rather than doing nothing** | **not pinned** |
| **a PR the forge rejected is not reported as opened** | **not pinned** |

Every pinned guarantee is about what the sequence **does**. Every unpinned one is about what it
does when a step **fails**.

`tests/test_kill_resume.py` drives the whole sequence end to end and asserts what landed, which is
why the success side is well covered. Nothing drove a step that goes wrong, so every refusal in the
module was a sentence.

## Why it matters here more than elsewhere

`ship` pushes branches and opens pull requests. **A sequence that reports success on a failed push
is worse than one that does not run**, because the operator believes it landed. The four holes are,
in order of what they would cost:

**A failed git command treated as having worked.** `_git` checks the return code; removing the check
left every test green. The step that would then report success is `push`.

**A commit over a dirty tree.** The probe deliberately reads two things, with a comment saying why —
*"a commit that exists while the tree is still dirty did not finish recording the change, and a
resume that treats it as done pushes half of it."* Dropping the second half left every test green.

**An effect with no writer doing nothing.** `_refuse` exists so that *"this runner will not invent
the content of a governance record."* Replacing it with a no-op left every test green, and the
effect would report success having written no record — the shape CHG-20260828-15 found at
`record_module`, a run claiming work it never did.

**A rejected PR reported as opened.** `gh` exits non-zero when it cannot create one: no remote, no
auth, a branch it cannot see. Reporting that as opened ends the sequence with the operator believing
a review is waiting for somebody.

## Tests, and their opposite direction

`tests/test_ship_refuses.py` — nine cases against a real repository, because these guarantees are
about what git actually returned. Four of them assert the **success** direction too: a check that
refused everything would pass a test that only asserts refusals, which is the failure this
repository keeps writing down.

### Not claimed

**That the sequence is right, only that its refusals fire.** Whether *record intent → branch →
commit → push → PR* is the correct order, and whether each probe reads the right postcondition, is
what `test_kill_resume` argues; this adds nothing to that.

**That `probes.py` is covered.** Every effect here delegates its probe to that module, which is the
sixth of the eleven with no mutation record and was not measured. A probe that answers wrongly
would defeat all seven of these guarantees from underneath, and nothing in this change would notice.
