## What was outstanding

The ruling had three clauses. Clause 3 (model configuration in SQLite) shipped in CHG-28; clause 1
(remove Mongo and TinyDB) in CHG-35. **Clause 2 has been open since**, and
`docs/DATABASE.md` has carried this sentence for four rounds:

> `conversations` and `turns` are **not created by any code yet** and arrive with the
> conversation-store migration: a table nothing reads or writes is a mechanism nobody invokes, and
> this repository has a test that refuses those.

They arrive here.

## The schema, exactly as designed

Schema 2 adds the two tables `docs/DATABASE.md` specified — no `opened_at`, because two seats called
it a guess and it would be a second copy of the OPENED turn's `at`; `body_json` holding **only** the
body, because the shipped code once had a body key overwrite `seq` and `at`.

Same migration discipline as schema 1, and for the same recorded reasons: the shape is verified
before anything is created, statements run individually inside one transaction, and the version is
stamped inside that transaction so a crash cannot leave a half-built store blessed as current.

## The guarantee CHG-35 weakened is back

That change had to record that a duplicate `seq` was *"reported and refused nowhere"* once Mongo and
TinyDB were removed — the JSONL backend cannot refuse one without a read per append.

```
UNIQUE constraint failed: turns.conversation_id, turns.seq
```

Refused at the moment of the write, by the database. A turn belonging to no conversation is refused
too — **but only because the connection sets `PRAGMA foreign_keys = ON`**, which is per-connection
and OFF by default. A test asserts the pragma rather than the schema, because a declaration that
enforces nothing is exactly the sort of thing this repository keeps finding.

## The import is a move, not a break

```bash
runner conversations --import-from .runner/conversations
```

- **Nothing is deleted.** A migration that removes its own source has no way back if it was wrong.
- **A conversation already present is skipped, never merged.** A turn whose `seq` matches and whose
  body differs has no answer that is not a guess.
- **Verified lossless against a real 306-turn conversation**: turn for turn, body for body, project
  for project.

And it is exercised on every build. `examples/demo/build.py` now renders the demo recording by
importing the JSONL fixture into a throwaway database and exporting from **that** — so the page is
byte-identical through the new path, and if the importer ever stops being lossless the demo's
byte-compare fails.

The fixture itself stays JSONL, deliberately: a committed fixture has to be readable in a diff, and
a `.sqlite` file is not.

## What it costs, said plainly

**A conversation is no longer readable with `cat`.** That was a real property of the JSONL store and
it is gone. `runner export --format json` is the replacement, and it is not the same thing at three
in the morning.

## Risk & rollback

- **The default store changes.** A run started after this writes to `conversations.sqlite`; an
  existing JSONL directory is not read unless `--store file` is given or it is imported.
- No automatic migration. That is deliberate: the operator runs the import, sees the count, and
  removes the old directory themselves.
- `store.py` goes to schema 2. A store at schema 1 is migrated in place; one from the future is
  refused rather than guessed at.
- Rollback: revert. The JSONL store is untouched by any of this.

## Status

**Under review.** The design was reviewed twice and corrected; `docs/design/sqlite-only.md` says of
its own corrected form that *"implementation should not start on the assumption"* a further round
finds nothing. This implementation has had no round at all.

### Not claimed

**That concurrency is now solved.** The design still declares one writer per conversation. What
changed is that a second writer's duplicate is now *refused* instead of silently appended — the
failure is visible, not prevented.

**That the old store is migrated.** It is importable. Nothing runs unless somebody runs it, and an
operator who upgrades and starts a new run will find their old conversations absent from the listing
until they do.

**That SQLite is faster here.** Nothing was measured. The reasons are refusals and one file instead
of a tree, not throughput.
