## L-54 — a filename with an arrow in it, in the tool that decides whether a round may proceed

`--porcelain` **without `-z`** renders a staged rename on **one** line as `R  <old> -> <new>`. Driven
in this worktree (`git mv LICENSE LICENCE.txt`, then restored):

```
git status --porcelain     R  LICENSE -> LICENCE.txt
frozen_tree.state()        ('86f01d3…', ['LICENSE -> LICENCE.txt'])
                                          ^ one string, not a filename,
                                            and neither of the two real paths
```

`state()`'s own docstring promises *"the paths that differ from it"*, and `main()` says it will
*"name the files when it is not"* frozen. It named a file that exists nowhere.

`-z` also removes v1's path quoting, which returned a non-ASCII name with its quotes and octal
escapes still attached.

After:

```
frozen_tree.state()   ['LICENCE.txt', 'LICENSE', …]
  LICENCE.txt   exists on disk: True     <- the new path
  LICENSE       exists on disk: False    <- the old one; a tree frozen at that commit
                                            matches neither, which is what is being reported
```

## L-48 — a seat that said *none* is recorded as having raised a problem called `False`

`intake._strings` reads an answer *"generously in shape and strictly in content"*. Its `str` and
`list` branches strip and drop blanks. Its fallback was `return [str(value)]`, which does neither:

```
_strings(False)  -> ['False']       _strings(0)  -> ['0']       _strings({})  -> ['{}']
```

`"problems": false` is a plausible JSON shape for *none*. A seat answering it was recorded as having
raised one problem, **attributed to that seat**, and printed to the operator by
`Survey.all_problems()`.

This is `CHG-20260903-27` L-30's shape — *"fabricated a verdict where there was no answer"* — one
module over. That record swept the three adjudication sites and stopped at the module boundary.

## The rule, and the two things it found that I did not

The transferable part is not either fix. It is: **a porcelain reader that turns the output into
paths must use `-z`**, because that is the only form in which a rename's two fields are separable
and paths are unquoted.

Written as a test over `src/` and `tools/`, it found **two** things a hand sweep would have missed:

1. **`worktree.py` has a second `[3:]` slice**, in `carry()`, four hundred lines from the one
   `CHG-20260903-31` fixed. **It is correct** — guarded by `entry.startswith("!! ")`, so an
   unprefixed old-path field is skipped rather than sliced. Found, checked, and left alone; a sweep
   that "fixes" a non-defect is worse than one that misses it.
2. **`probes.working_tree_clean` reads `--porcelain` without `-z`** — and does not need it. It asks
   only whether the output is empty and never parses a path. **The first version of this rule
   flagged it, and adding `-z` to satisfy a rule rather than for a reason is its own smell**, so the
   rule is scoped to readers that split or slice. That narrowing is in the test, with the reason.

## Risk & rollback

- **Task 1 changes what a verification round is told.** A rename now reports two paths where it
  reported one wrong one. Both are things a tree frozen at the commit does not match, so both belong
  — but a reader who counted entries will see one more per rename.
- **Task 4 changes what a seat's `false` means**, from *one problem named False* to *no problems*.
  That is the intent, and a seat that meant to raise a problem must now say what it is.
- **Task 7's rule is a heuristic over eight lines of context.** A reader that parses further away
  than that slips past it, and a reader that mentions `.split(` for an unrelated reason is a false
  positive. Narrow on purpose, and the docstring says so rather than calling it a proof.
- Rollback: revert. A verification round is told a filename that exists nowhere, and a seat that
  said nothing is recorded as having objected.
