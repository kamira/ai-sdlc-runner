## Veto 1: `MUTATION_IN_FLIGHT` was a one-`export` off switch

CHG-20260830-09 added the override so the guard's test would stop writing the repository's live
record. It shipped disclosed as safe: *"a leaked value points the harness at a file it will not
find, which fails loudly."* Three seats measured that sentence false in both halves — `begin()`
**creates** the record, so it is always found, and nothing fails.

```
a real stranded record at the default path, owner 4, src/ file mutated:
  no variable set             rc=1  1 failed      <- correct
  MUTATION_IN_FLIGHT leaked   rc=0  1 passed      <- the detector, off
  --recover under that value  rc=0  "nothing in flight; the tree is as it should be"
```

That printed sentence is character-for-character the round-5 veto's fingerprint. The change whose
whole subject is this detector shipped a switch for it, and told the next round the switch could
not exist.

Two fixes, because the first was partial:

- `mutation_check` **refuses to run** when the variable is set. A mutation run must write its record
  where the guard reads it.
- the guard checks **both** paths — the default and wherever the override points. Moving the record
  can hide nothing if the default is still read. The first fix alone left the guard disarmable, and
  the conformance seat measured that too.

## The two fixes that made things worse

**`>=` → `==` on the survey floors removed the finding the survey exists to produce.** Adding a
module with a real violation:

```
>=  (before)  these let an exception reach a person …: zzprobe.py:12 exc   <- the violation
==  (shipped) the survey read 22 modules; the package had 21              <- arithmetic
```

The count assertion fired first and `unstripped` was never evaluated. The floors stay; the
**finding is asserted before them**.

**`void` has the defect I rejected `wrong` for.** It is inside *avoid*, *avoided*, *unavoidable* —
and unlike `wrong`, this word now has teeth. `**Avoided**` parsed as a never-true verdict and
reopened its change. Matching is by whole word now.

## And an older hole that fix uncovered

未通過 contains 通過, so a Chinese acceptance recording a refusal read as **both** a pass and a
refusal and was rejected by the lint — in a repository operated in Chinese. Pre-existing, and found
only because the `void` fix put me in that code.

The first fix — keep the longest match — was wrong and an existing test caught it: `Pass /
withdrawn` is a *genuine* disagreement and must still be refused. Nesting (通過 ⊂ 未通過) and
juxtaposition are different things. Only contained matches are dropped.
