## Status

## What is already there, and what is not

Two halves of ②, and only one exists.

**「整理確認」 — consolidating, and it is there.** `intake.py` takes the **union** of every seat's
problems and keeps all of it, deliberately not a majority: *"a problem three seats missed and one
saw is still a problem, and outvoting it would be the panel agreeing not to know something."*

**「提出影響範圍」 — stating the impact scope, and it is not.** `grep -rin "impact" src/` returns two
incidental comments — one about a session's blast radius in `server.py`, one inside a refusal string
in `policy.py`. Nothing produces an impact scope, nothing carries one, and no stop shows one.

## Where it belongs

`lead_assess` already judges *"feasibility and risk"* before anyone is dispatched, is
`grades_risk=True`, and is the one node whose whole job is to answer *how bad is this*. What this
change proposes is that the answer to *how bad* is **not a grade alone**:

    grade   — one word, which row of the gate table every later node reads
    scope   — what this change can reach, and what breaks if it is wrong

A grade without a scope is a number nobody can check. `high` says stop; it does not say what would
be hurt, and the person the gate stops is being asked to approve exactly that.

## The design

**No new node.** Assessing feasibility, grading risk and naming what a change touches are one kind
of work — a judgement about the change, made by the lead, before anyone builds. Splitting them
would put two nodes on one act, which is the mirror of the mistake CHG-20260901-07 avoids by
splitting drawing from confirming.

So: `lead_assess`'s answer gains a required `scope`, and the gates that stop a person carry it.

1. **The assessment states it.** The work order for `lead_assess` asks for it; the answer is
   refused without it, the way `intake` refuses an unknown aspect rather than shrugging.
2. **It reaches the stop.** `before_dispatch` (at `pm_signoff`) is the last point before work
   starts and is where a person is already being stopped on a medium- or high-risk change. The
   halt's reason names the scope rather than only the grade.
3. **It is recorded.** A scope that exists only in a halt message is gone the moment the run
   resumes; it belongs in the report beside the grade.

### What a scope has to contain to be checkable

This is the part that decides whether ② is a mechanism or a paragraph. A free-text impact scope is
prose a model can always produce and nothing can ever check — the shape this repository has already
had to remove twice, most recently a test that measured a corpus rather than the rule it argued for.

The proposal is a closed shape, the way `intake.ASPECTS` is closed:

| field | what it is | how it is checked |
|---|---|---|
| `paths` | the files or directories this can reach | they exist in the tree |
| `interfaces` | the callers or contracts that could break | named, non-empty for `medium`+ |
| `reversible` | can this be undone, and how | one of a closed vocabulary |
| `blast` | what is worst-case affected if it is wrong | non-empty for `high` |

A model that cannot name a path is telling you something; a model that names a path that does not
exist is telling you more.

## Open questions for the panel

1. **Is a closed shape right, or is it `intake.ASPECTS`' mistake at a different node?** Six aspects
   is a closed list that has held. But a scope is per-change, and a field this list does not have —
   "this touches the deployment pipeline" — would be silently unsayable.
2. **Does `paths` verification belong here at all?** Checking that a path exists is cheap and real.
   Checking it is the *right* path is not possible, and a check that verifies the easy half may read
   as verifying the whole.
3. **What happens when the scope contradicts the grade.** A `low` grade with a `blast` naming the
   payment path is a contradiction a person should see. Nothing proposed here notices it, and
   noticing it would mean rules about content, which is a model's judgement wearing a lint's clothes.
4. **Whether `qa_verify` and `acceptance` should carry it too.** The scope is what QA should be
   testing against. Carrying it to those stops is nearly free; asserting QA *used* it is not.
5. **`reversible` overlaps `policy.PERMANENT_HALT_KINDS`**, which already names actions nothing may
   automate. Two places that must agree about what is irreversible will eventually disagree — this
   file's own comment says so about a different pair.

## Risk & rollback

- **`lead_assess` gains a required field.** Every existing plan and every replayed run that answers
  that node without a scope now fails there. That is a breaking change to the node's contract and
  is the main reason this is a design record first.
- **A refusal that fires on a model's omission** is a run that stops for a reason the operator did
  not choose. Bounded the same way intake is: say what is missing, and say it plainly.
- Rollback: revert. The grade travels alone again.
