## Read this first

```
policy.adjudicate({"conformance": "pass", "defect": "fail", "risk": "fail"})
  ->  fail,  "only 1/3 seats passed"

policy.adjudicate({"conformance": "pass"})
  ->  pass,  "1/1 seats passed"
```

The seat count does not merely shrink the panel. **It reverses the panel's verdict on identical
judgements**, because the two seats that said `fail` are never asked. Driven end to end with one
dispatcher and one set of judgements:

```
nothing set                              the change is rejected and cycles to the retry budget
{"review_seats":1,"high_risk_mode":true} suspended · lead_review = pass · reaches merge
--change-class standard, at the floor    still rejected: a class moves gate cells, not the panel
both                                     finished
```

Forty bytes, minified. The two seats those bytes remove are `defect` and `risk` - between them the
seats that found every live defect in the last six rounds.

## The three things wrong, each measured

### It is filed in the runner's voice, and it names nothing

`_finish` writes `report.relaxations` with `conversation.relaxation(relaxed)` and no `by=`, while
`report.relaxations_by_class` gets `by=(… or report.class_authorised_by or None)`. The seat-floor
crossing is in the first list. What lands is:

```
by=None   'high-risk mode: review opened with 1 seat(s), below the floor of 3'
```

byte-identical whether it came from `config/settings.json` or from a one-run `--high-risk-mode`
flag. `conversations.relaxation`'s own docstring draws the line this crosses: *"`--store-remote
allow` is the runner recording its own configuration, and a change class is a person
pre-authorising a type. The first is the runner's voice; the second is not."* A settings file is a
person pre-authorising a type - **a standing one, with no expiry and no authoriser** - and it is
filed in the runner's voice.

### A vouch that works leaves nothing at all

```
not vouched            recognise -> unrecognised   on_trust True    the run STOPS, and records why
vouches python.exe     recognise -> ordinary       on_trust False   nothing is written anywhere
```

`report.on_trust` is appended only where `policy.on_trust()` is true, which is only where the
target was **not** recognised. A vouch that works makes `unrecognised()` empty, so the branch that
records the trust is exactly the branch a successful vouch skips. The comment above it - *"What is
unacceptable is the trust being invisible, so it goes in the report where an auditor reads it"* -
describes the case where the vouch failed.

### The confirmation is bound to the toggle, not to the crossing

`tui.confirm_high_risk` has two call sites and both are avoidable:

```
GUI, seats->1 then bypass on   confirm shown       1
GUI, bypass on then seats->1   confirm shown       0     same result, same keystroke count
cli.cmd_run, file already has the bypass           0     the guard reads `saved.high_risk_mode`
cmd_serve / server.py                              0     no such branch exists; `SEAT_FLOOR`,
                                                          `confirm_high` and `review_seats` appear
                                                          in server.py 0 times
```

`_toggle_high_risk` returns early when nothing is being crossed *yet*, and `_edit_seats` never
asks - so two edits, neither a crossing on its own, compose into one that is never confirmed.

## Task 6 - what `resolve_seats` discloses and what it does not

Its docstring records that `undecided` becomes unreachable at one seat. That is the smaller half.
The half it does not carry is that **a `fail` becomes a `pass`** - which is not a property of the
seat count in isolation but of `adjudicate` counting the seats it was given. Both functions are
right; neither says the thing the pair does.

## Risk & rollback

- `RunConfig` gains a field naming where the seat count came from. Callers that do not set it get
  the empty string and the record reads as it does today.
- A successful vouch appends one line to `report.on_trust`. That list already reaches `--json`, the
  console and the terminal, so a run that vouches will print one more line than before.
- The confirmation moves from *turning the toggle on* to *the edit that crosses the floor*, so the
  order that skipped it now asks.
- Rollback: revert. The crossing goes back to being unattributable and the vouch to being silent.
