## The defect

A plan with `scope: ""`, `objective: ""`, `expected_outputs: ""` on the build nodes ran the entire
24-node flow: **25 asks, four files written, exit 0.** Nothing refused it and nothing warned.

`workorder.py::_check`:

```python
missing = [f for f in required if f not in supplied]
```

The presence of the *key*. A key whose value is `""` passes, and `render()` copies the blank into
the order it dispatches to a model.

This project's dominant defect class — a name standing in for a constraint — inside the module whose
whole job is refusing orders that are not truthful. **Found by running the example, not by reading
the code.**

## The rule

| | | why |
|---|---|---|
| `scope` | **must say something** | the field whose entire job is to be a boundary |
| `objective` | **must say something** | without it "done" is undefined and nothing can be measured |
| `instructions` | **must say something** | the payload of the ask; blank is an ask spent on nothing |
| `done_criteria` | **must say something** | blank lets a node declare itself done vacuously |
| `acceptance_predicate` | **must say something** | a blank predicate examines nothing by construction |
| `workdir` | **must say something** | `.` is a location; `""` is not |
| `input_artifacts` | may be empty | legitimate for any node with no inputs |
| `expected_outputs` | may be empty | `[]` on **14 of 15** nodes in `examples/plan.json` |
| `idempotence_probes` | may be empty | `[]` on every node of both example plans |

Blank means empty after strip, or a sequence that is empty or holds only blanks. Whitespace counts:
`" "` is the same defect one character deeper.

The refusal **names the allowed-blank set out loud**. A message that only scolds invites the caller
to pad `idempotence_probes` with a fake probe to be safe — manufacturing the defect the rule exists
to stop.

## Two boundaries, differing by one field on purpose

- **`plan.check`, at load** — five fields. So it costs no asks: a blank `engineer_build` caught only
  at dispatch surfaces after `intake_review` through `pm_signoff` have spent seven of them.
- **`workorder.render`, at dispatch** — all six. The choke point every order passes through,
  including callers that never open a plan file.

`instructions` is the exception, and the exception is the interesting part. Both seats returned
`refuse-blank`; they disagreed only about this field. **Settled by the code rather than by
averaging** — `engine.py:515` reads:

```python
own = spec.get("instructions") or ()
```

The engine joins `--instruction` text onto the node spec's own and explicitly tolerates a blank
there. A plan that leaves every node's `instructions` empty and supplies the text on the command
line is coherent and works today, so refusing it at load would be this same defect inverted, one
field over.

One definition of "blank" serves both, in `workorder.content_problem`. Two copies of this rule
drifting apart would give a plan that loads and will not dispatch, and a test asserts every field
sits on exactly one of the two lists.

## What it refused in this repository

**One test fixture**, and it was examined rather than patched. `test_store.py` built
`{field: "" for field in NODE_SPEC_FIELDS}` — enough keys to satisfy a check that only counted them.
That test is about which *model* gets dispatched; the spec only ever needed to exist. Given real
content it passes.

That is the only thing in 1182 tests the rule refused. Both example plans pass, and
`test_the_example_plan_survives_the_rule_it_documents` pins them against it permanently.

## Scenario C inverted, and three things moved together

| | before | after |
|---|---|---|
| exit | 0 | 2 |
| asks spent | 25 | **0** |
| files built | 4 | 0 |

`examples/tide-spa/README.md`, the results table's argument, and
`tests/test_example_tide_spa.py` all changed in this commit. The test that asserted the **broken**
behaviour was written that way on purpose in CHG-20260823-32, so the fix could not land without the
documentation moving with it. It worked.

The refusal names `scope` and `objective` — and **not** `expected_outputs`, which the same mutation
also blanked. `test_the_refusal_names_the_blank_fields_and_not_the_ones_allowed_to_be_blank` pins
that, because over-refusing is the failure mode a rule like this actually has.

## Risk & rollback

- **This refuses plans that previously ran.** That is the change, not a side effect. A plan blocked
  by it was dispatching a model against an empty brief.
- The load-time check only examines fields that are *present* — a missing key is still `_check`'s
  complaint, reported once rather than twice in different words.
- Rollback: revert. No governance definition, gate or risk grade changes.
- 1182 collected; 1179 passed, 3 skipped.

## Status


Accepted (see docs/acceptance/ACC-20260823-34.md) -- Pass, cleanly. One definition of blank at two boundaries, bitten from four directions including the over-refusal case. Both engines returned no reservation.

### Not claimed

**That every blank is now caught.** Three fields may still be blank, by ruling, and scenario C's
refusal deliberately does not mention `expected_outputs` even though the mutation blanked it.

**That a non-blank field says anything useful.** `scope: "x"` passes. This distinguishes *something*
from *nothing* — the distinction the old check failed to make. It does not judge quality, and
nothing here does.

**That the two boundaries check the same thing.** They differ by one field, on purpose, documented
at both ends.
