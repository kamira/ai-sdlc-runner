- Proposed by: the operator — 「mockup 如果遇到需要修正則需重新mockup交給用戶確認」. This is the
  second of the two paths that loop back, and the one that still did not converge
- Risk: **medium** — what every node a panel sends work back to is asked

## What happened

CHG-20260901-12 wired a **person's** rejection reason through to the node `rejects_to` names. The
design panel's conformance seat then measured the design that depends on it and found the loop
still did not converge:

```
pm_draw was asked 2 time(s): ['003-pm_draw.json', '005-pm_draw.json']
the two work orders compare equal: True
```

Because there are **two** paths back into the flow and only one was wired:

| how the run comes back | carries a reason |
|---|---|
| a person refuses a gate → `rejects_to` | **yes**, since CHG-20260901-12 |
| a panel does not pass → the `fail` / `no` branch | **no** |

## The brief that reached nobody

`_send_back` builds this when a panel does not pass:

```python
"brief": f"{node.id} did not pass: {outcome.get('reason')}. "
         f"Address what {', '.join(against)} raised.",
```

Its own comment calls that **"the instruction"**, and the docstring around it argues at length for
how it should travel: *"the words that were actually said travel with the words that replaced
them"*, with the appendix marked *"reference, not instruction"*.

It is appended to `report.send_backs`, serialised by `RunReport.as_dict`, put in the server
snapshot, and asserted by five tests. Measured, nothing else reads it:

```
$ grep -rn "send_backs" src/ tests/ --include=*.py --include=*.html
engine.py:358 (the field)   engine.py:392 (as_dict)   engine.py:874 (the append)
server.py:205 (the snapshot)
tests/test_sendback_retry_reject.py  (five assertions about the record)
```

`_order_for` never sees it. So the node being asked to rework something was handed its original
work order again, answered it the same way, and was failed again — the same non-convergence, on the
other path.

## The fix

The channel CHG-20260901-12 built, used for the other case:

1. `_send_back` **returns** what it recorded instead of only appending it.
2. Where a branch is taken, the brief is written to `sent_back[target]` — but only when the branch
   goes somewhere else. A panel that fails onto a terminal is not being asked to rework anything.
3. `_order_for` renders it, and **says truthfully who sent it back**. Two different events reach
   this text: a person refusing a gate, and a panel not passing. Telling a model *"a person
   refused"* about an adjudicated verdict would be the runner saying something untrue about who
   objected — and who said what is the whole argument for having panels.

## What this does not do

- **It does not bound the loop.** Same as CHG-20260901-12: what changes is that each lap answers a
  different question.
- **It does not summarise better.** The `brief` is what `_send_back` already wrote; this delivers
  it. Whether one sentence is the right summary of four objections is that function's argument and
  is untouched.
- **It does not reach the appendix.** `_send_back` records the verbatim objections beside the
  brief and marks them "reference, not instruction". The instruction now travels; the reference
  still lives only in the report. That is deliberate — an order that restates every objection is a
  rework with four masters, which is the reason the split exists — and it is reservation 2.

## Risk & rollback

- **Every node a panel sends work back to is asked something different.** That is the change, and it
  is a behaviour change to every `fail` path in the flow — `pm_confirm`, `pm_signoff`,
  `lead_task_review`, `re_review` and `qa_accept` all loop back on a panel verdict.
- **Only with more than one model configured.** `_send_back` fires from the panel path, so a
  single-model run is unaffected.
- **The order grows two lines**, and only when the run arrived that way.
- Rollback: revert. The brief goes back to being written, recorded, snapshotted, tested, and read by
  nothing.
