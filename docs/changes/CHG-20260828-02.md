## The gap, three times

Each was **reproduced before it was written down**, not inferred from reading.

### 1 · `tools/ledger_check.py` accepted an acceptance for a change that does not exist

Every check in that file starts at a CHG and asks whether an ACC exists. Nothing ever walked the
other way, so an ACC naming no change was invisible. Dropping `ACC-99999999-99` into
`docs/acceptance/` and running the checker printed **`ledger check passed (96 changes)`**.

Traceability is the entire reason both files are kept, and it only holds if it holds both ways.

### 2 · `tests/test_database_schema.py` let a frozen literal satisfy a computed claim

```python
assert f"{len(built)} of {len(designed)} tables are built" in flat or (
    "three of five tables are built" in flat.lower())
```

The `or` makes the computed half **optional**. Build a sixth table and the page may go on saying
"three of five" while this passes.

This is the shape quoted in `tools/mutation_check.py`'s own docstring as the defect that forced
that tool into existence — `assert good.id in report["imported"] or report["refused"]` — reproduced
in a file written after it.

### 3 · `tests/test_nothing_is_unwired.py` gated its strict rule behind a list of names

`COLLIDING` held eighteen names "common enough that an unrelated call elsewhere would mask an orphan
of the same name". Anything not on the list got the coarse pass. **A name list standing in for a
property**, inside the checker written to catch exactly that.

Demonstrated with two files: `alpha.close` never called, `beta` calling `io.open(p).close()`. The
word enters the used set and the orphan is not reported.

**The list bought nothing.** Applying the strict rule to every public symbol in `src/` reports
**zero** unconfirmed. It was not tolerating anything real; it was only deciding which orphans could
hide.

## And two the work itself turned up

`CHG-20260828-01` added a check that no shipped mutation has an **ambiguous** anchor. Nothing

## What could not be mutated, and why

Mutations revert a guarantee in `src/` (now also `tools/`) and require a **test** to notice. Two of
the three fixes live in test files, where that model does not apply:

* **The strict unwired rule** is pinned instead by construction: the check and the fixture share
  `_unconfirmed`, so reverting the rule fails
  `test_a_colliding_name_can_no_longer_hide_an_orphan`. The first draft had the fixture reimplement
  the rule inline, which would have let the rule be reverted with the fixture still green.
* **The table count** is a *deletion of a permissive branch*. There is no separate guarantee left to
  revert; the derived assertion runs against the real page on every suite run.

Saying "8/8 tasks, 2 mutations" without this paragraph would be the move this repository keeps
catching.

## Risk & rollback

- Nothing in `src/` changes; the runner behaves identically.
- The blast radius is what CI refuses. Three checks refuse more than they did, and the real ledger,
  the real page and the real `src/` all pass unchanged — so nothing currently on `main` is affected.
- Rollback: revert. The re-anchored mutations are strictly more specific and keep working either way.
