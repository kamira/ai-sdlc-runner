# CHG-20260905-04 - the guard is on the door nobody uses, and the manifest is truncated before it is written

- Project: ai-sdlc-runner
- Branch: claude/chg-20260905-04
- Date: 2026-09-05 (UTC+0)
- **Measured against `origin/main` at `2f26c94`**, on top of `CHG-20260905-03`
- Type: defect fix - behaviour, in `attachments.py`, with one helper in `paths.py`, one refusal in
  `cli.py`, one ordering fix in `server.py`, and the module's first mutation group
- Proposed by: all four seats of the **twelfth review round**. Three of them reached the headline
  independently. Every finding re-measured here before this record was written; two carried fixes
  that re-measurement reversed, and those are recorded as reversed.
- Risk: medium - `attachments.py` decides what string goes on every node's work order, and that
  string is read by the permanent-halt scanner. The changes are all refusals and one atomic write.
- Autonomy: high
- Target ACC: ACC-20260905-04

## Read this first

The module's design rests on one sentence, in its own docstring:

> attachments are stored under names that cannot collide. The stored path is `<store>/<sha256>` -
> no extension, no operator-chosen segment, nothing a scanner can mistake for a deployment target.

`Store.path_for` enforces it, and says so:

> Checked rather than assumed, because **this is the one function whose output becomes a string in
> a work order that a safety scanner then reads.**

That sentence is false. `path_for` has **zero production callers**. The function whose output
becomes `input_artifacts` on every node's work order is `order_paths`, and `order_paths` rebuilds
the path itself with no check at all.

```
manifest id                path_for      order_paths (the wired one)   policy.derive
secrets/prod.key           refused       admitted                       ('access',)
../.env.production         refused       admitted                       ('deploy',)
../../production/deploy    refused       admitted                       ()
```

Driven end to end through the real engine, one manifest row versus none:

```
--- clean store
   nodes dispatched: 16   visited=[intake … merge]
--- manifest row id='..production.x'
   nodes dispatched: 0
   halted_at='intake'
   halt_reason="permanent halt at 'intake': the paths it names are production deploy or release
                — [...att\688b9329…, ...att\..production.x]. No risk grade, confirmation, mode
                or change class relaxes this — a person does it."
```

That is verbatim the defect `CHG-20260823-11` says was designed out - *"an attachment filename can
permanently halt every run"*. The design closed the `add()` door and left the `order_paths()` door
open.

## The findings, and who found each

### 1. `order_paths` has no shape check (idiom L-1, defect L-1, conformance §3 - three seats)

Above. `all()` reconstructs `Attachment(**entry)` from the manifest with no validation, so whatever
the manifest holds becomes a work-order path. Entry is a manifest edit - a thing an operator's text
editor does.

`Store.path_for` is invisible to `test_nothing_public_in_src_is_unreachable_from_src` because
`_public_symbols` walks only `ast.parse(...).body` - **methods are outside that checker entirely**,
so the repository's dead-code guard cannot see a dead method.

**Re-measured: the obvious fix is wrong.** Routing `order_paths` through `path_for` would also apply
the *existence* check, which silently drops a missing attachment from every work order - precisely
what `missing()` exists to prevent (*"it becomes visible"*). The fix is the shape check only.

### 2. `_write` truncates before it writes (defect L-3)

`paths.write_text` opens `"w"`. There is no temp-and-rename. Measured directly:

```
manifest before the next write: 12086 bytes, 60 rows
   just after open(), before any write    -> 0 bytes on disk
   after half the payload was written     -> 6144 bytes on disk
manifest after : 12289 bytes, 61 rows
```

Two real processes adding at once, 40-row manifest:

```
trials in which a successfully-added attachment vanished: 4/10
      worker stderr: AttachmentError: manifest.json is not valid JSON: Expecting value: line 1 column 1
```

The single-writer case is worse than the concurrent one: a `Ctrl-C`, a full disk or a crash inside
that window leaves the manifest empty **permanently**, and nothing rebuilds it. The blobs survive;
the original filenames, which live only in the manifest, do not.

### 3. A torn manifest bricks the whole runner, not just attachments (risk R2, defect L-4)

```
--- after ONE torn manifest.json write ---
POST /attachments  -> 500  AttachmentError: manifest.json is not valid JSON
POST /run          -> 500  ...same...
POST /run/instruct -> 500  ...same...
```

`Runner._refresh_attachments()` is called unguarded from `start()`, `instruct()` and `attach()`, and
`AttachmentError` is not `ServerError`. Worse, `start()` sets `self.state = RunState(state="running",
version+1)` **and then** refreshes, so the raise leaves the runner permanently "running":

```
POST /run          -> 500, runner.state = running version 1     <- mutated, then raised
POST /run (again)  -> 409 "a run is already running"
```

There is no route back to idle short of restarting the process. And `GET /attachments` answers from
cached state, so the console shows zero attachments **and** zero missing while the store holds one -
inverting the guarantee that a run which has lost a document says so.

### 4. Six manifest shapes that are valid JSON raise the wrong class (idiom L-6, defect L-5, conformance §5 - three seats)

```
a list, not an object      -> AttributeError: 'list' object has no attribute 'get'
a row missing a field      -> TypeError: Attachment.__init__() missing 3 required positional arguments
a row with an extra field  -> TypeError: got an unexpected keyword argument 'note'
a row that is a string     -> TypeError: argument after ** must be a mapping
attachments is a string    -> TypeError: argument after ** must be a mapping
instruction is a string    -> all() ok, then add() dies in _write's sorted()
```

Every caller catches `AttachmentError` only. `test_a_malformed_manifest_is_an_error` writes
`"{oops"` - a JSON *parse* failure, the one shape that is handled.

### 5. The 32-character truncation has a collision surface, and its justification is stale (defect L-2)

On a stored-name collision `add` reports success, never writes the second file, and `path_for` hands
back the first attachment's bytes:

```
distinct bytes?  True    distinct ids?  True    same stored file?  True
bytes handed to first : b'payload 236'
bytes handed to second: b'payload 622'
bytes path_for(b) reads: b'payload 236'      <- different bytes, silently the same document
missing() []   len(all()) 2
```

The seat also measured that the docstring's three-paragraph justification for truncating is stale:
`paths.py` now supplies the extended-length prefix, so 64 characters works at every depth.

```
_NAME_CHARS=64  store dir 235 chars, full path 300 -> OK
_NAME_CHARS=64  store dir 400 chars, full path 465 -> OK
```

**Re-measured, and the seat's fix is reversed.** Bumping the constant orphans every existing store:

```
manifest id (full 64-hex) / file on disk 32 chars / missing() -> []
--- after _NAME_CHARS = 64, same store ---
missing()                          ['ec3f4a4cd18a...']   <- every existing attachment
order_paths points at a real file? False
```

There is no migration path in the module and none is added here. The fix is **collision detection**,
not a wider name: the surface is real, the width is not what makes it safe.

### 6. `media_type` never looks at the bytes (idiom L-3, P5 red)

```
add("screenshot.png", b"%PDF-1.4 this is a pdf, not a png") -> media_type = image/png
```

`_media_type` reads `Path(filename).suffix`. That is the one part of the filename this module
elsewhere refuses to trust, and the answer reaches the console and the models. Measured: renaming
`image/png` to `text/plain` in `ALLOWED` leaves 151 tests green.

### 7. Reachability and cost (idiom L-2, L-7)

`Attachment.instruction`'s own comment says it exists *"so a later brief can say where a document
came from."* Nothing says it: the console renders filename, media type and size; work orders carry
`order_paths()` only; the terminal prints one line, the directory. And `missing()` calls `all()`,
re-reading and re-parsing the manifest `_refresh_attachments` just read - 3 to 4 parses per
state-changing call.

## Recorded, not fixed here

- **The store directory is operator-chosen and it *is* in the scanned string** (risk R3, conformance
  claim 10). `order_paths` returns `str(self.dir / …)` and `--attachments` chooses `self.dir`:

  ```
  --attachments 'attachments'        derive=()            no halt
  --attachments 'spec prod files'    derive=('deploy',)   permanent halt on every node
  --attachments 'billing/att'        derive=('money',)    permanent halt on every node
  ```

  The conformance seat re-measured the tempting fix - making `order_paths` emit a relative name -
  and it breaks the property that the answering model can open the file. So the repair is a
  **startup refusal** in `cli.py serve`, which is in this change, plus a corrected docstring
  sentence, which is in `CHG-20260905-05`.

- **The HTTP body is read before it is bounded** (risk R4, defect L-8). `_body` reads
  `Content-Length` with no cap, so a 26 MB attachment is refused only after ~35 MB is resident, and
  a lying `Content-Length` parks a handler thread. That is `server.py`'s request layer, applies to
  every route, and belongs in a change about the request layer.

- **`Runner.attach()` calls `_advance()`** (risk R4), so every accepted attachment re-walks the run
  and re-dispatches models, and unlike `start`/`instruct` it does not require the run to be idle.
  Deliberate per `server.py:559-565`; re-costing it is a decision, not a defect fix.

- **Control characters in filenames** (defect L-9). NUL, CR/LF, BOM and U+202E are accepted and
  round-trip. The render path is safe - `textContent`, not `innerHTML` - so the harm is cosmetic.

## What changes

| where | change |
|---|---|
| `paths.py` | `replace(src, dst)` - one atomic move, long-path prefix on both ends |
| `attachments.py` `_write` | writes a temp file and replaces; a crash leaves the old manifest intact |
| `attachments.py` `order_paths` | applies `_STORED_NAME`. Shape only - **no** existence check, see §1 |
| `attachments.py` `all` | validates the document's shape and every row's types, raising `AttachmentError` |
| `attachments.py` `add` | refuses a stored-name collision by name; reads the manifest once instead of twice |
| `attachments.py` `_media_type` | refuses bytes that do not begin the way the declared type must |
| `server.py` `start` | refreshes **before** mutating state, so a torn manifest cannot wedge the runner |
| `cli.py` `serve` | refuses at startup when `policy.derive` reads the store directory as a red line |
