## Reservation 3 — closed, with the difference stated

`ACC-20260823-48` #3 said running `weather-spa` twice with `site/` populated produced
*"walk exceeded 200 steps — the flow is cycling without progress"*.

Run twice, 2026-08-28: `36 nodes, 26 asks, finished` — **both times, identically.** The cycling is
gone.

But the property that replaced it is not the one the reservation asked for, and saying otherwise
would be claiming something this repository does not have:

* **CHG-20260823-50** made `{"module": ""}` an answer the frontier reads instead of discarding.
  That is what stopped the cycling.
* **CHG-20260827-21** then gave each module a tree cut from a **commit**, so a second run no longer
  sees the `site/` the first one left. It rebuilds everything and finishes.

So a second run is **deterministic**, not **short-circuiting**. That is arguably the better property
— the old behaviour depended on leftover files in the working directory, which is exactly the
non-determinism the isolation exists to remove — but *"recognising there was nothing to build"* is
not what happens, and the closure says so rather than rounding up.

## Reservation 4 — left standing on purpose

`ACC-20260823-48` #4 says `tests/test_example_weather_spa.py` still invokes the agent directly
rather than through the CLI. Confirmed: that file contains **zero** CLI invocations.

The gap **behind** it is now covered — `tests/test_worktree_isolation.py` drives `weather-spa`
through the real command three times, including a full multi-module build. That coverage exists
because CHG-20260828-14 had to be written: no test drove a multi-module run through the CLI, and a
regression shipped through the hole.

The concern is addressed; the sentence is still true of that file. **Striking it would imply a
rewrite that did not happen**, so it is annotated instead.

### Not claimed
