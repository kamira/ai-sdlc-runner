## Measured with the harness, not a probe

`ACC-20260828-24` concluded that the probe I had written for the previous two modules should not
have existed: `mutation_check.py` answers the same question with a green-baseline check, anchor
uniqueness, an ambiguity outcome and a crash sentinel. So this time the mutations went straight into
the registry pointed at `tests/test_server.py`, and the ones that came back `NOT CAUGHT` are the
holes. One step instead of two, and it leaves a permanent record instead of a temporary one.

| guarantee | before |
|---|---|
| a non-loopback `Host` reaches the router (DNS rebinding) | pinned |
| the shell is served to any `Host` | pinned |
| a cross-origin request is answered | pinned |
| no operator token is needed | pinned |
| a `Host` with a port stops matching | pinned |
| **the token is compared with `==`, leaking its prefix by timing** | **not pinned** |
| **every route takes the token from the query string** | **not pinned** |
| **a body that is not JSON comes back as a traceback** | **not pinned** |

Five of eight. This is the security boundary of a server that holds an operator token, and three of
its guarantees had nothing that would notice them going.

## The three

**Constant-time comparison.** `accepts` uses `secrets.compare_digest`, with a comment saying *"a
comparison that leaks its prefix is free to avoid and awkward to explain afterwards"*. Replacing it
with `==` left all 56 server tests green. No behavioural test can see constant time, so the
**mechanism** is named: a spy over `secrets.compare_digest` asserts the comparison goes through it.

**The query-string fallback is one route wide.** `EventSource` cannot set headers, so `/run/events`
accepts `?token=`. The comment explains why it is not general — a query parameter reaches access
logs — and making it general left every test green.

**A malformed body.** `_body` catches `ValueError`; narrowing it to `TypeError` left every test
green while a bad body became a 500. The same shape as `cmd_serve` catching only `StoreError`, one
layer out.

## A mutation of mine that changed nothing

A fourth came back `NOT CAUGHT` and was **not** a hole:

```python
bool(presented) and secrets.compare_digest(presented, self.token)
#  → secrets.compare_digest(presented or "", self.token)
```

`secrets.token_urlsafe(32)` is never empty, so the two spellings agree on every input. The mutation
was a no-op, which the harness's own docstring warns about — *"the first draft of the importer's
first mutation rebound a dict to an equal dict"*. `NOT CAUGHT` cannot tell a missing test from a
mutation that broke nothing; that judgement is the reader's, and this one was mine to make and
nearly did not get made.

## A test of mine that could not fail

The first version of the query-string test sent `token=""`. `_guard` consults the query string only
when the header is **absent**, and an empty header is not absent — so the test passed, and the
mutation stayed `NOT CAUGHT` even with the test in place. The fixture's `call` now takes
`omit_token`, which sends no header at all.

Fifth time this session, third of them mine.

### Not claimed

**That the boundary is complete.** Eight guarantees were named by reading `_guard`, `accepts` and
`_body`. `server.py` is 943 lines; the routes behind the boundary — what each one accepts, and what
a wrong version or a concurrent walk does — were not surveyed, and several have their own refusals.

**That a spy proves constant time.** It proves the call goes through `compare_digest`. If that
function were itself replaced with something variable-time, the test would still pass. The
alternative is timing measurement, which is not reliable in a test suite.
