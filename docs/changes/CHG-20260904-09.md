## Read this first

Two live defects, both behaviour, both left behind by a fix of mine that shipped with a guard
looking one step past the thing it was guarding.

### L-37 - the rule compares two sets, and `POST /run/reject` has no passing test at all

`CHG-20260904-06` hardened the decision scan from the parameter *names* to the argument *values* -
that part was right. But it compares them as **sets**:

```
handed = {kw.value.id ...}
asked  = bool(calls) and handed >= (taken & {"gate", "node_id"})
```

so one token in `reject` satisfies it, because both names appear on both sides:

```
waiting = self._answering(gate=node_id, node_id=gate)
```

The swap is not cosmetic. `_answering` then compares `node_id` against `waiting["gate"]`, so
**every valid refusal dies**. Measured, driven through the real HTTP surface:

```
as shipped   a refusal naming the run's own stop      accepted
swapped      the same refusal                          "this run is waiting at 'plan_confirmed',
                                                        not 'pm_confirm'"

tests/test_server.py      82 passed   under the swap
tests/test_api_schema.py  19 passed   under the swap
```

The reason nothing sees it is the finding underneath: **all four `reject` tests assert a 4xx** -
nowhere to send a refusal, a mismatched gate, an empty gate, an incomplete stop. The swap only
makes refusals *more* likely, so the suite is structurally incapable of noticing.

### L-35 - the mark that counts an intake ask outlived the run it counts

`CHG-20260904-05` put `_instructions_when_last_asked` on `Runner`. `start` replaces `self.state`
with a fresh `RunState` - `instructions=[instruction]`, `intake_history=[]` - and does not reset
it, so its docstring (*"`0` before the first walk, so the first incomplete stop always counts"*) is
false for every run after the first in a process:

```
run A stop 1   instructions 1   mark 1   history 1
run A stop 2   instructions 2   mark 2   history 2
run B stop 1   instructions 1   mark 2   history 0      <- 1 > 2 is false; nobody counted the ask
```

Two consequences, both regressions of changes that shipped this week: it reopens
`CHG-20260904-03` - the `<p>` says *"(asked once)"* while `intake_asks_by_aspect` says `{}`, because
that map is derived wholly from `intake_history` - and `ASK_LIMIT` fires two asks late, which is
`CHG-20260904-05`'s own stated defect returning by another route.

`RunState.intake_history`'s comment already names the property: *"a counter that resets each walk
would ask forever."* The mark is a count **about a run**; it belongs on the run.

## Task 5, and why it is a task

The first attempt at reproducing L-35 used the default runner, whose stop is **not** incomplete.
Run 1 recorded `0` and run 2 recorded `0`, and the test failed - for the wrong reason. A guard that
can pass over the defect by never reaching it is the same failure as the two above, one level up,
so the floor is asserted before the claim: run 1 counts twice, and only then is run 2's silence a
finding.
