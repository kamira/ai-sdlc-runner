- Project: ai-sdlc-runner
- Branch: claude/chg-20260907-01
- Date: 2026-09-07 (UTC+0)

- Type: behaviour. One refusal in `intake.collect`, and the test doubles that had been walking past
  it.
- Risk: medium - a walk that used to continue now stops, and the shipped default backend reaches a
  different node before failing. It could not complete a walk before this change either.
- Autonomy: high
- Target ACC: ACC-20260907-01

## The finding

Reported by the **defect seat** (`fable`) in round thirteen; verified independently by `codex`,
which returned GREEN on six of its seven checks and PARTIAL on the seventh — that PARTIAL is
answered below.

`intake.collect` reads three keys: `missing`, `problems`, `unsafe`. An answer carrying **none** of
them was indistinguishable from a seat that looked and found nothing.

Eleven branches up, in the same function, `engine.walk` refuses exactly this for model panels:

> *"a voice that said nothing is not a voice that voted no"*

The survey had no equivalent, at the one node whose entire purpose is to find problems.

## It is not a hypothetical agent

The realistic bad answer is not prose and not a crash. It is `{"verdict": "pass"}` — **the shape
every other seat node in this runner expects** — from an agent that did not special-case this one.

Driven on `main` with the shipped default backend and no test harness at all:

```
nodes asked: ['intake_review', 'intake_review', 'intake_review', 'pm_plan', 'pm_confirm']
raised at  : node 'pm_confirm' decides on its answer, but the answer named no branch
```

`cli._Stub` — *"answers nothing, records that it was asked. The default, so a dry run costs
nothing"* — is what anyone gets running `runner run` without an agent configured. Three seats were
asked, all three said nothing about the requirement, the survey called it complete, the run
**planned** at `pm_plan`, and only the node after that refused it.

## Answering codex's PARTIAL

`codex` was right that existing tests and the shipped stub depend on keyless answers continuing,
and right to raise it. Re-measured, the two halves are different:

**The tests.** `test_a_complete_requirement_says_so` passes `{"a": {"problems": ["a nit"]}, "b":
{}}`. Its docstring states its subject: *"problems do not make a requirement incomplete — missing
aspects do"*. Seat `b` is filler. It **depends on** the behaviour; it is not **about** it. Changing
`{}` to `{"problems": []}` leaves it testing exactly what it says it tests.

**The stub.** This one is real, and the answer is that it changes a failure, not a success. The
walk above already fails. After this change it fails at `intake_review`, naming the contract it did
not meet, instead of two nodes later with a sentence about branches. Teaching `_Stub` to answer the
contract was considered and rejected: a stub that reports *"I looked and found nothing"* would make
a dry run print a **passed** intake review, which is worse than failing.

No governance decision was needed for that, because nothing is being permitted that was forbidden —
an existing failure is being moved to the node where its cause is.

## No record decided otherwise

Searched `docs/changes` and `docs/acceptance` for six phrasings — *said nothing*, *silence*,
*silent*, *answered with nothing*, *no keys*, *empty answer* — and cross-referenced every record
mentioning silence against every record mentioning intake. Nothing decides that an intake seat may
answer with nothing. The one `no keys` hit is about API credentials.

That is a claim about my search, and the search was six phrasings across two directories.

## What changes

`intake.collect` refuses an answer carrying none of the three keys, beside the refusal it already
makes for an aspect it does not recognise, and for the same stated reason. `ANSWER_KEYS` names the
set once so the code and `docs/SCHEMAS.md` cannot drift apart.

## The doubles, which are the finding at a second layer

The contract is written in three places — `intake.collect`'s docstring, `docs/SCHEMAS.md:169`, and
`examples/minimal/agent.py:17`, whose own agent honours it at line 40. **Nothing enforced it**, and
so almost nothing honoured it:

```
answered the survey properly    3   test_flow.Recorder · one sendback dispatcher · the example
answered with a verdict        34   across 18 test files, and cli._Stub
```

216 tests failed on the first run with the refusal in place. Not one of them failed on an
assertion: every failure was a test double answering `{"verdict": "pass"}` at a survey node. Each
was repaired by adding a branch that returns three empty lists — 194 insertions against 10
deletions, and no assertion touched.

Three of those doubles carry comments showing this confusion has bitten before, each time fixed
locally:

| where | what it says |
|---|---|
| `test_flow.Recorder` | *A survey, not a panel. It is asked what is wrong and what is missing* |
| `test_sendback_retry_reject` | *Counting its asks towards the review panel's rounds had the panel pass before it was ever asked to object* |
| `test_resume` | *a review panel that says nothing no longer passes for one that voted no (CHG-20260903-27)* |

The third is this same rule, for panels, **already decided and recorded**. This change gives it to
the survey.
