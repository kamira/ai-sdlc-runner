## The item, and the premise that had already been measured false

Item 8 of the handed-off queue said `cli.cmd_run`'s `record_intake_stop` guard is unreachable after
CHG-20260907-27. It is not, and the tree says so in the guard's own comment:

> **The state is still reachable, and this line stays honest only because the option ask replays
> too** (CHG-20260907-27, third round; the record said the engine had made it unreachable, and that
> was wrong).

The same comment then names what is left, and defers it:

> Remove only that replay — the same run with the option ask's journal entry gone, which is what an
> `_acceptable` rejection or an order that differs between runs leaves behind — and the row reads
> `resumed 3  asks 4  options YES  stops after 4`: a fourth stop recorded under a sentence that
> says *"asked 3 times"*. **Stating this over the survey's asks alone is its own record.**

This is that record. The item as handed over is not opened; the defect its brief was standing next
to is.

## The defect, constructed

`engine.walk` driven for real — three fresh runs each recording a stop, then `--resume` on the same
brief, then the same `--resume` with the option ask's journal entry removed:

```
run 1  fresh                          asks 3 (survey 3)  resumed 0  dispatched 3   guard True
run 2  fresh                          asks 3 (survey 3)  resumed 0  dispatched 3   guard True
run 3  fresh                          asks 4 (survey 3)  resumed 0  dispatched 4   guard True
run 4  --resume, same brief           asks 4 (survey 3)  resumed 4  dispatched 0   guard False
run 5  --resume, option reply gone    asks 4 (survey 3)  resumed 3  dispatched 1   guard True   <-
```

**`dispatched 1`** — one order left the process on run 5, and it was the option ask the escalation
itself sent. The survey's three all came back from the journal, so **the survey asked nobody**. A
session was opened on that lap; it was the runner's own, and the field is deliberately narrower than
"did this lap open any session?" (a seat, on four sentences that said the looser thing). The shipped guard
records a fourth intake stop anyway, and `intake.times_asked` counts it, under a suspension whose
sentence says the aspect has been asked three times.

### The server has the same expression and, on today's evidence, not the same defect

`server.Runner._walk_once` reads the same two counters. Handed a report of exactly that shape by
hand, `instruct` appends to `intake_history` — but **that report is one this record built, not one
the server was driven to**, and the first version of this record called that a measurement. It is
not. A seat refused it.

`server.py` carries the argument, and the argument is measured: the append's first conjunct is
`told > mark`, so the brief must have grown since the last incomplete stop — and a grown brief
changes every work order, so the journal's orders mismatch and every seat is re-asked. A fully
replayed survey and a grown brief are therefore mutually exclusive there. The one lap where
`told > mark` survives a fully replayed survey is a replayed `start`, whose `RunState` has an empty
`intake_history`, so `times_asked` is 0 and no option ask can be dispatched at all. Swept over every
sequence of `instruct` / `attach` / same-brief restart up to five operations: **2004 walks, 194
dispatching an option ask, 363 with `told > mark` and a fully resumed survey, and no lap that is
both** (CHG-20260907-27).

So: **the defect is reachable on the command line**, where `cmd_run` has no mark guard and reads
`intake_history` from a persistent journal. The server's line changes anyway, and the reason is
smaller and worth saying plainly — its correctness stops resting on that sweep. `told > mark`
forecloses the shape today; it does so through a chain about work orders and journal keys that
nothing in the append can see. Reading the engine's own answer makes the line true on its face.

## Why both callers had to recompute it, and why they no longer do

`engine.walk` already measures this, at the only moment it is knowable, over the halted node's asks
alone and **before** the option ask is dispatched:

```python
asks_before, resumed_before = len(report.asks), len(report.resumed)
for seat in policy.seat_names(seats):
    ...
asked_somebody = ((len(report.asks) - asks_before)
                  > (len(report.resumed) - resumed_before))
```

The two callers could not read it, so each wrote a report-wide `len(report.resumed) <
len(report.asks)` instead — which is the same pair of integers only while `intake_review` is the
only node that has asked anything, **and** while the option ask replays. The first condition is a
graph assumption, stated in both comments and pinned since CHG-20260907-27 by
`test_nothing_asks_anybody_before_the_node_the_append_guard_counts_over`. The second is this defect.

That test's docstring already rejected the obvious repair, for a reason that still holds:

> Scoping the server's expression to the halted node was the other way to close this, and it was
> rejected: `report.resumed` holds ask **ids** and `Ask` carries no id … so the server would have
> to recover the node from the spelling of `NNN-node-seat` — a string convention standing in for
> the thing it identifies.

It does not consider the third way, which costs no string convention and no assumption: **the
engine puts the fact it already has on the report.** `RunReport` gains one field, `engine.walk`
assigns it where `asked_somebody` is computed, and both callers read it instead of deriving it.

### The defect is the moment, not the expression

That sharpening came from the registry refusing a mutation. Putting `len(report.resumed) <
len(report.asks)` back **where the engine assigns the fact** was registered first and came back
`NOT CAUGHT` — because at that point the option ask has not been appended yet, so the report-wide
pair and the node-scoped delta give the same answer. The same expression is correct before the
escalation dispatches and wrong after it, and both callers evaluated it after.

A seat narrowed that sentence, and the narrowing matters: the option ask's absence is what makes the
two forms agree **at that moment**, and it is necessary rather than sufficient. They also agree only
while no earlier node has asked anything — the graph property this record leaves pinned. The
engine's own delta needs neither condition, which is the reason it is the form that ships rather
than a tidier way to write the same thing.

So the repair is not "stop using a bad expression". It is: **evaluate it once, where the answer is
knowable, and hand it on.**

This record then said the source-side reversion — the *move* — could not be staged as a before/after
string, and **a seat staged it**: the assignment's destination is a two-line anchor at the
suspension that occurs once, so moving the evaluation to after the option ask is one substitution.
It is registered, and it is CAUGHT. That entry is the only one of the four that pins the moment; the
other three pin the expression at three sites. The sentence claiming it could not be written was the
usual shape — a universal about a search, asserted without trying.

## What ships

- `RunReport.intake_asked_somebody`, set from the number the engine already computes, and emitted
  by `as_dict` — `test_the_report_emits_every_field_it_declares` allows no exemption list, and a
  field the report should withhold does not exist yet.
- `cli.cmd_run` and `server.Runner._walk_once` read that field. Neither recomputes it, neither
  rests on the graph assumption, and neither counts the escalation's own ask.
- The two comments say what their line now rests on.
- Tests for both callers, driven the way each caller drives a walk.

## What this does not do

- It does not change what `intake.times_asked` counts, or when the escalation fires. It changes
  which runs record a stop for it to count.
- It does not remove `test_nothing_asks_anybody_before_the_node_the_append_guard_counts_over`. The
  graph property is still true and still worth pinning; what changes is that these two callers no
  longer rest on it, so its docstring's reason is now history. Whether anything else rests on it is
  a question for the seats, with the measurement in hand.
