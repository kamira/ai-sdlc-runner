## Read this first

`walk` resolves the verdict twice for an `after` gate whose node grades the risk. The note block sat
after the first only.

```
lead_assess    gate feasibility_confirmed, gate_when after, grades_risk True
  feasibility_confirmed:  low -> auto     medium -> confirm     high -> halt

  entry, graded low        the gate is `auto`; nothing is relaxed and nothing is noted — correctly
  the panel grades medium  the gate re-resolves to `confirm`
  `standard` class         relaxes it to `auto`, and there was no note block there
```

Measured end to end, three voices grading `medium` on a run graded `low`:

```
no class          suspended at lead_assess          a person is asked
standard class    finished                          the stop is gone
                  relaxations_by_class: no lead_assess entry
                  relaxation_authorisers: no entry
                  and therefore no export, no `class relaxed:` footer
```

**A `grades_risk` node exists for the two grades to differ**, so this was the designed path rather
than an edge of it — and it is the case where the class matters most, because the entry grade never
stopped anything.

`report.relaxations_by_class`' own comment is the requirement: *"A relaxation nobody can enumerate
afterwards is a relaxation nobody can audit."*

## Why CHG-20260903-41's rule did not see it

That change added `test_every_class_relaxation_carries_an_authoriser`, which counts
`relaxations_by_class.append` sites against `relaxation_authorisers` writes. **It is structurally
incapable of seeing an append that was never written.** The rule was right about what it checked and
silent about what was missing.

The replacement counts *resolutions that carry a class* against calls to the one recorder, so a
third resolution cannot be added without recording. `_record_relaxation` is that recorder, and both
sites call it — the same move as `models.COMPUTED` (-39), `_declare_classes` (-41),
`asks_including_this_one` (-42), `_answering` (-44) and `check_review_date` (-45).

## My first reproduction passed over the defect

Written with `test_flow.Recorder` and `answers={"lead_assess": {"risk": "medium"}}`, it looked like
it exercised the post-work grade. Measured:

```
risk_proposed  {}          the answer never reached the grading path
risk_settled   low         so the second resolution never differed
halted_at      merge       and the run stopped somewhere else entirely
```

The test passed on the broken code by never reaching it. A single answer is not a panel; the shape
that works is `test_risk_adjudicated.py`'s — `node_models` naming several voices, each returning a
grade. **The repo's own harness, again**: my throwaway version agreed with me and was wrong.

The guard now asserts `risk_agreed == "medium"` and `halted_at == "lead_assess"` *before* the claim
it exists to make, so a future version that stops reaching the defect fails instead of passing.
