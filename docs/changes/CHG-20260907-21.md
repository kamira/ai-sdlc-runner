# CHG-20260907-21 - a test that held the right rule for the wrong reason

- Project: ai-sdlc-runner
- Branch: claude/chg-20260907-21
- Date: 2026-09-07 (UTC+0)
- **Measured against `origin/main` at `371738d`**, pinned by sha
- Type: coverage. One assertion changes shape; **no production line changes.**
- Risk: low - the assertion is green before and after on the current constants. What changes is
  which future edits it objects to.
- Autonomy: high
- Target ACC: ACC-20260907-21

## The finding

The debt CHG-20260907-20 filed. `test_no_host_is_accepted_that_the_bind_list_does_not_permit`
(that name is removed in CHG-20260907-21, this record, and the test is renamed
`test_the_header_set_is_the_bind_list_plus_the_one_name_a_standard_fixes` because the old name
states the wrong justification in the name itself)
asserted a containment:

```
{h.strip("[]").lower() for h in LOOPBACK_HOSTS} - {a.lower() for a in LOOPBACK}  ==  empty
```

read as *"an accepted authority that is not a permitted bind argument is a name this server
accepts for a socket it will never be asked to open"*. Measured at `371738d`, it is green:

```
permitted (bind spellings)   ['127.0.0.1', 'localhost']
accepted  (normalised)       ['127.0.0.1', 'localhost']
accepted - permitted         []
```

`localhost` satisfies it by being a bind spelling. **That is not why it belongs.** A browser at
`http://localhost:8765` reaches a server bound to `127.0.0.1` because RFC 6761 6.3 fixes what the
name means in the resolver - whether or not `localhost` is a spelling `serve` happens to accept.

## Why the prose was not enough

A subtraction only ever removes a reason to fail. Three consequences, measured:

```
state                             the containment   equality over authority forms
today                             passes            passes
localhost leaves LOOPBACK only    passes            passes
localhost leaves BOTH             passes            FAILS
a name is smuggled into HOSTS     FAILS             FAILS
```

Row three is the world where a person typing `localhost:8765` is refused, and the containment
passes it. A set that only subtracts cannot say *required*; it can only say *tolerated*. And an
exemption inside a subtraction is structurally an exception list whatever the comment says:
`RESOLVER_FIXED = {"evil.example"}` with no such member in `LOOPBACK_HOSTS` would be green.

**The wrong reason has already been load-bearing.** ACC-20260907-20's second measurement used
*this test's failure* under `LOOPBACK = ("127.0.0.1",)` as a reason to keep `localhost` in the
bind list. That was a circular vote: the test objected because of the very justification this
record is fixing. After this change, `LOOPBACK = ("127.0.0.1",)` is objected to by nothing in
`tests/test_server.py` - which is correct, and it re-opens that question on its own merits. **This
record does not take that decision**; it only stops this test from casting a vote it is not
entitled to.

## What I proposed and both seats refused

I proposed the exemption plus a check that every exempt name resolves, under `AF_INET`, to an
address the server permits. Both refused it, and the sharper reason was measured:

```
getaddrinfo(name, AF_INET)
  localhost               ['127.0.0.1']
  localhost.localdomain   ['127.0.0.1']   <- this resolver, not RFC 6761
  foo.localhost           gaierror        <- RFC 6761 covers it; this OS does not
```

*"Resolves to loopback"* is the rebinding attacker's precondition, not a rule - it is the relation
ACC-20260907-20 already recorded both seats refusing, and making it a **necessary condition** on
the exemption reintroduces it. It also licenses `localhost.localdomain`, which is exactly the
drift the check was meant to prevent.

## What ships

The relation, stated closed:

```python
expected = {_authority(addr).lower() for addr in server.LOOPBACK} | RESOLVER_FIXED
assert {host.lower() for host in server.LOOPBACK_HOSTS} == expected
```

- **Equality, so every term is required.** `RESOLVER_FIXED` forbids as well as permits, which is
  the difference between a definition and an exception list. No resolver is consulted.
- **`_authority`, not `strip("[]")`.** The bracket distinction is what CHG-20260907-19's forward
  test exists to protect, and comparing normalised forms throws it away. This is *not* the
  normalised equality one seat proposed and withdrew there: that was blind to `"[::1]"` deleted
  while `::1` was permitted, and this objects to it.
- **A shape check with no environment in it:** every member of `RESOLVER_FIXED` must be a name,
  not an address literal. An address's loopback meaning is IANA's and belongs in `LOOPBACK`.
- **`"fixed by RFC 6761"`, not `"fixed by the platform"`** - ACC-20260907-20's phrasing, which the
  `localhost.localdomain` measurement above shows is wrong on this machine.

And the header the whole argument is about, sent for real. It had no live case: the `call` fixture
defaults `Host` to `127.0.0.1:{port}` and every explicit host in the file is one being refused, so
removing `localhost` from `LOOPBACK_HOSTS` drew only `Origin`-side and table-side objectors.

## The mutations

`resolver-fixed`, two entries: a required name removed from the header set, and a bracketed IPv4
literal accepted - which the old containment let through, because it stripped the brackets and
found `127.0.0.1` permitted.

**Not registered, and named as unregisterable:** the state that made this record - both constants
losing `localhost` together. The harness applies one replacement per entry and the two constants
are separate statements, so no single anchor reaches it. It is measured in the table above
instead, and the first entry is its reachable half.

`loopback` entry 3 is **re-anchored**, not deleted. It went `NOT CAUGHT` under the new shape, and
that is this record working rather than a hole: its guarantee was the wrong justification. The
word it was missing is *address* - losing `127.0.0.1` from the bind list is still a defect, and
losing a name a standard fixes is not.

## What this does not do

- It does not derive `LOOPBACK_HOSTS` in production. `RESOLVER_FIXED` and `_authority` sit on the
  test side, as twins of rules `server.py` states in code; the derivation record CHG-20260907-19
  named is the one that lifts both across the line.
- The equality decides one thing neither earlier record did, observable only if IPv6 returns: it
  requires the **bracketed** form of an IPv6 bind address and forbids the bare one. That follows
  CHG-20260907-20, which removed the bare `"::1"` as unreachable. The derivation record must pick
  the same side - the sketch in CHG-20260907-19 emits both forms and would disagree.
- `*.localhost`: RFC 6761 6.3 covers it and browsers resolve it themselves, but this OS does not
  (`gaierror`), so only a browser could send it and accepting it would be a widening with its own
  record. Left measured so that *"exactly one member"* is seen to be the intersection of standard,
  OS and browser rather than an oversight.
- It does not decide whether `localhost` stays in `LOOPBACK`. See above.
