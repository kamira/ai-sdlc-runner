## `ACC-20260827-18` #4 — never true

It said `risk_override = args.risk or None` makes *"an operator who passes `--risk` matching the
plan's grade indistinguishable from one who passed nothing."*

`--risk` is declared with `default=None`:

```
nothing passed              args.risk=None    risk_override=None
--risk low, plan also low   args.risk='low'   risk_override='low'
```

They are distinguishable, and were when the reservation was written. The `or None` is a no-op on a
value that is already `None` or a non-empty grade.

The **concern** is sound — *"it stops being harmless if anything later reports why a grade was
chosen"* — and the mechanism it feared is already absent. Struck as a claim, kept as a caution.

## `ACC-20260823-51` #2 — real, and worse than "unchanged" suggests

It said `record_module` can run *"in the same lap the engineer reports nothing was built"*, and
marked it **Unchanged**. Reproduced:

```
engineer_build ({"module": ""}) → engineer_selfverify → lead_task_review
  → record_module → next_module → lead_review
```

The engine reaches `_run_effects` for `record_module` on that lap. And this is **not latent**:
`examples/weather-spa` **declares operations for `record_module`**. The node's own note is *"tick,
commit, update the worklog — one kind of work, three ordered effects"*, so a worklog entry would
claim a module that was never built.

`minimal` and `tide-spa` declare none, which is why the shape has gone unnoticed: two of the three
shipped examples cannot exercise it.

## Why the fix is not in this change

It is a design choice, and picking it quietly inside a records pass would be the wrong way to make
it. Two candidates, neither obviously free:

* **The flow branches on an empty build.** Governance as data, which is this repository's thesis —
  but the node holding the answer is `engineer_selfverify`, a `follows` step, and making it a
  decision changes the graph's shape and every count that describes it.
* **`record_module`'s effects become conditional in the engine.** Smaller, and it is exactly the
  id-matching this repository argues against elsewhere: *"declared here rather than matched on the
  node's id in the engine"*.

Handed on with the reproduction attached, the same way CHG-20260827-21 stopped on *is a module a
commit?* rather than inventing an answer underneath a record that had not considered it.
