## Why this one followed directly

Every effect in `ship` delegates its probe here. A probe that answers wrongly defeats all seven of
the guarantees pinned yesterday **from below**, and nothing in that change would have noticed.

Ten guarantees; **six pinned**.

| | |
|---|---|
| an unreachable remote is not "not pushed" | pinned |
| the push probe asks the remote, not a local ref | pinned |
| an unreachable forge is not an absent PR | pinned |
| a missing binary is not an answer | pinned |
| a half-written CHG with no `Branch` is not recorded intent | pinned |
| an unticked task is not ticked | pinned |
| **a CHG id is matched literally, not as a pattern** | **not pinned** |
| **a failed `git log` is unanswerable, not "no commit"** | **not pinned** |
| **a failed `git status` is unanswerable, not "clean"** | **not pinned** |
| **a timeout is unanswerable, not an answer** | **not pinned** |

## The pattern, sharper than yesterday's

CHG-20260830-03 found that `ship`'s **failure** paths were unpinned while its success paths were
covered. This module is all failure paths — that is what a probe is for — so the split fell
somewhere finer:

**The three refusals that were pinned are the three with a comment beside them saying so.**

> *"Refusing to report 'not pushed' — an unreachable remote is not an empty one."*
> *"An unreachable forge is not an absent PR."*

`git log`, `git status` and the timeout make the identical guarantee. Nobody wrote the sentence, and
nothing held them.

**The comment earned the test; the guarantee did not.** That is a more uncomfortable finding than
"failure paths are under-tested", because it says the tests were written from the prose rather than
from the code — and the prose is exactly what a reader would check against.

## The worst of the four

`working_tree_clean` answering `True` when git could not be asked. `ship`'s commit probe reads
`commit_exists_for(...) and working_tree_clean(...)`, so a `True` there marks a half-committed tree
as finished and the resume pushes it — the failure CHG-20260830-03 pinned one layer up, defeated
from underneath by the layer it depends on.

## `--fixed-strings`, and the test that could not tell

`commit_exists_for` takes a **needle**, not a `chg_id`; the one caller today happens to pass an id.
Dropping `--fixed-strings` is invisible for ids, which have no metacharacters, and live for anything
else.

The first version of the test used `a?b` and did not catch the mutation: git's default grep is a
*basic* regular expression, where `?` is a literal. `.` is the discriminating character — `a.b`
finds `axb` as a pattern and finds nothing as a string.

### Not claimed

**That every probe's refusal is now checked on every command it runs.** `_run` is shared; the
timeout is pinned through `pr_open_for`, whose command is a parameter, and the other probes are
assumed to inherit it. They do, by construction — but by construction is not by test.

**That the ledger probes read the right thing.** `chg_recorded` looks for a `Branch:` field and
`task_ticked` for a tick mark. Whether those are the correct postconditions is D6.1's argument, and
this pins them rather than examining it.
