## Motivation

Five tests fail on Windows with `OSError: [WinError 193] %1 is not a valid Win32 application`:

- `tests/test_executors.py::test_command_executor_stdin`
- `tests/test_executors.py::test_command_executor_arg`
- `tests/test_executors.py::test_command_executor_extra_args_appended`
- `tests/test_executors.py::test_command_executor_extra_env_merged`
- `tests/test_workspace.py::test_command_executor_runs_in_workdir`

**Cause.** Each test writes a `#!/bin/sh` script into `tmp_path`, `chmod +x`s it, and hands the bare
path to `CommandExecutor(argv=[str(script)])`. On POSIX the kernel honours the shebang. Windows has
no shebang concept — `CreateProcess` inspects the file header, finds no PE image, and raises
WinError 193. `CommandExecutor.run` wraps that `OSError` into `ExecutorError`, so the failure
surfaces as a launch failure of the fixture, never as a defect in the executor.

**This is a test-harness defect, not a runner defect.** `CommandExecutor` is documented as
platform-agnostic ("it works with any tool that reads a prompt and writes a reply"); the fixtures
are what assumed POSIX. The runner is correct on Windows today — it simply has no green evidence of
it, because the only tests that exercise the command backend end-to-end cannot start their stub.

These five failures are pre-existing and were explicitly deferred by ACC-20260817-01 Reservations
#1 ("Fixing them is out of scope here and belongs in its own CHG"). This is that CHG.

## Decisions & trade-offs

| Decision | Options | Assumptions | Why this choice |
|----------|---------|-------------|-----------------|
| How to make the stub executable everywhere | (a) Python stub invoked as `[sys.executable, script]`; (b) keep `.sh` and prepend a discovered `sh`/`bash`; (c) `shell=True`; (d) skip the tests on Windows | The interpreter running pytest is always present and always executable | **(a)**. `sys.executable` is guaranteed available in a pytest run — no PATH probing, no Git-Bash dependency. (b) makes green-ness depend on a Git-for-Windows install; (c) changes what is being tested (a shell now sits between executor and stub, so argv/env passthrough is no longer proven end-to-end); (d) hides the gap instead of closing it and would leave the command backend with **zero** end-to-end coverage on the maintainer's platform |
| Where the stub-writing helper lives | per-test inline vs one shared `conftest.py` fixture | two test modules need the same mechanic | Shared `py_stub` fixture in `tests/conftest.py` — the two modules already share `conftest.py`, and one definition keeps the `sys.executable` convention from drifting apart |
| What each stub does | one multi-mode stub with a switch vs one body per test | each test asserts on different output | One body per test. A mode switch would put shared logic between the test and its assertion; a 2–4 line body per test keeps each fixture as readable as the `sh` one it replaces |
| Whether to touch `src/` | fix the executor vs fix the tests | the executor is already correct — the reported error is the OS refusing the *fixture* | Tests only. Nothing in `src/` is at fault; changing it to accommodate a POSIX-only fixture would be the wrong repair |
| The workdir assertion | keep `== str(proj)` vs relax to a path compare | `os.getcwd()` returns the same resolved form pytest's `tmp_path` yields on this machine | Keep the exact-string assertion. It is the stronger claim and it passes; relaxing it would weaken the test for no gain |

Confirm gate: low risk, test-only, fully reversible → auto per the halt policy. No human gate owed.

## Modification Guide

### Goal

The command backend has real end-to-end coverage on Windows and POSIX alike: the five tests exercise
the same behaviours they always asserted, through a stub the OS can actually launch. Whole suite
green; `doc_integrity_check.py --repo .` exit 0.

### Global constraints (all tasks)

- **Do not touch `src/`.** No runner source, no interface, no config, no governance logic.
- Touch only `tests/conftest.py`, `tests/test_executors.py`, `tests/test_workspace.py`.
- **Assertions are preserved verbatim.** The replacement stub must reproduce what each `.sh` did, so
  every existing `assert` keeps its original meaning. No assertion is weakened, relaxed, or deleted.
- No `shell=True`, no PATH probing for `sh`/`bash`, no platform `skipif` — the tests must run the
  same way on every platform, not be conditionally excused on one.
- Remove the now-dead `import stat` from each file it becomes unused in.
- Verification bar: whole suite green on Windows (from 144 passed / 9 skipped / **5 failed** to
  **149 passed / 9 skipped / 0 failed**), and `doc_integrity_check.py --repo .` exit 0.

### Tasks

TDD note: the tests **are** the unit under change. The red state already exists and is reproducible
(`WinError 193` ×5); "green" is those same five tests passing with their assertions intact, plus no
regression in the other 144.

| # | Task | Interface / output | Done-when |
|---|------|--------------------|-----------|
| 1 | Add the shared stub fixture | `tests/conftest.py`: `py_stub(body, name="agent.py") -> list[str]` — writes `body` into `tmp_path` and returns `[sys.executable, str(script)]`; docstring states why (Windows cannot exec a `.sh`; the shebang means nothing to `CreateProcess`) | fixture importable by both test modules; returns argv, not a path |
| 2 | Port `test_command_executor_stdin` | stub echoes stdin: `sys.stdout.write(sys.stdin.read())` | `"HELLO-123" in r["output"]`, `returncode == 0`, `backend == "command"` |
| 3 | Port `test_command_executor_arg` | stub echoes `sys.argv[1]` | `"ARG-PROMPT" in r["output"]` |
| 4 | Port `test_command_executor_extra_args_appended` | stub prints `ARG:<a>` for each of `sys.argv[1:]`, then echoes stdin — matching `for a in "$@"` + `cat` (the interpreted script path is `argv[0]`, so `argv[1:]` is exactly the old `"$@"`) | `ARG:--settings`, `ARG:config/pure-ai-sdlc.settings.json` and `BODY` all present; `returncode == 0` — proves `extra_args` land **after** `argv` and that stdin still flows |
| 5 | Port `test_command_executor_extra_env_merged` | stub prints `BASE=<ECC_BASE_VAR>` and `EXTRA=<ECC_EXTRA_VAR>` from `os.environ` | `BASE=base` (inherited env survives) and `EXTRA=injected` (`extra_env` merged on top) |
| 6 | Port `test_command_executor_runs_in_workdir` | stub prints `os.getcwd()` — matching `pwd` | `r["output"].strip() == str(proj)` |
| 7 | Drop dead imports | `import stat` removed from `tests/test_executors.py` and `tests/test_workspace.py` | no unused-import residue from this change |
