## `-B` does not mean "not trusted"

The comment shipped last round read *"`-B`: no bytecode written, **none trusted**"*. It gives the
first half and not the second: `-B` stops bytecode being **written** and never stops a `.pyc` being
**read**. `__pycache__` is validated on `int(st_mtime)` plus size, so a same-size rewrite inside one
second is served from the stale bytecode — which turns `BROKE`, the outcome that says the probe
learned nothing, into `CAUGHT`, the harness reporting a result about code it never ran.

Measured on a planted module, same size, `os.utime` back to the same second:

```
no flag   rc=0   imports -- the stale .pyc is trusted
-B        rc=0   imports -- the stale .pyc is trusted
prefix    rc=1   refuses -- the cache is not shared
```

The probe uses a fresh `PYTHONPYCACHEPREFIX` in a `tempfile.TemporaryDirectory` now, and
`test_the_import_probe_is_not_answered_by_a_stale_pyc` drives `_import_fails` itself rather than a
synthetic probe: it is `1 failed` under `-B` and `1 failed` with no flag at all. Three records
asserted a closure that did not exist.

## And the new refusal told the operator to destroy the only copy

For a record with an unusable `owner`, the gate added last round said:

> If you know no run is active, **delete the record** and use `git status` and `git diff` to see
> what was left mutated.

Followed literally, with the mutation **staged** — the case this same module's pid-reuse refusal
warns about — in a scratch repo:

```
git status:  M  x.py        git diff:  (empty)
file:        MUTATED SOURCE  record:    gone
```

Both commands the remedy names come up empty-handed. `git diff` shows nothing at all once a change
is staged, and `git status` says only that *something* changed, never what it held — while the one
artefact that did hold the original text verbatim has just been deleted on the same instruction.
Where the pre-run state of the file was itself uncommitted, that is the text gone.

The sentence contradicts the rule stated twelve lines below it — *"a refusal that also throws away
the original strands the file for good"* — and it is the same shape as the `unlink`-on-unreadable
defect two earlier rounds closed. No remedy says delete before restoring now, and the branches
whose record genuinely cannot be repaired say to check **staged** changes as well, because that is
the case where the obvious command is silent.

Reverting to that wording is `6 failed`.

## A census a record cannot take about itself

Five statements of this census in a row published a denominator that excluded the recording
record's own two files. The ledger calls CHG-20260901-02's the **fourth** instance and
CHG-20260901-03's the **fifth**, and each of those two was written to correct the one before it —
so the correction for "it excluded its own records, again" excluded its own records again. `269` is
the tree at `2afec9d`; the tree carrying CHG-20260901-03's own records is **271**, and the five
published figures reproduce exactly one commit back.

| | at `2afec9d` (269) | at `3a49c57` (271) |
|---|---|---|
| a capital | 4364 | 4405 |
| something else | 3287 | 3323 |
| a backticked identifier | 431 | 435 |
| a digit | 363 | 370 |
| a lowercase word | 67 | 67 |
| **not a capital** | **4148 of 8512** | **4195 of 8600** |

Five times is not five instances of carelessness. "The current tree" is not a quantity a record can
measure about itself, because writing the record changes it — so the census names a **commit**,
which one `git ls-tree` settles and which cannot drift. The `244 more` parenthetical was also wrong
on every tree: it is 245 at `2afec9d` and 247 at `3a49c57`, and it is exactly the number of files
whose text ends in sentence punctuation, one apiece.

And the *claim* — that requiring a capital after the full stop would leak on this repository's own
house style — is re-measured over whatever tree it runs on by
`test_the_capital_rule_would_still_miss_about_half`. No figure in it goes stale when a record is
added.

## A rename that vouched for a ghost it disclaimed, still

Last round's guard asked whether the **new** name was test-shaped and resolved. It never asked
whether the rename was *of the name being excused*, which was the defect. Against `3a49c57`:

> The helper was renamed to `<a live test>` in CHG-…; `<the ghost>` is unaffected.

still excused the ghost, in a sentence saying outright that it did not. So did a rename of a
different **named** test. The pinned row used a helper name that was not test-shaped, so it pinned
the accidental property rather than the shape.

Three further ways the guard was wrong, and each is now a row: a literal single space where the
rule itself writes `\s+`, so two spaces or a line wrap walked past it — in a ledger where every
record is hard-wrapped; `re.search` over the whole sentence, so an unrelated helper's rename
decided this test's excuse in either direction; and `startswith("test_")` as a third bound that no
row could tell apart from the must-resolve one.

The rule is now one sentence: a rename excuses this test only if it is **this test's** rename,
written forward, to a name the checker can find.

## A bound that stopped being one patch

Adding `_REMOVED_NO_RENAME` last round spelled the removal phrase out twice — and silently unpinned
a figure. Dropping `(?i:` from one copy left all 49 rows green, so the widening the acceptance table
records as `2` measured nothing. Both variants are built by one function now, and one edit measures
it again.

## Risk & rollback

- **`_import_fails` costs one temporary directory per probe** — 19 of them in the cheap half, and
  it cannot be fooled by a same-second rewrite. No mutation reclassifies.
- **`--recover` refuses exactly the shapes it refused.** What changed is what it tells the operator:
  every broken field named, one ordering, and no instruction that destroys the original.
- **`ledger_check` refuses two rename shapes it accepted** — someone else's rename, and a rename
  written backwards — and accepts one it refused: a foreign rename beside a valid removal note.
  Over the real ledger nothing reclassifies.
- **`_excused` now requires `known`.** One caller, which always passed it.
- Rollback: revert. A disclaiming sentence excuses a ghost, the probe trusts a stale `.pyc`, and
  the refusal tells the operator to delete the only copy of the original.
