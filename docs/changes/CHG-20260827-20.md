# CHG-20260827-20 — a change type assessed once should not be assessed every time

- Project: ai-sdlc-runner
- Branch: claude/chg-20260827-20-change-classes
- Date: 2026-08-27 (UTC+0)
- Type: one missing column in the gate table
- Proposed by: the decision to target a mid-to-large organisation shape, where `merge = confirm` on
  every change makes throughput a function of one person's availability
- Risk: **high** — this is the only change here that can make a gate stop less often. Everything
  about it has to be built so that relaxing is a recorded human act, never a default.
- Autonomy: high
- Related: CHG-20260823-01 (GATES)

## The gap

`merge` is `confirm` even at `low`. That is correct reasoning — merging is a one-way door — and it
means **every change needs a person**. At the scale now being targeted that is not a strict policy,
it is a policy that gets bypassed, which is the failure this repository already documented once
about the red-line word list.

## The shape borrowed from somewhere it already works

ITIL splits changes three ways, and the split is exactly what is missing here:

| class | what it means |
|---|---|
| **standard** | the *type* was assessed once by a person and pre-authorised; individual instances do not stop |
| **normal** | full approval, which is what every change is today |
| **emergency** | proceeds, and is reviewed after |

This does not weaken the axiom that governance is not a model's judgement. What a standard class
records is **a person's** judgement about a type, made once, written down, and revocable.

## The guards this needs to be safe

1. A standard class is declared by a person, never inferred, and never by a model.
2. The six permanent halts are **never** available to a standard class, at any grade.
3. Every standard-change run records which class let it through, and who authorised that class.
4. A class carries a review date. An unreviewed class expires back to `normal` rather than
   persisting on nobody's authority.
5. Emergency runs are marked and queued for review; nothing marks itself emergency.

## Risk & rollback

- This is the one change that can let something through that used to stop. Tasks 2–5 exist to make
  that a decision somebody made and signed, with an expiry.
- With no classes declared, every change is `normal` — today's behaviour exactly.
- Rollback: revert, or delete the classes.

## Status

**Proposed.**

### Not claimed

**That a type stays safe because it was safe.** Task 5 is an admission that it does not. The expiry
is a floor under the drift, not a fix for it.

**That anyone will review classes on time.** An expiry that fires and is renewed without thought is
a rubber stamp with a calendar. This change makes the renewal visible; it cannot make it considered.
