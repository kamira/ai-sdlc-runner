## Why a list was not enough

The flow panel was 23 lines of text. It could tell you *what the nodes are* and not *what the flow
is*: nothing showed that `next_module` loops, that `lead_task_review` has a fail branch into
`fix_pass`, or that `review_failed` goes backwards. And "where is the run" was one line in bold
among twenty-three — findable if you were looking for it, invisible if you were not.

## The diagram is computed, not drawn

Layers come from a **breadth-first walk of the real edges** in `/flow`. Nothing is hand-placed.

That is not tidiness. A hand-drawn diagram is a *second description of the graph*, and a second
description is one that goes stale — this project has already shipped a mock-up that claimed 23 nodes
while drawing 18, and an independent seat found it. A node added to `graph.py` now appears here
without anybody redrawing anything, because there is nothing to redraw.

The layout comes out at 14 layers, at most 4 wide.

## Four states, four colours

| | what it means |
|---|---|
| **amber, filled, with a halo** | **where the run is** — the question this panel exists to answer |
| dimmed | already visited |
| plain | not reached yet |
| **green edge** | an edge *this run actually took* |
| amber pin | the node has a gate |

Back-edges — the module loop, the send-backs — are drawn dashed and routed round the right-hand
side, so they read as *going back* rather than as a stray line crossing the spine. Branch labels
(`yes`, `none`, `module`, `pass`, `fail`) sit on the edges they belong to.

The current node is scrolled into view on every update, with `block: "nearest"` so a run that has not
moved does not yank the view.

## The second panel: where each model is used

A registry answers *what models does this project have*. It does not answer the question an operator
actually has, which is **where does this one get used** — and that is the question that decides
whether a configuration is the one they meant.

So `GET /config/nodes` returns the assignment, and the panel shows, per model: its vendor and
transport, its **reach** as a badge, every node it is on **with that node's mode**, and every seat it
answers for.

The mode matters as much as the node. Three models on a `pool` is one of them doing the work; on a
`model_panel` it is three voices being adjudicated. **Same list, different run** — so the panel shows
the mode next to the node rather than leaving the reader to remember which is which.

A model the registry has and nothing dispatches to says so, in words: *"nowhere — this model is
registered and nothing dispatches to it"*. "Configured" and "used" look identical in a list, and only
one of them does anything.

## What building the panel found

**`seat_models` and `node_models` named backends two different ways.** A node named a **model id**; a
seat named an **argv**. So `claude` and `python3 agent.py --as claude` appeared in the panel as two
separate models — which is what a view of the assignment is for: it made an inconsistency visible
that had been sitting in the config format unnoticed.

A seat may now name a registry model id, resolved the same way a node's is. Argv still works — it
predates the registry — and is the *fallback*, so the older scheme is what a non-matching string
falls back to rather than the looser one being tried first.

Before:

```
claude                        nodes=lead_task_review(model_panel), engineer_build(pool)  seats=(none)
python3 agent.py --as claude  nodes=(none)                                               seats=conformance
```

After:

```
claude   nodes=lead_task_review(model_panel), engineer_build(pool)  seats=conformance
codex    nodes=lead_task_review(model_panel), engineer_build(pool)  seats=defect
gemini   nodes=lead_task_review(model_panel), engineer_build(pool)  seats=risk
```

**That the diagram is good at 40 nodes.** It is laid out for the flow that exists — 14 layers, 4
wide. A much wider graph would need either a different layout or a zoom, and neither is written.

anybody change that. `GET/PUT /config/nodes` was specified in CHG-20260823-11 as read *and write*,
and only the read half is built.
