## Veto 1: a mutation caught by a SyntaxError

The `closure` mutation added last round to pin the excuse window anchored on the **first physical
line** of a two-line condition. Replacing it with `if False:` orphaned the continuation
`and found.group(1) in ledger_ids):`, so `tools/ledger_check.py` stopped parsing:

```
$ python tools/mutation_check.py --only closure
  CAUGHT     the excuse stops being bounded, so any removal note launders a ghost
             1 error in 0.47s          ← a collection error; the module will not import

all 9 caught.
```

Every other row in the group reports `1 failed, N passed`. This one reported CAUGHT because
`ledger_check.py` does not compile — proving only that. The bound the mutation exists to pin was
measured by the harness not at all, and the round's veto 3 was about that very bound.

`run()`'s own docstring says the green-first baseline exists to stop exactly this: *"a mutation that
merely made a module unimportable would have been 'caught' by every test file in the list."* The
baseline cannot catch it, because the baseline runs **unmutated**.

**`test_no_shipped_mutation_makes_its_file_unparsable` is the fix**, and it is the durable one: it
compiles the result of every shipped mutation. 196 of 197 parsed; the one that did not is the line
this repository wrote last round.

## Veto 2: the console mutation was inverted, and nobody was told

The `console` mutation's replacement went from `if False:` to `if True:` against the anchor
`if not _loopback_host(self.headers.get("Host")):`, while its description — *"a non-loopback Host
reaches the router, so DNS rebinding works again"* — was left alone. The two are opposites.

| replacement | what happens | what fails |
|---|---|---|
| `if False:` (before, and now) | the guard never fires — rebinding works | the three rebinding tests |
| `if True:` (shipped) | **every** request is 403'd, loopback included | 28 tests about anything else |

Measured: under `if True:` the three rebinding tests **pass**, and the group is "caught" by a
cross-origin assertion. Deleting every rebinding test would have left `--only console` green. The
repository's only pin on its DNS-rebinding defence had been converted into a pin on "the server
starts", and the record enumerated two mutation edits where there were three.

## The recovery truncated a file and left no copy

A record with `"original": null` — a half-finished hand edit, which the refusal itself invites —
reached `write(path, None)`. `write` opens the file `"w"` **before** the `TypeError`, so:

```
before: 'ORIGINAL SOURCE TEXT\n'
after : ''
record: still on disk, "original": null
```

No copy anywhere. That is the outcome the module's own rule exists to forbid: *"a refusal that also
throws away the original strands the file for good."* Types are checked before anything is written
now, `write` refuses a non-string before it can truncate, a path that is not a file is refused
rather than opened, and a non-integer owner is not a process.

## And two messages that contradicted each other

The in-flight guard said a truncated record *"holds nothing"* and to delete it; `--recover` says a
truncated record *"may still contain the only copy"* and keeps it. The guard is the message a person
hits first, and it was pointing the destructive way. It now says what `--recover` says.

`cmd_serve`'s comment claimed the escape it refuses is *"which the store refusal below tells
operators about"*. No `serve` message has ever mentioned it. The people passing it came from
`cmd_run`'s refusal, from `README.md`, and from `run --assignment-store`'s help — all three say where
it works now.
