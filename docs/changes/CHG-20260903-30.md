## The defect CHG-20260828-25 found, in its own words

`sandbox.py`, inside `_seatbelt`:

```python
lines.append(f'(allow file-write* (subpath "{root}"))')
...
return [tool, "-p", " ".join(lines), *argv]
```

`root` is `os.path.abspath(workspace or os.getcwd())`, interpolated into an sbpl string literal with
**no escaping**, and the assembled profile is handed to `sandbox-exec -p`. macOS paths may contain
`"`. A path that does turns a policy into a broken one — and a path chosen to do so turns it into a
**different** one:

```
root = /tmp/x") (allow network*) (allow file-write* (subpath "/
```

renders a profile that allows the network the grade denied.

**Refused, not encoded**, because sbpl has no escape for `"` inside a string literal and because
that is what this module's neighbour already does with a value it cannot implement. Measured after
the fix:

```
the crafted path              -> SandboxError, naming the character
/tmp/a b/c                    -> ok
/tmp/中文/專案                 -> ok        <- the false-stop guard: ordinary paths must survive
/tmp/o'brien                  -> ok
/tmp/x(y)                     -> ok
bwrap, the same crafted path  -> accepted unchanged
```

That last line is the asymmetry CHG-20260828-25 named and nothing said: `_bwrap` passes `root` as an
**argv element**, where quoting does not arise. The two mechanisms differ not only in what they
enforce but in **which inputs they can represent at all**, and a path legal for one is a refusal for
the other.

## L-36 — and the seat's finding is half right, which matters

The report was that *"both wrappers grant `/tmp` writes under `write: none`"*. Measured, they are
not the same thing:

```
_bwrap      --tmpfs /tmp                                a PRIVATE tmpfs. The host's /tmp is
                                                        neither visible nor writable. Containment.
_seatbelt   (allow file-write* (subpath "/tmp"))        the HOST's /tmp, shared with everything
                                                        else on the machine. A real grant.
```

Both are unconditional, including at `write: none` — the scope `policy` describes as the one a
verifier gets *"so it cannot fix while verifying"*. **The seatbelt one is the real finding.**

**Not narrowed here, and the reason is stated rather than implied.** Denying `/tmp` outright would
refuse `npm`, `pip` and every compiler; scoping it to a per-run directory needs `TMPDIR` plumbed
into the child's environment, which is its own change. What is fixed is that the module stops
describing a boundary it does not draw:

- `_bwrap`'s *"Read-only everywhere"* becomes what the argv is — the host read-only, a private
  tmpfs at `/tmp`.
- `_seatbelt`'s *"generated from the same policy … no second document to drift"* now names its one
  exception, because otherwise that sentence is false.

## What is NOT claimed

Carried from CHG-20260828-25, because all three still hold:

- **That this is exploitable today.** `root` comes from the operator's `--workspace` or `cwd`. An
  operator who wants a wider sandbox can pass a flag. What this fixes is a boundary that stops being
  one if that ever stops being true — a policy alterable by a filename is not a policy.
- **That refusing is better than encoding.** It is the answer consistent with this module's
  neighbour. If someone finds a representation sbpl accepts for every path, that is a better fix and
  this record should be argued with rather than followed.
- **That the blocklist is a proof.** Whether sbpl has other metacharacters inside `subpath` was
  not established by anyone who wrote it down, and the check names the character it met rather
  than saying *"invalid path"* so a later reader can see how narrow it is.

**Deviating from the record it adopts, and saying so:** CHG-20260828-25 proposed refusing `\`
as well. Measured, that refuses a path this suite legitimately produces — `wrap` computes
`root` with `os.path.abspath`, which uses the **host's** separators no matter what `system=`
says, so `workspace="/w"` becomes a backslashed path on Windows and
`test_the_macos_profile_is_generated_from_the_same_policy` stops being runnable. A blocklist
that fires on a legal path is the trade this repository has a record about, so only `"` is
refused: it is the character that provably ends the literal, and the rest was speculative in
the record that proposed it.

Added by this record:

- **That the sbpl claim was verified on macOS.** It was not: this ran on Windows, and the assertion
  that sbpl has no escape for `"` is CHG-20260828-25's. Refusing is safe either way — if an escape
  does exist, this is merely stricter than it needs to be — and that is the only reason it is
  shipped without the platform to check it on.

## Risk & rollback

- **Task 1 turns some paths into refusals** that currently produce a broken profile. Both fail; this
  one fails with a reason, before anything starts.
- **Task 5 is the false-stop guard** and is the half that can go wrong: the fix must not refuse a
  path with a space or a CJK component. Measured above, on four shapes.
- **The `/tmp` grant is unchanged**, so nothing about what a `write: none` run can actually do
  moves. Only the description does. That is a smaller fix than the finding asks for and the record
  says so where a reader will see it.
- **`#99`'s two records are not adopted.** `CHG-20260828-04` and `-05` propose a conformance suite
  for the sandbox mechanisms — which is what would have caught both halves of this record — and
  they are still `Proposed`. Named here rather than quietly left: they are the natural successor to
  this change, and this record does not build them.
- **A gap in CHG-20260903-26's own lint, found by using it.** Its three checks all start at a
  `Supersedes:`, so a `Superseded by:` naming a record that does not exist was invisible — the
  same asymmetry that record was written to close, one field further in. Closed here as task 8b
  because this is the change that first wrote a back-pointer by hand.
- Rollback: revert. A filename can rewrite the policy again and the two docstrings overstate again.
