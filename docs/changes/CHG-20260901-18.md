## One root, three surfaces

The three are one fact: **the grade a panel decides reached nothing that names it.**

| | the declaration | what it reached |
|---|---|---|
| D-1 | `_Process.risk` — *"Derived from **the grade in force**"* | the plan's proposal, bound once |
| D-2 | `Node.settles_risk` | only a node with >1 model configured |
| D-3 | `SCHEMAS.md`'s `closed` turn — `state · at_node · why · risk · change_class` | no `risk` key at all |

## D-1 — a process bounded at the plan's proposal, told it is at the grade in force

`policy.sandbox_for(risk, can_write)` takes two arguments. `can_write` is a property of the **role**
and is wired per ask, with a test — `test_the_dispatched_process_gets_the_roles_capability_not_a_guess`,
written because an earlier version looked at the seat name and *"the table was right and the promise
was still not kept."*

`risk` was bound **once**, at factory construction, from `cfg.risk`. `cmd_run` says what `cfg.risk`
is, in as many words: *"`risk` is the plan's **proposal**"*. `_Process.risk`'s docstring says the
opposite: *"Derived from **the grade in force** and narrowed by the role's `can_write`."*
`engine._grade_in_force` is the function literally named that, and nothing called it from the
dispatch path.

Measured by the seat — a plan proposing `low` whose grading panel unanimously answers `high`:

```
cfg.risk (the plan's proposal)   : low
report.risk_agreed               : high
_grade_in_force at `merge`       : high

_Process(role='engineer').risk = 'low'  -> {'write': 'workspace', 'network': True}
```

**The same ask carried `policy_verdict.risk = "high"` in its work order while running in a `low`
sandbox.** All three shipped example plans declare `risk: low`, so this is the default case.

### The fix, and why it needed no new parameter

The grade is **already in the order**: `workorder.render` puts the resolved verdict in
`policy_verdict`, and that verdict was resolved at `_grade_in_force`. So `_ask` reads it off the
order it is already holding and hands it to `_open`, which passes it the same *ask-if-you-want-it*
way `role` and `workspace` are passed — a factory written before this change is unaffected.

Zero new parameters and zero changed call sites. And the two values that disagreed are now the same
value, which is the whole defect stated as a fix. Measured over a full walk: **0 asks where the
sandbox grade differs from the grade the order states**.

## D-2 — the ratifier only ratified when it was a panel

`report.risk_settled` was written at exactly one line, inside:

```
walk                                          engine.py:1687
  for _ in range(cfg.max_steps)               engine.py:1836
    if node.role                              engine.py:1972
      if node.mode == MODEL_PANEL and len(configured) > 1     engine.py:1975
        if node.settles_risk and outcome == PASS              engine.py:2075
          report.risk_settled = ...                           engine.py:2084
```

`pm_signoff` is the only `settles_risk` node. A default install has `node_models = {}`, so it takes
the single-ask path and **the grade is never settled at all**. Measured:

```
default install (node_models={}), risk=low    risk_settled = None      <- before
                                              risk_settled = 'low'     <- after
```

`_grade_in_force`'s entire per-workstream branch is guarded on `if not settled`, so **CHG-20260827-18
was dead code on a default install** — every node read one strictest scalar, the exact shape that
change replaced. Its docstring's promise — *"Once the grade is settled the settled grade is used,
including where it is lower than a candidate. Signing off is what makes it the answer"* — never
happened. Two tests assign `report.risk_settled` on a hand-built report; none drove a walk to it.

### Moved to where the two paths meet, and keyed on the answer

The settling now sits at the branch-taking site, where `choice` is the node's answer **however it was
reached** — panel outcome, `answer_decides`, or a supplied decision. Keyed on the answer, never on
the mode: the mode is *how* the answer was produced and the settling is about *what it says*.

**One thing this change nearly got wrong, recorded because it is the same defect class.** The first
version compared `choice == policy.PASS`. `pm_signoff` offers `yes`/`no`; `pass` is what a *panel*
answers, and `panel_branches` is the translation. Writing the literal `"yes"` would have been a
branch name standing in for a constraint — what `graph.py` names as a defect class — so the
ratifying branch is read off the node's own declaration:

```python
ratified = node.panel_branches.get(policy.PASS, policy.PASS)
```

## D-3 — the durable record dropped the grade

`SCHEMAS.md` declares the `closed` turn as `state · at_node · why · risk · change_class`.
`engine.walk` passes `risk=report.risk_settled`, and `conversations.close` drops falsy values. With
D-2, that is `None` on every default install:

```
{"at": …, "at_node": "done", "change_class": "nothing was declared",
 "kind": "closed", "seq": 56, "state": "finished", "why": "…"}
'risk' in closing turn: False
```

`change_class` sits right beside it, which is what makes the omission read as *"this run had no
grade"* rather than *"this field is unwired"*. Same root as D-2; no separate fix, and named here
because it is its own declaration and its own surface — the one `close`'s docstring calls out: *"A
governance record that keeps every question and loses the reason the run stopped has kept the least
important half."*

## Risk & rollback

- **Every dispatched process on a run whose panel raises the grade is now more tightly bounded.**
  That is the fix. A run that used to write to the workspace at a settled `high` now gets
  `{'write': 'none', 'network': False}` — work that previously succeeded can now fail, and it will
  look like a regression to whoever hits it first.
- **A settled grade may also be *lower* than the plan proposed**, and then the sandbox widens. That
  is CHG-20260827-18's stated intent — *"being signed off is what makes it the answer"* — and it is
  a widening this change makes reachable for the first time.
- **`_grade_in_force`'s per-workstream branch runs for the first time on default installs.** It has
  tests, but they built the report by hand; this is its first exercise through a real walk, and a
  node in a `low` workstream will now be graded `low` where it was graded at the strictest candidate.
- **The closing turn gains a key.** Anything parsing conversation exports and treating `risk` as
  absent-means-ungraded will now see a grade. `SCHEMAS.md` has declared it all along.
- **The mutation anchor moved for the third time.** Its own comment argues that the staleness check
  is the reason this keeps being caught rather than remembered; it caught it here too, same day.
- Rollback: revert. Each of the three is independent, though D-3 has no fix of its own.
