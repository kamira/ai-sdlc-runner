## The gap

`CHG-20260827-20` guard 5: *"Emergency runs are marked and queued for review; nothing marks itself
emergency."*

**Marked** was done. `emergency` is reachable only from the command line, `plan.check` refuses the
key, and every run records the class it used.

**Queued** was not, and the record said so plainly rather than ticking the task. `policy.ChangeClass`
carries `reviewed_after=True` for `emergency` and nothing anywhere reads it. An emergency run
relaxes `confirm` to `auto` — a person who would have been asked was not — on the promise that
somebody looks afterwards, and nothing in this runner has ever asked anybody to look.

**A promise nobody is reminded of is not a promise.** It is the same shape as the defect
CHG-20260828-17 found in the ledger: an obligation recorded in a place no reader is sent to.

## The design

**The queue is derived, not stored.** An emergency run is already in the conversation record — its
`CLOSED` turn carries the class that was in force. A second list of outstanding reviews would be a
second source of truth about the same fact, and this repository spent CHG-20260828-17 on what
happens when two readers of the same files disagree. So `runner emergencies` is a **view**: it walks
the store and reports the runs that relaxed a gate under `emergency` and have no review turn.

**A review is a turn in the conversation it reviews.** Not a separate file. The record of the run
and the record of somebody having looked at it belong in one place, in order, for the same reason
every other governance act is a turn.

**Nothing marks itself reviewed.** The axiom that made `emergency` operator-only applies unchanged to
closing one: an answer that could record its own review would be a model granting itself an
exemption *and then signing off on it*. The review is reachable only from the command line, it must
name a person, and no work order carries a key that reaches it.

**Something has to be shown the queue.** A queue nobody reads is the original defect one step
further in. So `runner run` reports what is outstanding when it finishes — the next run tells you
about the last one that was let through.

## Risk & rollback

- This adds a way to record a governance act. The failure that matters is a **false close** — a run
  marked reviewed by something that is not a person — so tasks 3, 4 and 6 are the ones that carry
  the risk, and each is pinned separately.
- It cannot make a run stop less often: the class machinery is untouched. It can only add a report
  and a turn.
- Rollback: drop the subcommand and the turn kind. Emergency runs go back to being marked and
  unchased.

### Not claimed

**That a review happened because a turn says so.** This records that somebody claimed to have
looked, with their name on it, and makes the absence of that claim visible. It cannot tell a real
review from a rubber stamp — the same limit `class_in_force` already states about renewal: *"a class
renewed without thought is a rubber stamp with a calendar."*
