## Measured before, measured after

`_already_there` called `into.conversations()` for **every source conversation**. On a SQLite target
that is a SELECT over a growing table; on a **file** target it re-opens and re-parses the first line
of every file in the store, every time.

File target, importing N conversations:

| conversations | before | ms each | after | ms each |
|---:|---:|---:|---:|---:|
| 100 | 3.86 s | 38.6 | 0.93 s | 9.3 |
| 200 | 11.43 s | 57.1 | 1.29 s | 6.5 |
| 400 | **43.40 s** | **108.5** | **2.80 s** | **7.0** |
| growth per doubling | **3.80×** | | **2.17×** | |

4.00× is quadratic; 2.00× is linear. The per-conversation cost stopped climbing, which is the part
that matters: before, every conversation added made every later one slower.

## What changed

The target's ids are read **once**, before the loop. A conversation in the target is read only when
its id actually collides — which is rare, and unavoidable when it happens, because deciding
"already here" honestly means comparing the turns (CHG-45's finding: id plus count is not identity).

The index is kept current as conversations are imported, so a source containing two files claiming
one id is still caught.

## Pinned by counting, not by timing

A timing assertion on a shared machine is a coin flip. Two tests wrap the target in a counter:

- twelve conversations imported ⇒ the target is listed **once**;
- nothing collides ⇒ the target is read **zero** times; everything collides ⇒ each is read exactly
  once, and the listing is still one.

Both fail against the previous implementation.

## Status


Accepted (see docs/acceptance/ACC-20260823-46.md) -- Pass. A performance change whose tests count calls rather than seconds -- the old per-conversation listing could not pass them.

### Not claimed

**That the import is now fast.** It is linear. 400 conversations into a file target still takes
under three seconds, and into SQLite about one and a half — those are the numbers, not a claim that
they are good.

**That `FileBackend.conversations()` is efficient.** It still reads the first line of every file in
the store. Calling it once makes that cost paid once instead of N times; it does not make it
cheap.

**That the remaining reads are minimal.** A genuine re-import reads every target conversation to
compare turns. That is the honest cost of not calling a count an identity, and it is linear.
