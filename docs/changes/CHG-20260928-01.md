## Why

The recent panels here were `fable` + `codex` (ACC-20260907-25, ACC-20260906-03) — practice, not a
directive. DIR-1 is the directive, and what it set is the fallback: two `fable` and two `opus` seats
when `codex` could not be reached. In this session `codex` was logged in with a ChatGPT
account (device-code login, after the environment's network policy allowed `auth.openai.com` and
`chatgpt.com`), and its model catalog listed `gpt-6-astra` first. The user then set the panel:

> 審議席設定為 fable (effort medium) / opus (effort medium) / gpt-6-astra (effort medium)

Asked whether that meant this repo's review panel or the runner's own seat routing (`seat_models`
over `conformance` / `defect` / `risk`), the user chose **this repo's review panel**. The runner is
not touched.

## Interpreted, and what it was chosen over

- **No fallback.** DIR-1's four-seat fallback is not carried into DIR-2: the user named none. An
  unreachable seat stops the review and asks the user, rather than proceeding on two seats or
  substituting an engine. Chosen over keeping DIR-1's fallback, which would be a rule the user did
  not give for a panel the user replaced.
- **Versions are not pinned.** The user said `fable` and `opus`; DIR-2 records the ids used today
  (`claude-fable-5-1`, `claude-opus-5-5`) as how the seats were invoked, not as a requirement.
  Chosen over pinning, which would make the next release of either family a rule change.
  (Raised as blocking by the `gpt-6-astra` seat in the design review.)
- **Seats are read-only, and can read the repo.** `--tools "Read,Grep,Glob"` for the two `claude`
  seats, run from the repo root, brief on stdin; `-C <repo> -s read-only` for `codex`. Round 2 of
  the acceptance ran the `claude` seats from another directory, and both were refused every read. The first version said `--allowedTools`, which does not restrict
  anything — see acceptance round 1 in ACC-20260928-01.
- **The record names the panel.** DIR-1 asked the record to say `codex` was absent and why; DIR-2
  asks it to name all three engines and the effort. Chosen as the same idea for a full panel.
- **`gpt-6-astra` goes through `codex`.** The only access to it here is the logged-in `codex` CLI;
  effort maps to its `model_reasoning_effort` setting.

records `"model":"gpt-6-astra"` and `"effort":"medium"`. That shows the setting left the client; it
does not by itself show the backend applied it, and nothing here measures that. The two `claude`
calls leave no log in this container. These are container-local and go when it does.

Each seat's restriction, measured with the DIR-2 command line, asked to read a repo file and then
to create `probe-written.txt` in the repo:


line as `opus` with another `--model`, and was not probed separately.
