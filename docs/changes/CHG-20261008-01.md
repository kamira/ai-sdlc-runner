- Project: ai-sdlc-runner
- Branch: ccr-b4f701af-6yuu94

- Type: governance (DIR-3 amended) and `tools/panel.py` / `config/panel.json`; nothing in `src/`
- Proposed by: the user, 2026-10-08
- Risk: **medium**. It replaces DIR-2's "an unreachable seat stops and asks" with a substitute engine
  for one seat, decided before the round. A wrong availability reading would put sonnet on a seat
  codex could have taken. That is visible in the report, and undone by reverting.

## Why

The user, verbatim:

> codex 不可用時採取 fable + sonnet + opus
> 可用時優先採用codex 取代sonnet

Asked when codex counts as unavailable, the user chose **before each round**. Asked whether the
CHG 2 review should use it, the user chose **now**: this change first, then CHG 2 with whichever
panel this rule picks. The review scheduled for 2026-10-12, which was waiting for the codex quota,
is cancelled.

## What changes

1. **`config/panel.json`.**
   - The `gpt-6-astra` engine gains a `substitute`: a full engine entry, `sonnet`
     (`claude-sonnet-5-5`, effort `medium`, the same read-only `claude` invocation as `fable` and
     `opus`).
   - It also gains an availability rule: `min_remaining_percent` (10).
2. **`tools/panel.py run`, before the round.**
   - For each engine that has a substitute, it checks whether that engine can be used. For a
     `codex` engine, that means `codex login status` succeeds, and the latest quota reading on this
     machine shows every window at or above `min_remaining_percent`, or the window has reset since
     the reading.
   - If the engine cannot be used, the substitute takes its seat for the whole round.
   - The matrix, the report and the cross-read use the substitute's id.
   - The report states which engine was replaced and why.
   - `--brief-for` naming the replaced engine does not apply to the substitute, which gets the main
     brief. The codex-increment amendment was made for codex.
   - A `--resume` keeps the resumed round's panel decision and does not check again.
3. **Mid-round exhaustion is unchanged.** A codex cell that becomes unreachable during the round is
   unreached, and the round is incomplete and asks, as DIR-2 says.
4. **DIR-3** gains the amendment and its INDEX row says so. DIR-2's INDEX note "no fallback panel"
   is marked superseded by this amendment.

## Interpreted, and what it was chosen over

- **"不可用" is decided once, before the round, from local facts:** the login and the quota windows
  codex last wrote on this machine. A missing reading counts as usable, and the round finds out.
  - Chosen over a live probe call, which would spend quota to learn about quota.
  - Chosen over swapping engines mid-round, which the user declined.
- **The threshold is 10% remaining in any window.** It is a guess at what one round needs, kept in
  `config/panel.json` for the user to change. A lower bar risks rounds that stop mid-way. A higher
  one gives codex's seat to sonnet more often.
- **The newest session log is read for its quota only.** The log may belong to another codex
  session on this machine, which is acceptable for an account-wide quota. Only `rate_limits` and
  its timestamp are kept.
- **sonnet both writes the code (DIR-3) and, on fallback, reviews it.** The user named this panel,
  and fable and opus still sit on every cell. The report says when the coder's model is also a
  seat, so it is never silent.

## Round 1 — on `15139b1`

The panel was picked by this change's own check: codex's weekly window had 2% remaining, so
`sonnet` sat in its seat (fable, opus and sonnet, 12 dimensions, 72 cells, all reached, $50.84). The
result was **fail**: CI and portability failed on all three seats, defect on sonnet, docs on opus.

| finding | seats | fix |
|---|---|---|
| the fake `codex` in the new tests is an extensionless `#!` file, which Windows cannot run, so every "usable" case read as unusable (CI agreed: both Windows cells red) | all three, CI and portability | on Windows the fake is `codex.cmd` calling a script (`c915dc9`); the repo-planted test uses the same helper, so on Windows it no longer passes by accident |
| a `--resume` after codex ran out mid-round re-checked availability, swapped in `sonnet` and was refused as a different matrix | sonnet, defect | a resume keeps the resumed round's panel and does not check again |
| DIR-2's body still said "no fallback panel" | opus, docs (fable and sonnet rated it blocking in the cross-read) | DIR-2 carries a "partly superseded, 2026-10-08" note |

Found by CI after the round, on windows py3.9: a resume test from CHG-20260929-01 counted 5 cross-reads
for 6, failing twice in a row. The fake seats appended to one shared log, and two processes
appending at once on Windows can lose a line. Each invocation now writes its own file.

## Round 3 — on `5873221`

Same panel, chosen by the same check: `sonnet` in the codex seat, codex's weekly window at 2%. All 72
cells were reached, and 71 passed ($55.08).

| finding | seats | fix |
|---|---|---|
| the login check's timeout is not honoured on Windows through a `.cmd` shim: `subprocess.run` kills cmd.exe on timeout but not the codex under it, which still holds the pipes, so `communicate()` blocks past `LOGIN_TIMEOUT` (blocking, portability) | fable; opus agreed in the cross-read; sonnet rated it follow-up | the check runs through `_run_process`, which reads with its own threads and kills the process tree; it gets a `_Fleet` of the reviewed repo, so PATH still loses the repo. The check's directory is made with `mkdtemp` and removed with `rmtree(ignore_errors=True)`: on Windows a codex still exiting can block the delete, and cleanup must never turn "timed out" into "could not run" (found reading the fix, not by a seat) |
