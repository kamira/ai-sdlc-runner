# CHG-20260823-48 — `agent_command` means a different thing in each shipped example

- Project: ai-sdlc-runner
- Branch: claude/chg-20260823-48-agent-cwd
- Date: 2026-08-27 (UTC+0)
- Type: one correctness fix, plus the three examples it makes consistent
- Proposed by: the user — *「把 agent.py 相對 cwd 那個 bug 開成 CHG-48」*, on a failure hit while
  driving the console for CHG-20260823-47
- Risk: **medium** — it changes where a configured command is run from. Anyone with an existing
  `runner.yaml` whose paths are written relative to *their* shell's directory is affected. Medium
  rather than high because the break is loud: `can't open file`, at the first ask. The defect being
  fixed was the quiet one.
- Autonomy: high
- Related: CHG-20260823-47 (found while starting the server for its recording)

## How it was found

Not by the suite. By starting the server to record an actual operation, because the operator asked
why a change was called recorded when nothing had been run:

```
runner --config examples/weather-spa/runner.yaml serve --plan examples/weather-spa/plan.json
```

```
CliError: 'python3' failed 1 time(s) answering 'intake_review'; giving up. Last failure:
'python3' exited 2 answering 'intake_review': python3: can't open file
'...\ai-sdlc-handshake-a967df\agent.py': [Errno 2] No such file or directory
```

## What is actually wrong

`agent_command` is used verbatim as argv (`cli.py:178`), so a relative path in it resolves against
**the shell's working directory** — not against the config file that contains it. That is never
stated anywhere, and the three shipped examples do not agree on which directory they mean:

| example | `agent_command` | relative to | runs from repo root? |
|---|---|---|---|
| `examples/minimal` | `["python3", "examples/minimal/agent.py"]` | the repo root | **yes** |
| `examples/tide-spa` | `["python3", "agent.py"]` | the example directory | **no** |
| `examples/weather-spa` | `["python3", "agent.py"]` | the example directory | **no** |

Two conventions, one field, nothing documenting either. Both were run to confirm:

```
$ runner --config examples/minimal/runner.yaml run --plan examples/minimal/plan.json --risk low --confirm merge
state:         finished                      # 20 nodes, 17 asks

$ runner --config examples/tide-spa/runner.yaml run --plan examples/tide-spa/plan.json --risk low
halted: 'python3' exited 2 answering 'intake_review': can't open file '...\agent.py'
```

The first of those two commands is **README.md:458**, verbatim. It works only because
`examples/minimal` happens to use the other convention. Neither `examples/tide-spa/README.md` nor
`examples/weather-spa/README.md` says to `cd` first.

## Why no test caught it

`tests/test_example_weather_spa.py:163` copies `agent.py` into `tmp_path` and runs it with
`cwd=str(tmp_path)` — and invokes the agent **directly**, `[sys.executable, str(tmp_path /
"agent.py")]`, never through `runner --config`. So the test performs the `cd` the documentation
omits, and never exercises `agent_command` resolution at all.

That is this project's most-recorded shape: a test that arranges the exact conditions under which
the defect cannot appear, and then reports the thing as covered.

## It had already written into the repository

The record above was written before anything was run. Running it found the other half.

`examples/minimal/agent.py:43` does `pathlib.Path("greet.py").write_text(...)` — relative to the
working directory. So the one example that *worked* from the repository root worked by writing its
build output **into the repository**. A copy of it was committed:

```
$ git log --oneline -1 -- greet.py
2f7973b feat: every conversation stored by project, and exportable (CHG-20260823-17) (#49)
```

Byte-for-byte the string on line 43. It sat in the repository root for thirty changes.

A review seat did see it — `docs/design/reviews/conversation-store-round2-fable-seat.md:13` notes
`greet.py` among "untracked files" from "a concurrent process" and moves on. It was not a concurrent
process; it was this. The observation was correct and the explanation was wrong, and nobody followed
it.

So the failure had two faces, and only one of them was loud:

| | |
|---|---|
| `tide-spa`, `weather-spa` | halt at the first ask — **loud**, and the reason this was found at all |
| `minimal` | run fine, writing into whatever directory you were standing in — **silent**, for thirty changes |

The loud one is what got reported. The silent one is what actually did damage.

## Proposed fix

**Not** "resolve the path in `agent_command` relative to the config file". `agent_command` is an
argv list, and deciding which element is a path means guessing — `agent.py` from a flag, a bare
program name from a script. A heuristic there would be a name standing in for a constraint, which
is the defect class this log names most often.

Instead: **run the agent with its working directory set to the config file's directory**, and make
that explicit.

1. An `agent_cwd` key in `runner.yaml`, defaulting to **the directory the config file is in**. Every
   relative path in `agent_command` then means one thing regardless of where the operator stands.
2. `examples/minimal/runner.yaml` changes to `["python3", "agent.py"]` so all three agree.
   README.md:458 keeps working, for a different reason than before.
3. Each example README states the directory it runs from, because a default is not documentation.
4. A test that runs each shipped example **through the real CLI from the repo root**, which is the
   test that does not currently exist.

### What this breaks

An existing `runner.yaml` whose `agent_command` path is written relative to the operator's shell
rather than to the config file. That configuration stops working, loudly, at the first ask. It has
to: the two meanings cannot both be honoured, and the current behaviour is the one nothing
documents.

## The test's first draft was wrong in the way this project keeps being wrong

Draft one ran each example from the repository root and claimed all three failed against the unfixed
code. **`minimal` passed** — and passed for a worse reason than failing: its path
`examples/minimal/agent.py` resolved from the root to the **original example still in the
repository**, so the copy under test never ran its own agent and nothing noticed.

A second working directory — an unrelated empty one — removes the coincidence. All three fail there.

Then `test_a_shipped_example_writes_only_inside_itself` passed against the unfixed code too, which
would have made it a test that cannot fail. The reason was the fossil: `greet.py` was **already in
the repository root**, so "what appeared during the run" was empty. Deleting the committed artefact
is what gave that test teeth:

```
AssertionError: running minimal from the repo root created ['greet.py'] in the repository.
The agent ran in the operator's directory instead of its own.
```

Both were caught by running the tests against the previous commit rather than by writing them
carefully. That check is now the habit CHG-20260823-47 shipped `tools/mutation_check.py` for.

### Not claimed

**That `agent_command` is the only field with this problem.** `--plan`, `--ask-journal`,
`--store-root` and `--token-dir` are all paths, and nothing here has checked whether each one means
what it should relative to the config that named it. Task 1 fixes one field; it does not survey the
rest, and a survey is the honest next question.

**That failing loudly makes the break safe.** It makes it *visible*. An operator whose overnight run
halts at the first ask has still lost the run.

**That `greet.py` was the only thing written into somebody's working directory.** It is the only one
in *this* repository. Any `agent.py` anywhere that writes a relative path has been doing the same
thing, and this change silently relocates its output to beside the config. That is the intended
behaviour and it is still a relocation nobody asked for on the day they upgrade.

**That the example run is idempotent.** Running `weather-spa` twice with `site/` already populated
made the walk cycle to `walk exceeded 200 steps — the flow is cycling without progress` rather than
recognising there was nothing to build. Reproduced while verifying this change; out of scope, not
fixed, and not filed as its own record yet.
