## Read this first

`drawDecisions` renders **every** adjudication a run made. The *"Waiting for you"* box - the one
being read when the decision is actually taken - renders `reason`, a button, and nothing else. Two
blocks apart, on the same page.

`CHG-20260903-24` proposed closing that gap by showing `report.adjudications[-1]`, and was withdrawn
partly over it. `[-1]` is whichever adjudication happened **last**, which is not the same thing as
the one belonging to this stop. Driven, on a **default install** with no model configured anywhere:

```
merge@low, node_models = {}   stop = merge      adjudications[-1] = lead_review -> pass
                                                                    | 3/3 seats passed
```

`lead_review` is a `graph.SEAT_PANEL`, so `_adjudicate` appends its entry regardless of
`node_models`. The one-way door would have been pre-answered with the code review panel's verdict
on built work, on every default install, unconditionally.

## So it is bound to the node, and the binding is not in the browser

`snapshot()` gains `adjudication_here`: the last adjudication whose `node_id` is the stopping node,
or `null`. The rule lives in `server.py` rather than in the page because **the page cannot be
executed here** - there is no JavaScript runtime in this repository, and every console guard is a
text search over the HTML. A rule that reads plausible and measures wrong is exactly what this
record exists to correct; putting it where it can be driven is the point.

`panel_rounds` exists, so a node can adjudicate more than once. What a person is shown is the last
one - what the panel settled on, not its first attempt.
