## Two holes, from opposite directions

### codex-seat: vouching for an interpreter vouches for everything

```
rm important-backups.tar
python -c "__import__('pathlib').Path('customers.db').unlink()"
```

Both ordinary, both to `done`, under the **default** safe setting, because somebody had vouched for
`python` and `rm`.

The flaw is in the premise I chose. "The operator knows their toolchain" is true. What I built on it
was not: I treated every command *name* as if it constrained what happens. For `pytest` it does. For
`python` it does not — the name is an execution engine and the argument is the program. **Vouching
for one is not a declaration; it is a blank cheque wearing a declaration's clothes.**

`policy.EXECUTORS` — interpreters, shells, `rm`, `mv`, `dd`, `curl`, `xargs`, `ssh`, `sudo`, plus
the stdlib modules that are themselves execution engines — can never be `ordinary`, and
`settings.load` **refuses to accept one**, so the operator finds out while configuring rather than
while it matters. The common case survives through *shape*: `python -m pytest` is ordinary because
**pytest** is vouched, never because `python` is.

### fable-seat: the argument guard matched flags, not verbs

```
docker volume rm pgdata          # `docker` vouched → ordinary → done, on_trust EMPTY
git push origin +main:main       # `git` vouched   → ordinary → done, on_trust EMPTY
```

Neither stopped nor recorded — because a "recognised" target suppresses `on_trust`, so the safety
net had a hole shaped like the thing it was there to catch. **KN-11 violated at the vouching layer,
in a design that had already fixed it once at the target layer.**

And the same list was stopping `cargo build --release` and `docker compose up -d` on benign flags.
Too loose and too tight at once, for the third time, and for the same underlying reason: it was
matching the wrong thing. A destructive **verb in subcommand position** is a statement about what
the command does; the same letters in a flag value are not.

`_suspect` now matches verbs positionally (`rm`, `remove`, `stop`, `clean`, `prune`, `drop`,
`publish`, `deploy`, `release`) plus a short list of dangerous forms (`--force`, `--hard`,
`+refspec`, `-rf`). `push` is deliberately absent — an ordinary push is how work ships, and its
destructive forms are caught as forms.

## What this costs, stated rather than buried

**Executor commands now stop, and some of them are ordinary work.**
`python scripts/build_docs.py`, `node index.js`, `curl localhost:8000/health` are real development
commands and they are `unrecognised`. Not because they are dangerous — usually they are not — but
because the name cannot tell you, and trusting it anyway is what produced this round's findings.

The operator's options are to declare the operation's kind on that piece of work, or to use the
`python -m <tool>` form. `tests/test_targets.py::EXECUTOR_COMMANDS` pins the list so the cost is
counted rather than discovered.

## The numbers check, checked

Both seats went after `tests/test_documented_numbers.py` itself, and both were right:

- it did not scan `src/`, where `policy.py`'s own docstring still said "36 real briefs";
- it did not scan `docs/knowledge/`;
- its tripwire asked whether **any** document contained a node count, so a whole category could
  vanish from every file while the guard stayed green — *"nothing matched = all fine"*, the exact
  defect it exists to prevent, in the guard that prevents it.

Now: source and the knowledge base are scanned, each category is asserted present **by name**, and
role/seat/asking-node counts are checked too. `docs/changes/` and `docs/acceptance/` stay out on
purpose — a change record states what was true when it was written, and rewriting history to match
the present is how a ledger stops being one. The same distinction applies inside `knowledge.md`,
where "19 of 20 briefs were stopped" is a past measurement: only present-tense claims are compared.
