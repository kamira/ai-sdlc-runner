## Read this first

Four guards, each written this session to close a defect, each walked past by something the
defect's own shape suggests.

### L-45 - the prose strip is line-based, and one token of placement re-arms it

`CHG-20260904-11` shipped `_console_code()` because a guard searching the whole page was satisfied
by the comment above the code. It strips lines whose first token is `//`. Moving the same words to
the end of the same line restores the defect exactly:

```
var here = null;   // was state.adjudication_here - restore after the redesign
```

Measured: **109 passed**. The page already uses trailing comments — `body.version = state.version;
// what stops two tabs from both being right` — so this is the file's own idiom, not a contrivance.

### L-46 - the sibling guard still reads prose, and `-11` said in writing that it does not

`test_every_key_the_server_sends_reaches_the_console` reads `page = _console()`, not
`_console_code()` — the helper written 110 lines below it, in the same change, for this exact
failure. `-11`'s Risk section says that guard *"requires the page to render it"*. It requires the
token to **appear**, comments included, and `-11` shipped a comment naming `adjudication_here` two
lines above the read.

### L-47 - the decision rule intersects with the two names today's methods happen to use

`taken & {"gate", "node_id"}`. A fourth decision method naming its stop anything else empties the
intersection, and `all(...)` over an empty set is `True` — so the rule collapses to `bool(calls)`,
which is the vacuity the comment directly above it says was closed.

Re-measured, and the seat's account moves: the floor `test_the_rule_looks_at_the_three_methods
_that_exist` **does** fire on a fourth method, along with `test_only_attach_reaches_advance
_without_a_state_gate` — 2 failed. So a fourth method is not silently accepted. What is true is
sharper and worse: the floor's remedy is *"this floor is the place to say so"*, i.e. add the method
to its set — **and after that the real rule passes over a method that checks nothing.** The names
are now read from `_answering`'s own signature rather than written twice.

### L-44 - the seat's measurement holds and its explanation does not

The seat reported that `adjudication_here` is `None` at every stop of a default install *"including
`lead_review` — the seats have already voted"*. Measured, they have not:

```
engine.walk   stop = _gate("after")            returns the suspension
              elif node.mode == graph.SEAT_PANEL:  _adjudicate(...)   43 lines later
```

A `SEAT_PANEL` adjudicates **after** its own gate, so `None` at `lead_review` is correct — there is
nothing to show at that moment. The measurement is right and there is no behaviour defect.

**The gap is in the guards.** `-11`'s only *driven* test asserts `_adjudication_for(report) is
None` and treats that as success. The two non-null tests hand-build a report no walk produces. So
task 4 — *the box renders it* — was exercised by nothing driven. It is now, and the record says
plainly what a default install gets: at `plan_confirmed@medium` with panels, `('pm_confirm',
'pass')`; with `node_models = {}`, nothing at any stop.

### L-48 - `docs/API.md` §4 is false about a second field, in the block `-10` corrected

`reason` sits under `// meaningful when \`undecided\` — the tie`. Driven at an incomplete stop:

```
incomplete = True   undecided = False
reason     = "The requirement does not say: the architecture - what the pieces are ..."
verdicts   = {}
```

It is meaningful for **two** of the three questions, and the incomplete one is where the console
takes its only ask text. That is the field `CHG-20260904-07` moved earlier in the walk *so that the
shape could carry it*. `-10`'s guards check the count and the phrase; neither asks which question a
field is meaningful for.
