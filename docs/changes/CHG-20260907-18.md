## The finding

`graph.py` says it twice:

```
SINGLE = "single"          #: exactly one model, one session
… a `SINGLE` with three configured is a configuration error, not a panel.
```

`README.md`'s mode table says `single | exactly one model | 1`. And
`tests/test_panel_and_pool.py`'s own docstring says *"Three models there is a configuration error,
not a panel."*

Measured, nothing required it:

```
plan.check, pm_plan   1 model ACCEPTED   2 ACCEPTED   3 ACCEPTED
the engine, three models on each SINGLE node:
    pm_plan     asked 1 time, 0 adjudications, no complaint
    qa_verify   asked 1 time, 0 adjudications, no complaint
    pr          asked 1 time, 0 adjudications, no complaint
    merge       (not reached in this run)
```

Two of the three models silently vanish. That is *"a setting that looks configured and does
nothing"* — the sentence `plan.py`'s own closed-schema rule gives as its reason for refusing an
unknown key, one screen above.

## The test that had been saying it

`test_the_mode_and_not_the_node_name_decides` opens with *"Three models there is a configuration
error, not a panel"* and its body asserted the run **proceeds**: one ask, no adjudication. The
docstring and the assertions disagreed, and the assertions were what held.

Its neighbour four lines up refuses a *panel* short of voices with `EngineError("short of a
voice")`, so the vocabulary for refusing a mis-configured node was already there — it had just
never been pointed at this.

## What ships

One rule in `plan.check`, beside the shape rule that was already there:

```python
if (key == "node_models" and owner in graph.BY_ID
        and graph.BY_ID[owner].mode == graph.SINGLE and len(value) > 1):
```

Only `SINGLE`, and only **too many**. A `MODEL_PANEL` with one model is a panel of one and
`graph.py` says so in the same paragraph; a `POOL` is a list on purpose. Measured after:

```
pm_plan        single       1 model   ACCEPTED
pm_plan        single       2 models  refused
qa_verify      single       3 models  refused
lead_review    seat_panel   3 models  ACCEPTED
engineer_build pool         3 models  ACCEPTED
```

## The blast radius, measured

A scoped AST sweep of every `node_models=` argument in `tests/` and every `examples/**/*.json`:

```
a SINGLE node given more than one model    1    test_panel_and_pool.py:197
examples/                                  none
```

That one site is the test above. It is rewritten, not removed: it now asserts the **refusal** at
`plan.check`, and then reaches around it — `_run` builds a `RunConfig` directly, which is the only
way left to put three models on a `SINGLE` node — to keep proving what its name is about, that the
engine reads the **mode** and not the node's name. The guard behind the guard, said as that.

Two mutations in `single-model`: the rule removed, and the rule widened to bite the panel and the
