## The one that undoes the previous round's verification

`ACC-20260830-06` claimed `--only stranded` 9/9 and 91/91 across twelve groups. Those numbers were
produced by an instrument that could not tell a mutated tree from an unmutated one.

`apply()` writes the real `tools/.mutation-in-flight.json`; `test_this_repository_has_no_mutation_in_flight`
asserts that file does not exist; `_pytest` runs with `-x`. So every mutation in the group stopped
the run at test nine of fifteen, and the four tests written to pin the lock never executed. Measured:

```
with a record on disk, the harness's own pytest command:
  pristine, unmutated source        1 failed, 8 passed   test_this_repository_has_no_mutation_in_flight
  MUTATED: owner check removed      1 failed, 8 passed   (the same one)
  MUTATED: end() drops any record   1 failed, 8 passed   (the same one)
```

Six of the nine `stranded` mutations had this signature. The guard was changed to skip when the
record's owner is **alive**, on the argument that it exists to catch a *killed* run's leftover and a
live owner is not that. That argument was half right, and the half it got wrong is round 4's
largest finding — see CHG-20260830-08. After the change:

```
  pristine, unmutated source        18 passed, 1 skipped   <- 17/1 as first recorded, which
                                                              was a mid-work reading taken before
                                                              the fourth test landed and never
                                                              re-taken (CHG-20260830-08)
  MUTATED: owner check removed       1 failed             test_a_second_run_does_not_recover_over_a_live_run
  MUTATED: end() drops any record    1 failed             test_a_run_does_not_drop_a_record_it_does_not_own
```

The first real run then reported **1 of 9 NOT caught** — the ordering guarantee, hidden until now
behind the false red. `apply()`'s *"record before you break"* is what the whole module rests on, and
`test_the_record_is_written_before_the_mutation_not_after` observes at `_pytest` time, when both
writes have happened in either order. Swapping the two lines left all fifteen tests green. There is
now a test that intercepts the write of the subject itself and asks what was true at that instant.

## `_alive` answered wrongly three ways

The owner check is only as good as its liveness probe, and nothing tested whether the probe was
right — `ACC-20260830-06` row 16 checked only that it does not *kill* what it asks about.

| what was shipped | what it does | found by |
|---|---|---|
| `OpenProcess` denied → `False` | a running process reads as dead, so recovery writes over its live mutated file | risk 1, defect 4, conformance |
| `GetExitCodeProcess == 259` | a process that exits with code 259 reads as alive, for ever | defect 5 |
| `GetExitCodeProcess.argtypes` unset | an untyped `HANDLE` raises `ArgumentError` out of `_alive` | conformance 7 |

Measured: `_alive(4)` — the Windows System process, certainly running — returned `False`, and
`GetLastError` was 5 (`ERROR_ACCESS_DENIED`) against 87 (`ERROR_INVALID_PARAMETER`) for a pid that
does not exist. The two are separable and were collapsed. The POSIX branch twelve lines below has
always had this right; it was the Windows branch, on the platform this module exists for, that did
not.

The fix uses `WaitForSingleObject`, which needs `SYNCHRONIZE` — and asking without it made every
live process read as dead. That regression was caught by measurement while writing this, not by
review, which is the fourth wrong answer this one function has now produced.

## The survey still passed by examining nothing

`CHG-20260830-06` gave the AST rule a floor and recorded it as closing this. The floor pinned the
**rule** and not its **reach**: pointing the glob at a suffix no file has left every test green.

```
glob("*.NOPE")  ->  8 passed, including the three that exist to keep this honest
```

Its own docstring said *"Without it the survey below passes by examining nothing"*. It still did.
There are now floors on modules read and handlers examined, which is the shape
`tests/test_subprocess_codecs.py` has had at two places all along.

Separately, the test that claimed renaming could not defeat the rule (named in plain text because
this change replaces it: test_the_rule_is_not_satisfied_by_the_name_of_the_variable) used `err` —
the second most obvious name for a caught exception. So replacing the rule with
`expr.id in ('exc', 'err')`, a keyword match by any reading, left the whole file green. It is now
parametrised over five names, `z9_caught` among them.

## Risk & rollback

- No `src/` change at all — measured, and true. The surface is `tools/mutation_recovery.py` (the
  liveness probe and one refusal message), `tools/mutation_check.py` (two registry entries and
  three comments), `tools/ledger_check.py` (one vocabulary word), two test files, ~~eight~~ **seven**
  records, `README.md`, and `.claude/launch.json` — the last two named nowhere in this record and
  outside every category it listed. Corrected in CHG-20260830-08, which untracks the stray file.
- `_alive` now answers **alive** in the denied case, so recovery refuses more often than it did.
  That is the direction to fail in: the tree stays wrong and says so, rather than being silently
  overwritten while a run is measuring it.
- The in-flight guard skipping on a live owner is a narrowing. A record whose owner is gone still
  fails it, which is the incident it was built for.
- Rollback: revert. The harness goes blind to its own `stranded` group again.
