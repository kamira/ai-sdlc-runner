## What exists today

`models.Model` has eight fields, no tier and no effort (models.py:208-223). A cli model's argv is
fixed (cli.py:437), and nothing composes arguments per call. `engineer_build` (POOL) is the only
coding node that picks a model; `fix_pass` and `engineer_selfverify` follow it. Unassigned, it falls
to `agent_command` or the stub (cli.py:443-448). There is no setup command and no detection of
installed CLIs. An `api` model cannot be dispatched (cli.py:429-436).

## What changes

1. **The registry gains two optional fields.**
   - `tier`: `high`, `mid` or `low`, or empty for unclassified.
   - `effort_argv`: an argv template containing `{effort}`.

   - `declared_reach` (round 2): optional, one of `local` / `internal` / `external`, overriding the
     reach derived from the transport. It may only raise it. `setup` sets `external` for claude and
     codex.

   A template rather than a vendor table: the runner holds no claude- or codex-specific knowledge,
   and a local model needs no code. `effort_argv` is refused on an `api` model, because nothing
   dispatches one and a field nothing reads is refused (models.py:272-275). Store schema 3 → 4.
2. **Effort reaches the process.** When an effort is in force and the model has an `effort_argv`,
   the substituted template is appended to the argv. When the model has none, the run reports that
   the effort was not applied, rather than refusing (KN-11).
3. **The coding role's default.**
   - New settings `coder_model` (registry id, default empty) and `coder_effort` (default `medium`).
   - When nothing is assigned to `engineer_build`, it gets `coder_model`, or else the registry's only
     `mid` model. This is injected after `store.resolve`, so dispatch recording is unchanged.
   - Several `mid` models with no `coder_model` is reported, not chosen at random.
   - `coder_effort` applies to `engineer_build` and the nodes that follow it.
4. **`runner setup`.**
   - It looks for `claude`, `codex` and `ollama` on absolute PATH entries, never in the working
     directory, and lists ollama's models with `ollama list`. It makes no network probe.
   - It proposes registry entries: only claude gets a tier (`mid`), codex gets an effort template,
     ollama models get neither. The user adds, edits (id, tier, effort template) or skips each, or
     nothing is written. `command[0]` is the absolute path found. Ollama models become cli wrappers (`ollama run <m>`).
   - When nothing is found, it says how to add a model by hand.
   - It assigns nothing to nodes, except setting `coder_model` if the user agrees.

## Interpreted, and what it was chosen over

- **"中階" is a label, not an inference.** The user or `setup` gives a model its tier. Chosen over a
  built-in name→tier table, which goes stale with every model release.
- **Detection is local only:** PATH lookups and `ollama list`. Chosen over probing localhost ports,
  which reaches outside the process unasked.
- **The lone-`mid` fallback.** With exactly one `mid` model and no `coder_model`, that model codes.
  Chosen over requiring `coder_model`, because the user asked for mid-tier *by default*.
