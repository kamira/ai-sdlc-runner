## The veto

Round fourteen's **conformance seat holds a veto** on this rule, and it was right:

```python
if node.gate_when == "after" and not node.gate:
    raise GraphError(f"node {node.id!r} has a gate phase but no gate")
```

`gate_when` defaulted to `"before"`, so **every** node had a gate phase. The message states a
contract about any phase without a gate; the condition refuses one of the two ways to be in that
state, and the sentence is literally true of the twenty-one ungated nodes it accepts. A validator
message that claims more than the validator holds is the class of defect this repository keeps
recording — and `test_an_after_phase_may_not_name_no_gate` had already written the veto into its
own docstring rather than resolving it, which is why that test is **removed in CHG-20260907-11**
and replaced by `test_a_phase_without_a_gate_is_refused` plus
`test_a_gate_without_a_phase_is_refused`, one per half.

Widening the condition in place was not available: it would refuse all twenty-one.

## The larger half, which the veto led to rather than named

```
gated nodes                 10
  gate_when="after"          7   pm_confirm lead_assess pm_signoff lead_task_review
                                 lead_review qa_verify qa_accept
  gate_when="before"         3   engineer_selfverify pr merge
ungated nodes               21   all carrying "before" by default
```

**The default was the minority case.** Seven of the ten gated nodes must remember to say `after`;
the one that forgets gets, silently, what the field's own comment calls a defect: *"a review that
halts before it runs is a review a high-risk change can never get, which is exactly what an
independent verifier found here."* And `validate` could not tell an omission from a decision,
because a default is indistinguishable from a value.

## What the suite caught, measured rather than grepped

I first grepped `gate_when` across `tests/` and wrote down the nodes no test names. That was the
wrong question and it produced a wrong sentence: **a test protects a phase through behaviour and
need not mention the field.** So each node was flipped and the suite run.

`test_documented_numbers.py:1045` asserts `len(gated) == 10 and len(before) == 3` — a **count**,
which refuses any single flip while saying nothing about which node.

```
pm_confirm           after -> before   2 FAILED   <- protected, by tests that never say gate_when
pm_signoff           after -> before   244 passed
engineer_selfverify  before -> after   244 passed
pr                   before -> after   244 passed
```

Three of the ten phases were held by a count and nothing else, and a **pair** among those three
keeps the count. Full suite with `pm_signoff -> before` and `engineer_selfverify -> after`:

```
2292 passed, 4 skipped, 0 failed
```

### Why the suite was blind, exactly

```
gate_when=after    halted_at='pm_signoff'   pm_signoff was asked: True    (7 asks)
gate_when=before   halted_at='pm_signoff'   pm_signoff was asked: False   (6 asks)
```

**The run stops at the same node either way.** The only difference is that nobody is asked. Every
test that pinned this node checked *where the run stopped*, so the suite was green on a sign-off
nobody had been asked for. `pm_confirm` was caught because its test asserts the **ask** —
`any(a.node_id == "pm_confirm" for a in report.asks)` — and that assertion is the only shape that
can tell the two phases apart.

## What ships

1. `gate_when: Optional[str] = None`. There is now a "no phase" state, so the whole contract is
   sayable and the default no longer picks the minority value for anyone who forgets.
2. One rule replacing the vetoed one: `(node.gate is None) != (node.gate_when is None)` — a gate
   without a phase and a phase without a gate are both refused.
3. `engineer_selfverify`, `pr` and `merge` declare `gate_when="before"` explicitly.
4. `test_which_gate_is_consulted_when_is_pinned` — a **dict equality**, not ten assertions, so a
   newly added gated node fails it and has to be entered deliberately. This subsumes the count.
5. `test_a_sign_off_gate_is_asked_for_before_the_run_stops_on_it` — the behavioural half, because a
   pin can still pin the wrong value.

Both reviewers reached (1)+(2) independently, and both said a pin is necessary *as well as*, not
instead of: a validator cannot choose between two valid values, and a mapping test cannot tell you
that the value it pins is the right one.

## Four things the reviewers found that this record did not start with

1. **`engine.py:2953` already writes `gate_when=None`** for a split panel, so `Optional` is the
   suspension record's actual type today and `docs/API.md:296` (`"before" | "after"`) was already
   false. Corrected here.
2. **`engine.py:2766`** writes the intake-incomplete stop at `intake_review` — an ungated node —
   with `gate: null, gate_when: "before"`: the exact pair the old message forbade, shipped in a
   public record. It is `null` now.
3. **`docs/API.md:53`** says the `/flow` payload carries `// all 28` nodes. There are 31, and no
   test pins it. Corrected in the same jsonc block as the field above it — leaving a known-wrong
   number two lines from a line being edited is worse than the scope discipline it would protect.
4. **The console never reads `gate_when`** (`console/index.html`: zero references), so shipping
   `null` for twenty-one nodes changes nothing a reader consumes.

## A trace of mine that a reviewer corrected

I wrote that an ungated node reaches `policy.verdict(node.gate, ...)` and gets `auto` from a falsy
gate. It does not: `resolve_verdict` short-circuits at `engine.py:823` with an explicit
`if not node.gate:` and never calls `policy.verdict` at all. The conclusion was right — an ungated
node's phase has no behavioural meaning, both `_gate` sites are unguarded, and `policy.stops` is
`!= AUTO` — but the path was wrong.
