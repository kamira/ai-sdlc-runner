## Read this first

```
store.resolve(plan, stored) -> source[key] = FROM_PLAN if key in from_plan else FROM_STORE

  plan says X, store says X    FROM_PLAN    the plan overrode the store
  plan says X, store silent    FROM_PLAN    the plan overrode NOTHING
  plan silent, store says X    FROM_STORE

cli.py:1522   overridden = sum(1 for v in source.values() if v == FROM_PLAN)
              print(f"... {overridden} assignment(s) from the plan override it")
```

Reproduced against an **empty** store:

```
store said nothing at all
  cmd_serve prints    3 assignment(s) from the plan override it
  actually overrode   0
```

## What is not wrong, and why the scope is one function

`resolve`'s docstring says it answers **"which source put an assignment there"**. For that question
`FROM_PLAN` is correct on both rows above, and every existing reader but one uses it that way —
`cmd_run`'s footer counts `FROM_STORE` and says *"the plan did not name"*, which is exactly what
`FROM_STORE` means.

So `resolve` is not changed, no third constant is added, and no existing test moves. **One sentence
in `cmd_serve` reads a "who put it there" map as a "what did it displace" map**, and `cmd_serve`
holds both `plan_assignments` and the store's dicts, so it can compute the real answer itself.

## Why no test contradicted it

Both tests of `resolve`'s `FROM_PLAN` use a key **the store also named**:

```
test_the_plan_wins_and_the_store_fills_and_both_are_named   lead_review: plan AND store
test_an_override_is_never_silent                            defect:      plan AND store
(no test)                                                   plan names it, store never did
```

Every exercise of `FROM_PLAN` is the override case, so the reading "plan means override" was never
put in front of a case that would refute it. The missing case is added here — not because `resolve`
is wrong on it, but because a value whose only tested shape is the one it is later misread as is a
value nothing is holding.
