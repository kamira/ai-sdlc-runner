## The finding

Deferred, deliberately, by CHG-20260907-10: *"three test modules carry an implementation of 'swap
the graph, validate, restore' ... it is a ~40-signature edit across three files, and folding a
mechanical refactor of that size into a rule change makes both harder to review."* This is that
change.

`graph.py` keeps two views of one graph, `NODES` and `BY_ID`. A test that wants `validate()` to
judge a graph other than the shipped one must rebind **both** and restore both whatever happens.
Measured at `c014889`:

```
tests/test_graph_validation.py:37   _validate_with(nodes)             both views   23 calls / 23 test fns
tests/test_execution_mode.py:42     _validate_with(nodes)             both views   14 calls / 14 test fns
tests/test_risk_adjudicated.py:150  _validate_one(node)               both views    2 calls /  2 test fns
tests/test_graph_validation.py:403  _validate_with_nodes_only(nodes)  HALF swap     1 call   /  1 test fn
```

### Two corrections to how earlier records described it

**CHG-20260907-10 says the first two are "byte-identical". They are not.** Their *bodies* are -
`ast.unparse` of each, docstring stripped, returns the same string - and
`test_graph_validation`'s carries a ten-line docstring where `test_execution_mode`'s carries none.
The difference is the whole of what this record had to decide about: the bodies fold, the
explanation has to be rehomed rather than deleted.

**`_validate_one`'s own docstring says the other two "each carry a byte-identical copy of this".
Also false, and further out.** `_validate_one` takes **one node** and splices it into the shipped
`NODES` by id; the other two take a whole tuple. Same operation, different arity - which is why
the arity stays local and only the swap is shared.

### The fourth is not a fourth copy

`_validate_with_nodes_only` rebinds `NODES` and leaves `BY_ID` alone, and says so: *"This one
exists to be wrong, so that the rule refusing it has something to refuse."* It is the
counter-example CHG-20260907-10's new rule (`if BY_ID.get(node.id) is not node`) is aimed at.
Folding it in would delete the only thing in the suite that performs a half-swap, and the rule
would be `NOT CAUGHT` the day after. It stays, unchanged.

## The abandon condition, and why it is not met

The operator's condition was: abandon if the four do not have identical restore semantics, in
particular exception-safe restoration of **both** views. Measured, and both seats checked it
independently:

```
tests/test_graph_validation.py:45  original_nodes, original_by_id = graph.NODES, graph.BY_ID
tests/test_graph_validation.py:51      graph.NODES, graph.BY_ID = original_nodes, original_by_id
tests/test_execution_mode.py:43    original_nodes, original_by_id = graph.NODES, graph.BY_ID
tests/test_execution_mode.py:49        graph.NODES, graph.BY_ID = original_nodes, original_by_id
tests/test_risk_adjudicated.py:166 original_nodes, original_by_id = g.NODES, g.BY_ID
tests/test_risk_adjudicated.py:172     g.NODES, g.BY_ID = original_nodes, original_by_id
```

All three capture both views before the `try` and restore both in the `finally`. `_validate_one`
puts its assignments *inside* the `try`; the capture still happens first, so if the splice
expression raised, the `finally` would rebind the originals onto themselves - the same outcome.
Identical semantics. The half-swap is deliberately unlike and is a keep, not a blocker.

## The decision both seats were asked to take, and took

CHG-20260907-10 recorded **both** reviewers recommending one callable fixture in
`tests/conftest.py`, and `_validate_one`'s docstring calls that *"the agreed repair"*. I then
measured what that round did not have:

```
                                    signature changes at call sites   new lines per file
support module in tests/                       0                      1 import  (3 total)
fixture in tests/conftest.py                  39                      0
```

39 is every test function that would have to declare a fixture parameter. The measurement behind
the 0: the helper takes nothing from pytest - its whole body is two module attributes and a
`try/finally`; there is no `tests/__init__.py`; `pyproject.toml` sets `testpaths = ["tests"]` and
no `importmode`, so pytest's default `prepend` mode puts `tests/` on `sys.path`. Verified by
running it rather than by reading the docs: a throwaway `tests/_probe_support.py` imported by
`from _probe_support import MARKER` gave `1 passed` invoked as a single file and resolved under a
whole-suite collection as well.

The measurement went to both seats with the instruction to decide and not to average. **Both,
independently, reversed their predecessors and chose the support module.** What the earlier round
did not know:

- **The suite already shares test-side helpers this way, 36 times.** `from test_flow import
  DECISIONS, SPEC` appears in eight modules; `test_module_built.py:32` inserts `tests/` on
  `sys.path` explicitly. A bare sibling import is the house shape, not a novelty, and this record
  introduces no import-mode dependency that eight files did not already carry.
- **A fixture would be worse than merely costly - it would be wrong in a case this suite can
  reach.** Fixture teardown runs *after* the test body. A test that catches the expected
  `GraphError` and then looks at `graph.NODES` or `graph.BY_ID` would read the **hypothetical**
  graph, not the shipped one. Keeping the inner `try/finally` is what prevents that, and once it
  is kept the teardown buys nothing at all.
- **What the 39 signatures would buy is pytest injection, and nothing else** - no temporary path,
  no monkeypatching, no parametrisation. `conftest.py`'s one existing fixture shows what a
  legitimate one looks like: `py_stub` consumes `tmp_path`.

Collision checks, so the choice is measured rather than argued: `importlib.util.find_spec` returns
`None` for `_graph_swap`; `tools/` holds no such name; all tests live in one flat unpackaged
directory, so the duplicate-basename hazard cannot arise; pytest collects `test_*.py` only, so the
underscore-prefixed module is not collected; `docs/structure/directory.md` lists `tests/` as one
row, so no structure document names it.

### And a function, not a context manager

Asked separately, because searching for the whole population rather than the four the backlog
named turned up two more swap-and-restore sites that a function cannot absorb:

```
tests/test_module_built.py:167-175      swaps both views, restores both — but runs validate()
                                        PLUS two assertions about module_cycle() and _workspace()
                                        inside the swap
tests/test_graph_validation.py:243-250  swaps NODES only, never calls validate() at all — it calls
                                        engine._whole_change_rejected(), which reads NODES
```

Measured usage of the 39 sites that *are* in scope: **39 of 39 are inside `pytest.raises`, 37 with
a `match=`, and none expects success or runs anything else inside the swap.** A context manager
would nest a second `with` inside every one of them to gain a flexibility no caller wants, and a
manager *plus* a thin `validate_with` is two names for one idea. Both seats chose the function,
and both refused folding in either extra site - the second is deliberately `NODES`-only and
absorbing it into a both-view helper would change what it exercises. Neither is touched here.
`test_module_built.py:167` is left on the record as a candidate for its own change, which would
have to argue that a manager is worth having for one site.

## What ships

1. **`tests/_graph_swap.py`**, one function `validate_with(nodes)`, whose body is the body all
   three already had. Imported as `from _graph_swap import validate_with`, the same shape as the
   six existing `from test_flow import ...` lines.
2. The three helper definitions are removed and their 39 call sites now name `validate_with`. A
   call-site rename is not the fixture's cost: no test function's parameter list changes, which is
   what the 39 in the table above counted.
3. `test_risk_adjudicated._validate_one` **keeps its arity** and delegates the swap:
   `validate_with(tuple(node if n.id == node.id else n for n in graph.NODES))`. Its two callers
   have a single `Node` in hand (`single_grader`, `step_that_grades_nothing`), not a tuple.
4. **One new test**, and it is the reason a restore mutation can be registered at all -
   `test_the_shared_swap_puts_both_views_back_when_validate_raises` asserts by **identity** that
   `graph.NODES` and `graph.BY_ID` are the shipped objects after `validate_with` has raised. Thirty-
   nine test functions now share one `finally`; the property the abandon condition was written
   about is executable rather than read.
5. Three false or spent sentences removed, and the two measurements inside them rehomed to
   `_graph_swap.validate_with`'s docstring:
   - `test_graph_validation.py:41-45`, *"`test_risk_adjudicated._validate_one` swaps only the
     first"* - false since CHG-20260907-10 repaired it. The mechanism it explains (`validate`
     compares the two lengths and then traverses `BY_ID`, so a replacement can be half-validated)
     is true and survives.
   - `_validate_one`'s *"byte-identical copy"* sentence - false as shown above.
   - `_validate_one`'s paragraph deferring the refactor *"to its own change so that a
     forty-signature refactor is not folded into a rule"* - that change is this one.

## The mutations

`graph-swap`, two entries, both anchored in `tests/_graph_swap.py` - a `tests/` path is an
established target here (see the `phantom-flag` group).

```
the helper may stop rebinding BY_ID     tests/test_graph_validation.py::test_the_half_swap_used_to_certify_a_graph_that_does_not_run
the helper may stop restoring           tests/test_graph_validation.py::test_the_shared_swap_puts_both_views_back_when_validate_raises
```

**Both name a test node rather than a file, and the first one has to.** Measured on a copy of the
tree: dropping the `BY_ID` rebind fails **43 of 74** tests across the three files - but 41 of them
fail collaterally, because their own `match=` string no longer matches the message they now get.
Measured over all 34 distinct `match=` patterns in the three files, exactly one - `"rebound
separately"`, the half-swap's own - matches `validate`'s identity-rule message, so every other
site fails for a reason about its regex rather than about the swap. The node registered is the one
whose stated guarantee **is** that both views move: its docstring says *"Swapping both views
instead refuses it, for a reason about the graph rather than about the rebinding."*

**The second entry exists because the test was written for it.** Measured first: with the `finally`
body removed and one mutating node run alone, the result is `1 passed` - nothing named catches it.
Run wider it fails 49 tests, every one of them a later test inheriting a polluted graph, which is
ordering rather than a guarantee (`pytest-randomly` is not installed, so the order is stable, which
makes the collateral *reliable* and no more meaningful). Registering that against a file would have
produced a clean `CAUGHT` for a hole. The honest options were to write the test or to leave the
mutation out with the group comment saying why; the test is one assertion of identity over a
property the change is already claiming, so it was written.

**What is absent, and why.** No mutation is registered for the *arity* of `_validate_one`, and none
could be: `validate_with(tuple(node if n.id == node.id else n for n in graph.NODES))` and the
shipped `_mutate` produce the same tuple for the cases its two callers exercise, so an edit between
them is not observable by any test - and inventing one to make the group look thorough is the thing
this harness's own docstring warns against.
