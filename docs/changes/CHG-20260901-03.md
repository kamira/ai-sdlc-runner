## A fixture that translated the bytes it was measuring

The structural one, found by the defect seat and confirmed by the idiom seat. `GHOST_EXCUSES`'s
fixture wrote with `Path.write_text`, which translates a newline to `os.linesep`. So the two rows
written with an explicit CRLF became `\r\r\n` on Windows and read back as a **paragraph break** —
decided by `_PARAGRAPH_BREAK` there and by `_SENTENCE_END` on Linux.

The same revert therefore measured differently on the two CI cells:

| removed | POSIX | Windows |
|---|---|---|
| the sentence rule | 7 | 5 |

Two rounds of "corrected" figures came out of that: `7` was right on Linux, my correction to `6` was
right on neither, and `_excused`'s docstring was calibrated to Windows alone. The fixture writes the
bytes it names now — `io.open(newline="")`, because `write_text(newline=…)` is 3.10+ and the floor
is 3.9 — and both platforms agree:

```
_PARAGRAPH_BREAK 6 · sentence rule 7 · _SPAN 2 · EXCUSE_WINDOW 1 · id 8 · case 1 · rename 3
```

The `id` figure is 8 when the check is disabled and 1 when it is loosened, which is why three rounds
disagreed about it. Both are now recorded, with the patch that produces each.

## The refusal blamed one field for every fault

The shape gate added last round names the broken field in its first sentence and then, for every
shape, printed a second paragraph about `owner`:

```
… the field(s) ['original'] are not there. The file is **kept**.
  `owner` is the field that says whether a run is still mutating this tree, so a record
  without a usable one cannot be acted on: putting the `original` back by hand may …
```

For a record whose `owner` was the running process's own pid. That is exactly the defect the same
change's comment says it removed — *"sends the operator looking for the wrong thing"* — reproduced
one paragraph below the fix. And its remedy, *"repair the field this names"*, let the operator
**invent a pid**: `0`, `-1` and any integer all restored the file, defeating the hazard the same
sentence cites. Each fault names its own field now, and the `owner` case says *do not invent a pid*.

## Three instruments that reported about themselves

- **`_import_fails` trusted `__pycache__`**, which is validated on `int(st_mtime)` plus size, so a
  same-size rewrite inside one second imports the stale bytes — a false `""`, which downgrades a
  `BROKE` to a `CAUGHT`. The defect seat demonstrated the mechanism and could not land the shipped
  harness in the window; `-B` closes it either way.
- **`render_cast.py` left its output file unclosed.** `Path.write_text`, which it replaced, closed
  deterministically; `io.open(...).write(...)` does not, and `-X dev -W error::ResourceWarning`
  prints `unclosed file`. Output verified byte-identical.
- **The assertion written to stop a message pinning nothing was satisfied by boilerplate.**
  Blinding the diagnosis to *"something is not there"* left nine of eleven rows green, because the
  constant remedy paragraph contained the words `owner` and `original`. It reads the first line now.

## And the census excluded its own records, again

`CHG-20260901-02` re-measured the sentence-boundary census specifically because the previous one
*"excluded that change's own two records"* — and took it over 267, which is the tree **before** its
own two records. The fourth instance of that shape, in the correction for the third.

Over 269, under `[.!?]\s+(.)` — the rule as actually run, which classifies the character that
follows and so does not count a boundary at end of text (`[.!?]\s+` alone matches ~~244~~ **245**
more):

| what follows a sentence end | ~~count~~ at `2afec9d` (269) | at `3a49c57` (271) |
|---|---|---|
| a capital | 4364 | **4405** |
| something else (punctuation, a dash, a quote) | 3287 | **3323** |
| a backticked identifier | 431 | **435** |
| a digit | 363 | **370** |
| a lowercase word | 67 | **67** |

~~`4148` of `8512` are not capitals. The record now names the tree it was measured on rather than
saying "all".~~

**The fifth instance, in the paragraph calling it the fourth.** `269` is the tree at `2afec9d` —
*before* this change's own two records. The tree that has them is **271**, at `3a49c57`, and it
measures `4195` of `8600` not capitals. Both columns are given because that is what makes the
error legible: the published five reproduce exactly one commit back.

Four corrections in a row wrote a denominator that excluded the correcting record's own files,
each one written to fix the last. The cause is not carelessness five times over — it is that "the
current tree" is not a quantity a record can measure about itself, because writing the record
changes it. From CHG-20260901-04 the census names a **commit**, which one `git ls-tree` settles,
and the *claim* is re-measured on every run by
`test_the_sentence_rule_ends_a_sentence_a_capital_would_not`. Corrected in CHG-20260901-04 (VETO).
