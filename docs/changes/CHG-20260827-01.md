## The finding

`conversations.backend()` refuses a retired store **by name**, telling the asker what happened to
it (`conversations.py:764-765`). No CLI user can ever see it. `--store` is declared with
`choices=conv_mod.BACKENDS` (`cli.py:556`), so argparse rejects `mongo` first:

```
runner export: error: argument --store: invalid choice: 'mongo' (choose from 'sqlite', 'file')
```

Exit 2, from argparse - the typo-style message CHG-35's record explicitly argues against. The
`choices=` constraint was already present at CHG-35's own commit `52017b4`, so this was never
reachable: not drift, never true.

This is KN-8's shape - a correct mechanism nothing that matters can reach - and the existing test
cannot catch it, because it calls `backend()` directly and would pass with the CLI wire cut.

## What changes

`--store` stops using `choices=` and takes a `type=` function that defers the decision to the one
place that already knows it. Unknown and retired both keep their current wording; the difference is
that the retired branch becomes reachable.

`--help` must still name the usable backends, so the parameter keeps an explicit `metavar`. The
retired names are deliberately **not** advertised as choices - they are accepted only to be refused
with an explanation.
