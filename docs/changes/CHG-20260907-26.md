## A - `Node.mode` defaulted to the minority value

`mode` said *"Declared, never inferred"* one line above `mode: str = SINGLE`. Measured:

```
runner       15
model_panel   6
single        4      <- the default
pool          2
follows       2
survey        1
seat_panel    1
             31
```

`SINGLE` is **4 of 31**. So a node whose author never thought about its mode was read as one model
in one session - and the value that node most likely wanted, `RUNNER`, is the one `validate` would
have caught, because `(node.role is None) != (node.mode == RUNNER)` refuses a role-less node that
is not `RUNNER`. A node **with** a role has no such protection. Measured on the shipped graph:

```
lead_task_review, rebuilt from its own fields minus `mode`   -> mode 'single'  (really model_panel)
validate() over that graph                                   -> ACCEPTED
```

This is the shape CHG-20260907-11 removed from `gate_when` one field up: that defaulted to
`before`, which is 3 of the 10 gated nodes, and the record's own words were that *"a gated node
whose author forgot the phase silently got the shape the paragraph above calls a defect"*. The
same sentence is true here with different numbers.

**And it was named when the field was written.** CHG-20260823-11, the record that introduced
`mode`, says *"`single` is the dataclass default, so every unconsidered node would land there
silently"* - and shipped the default anyway. This record is the sentence being acted on rather
than repeated.

### The abandon condition, and why it is not met

The operator's condition was: abandon if constructing a `Node` without `mode` is an intentional
supported API with a documented majority use case. Measured:

- **Every one of the 31 shipped nodes passes `mode=` explicitly.** AST walk over every `Node(...)`
  call in `graph.py` for one without a `mode` keyword returns `[]`.
- Repo-wide, **exactly one** construction omits it: `tests/test_rerun_idempotence.py:118`, a stub
  for `next_module` - which is `RUNNER` in the shipped graph and was silently getting `SINGLE`.
- **No document describes a default.** `grep -rni default docs/ README.md | grep -i mode` returns
  only `high_risk_mode`, an unrelated settings key.
- If there were a majority use case it would be `RUNNER` (15/31), not `SINGLE` (4/31).

Not met. Both seats checked it independently and both said so.

### What ships, and the shape both seats chose over the alternative

`mode: Optional[str] = None`, plus its own rule in `validate()` ahead of the closed-set check:

```python
if node.mode is None:
    raise GraphError(f"node {node.id!r} declares no mode. How its models are read is declared "
                     f"and never inferred, so a node that says nothing is a build error rather "
                     f"than a {SINGLE!r}. It must name one of {MODES}")
```

**Not a field with no default at all**, which is the other reading of "required". Both seats
refused it, and the defect seat's reason is the one that decides it: a field with no default makes
the omission **unrepresentable**, so it becomes a `TypeError` raised from a constructor, outside
`validate`, with no node named and no sentence - and no test in this suite could pin it, because
every refusal here is `validate_with(...)` plus `pytest.raises(GraphError)`. The sentinel keeps
the omission sayable, which is exactly the reasoning CHG-20260907-11 recorded for `gate_when`
(*"with no default, 'no phase' is a state the graph can be in, so the whole contract is
sayable"*). Reordering would also move the field and its comment block above seven others for no
reader's benefit; no call site would break, since the most positional arguments any of the 31
`Node(` calls passes is 3.

**A dedicated rule, not the existing closed-set one.** `if node.mode not in MODES` already raises
for `None` - measured, the message is `node 'pm_plan' has unknown mode None`. That sends a reader
after a typo when what happened is an omission. Both seats asked for the specific message; -11
wrote one for the same reason.

`None` is never a valid state here, unlike `gate_when` where "no phase" is correct for the
twenty-one ungated nodes. The field comment says so, so that nobody reads the `Optional` as
permission.

### The unenforced edit

`tests/test_rerun_idempotence.py:118` gains `mode=graph.RUNNER`. **Nothing forces it**: that stub
goes only to `engine._frontier`, which never reads `mode` (measured: zero occurrences of the string
in `engine.py:1407-1539`, the whole function), and never to `validate()`. Left alone it would
silently carry `None` and every test would stay green. It is corrected because the stub models a
node that is `RUNNER`, and a stub that disagrees with its subject is a stub testing a different
function - which is the reason its neighbour four lines up already gives for carrying `dispatches`.

## B - "three nodes are `role="lead"`", where there are five

`graph.py:185`, inside `follows`'s comment. Measured:

```
role == "lead"   5   ['lead_assess', 'lead_task_review', 're_review', 'pr', 'merge']
```

And it was false **on arrival**. `git log -S 'three nodes are ``role="lead"``' --
src/ai_sdlc_runner/graph.py` returns exactly one commit, `988ef22` (2026-08-23, CHG-20260823-11
task 12), which introduced it; at that commit `grep -c 'role="lead"'` is 6 - the comment line plus
the same five nodes. Sixteen days, never true.

**The count is removed rather than corrected**, and the sentence keeps its point:

> roles are not unique - several nodes are ``role="lead"`` - and "verify what *this* build
> produced" cannot be said by naming a role.

The number carried no argument. Contrast `graph.py:107`, *"seven of the ten gated nodes are
`after`"*, where the ratio **is** the argument for removing a default; here the argument is
"roles are not unique", for which *several* is the entire claim. `several` is also this file's own
word for it, 11 times.

### The rule this declines, named

A seat corrected the draft on this. KN-17 is about a count with a **qualifier** beside it (a total
against a subtotal) and does not govern this sentence. The rule that does is CHG-20260907-12's, in
`tests/test_documented_numbers.py::test_a_field_count_in_prose_is_checked_against_the_thing_it_counts`:
*"A number in prose is checkable only where the sentence says what it counts... Name the referent -
that is the repair."* This sentence **does** name its referent inside the phrase, so a grammar
could be written for it: `(\w+) nodes are ``role="(\w+)"``` against `sum(n.role == r for n in
NODES)`. It is not written, for two reasons and the second is the measured one:

1. It would be a sweep grammar serving exactly one sentence, in the file this change is already
   repairing. The operator asked for the count removed.
2. **The existing node-count rule's digits-only match is a design, not a gap.** It matches
   `(\d+)\s+(?:nodes|節點)` and compares against `len(NODES)`. Measured across the swept files,
   there are **12** spelled-out `<word> nodes` phrases and **11** of them are true counts of a
   *subset* - "eight nodes carry `rejects_to`" (true, measured), "two nodes, because planning and
   confirming are two kinds of work", `graph.py:22`'s own "so they are three nodes". A word-aware
   version of that rule would fail eleven true sentences to catch this one.

## B, folded in - a stale count in a test's name

`tests/test_execution_mode.py:52` was `test_the_modes_partition_all_twenty_three_nodes` - a name
removed in CHG-20260907-26, this record, and replaced by `test_the_modes_partition_every_node` -
and the graph has 31. Its **assertion** is count-free (`counted == len(graph.NODES)`); only the name
carried the number, and no sweep reads test names - `tests/` is not in the documented-numbers
`DOCS` tuple, and `test_nothing_is_unwired` reads `def test_*` names only to find duplicates. So
nothing would ever have caught it.

Renamed `test_the_modes_partition_every_node`. **Folded in rather than filed**, which both seats
decided independently and the conformance seat made the stronger case for: this record already
edits that file - the new test below lives in it, and the comment above must be rewritten in it -
and leaving a known-false number in a file being edited is worse than the scope discipline that
would protect. Unlike A and B this one was **true when written**: `988ef22` again, when the graph
had 23 nodes. It drifted; the others never were true.

## And one justification that this record makes false

`tests/test_execution_mode.py:73`, on `test_a_runner_node_declared_single_is_refused`:

> The direction that would otherwise pass silently: SINGLE is the dataclass default, so a node
> added without thinking about its mode lands here.

True until this change, false after it. The test keeps its value and loses that reason: what it
holds now is the case where somebody wrote `SINGLE` on a node that asks nobody, deliberately. The
omission has its own refusal. Rewritten, not deleted - a seat named removing a justification
without rehoming it as the failure condition here.

## The mutations

`mode-declared`, two entries, both in `graph.py`, both naming the same test node.

```
a node may take a mode nobody chose for it again   -> mode: Optional[str] = None  ->  mode: str = SINGLE
an omitted mode may be reported as a typo again    -> if node.mode is None:       ->  if False:
```

The first must reach the default **through the constructor**, because that is the only place a
default acts. The obvious test does not: `_mutate("pm_plan", mode=None)` passes with the default
restored, since what it trips is the `is None` rule and that rule survives the mutation. So the new
test rebuilds `lead_task_review` from `dataclasses.fields` minus `mode` and asserts both that the
field comes back `None` and that `validate` refuses the graph.

**And it is the only witness.** Measured with the default restored and the new test deselected:
`61 passed` across `test_execution_mode`, `test_graph_validation` and `test_rerun_idempotence`.
Nothing else in the suite objects, because no shipped node omits `mode` and the one construction
that did is never validated. Written first, measured second, in that order - the test exists
because the measurement said the mutation would otherwise be `NOT CAUGHT`.

The second entry pins the **message** rather than the refusal: with the `is None` rule gone, the
closed-set rule still raises, so a file-level objector would report `CAUGHT` while the diagnostic
had silently gone back to naming a typo.

**Nothing is registered for B**, and the group comment says why: a deleted number in a comment is
not executable, and the measurement above shows that the sweep which could have caught it cannot be
widened without failing eleven true sentences. A deleted number is guarded by nothing. That is a
smaller claim than a rule, and it is the honest one.

## What this does not do

- It does not touch the shipped graph. All 31 nodes declared their mode before this change and
  declare it after; `validate()` accepts the same graph.
- It does not delete `test_the_modes_partition_every_node`, which an idiom seat noted is close to
  a restatement of `test_every_node_declares_a_mode_from_the_closed_set`. That was not asked for.
- It does not touch `graph.py:140` / `engine.py:2988`, which both say **three** nodes name their
  branches `pass` and `fail`. Measured: three if the count is of `MODEL_PANEL` decisions
  (`lead_task_review`, `re_review`, `qa_accept`), four if the `SEAT_PANEL` `lead_review` is
  included - and it names `pass`/`fail` and declares no `panel_branches` exactly like the other
  three. Neither sentence says which population it counts. That is a KN-17 ambiguity - *"which one
  the bare number carries has to be stated, not inferred"* - and KN-17's own instruction is that a
  check must not pick. This record does not pick either; it is recorded here so somebody who knows
  which reading was meant can settle it.
