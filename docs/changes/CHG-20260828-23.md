# CHG-20260828-23 — the closed-schema renderer had no test file and no mutation, and two of its guarantees were real holes

- Project: ai-sdlc-runner
- Branch: claude/chg-20260828-23-the-renderer-is-pinned
- Date: 2026-08-29 (UTC+0)
- Type: coverage for guards, measured before it was written
- Proposed by: a survey — 11 of 20 modules carry no mutation at all, and `workorder.py` is the most
  load-bearing of them
- Risk: **low** — tests and a mutation group; `src/` is untouched
- Autonomy: high
- Related: CHG-20260828-02 (*"a guard is code that can be wrong"*, the argument this applies),
  CHG-20260823-34 (the blank-field defect this pins)

## Why this module first

`tools/mutation_check.py` covers 9 of the project's 20 modules. `workorder.py` was in the other
eleven, and it is the one the governance argument leans on hardest: it renders the **closed schema**
every ask is given, and its docstring says a partial order is *"the silent fallback this design
refuses"*.

## What was measured, and it is not what I expected

Nine guarantees, one mutation at a time, against the test files that mention `workorder`
(`test_flow`, `test_plan`, `test_schemas`):

| guarantee | before |
|---|---|
| a harness-specific field rides in through the caller | pinned |
| a partial node spec is accepted | pinned |
| whitespace stops counting as blank | pinned |
| a list holding only blanks passes | pinned |
| a blank field is accepted, as long as the key exists | pinned |
| an unknown seat is accepted | pinned |
| the permanent halts are emptied out of the order | pinned |
| **the rendered order stops being checked against the closed schema** | **not pinned** |
| **the order is serialised in whatever key order it happens to have** | **not pinned** |

**Seven of nine were already caught.** No mutation record did *not* mean no coverage, and the survey
that proposed this change implied it did. That is worth writing down because the opposite is the
easy assumption, and acting on it would have meant treating well-tested code as untested.

## The two that were holes

**The rendered order is never compared against the closed schema.** `render` builds the order
literally and then checks its shape against `WORK_ORDER_FIELDS`. Removing that check entirely leaves
the suite green — and the source already says so:

```python
raise WorkOrderError(                                # pragma: no cover - structural guard
```

A `pragma: no cover` is the code admitting nothing exercises it. It is the only thing between a
future edit to `render` and an order whose shape no longer matches the contract every consumer reads
it by.

**`to_json` promises sorted keys and nothing checked.** Its docstring is *"Serialise
deterministically: sorted keys, LF, UTF-8"*. The LF and the UTF-8 were checked; the sorted part was
not. That is the byte stream a dispatched agent reads, and CHG-20260828-16 has just made the
encoding of exactly these bytes something that matters.

## The test that would have passed either way

`test_the_rendered_order_matches_the_closed_schema_exactly` asserts a *correct* order has the right
shape — which is true whether or not the guard exists. So it is joined by
`test_an_order_missing_a_contract_field_is_refused_rather_than_dispatched`, which widens
`WORK_ORDER_FIELDS` so `render` produces a wrong order and must refuse it. The mutation is what
forced the second one: the first alone came back **NOT CAUGHT** in the probe.

## Risk & rollback

- No `src/` change. The suite grows by 19 cases and the mutation registry by 9.
- Rollback: delete both. The two holes reopen; the seven pinned guarantees stay pinned by the tests
  that already pinned them.

## Status

### Not claimed

**That nine is all of them.** These are the guarantees `workorder.py` states in prose — its field
sets, its refusals, its docstrings. A guarantee nobody wrote down is not in the list, and mutation
coverage cannot propose one; the module docstring of `mutation_check.py` says exactly this about
itself.

**That the other ten unmutated modules are in the same state.** The measurement here says seven of
nine were pinned in *this* module. `store.py`, `server.py` and `models.py` are larger and were not
measured. Assuming the ratio transfers would be the same mistake this change just corrected.
