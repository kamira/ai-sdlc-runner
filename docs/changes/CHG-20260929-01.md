## Interpreted, and what it was chosen over

- **Three dimensions ship off** (錯誤處理/可觀測性, 相依/供應鏈, 國際化/在地化). The user asked for as many
  as possible and for the choice to be theirs; shipping them on spends quota on a choice the user
  did not make. Chosen over all-on.
- **Cross-read is per dimension.** Each engine reads the other engines' answers on the same
  dimension only. Chosen over reading all 36, which would carry every dimension's framing into every
  seat.
- **A dimension that does not apply still opens its session** and says so. Chosen over the
  orchestrator skipping it, which would be deciding what applies — the choice the user kept.
- **A cross-read DISAGREE does not by itself fail the round**; it is listed in both reports and
  printed, for the user to decide (escalated, not averaged). A seat that thinks a disagreement
  blocks says `VERDICT: fail`. Chosen over any DISAGREE failing the round, which would turn a
  difference of reasoning into a veto held by whichever seat disagrees.
- **`--out` inside the repo is refused**: raw seat output there would dirty the tree and fail the
  closing freeze check every time.
- **The coder rule is recorded, not enforced by the tool.** `coder` in `config/panel.json` is
  validated and documented; nothing can check which model wrote a diff.

## Round 1 — `tools/panel.py` on its own change (c02b114)

Run as DIR-3 says, 36 review + 36 cross-read sessions. **Result: `incomplete`.** All twelve
`gpt-6-astra` cross-read cells exited 1: *"You've hit your usage limit … try again at 9:39 AM"*.
The tool did what the rule says — no pass on an unreached seat.

**What one round costs, measured by the tool's own usage report:**
- codex 5-hour window: 0% → exhausted (resets 09:39 UTC); weekly window 6% → **21%** (~15 points
  a round).
- claude: 48 cells, **$43.71** at API prices (on a subscription, plan limits instead; the CLI
  reports no remaining figure).

The user was asked and chose to **keep the full matrix and schedule rounds by quota** — at most
one round per codex 5-hour window.

**Review phase findings, all taken** (blocking ones; minors in the same commit):

| finding | seats | fix |
|---|---|---|
| `VERDICT: pass` followed by any other last line still counted as pass | astra ×5 dims, fable | the verdict must be the last non-empty line; anything else is unreached |
| `--no-cross-read` could report `pass` though DIR-3 requires cross-read | fable, astra ×3 | such a round can never pass: `incomplete`, exit 3 (a `fail` stays `fail`) |
| an unreached seat did not stop queued sessions (quota spent after the round was lost) | astra ×3 | pre-flight check of every executable; fail-fast cancels queued cells |
| a relative `--repo` was applied twice for codex | astra ×2 | resolved to absolute once |
| remaining quota taken from list order, not the latest observation | astra | rate limits carry their rollout timestamp; the latest wins |
| a Windows `.cmd` launcher could defeat the timeout | astra | process-tree kill (killpg / `taskkill /T`) and a bounded read |
| the brief was sent without saying to whom | astra | recipients, executable, `reach` and brief size printed and reported first |
| the reviewed tree can instruct its reviewers (AGENTS.md / CLAUDE.md) | fable | claude seats get an appended system prompt; codex gets `project_doc_max_bytes=0` |

Verified by the orchestrator: the claude seat's new argv run for real — it read `AGENTS.md:1` and
called it the subject of review, not an instruction. **Not yet verified:** codex's
`project_doc_max_bytes=0` (no quota until 09:39 UTC) and the Windows `taskkill` path (no Windows
here; CI's Windows job runs the suite, not a real hang).

The coder reported which new tests fail on the old code: all fix-specific tests do, except three
guards (fail-stays-fail, a binary vanishing after pre-flight, running cells finishing) and the
bounded-read case, which pass on both — recorded as guards, not proofs.

## Round 2 — after round 1's fixes (e70791a)

Before the round, measured: `codex exec … -c project_doc_max_bytes=0` answered `NO-AGENTS` when
asked whether its context held AGENTS.md; without the setting it quoted AGENTS.md's first line.

**Result: `incomplete` again.** The review phase completed (36 cells: `fable` 12 pass; `opus`
4 fail; `gpt-6-astra` 7 fail). The codex 5-hour window ran out after three cross-read cells, and the
fail-fast added in round 1 stopped the queued rest: 30 cross-read cells not run. Cost: claude
$35.36 at API prices; codex weekly window at 25% or more.

**Findings, all taken:**

| finding | seats | fix |
|---|---|---|
| a reduced panel (`--only-dimensions`) could pass | astra | a matrix smaller than enabled × all engines is `incomplete`, never pass |
| Ctrl-C did not stop a round; queued cells ran on and no report was written | opus, astra; fable and opus again in cross-read | interrupt cancels queued cells, kills running seats' process trees, writes the report, exit 130 |
| Windows: the brief was written to stdin synchronously before the timeout applied | astra ×2, opus | the brief is a file (`cells/<stem>.brief.txt`) passed as stdin; the pipe only reads |
| repo-defined hooks could make the claude seats run commands | opus, astra | claude seats load only user settings: `--setting-sources user` |
| the disclosure test compared sizes across newline conventions (fails on Windows) | astra, opus | size is the brief's byte length, read in binary |
| README still described a two-seat panel | astra | README describes DIR-3 and `tools/panel.py` |
| a round cannot finish inside one codex window, and every retry re-paid all of it | opus | `--resume DIR`: same commit and same brief, keeps reached cells, re-runs only unreached ones |
| the quota line read "not reported" when a newer reading had no window values | orchestrator | the latest reading that carries a window value wins |

The coder also added `brief_sha256` to the report so that `--resume` refuses a different brief,
because answers it keeps would otherwise belong to a different question. It said which new tests
fail on the old code and which are guards. The Windows hang cannot be reproduced on POSIX; what
proves the fix is that stdin is now a regular file.
