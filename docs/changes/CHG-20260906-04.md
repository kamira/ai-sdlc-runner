## The change: `Attachment.instruction` reaches somebody

The field is set by `Store.add(..., instruction=len(instructions))`, validated on read, used as
`_write`'s sort key, and serialised into the manifest, `/attachments` and `/run`. Its own comment
says why it exists:

> so a later brief can say where a document came from

Nothing said it. Measured — every load of `.instruction` in `src/`:

```
attachments.py:218  instruction=            add()
attachments.py:263/264/267  .instruction    all(): the "is it an int" check
attachments.py:340  .instruction            _write(): the sort key
server.py:385       instruction=len(self.state.instructions)
console/index.html  0 occurrences
```

and the row the console actually rendered:

```js
b.textContent = f.filename + "  (" + f.media_type + ", " + f.size + " bytes)";
```

`KN-8` is the rule the guideline checks as a box: *"A comment describing behaviour is a claim …
either make it true or delete the sentence."* Two honest resolutions, and the current state was
neither.

The row now names it. The number is the same 1-based count the instruction rows above it are
labelled with, so *"with instruction 2"* points at the row marked `2.` without translation; zero is
spelt out, because no row is labelled `0.`

```js
var when = f.instruction ? "with instruction " + f.instruction
                         : "before the first instruction";
```

Storage, the API and the work order are untouched. Both engines refused putting it on the work
order: orders carry hashed paths only, and *where a document came from* is a brief for a person.

## The no-change: what an attachment filename may carry

Eight shapes, all accepted and round-tripped — NUL, newline, carriage return, BOM, a right-to-left
override, `CON.md`, three hundred characters, an ANSI escape.

**The two engines disagreed, and nothing lands without both.** `codex` would escape control and
bidi characters at the console boundary. `fable` would change nothing, and brought two facts
`codex` did not have. Both were re-measured here:

```
raw NUL on the wire      : False        json.dumps escapes C0 on disk and on the wire,
raw ESC on the wire      : False        so the only characters that travel as themselves
raw newline on the wire  : False        are the bidi override and the BOM
raw U+202E on the wire   : True
raw BOM on the wire      : True
```

and the decision this repository already took for its **other** human surface:

```
CHG-20260823-47:213   "_printable … defuses C0 and C1 control characters. Right-to-left …"
ACC-20260823-47:148   the same, accepted
tests/test_cli.py     test_the_terminal_and_the_console_name_the_same_thing
```

So most of what `codex` proposed is already done by JSON, and the live remainder — defusing bidi —
would be done on the console and not on the terminal, putting the two surfaces out of step against a
guard whose whole subject is that they agree.

**Recorded, not fixed.** The sentence this rests on is `attachments.py:116`: the filename is *"Data,
never a path — it is shown to a person and never joined onto the store"*. Measured, every surface
honours it: it is not a path, not scanned, JSON-escaped on the two machine surfaces, and rendered
with `textContent` on the one human surface. It reaches no `print`, no log and no work order — the
only `print` mentioning filenames is the line saying the filename never becomes a path, and
`workorder.py` does not mention `filename` at all.

What the ledger should say, so the next round does not re-open it:

> An attachment filename is accepted with any content except emptiness and padding. It is data on
> three surfaces — the manifest and the API, both JSON-escaped, and the console row via
> `textContent` — and reaches no path, no print, no log and no work order. Bidi controls are not
> defused on the console, as they are not on the terminal (`CHG-20260823-47`, accepted): a name can
> be made to *display* as another name, and nothing in this runner acts on a displayed name.
> Changing this would mean changing both surfaces together, and would need a new reason — a surface
> that acts on the name.

## The guard, and why its first version did not hold

The page-string pattern this repository already uses (`test_the_terminal_and_the_console_name_the_same_thing`). The first version asserted:

```python
assert "f.instruction" in page
```

and was measured `NOT CAUGHT`: the registered mutation replaces the condition with `false`, which
leaves the identifier sitting in a branch that no longer runs, so the substring is still there and
the guard still agrees. Its subject was the text; the property is that the **field decides what the
row says**. It asserts `"f.instruction ?"` now — the read, not the name.
