- Type: behaviour. One constant loses a member, one constant becomes an expression, one moves from

- Risk: low - the shipped table is byte-identical before and after, measured. The user-visible

## The finding, which is three records old

CHG-20260907-19 found one boundary written twice four lines apart and named the derivation as a
follow-up. CHG-20260907-20 narrowed both halves to what the socket does. CHG-20260907-21 stated the
relation between them as an equality a test asserts:

```python
expected = {_authority(addr).lower() for addr in server.LOOPBACK} | RESOLVER_FIXED
assert {host.lower() for host in server.LOOPBACK_HOSTS} == expected
```

with `_authority` and `RESOLVER_FIXED` on the test side, and a sentence saying the record that
derives `LOOPBACK_HOSTS` is the one that lifts both across the line. This is that record. The
equality becomes true by construction:

```python
LOOPBACK = ("127.0.0.1",)
RESOLVER_FIXED = frozenset({"localhost"})            # RFC 6761 6.3

def _authority(addr):     return f"[{addr}]" if ":" in addr else addr
def _accepted_hosts(addresses):
    return frozenset({_authority(addr).lower() for addr in addresses}) | RESOLVER_FIXED

LOOPBACK_HOSTS = _accepted_hosts(LOOPBACK)
```

Measured at `c014889` and again after: the table is the same object it was.

```
LOOPBACK_HOSTS  before  ['127.0.0.1', 'localhost']
                after   ['127.0.0.1', 'localhost']
```

## The question the earlier records left open, and the measurement that answers it

Should `LOOPBACK` collapse to `("127.0.0.1",)`? It has been open since ACC-20260907-20, where codex
proposed it and fable did not, and where the tie-breaker was **this repository's own test failing**
under the narrowing. CHG-20260907-21 showed that vote was circular - the test objected because of
a justification it was in the middle of replacing - and re-opened the question saying nothing in
`tests/test_server.py` objects to the narrowing any more. Measured here, on the merged tree with
`localhost` removed from `LOOPBACK` and **nothing else changed at all** - no derivation, no test
edited: **138 passed, nothing failed.**

138 and not 139, because `test_every_permitted_address_can_actually_be_bound` is parametrised over
`LOOPBACK` and the narrowing takes a parameter with it. An earlier draft of this sentence said
*"142 tests passed"*, which is the finished tree's count pasted onto a measurement of a different
one; a review seat caught it by collecting all three trees. The claim survived the correction and
the number did not, which is the order those two things have to be checked in.

So the question had to be decided on its merits, and deriving the table is what supplies them:

```
                                    derived table            equal to what shipped?
LOOPBACK = ("127.0.0.1","localhost")
    with   | RESOLVER_FIXED         ['127.0.0.1', 'localhost']      True
    without                         ['127.0.0.1', 'localhost']      True     <- the finding
LOOPBACK = ("127.0.0.1",)
    with   | RESOLVER_FIXED         ['127.0.0.1', 'localhost']      True
    without                         ['127.0.0.1']                   False
```

Row two is the whole argument. While `localhost` is both a bind spelling and a name RFC 6761 fixes,
it supplies itself twice, and the standard's term is **dead by data**: deleting `| RESOLVER_FIXED`
from the derivation changes no table, refuses no request and fails no test. CHG-20260907-21 spent a
whole record making that term *required* rather than *tolerated* in an assertion; carrying it into
`src/` beside a second supplier would have undone that on the day it landed.

Run as a mutation rather than as set arithmetic, on a tree with `localhost` put back into
`LOOPBACK` and the union term dropped:

```
FAILED test_it_refuses_to_bind_anything_but_loopback[localhost]
FAILED test_the_derivation_is_the_authority_form_plus_the_name_a_standard_fixes
2 failed, 142 passed
```

Both failures are this record's own assertions, which encode the decision. **Every behavioural
test passed** - the two live `Host: localhost` tests and the `Origin` test among them - which is
the statement that matters: with `localhost` in both constants, deleting RFC 6761 from the server
changes no answer this server gives.

So: **`localhost` leaves the bind list.** One address, one reason each. It was never
configurability - `cli.py` calls `serve(runner, operator, port=args.port, ...)` and has no `--host`
flag, and the only caller in the repository that passes `host=` is a test - and binding the name
bought nothing over binding what it resolves to under `AF_INET`, measured in ACC-20260907-20. It is
still accepted as a `Host` and an `Origin`, through the term that now has to carry it alone.

`serve(host="localhost")` is a `ServerError` from today, and that is asserted rather than left as an
absence: `test_it_refuses_to_bind_anything_but_loopback` gains it beside `0.0.0.0` and `::1`, which
is CHG-20260907-20's own precedent for a removal - refused is a stronger thing to say than absent
from a tuple.

## `_authority` in `src/`: the third piece, and why it is not the third dead one

CHG-20260907-20 left two normalisations dead-by-data on purpose, with a comment at the code saying
which record decided that: `_loopback_host` keeps an IPv6 literal's brackets, `_loopback_origin`
strips them off the table, and with no IPv6 address permitted, removing either left the file green.
Lifting `_authority` into `src/` adds a third piece of bracket logic to a server that cannot bind an
IPv6 address, and the honest question is whether that is one dead branch more.

**It is not, and the difference is measured.** A dead branch inside a function that reads a module
constant cannot be asked about anything but that constant. A dead branch inside a *function* can:

```
mutation                                          objectors, whole file, -x off
_authority stops bracketing                       2   the derivation test, the two-lookup test
_loopback_host loses its bracket branch           1   the two-lookup test
    ... with the two-lookup test deselected       0   139 passed
_loopback_origin loses strip("[]")                1   the two-lookup test
    ... with the two-lookup test deselected       0   139 passed
```

The last two are CHG-20260907-20's dead pair, **NOT CAUGHT by anything before this record and
caught now** - because `test_the_derived_table_answers_both_lookups_for_any_address_it_is_given`
derives the table for a bind list the constant does not have and asks the same two questions a
browser asks.

### And the count was wrong, in the direction that mattered

The first draft of this record said the bracket rules in `src/` went from two to three. **There
were three already**, and a review seat found the third by reading the file this record is about:

```python
# _loopback_origin, ninety lines below the new function
literal = f"[{host}]" if ":" in host else host      # byte-identical to _authority's body
```

One boundary written twice, in one file, added by the record whose subject is one boundary written
twice - and the draft closed by asserting *"there is no second copy"*. It reads `_authority(host)`
now, which is the fix the finding deserves and not a wider one: that call site is where the bracket
is **reached in production**, on every request carrying an IPv6 `Origin`, which
`test_an_ipv6_origin_is_refused_because_nothing_serves_one` sends on every run. So the honest
inventory is three rules before and three after, one of them now named and shared by both callers,
and the count that nothing can falsify goes from three to zero.

Putting the inline copy back is **NOT CAUGHT** - 142 passed, no objector - for the same reason
hardcoding the table is not, and it is written into the group comment rather than registered.

The alternative was a derivation with no bracket rule at all, and it fails the constraint the
earlier records set: it emits the **bare** `::1`, which CHG-20260907-20 deleted as unreachable by
any compliant request, and it would put it back automatically the day an IPv6 address returned.
CHG-20260907-19's sketch `frozenset(LOOPBACK) | {f"[{a}]" ...}` emits **both** spellings and
disagrees with the equality CHG-20260907-21 shipped. The shipped side is bracketed-and-not-bare,
and it is now asserted against literals rather than encoded in an expression that never sees an
IPv6 input.

## What holds the two boundary tests honest, now that the relation is true by construction

Both seats called the tautology the better end state, and it arrives:

- `test_every_address_the_bind_list_permits_is_accepted_as_a_host` **became one** the moment the
  table was derived from the list it was checked against, so it is removed in CHG-20260907-24 and
  replaced by `test_the_derived_table_answers_both_lookups_for_any_address_it_is_given`,
  parametrised over
  `set(LOOPBACK) | {"::1", "127.0.0.2"}`, which derives the table for that one address, patches it
  in and calls `_loopback_host` and `_loopback_origin` with the authority a client would send. Over
  the constant alone nothing could fail; past it, two things can, and the table above is them.
- The set equality is **not** re-asserted. Comparing the shipped table against the shipped
  derivation of the shipped list is the tautology written down, and it is not in the file.
  `test_the_derivation_is_the_authority_form_plus_the_name_a_standard_fixes` states the rule
  against literals instead - `("::1",)` gives `{"[::1]", "localhost"}` and not the bare form,
  `("FE80::1", "MyMachine")` gives `{"[fe80::1]", "mymachine", "localhost"}`, `()` gives
  `{"localhost"}`.
- The **forbidding** half of the exemption moves to
  `test_the_names_a_standard_fixes_are_the_one_member_that_was_measured`. This is a real loss the
  derivation causes and the record has to pay for: under a hand-written table, `runner.local` was
  refused *because nothing derived it*. Now a name added to `RESOLVER_FIXED` flows into
  `LOOPBACK_HOSTS` and every set relation still holds. So the set is pinned against a literal.
- CHG-20260907-21's **three shape conditions do not come with it**, and that is the second thing
  the review changed. Beside a derived expected set they constrained something that could vary;
  beside a literal pin they cannot fail on their own - a member added is refused by the equality, a
  member replaced or recased is refused by the live `Host` test, which reads the same literal - so
  the loop ran over `["localhost"]` and asserted three constants, kept green by the paragraph
  explaining it. That is the exact shape this repository keeps finding, and the record that says
  an entry which cannot fail must not be registered cannot ship an assertion that cannot fail. The
  rule moved to `RESOLVER_FIXED`'s comment in `server.py`, addressed to whoever adds the second
  member, which is the only moment it can be acted on.
- `test_the_name_a_standard_fixes_is_accepted_as_a_live_host_header` is untouched and is now the
  load-bearing one: it is what fails when the union term goes.

### The test-side literal is not a twin, and keeping it is measured

`RESOLVER_FIXED` still exists in `tests/test_server.py`, and importing the production constant
instead would look tidier and would be wrong:

```
parametrised over the test literal   RESOLVER_FIXED emptied -> 5 objectors
parametrised over server.RESOLVER_FIXED                    -> "got empty parameter set",
                                                              1 skipped, exit 0
```

`pytest` turns an empty parameter set into a **skip**, not a failure, so the live-header test would
answer the mutation that matters most in this group by collecting nothing at all, and
`--only resolver-fixed` would report `NOT CAUGHT`. Measured both generically and on this file.

## The mutation that is deliberately not registered

Hardcoding `LOOPBACK_HOSTS` back to `frozenset({"127.0.0.1", "localhost"})`:

```
tests/test_server.py    142 passed, no objector
```

It is behaviour-preserving today, which is what a refactor means and not a hole in it. There is no
test that can fail on it and there should not be one: what this record makes checkable is the
*rule*, on inputs the constant does not have. Registering an entry that cannot fail to make the
group look complete is the thing `tools/mutation_check.py` exists to refuse, so it is written in
the group's comment instead.

## Two costs, measured

```
state                        objectors before          objectors after
LOOPBACK gains 0.0.0.0       3  refuses_to_bind,        2  refuses_to_bind, socket
                                forward table, socket
LOOPBACK gains 127.0.0.2     2  forward table, socket   1  socket
```

The forward table test objected to both because the header set did not follow the bind list. It
follows now, so it does not - and that is the defect being removed, not coverage being lost: the
rule *"an address `serve` permits must be an address a request may name"* is not something a test
can hold any more, because nothing can make it false. Both registry entries are re-anchored to name
the test whose guarantee they now are.

The second cost is smaller and is a direct consequence of a one-member list. `bind` entry 4
mutated `' or '.join(LOOPBACK)` to `LOOPBACK[0]`; with one address those are the same string, and
it measures `NOT CAUGHT`. The assertion is unchanged and still refuses a refusal that names fewer
addresses than `serve` takes - it is the *edit* that stopped being an edit. Re-anchored to a
refusal that names none, which is `CAUGHT`.

## Registry

`derived-hosts`, five entries, and three groups re-anchored. Deleted **with their guarantees**,
because deriving the table made the states unreachable rather than untested:

```
resolver-fixed  "a name a standard fixes may leave both constants together"
                    localhost is in one constant now; entry 1 is the same state in one line
bind            "the header set may accept an authority no listener can answer on"
                    no hand-written header set to edit; both doors are covered elsewhere
loopback        "the header check may be tightened below what the bind list permits"
                    it follows the bind list by construction
loopback        "the bind list may lose an address the header check still accepts"
                    the header check cannot still accept it
```

The last is replaced by what is still true and still falsifiable - `serve`'s own default has to be
a member of its own permit list - naming `test_binding_loopback_is_allowed`, measured at ten
objectors and 52 errors, which is why it names one test and not the file.

## An accepted criterion is retired by name

ACC-20260907-20 criterion 4 reads *"`localhost` still binds and is still accepted | both halves
asserted"*, and half of it is inverted here: it is still accepted, and it no longer binds. A
criterion in a merged acceptance is not something to leave a reader to discover from a diff, so it
is named. What retires it is not this record's preference but the measurement above - the reason
that criterion existed was ACC-20260907-20's second measurement, which CHG-20260907-21 showed to
have been a circular vote, and the reason it now goes is that the term it protects becomes
unfalsifiable if it stays. The half that mattered to a person typing `localhost` into a browser is
the half that is kept, and it is the half with a live test.

## What this does not do

- It does not build IPv6. `address_family` is still `AF_INET` and `LOOPBACK` still holds no address
  that could carry a bracket. What changed is that the rule for one is now stated where a test can
  ask it.
- It does not touch `cli.py`. It prints `http://{host}:{port}` from `httpd.server_address[0]`,
  which under `AF_INET` is a dotted quad and never a name or an IPv6 literal - checked, because the
  same authority-building rule now exists in `server.py` and a copy of it anywhere would be exactly
  the defect this record removes. `cli.py` holds no copy; `server.py` held one, and the section
  above is what happened to it.
- It does not decide whether `LOCALHOST.` (the RFC's own spelling, trailing dot and all) or
  `*.localhost` should be accepted. Both are refused today and CHG-20260907-21 measured why; the
  set they would join is now a production constant with a literal pin, so either is a one-line
  widening with a record.
