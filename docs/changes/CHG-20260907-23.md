# CHG-20260907-23 - a temp path derived from the machine, and two suites deleting each other's tree

- Project: ai-sdlc-runner
- Branch: claude/chg-20260907-23
- Date: 2026-09-07 (UTC+0)
- **Measured against `origin/main` at `03322b1`**, pinned by sha
- Type: test isolation. One helper takes its base as an argument instead of inventing a shared one.
- Risk: low - `tests/` only, and the path is unique per process rather than per machine.
- Autonomy: high
- Target ACC: ACC-20260907-23

## The finding

`tests/test_attachments.py` builds its long-path case under a name that is fixed for the whole
machine:

```python
base = pathlib.Path(tempfile.gettempdir()) / "aslr_deep"
...
shutil.rmtree("\\\\?\\" + str(base), ignore_errors=True)     # before building
```

Nothing in that path comes from the checkout, so two pytest processes in **different worktrees**
share it, and the first thing each one does is delete it. Measured, without needing a race,
because the shared name is the mechanism and the timing only decides who loses:

```
suite A builds its tree, file exists            True
suite B starts (rmtree of the same base)
suite A's file exists now                       False    <- A is now failing
```

`tmp_path` is not the answer, **and the reason the first draft of this record gave was a
non-sequitur**: it said `tmp_path` is "already about sixty" against a guard of 120, which is an
argument that it fits. A seat measured it - 89 characters here, 104 on CI, both under the guard -
and `tests/test_paths.py` grows a 320-character path from `tmp_path` today.

The real reason is that `tmp_path` carries the username **twice**
(`C:\Users\<u>\...\pytest-of-<u>\...`), so each extra character of a username costs two, and
around nineteen it crosses 120 and this test begins skipping itself in silence. `mkdtemp` pays the
username once and leaves about seventy characters of headroom.

## What ships

`_deep(target_len, base)` takes the base rather than inventing one, and the test makes it with
`tempfile.mkdtemp(prefix="aslr_")`:

```
the old fixed name   C:\Users\...\Temp\aslr_deep       46 chars, shared by the machine
mkdtemp              C:\Users\...\Temp\aslr_ixzkwmcm   50 chars, unique per process
the skip guard                                         120
```

Four characters longer, well inside the guard, and it cannot collide. The pre-emptive `rmtree`
goes with it: it existed to clear leftovers from a name that had them, and a fresh directory has
none **at creation**. The `finally` still removes what this process made.

A unique name cannot collide and cannot be cleaned by the next run either, so a killed process
would strand its tree forever: `%LOCALAPPDATA%\Temp` is swept by nothing on Windows, which
`tools/mutation_check.py` already records. **The proof is this record's own working:** while
measuring the fix I left four `aslr_*` entries in `%TEMP%`, including a 30-deep tree, and the
first draft of this paragraph said a fresh directory has no leftovers.

So the pre-emptive cleanup comes back with the collision taken out of it - siblings only, by age:

```python
cutoff = time.time() - 3600
for stale in base.parent.glob("aslr_*"):
    if stale != base and stale.is_dir() and stale.stat().st_mtime < cutoff:
```

A live run's directory is minutes old and is never touched; `base.parent` rather than
`gettempdir()`, because the rule this file now holds refuses *building a name* from the shared
directory and this builds none. Run against the four I had stranded: two removed, and the two kept
were a file (not a directory) and a directory 1.4 minutes old.

## Why this is phase 0 of the queue

It shares a trigger with CHG-20260907-22, which is the other half of this phase: **concurrent
pytest processes**. ACC-20260831-03 recorded that trigger a week ago against the server's listen
backlog, and this is the second thing it breaks. Both had to land before the queue starts running
two tracks at once, or every red in those tracks would be ambiguous.

Different file, different fix, separate records - the split both seats asked for.

## Tests

The first draft of this record said no test was possible without starting a second pytest process.
**A seat pointed out that was wrong** - the property is a rule about the source, and the
repository already tests rules that way:

```python
test_no_test_module_builds_a_path_from_the_machine_s_temp_directory
```

Asked of the syntax tree, so a mention in a docstring does not count and a call cannot hide behind
a rename. `mkdtemp()` and `TemporaryDirectory()` are not matched: they are unique per call, and
what is refused is deriving a **name** from a directory every process shares. Measured: 0 offenders
today, and reverting `_deep` to the fixed name reports `test_attachments.py:497`.

One mutation in `shared-temp`, and its anchor is in `tests/` rather than `src/` - the defect lived
in a test helper, and a mutation that could only be spelled in `src/` could not have reached it.
