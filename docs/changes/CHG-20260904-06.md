Each rule was written to replace a weaker one, and each replacement asks about **the text of the
code** rather than the property.

### L-22 — the scan matched the identifier, not the argument position

`-04` widened `n.args` to args + keywords and left `a.id == "here"`. An alias walks past it, and by
`-04`'s own reasoning no behavioural test can see the difference. **`resolve_verdict` takes the
class as its fourth parameter**, so the question is whether a fourth argument is given at all —
which no renaming dodges.

### L-24 — the scan collected parameter names, never their values

```python
given = {kw.arg for call in calls for kw in call.keywords}
params = {a.arg for a in fn.args.args} - {"self", "version"}
```

`kw.arg` is the parameter name, so `self._answering(gate=None, node_id=None)` read as compliant —
**worse than the original defect, because it looks like it passes them**. And `fn.args.args` misses
keyword-only parameters, so `def veto(self, version, *, gate, node_id)` emptied `params` and the
comparison was vacuously true. Both are one-token edits to the counterexample `-01` shipped.

### L-23 — the ban saw one spelling, and a live citation had been rotten for twelve days

`src/ai_sdlc_runner/plan.py` says *"`engine.py` joins any `--instruction` text onto the node spec's
own, and **line 515** reads `own = spec.get("instructions") or ()`"*. Measured: `engine.py:515` is a
**blank line**; the quoted string is at three places, inside `_brief` and `_order_for`. Written by
`CHG-20260823-34`, wrong for twelve days.

`ACC-20260904-04` reservation 1 said *"The rule bans a pattern that now appears nowhere."* **That
was false when written.** The pattern appeared, in a spelling requiring `.py:` immediately before
the digits — which this one does not have, and which sits 62 characters and one line-wrap away from
the module name.

**And tuning the window was the wrong second attempt.** What makes a citation a citation is the
number, not its distance from a filename. Two patterns, no window.
