## Process failure first, because it is mine

`codex-seat`'s most serious finding is not about the code:

> 驗收中的工作樹從乾淨變成不乾淨,而且修改正好改變核心安全檢查;本輪結果已遭污染。

**I edited the working tree while a verifier was mid-verification, and the edit changed the exact
safety check it was auditing.** It started with a clean tree, found `M src/ai_sdlc_runner/engine.py`
partway through, and correctly refused to certify the result. `fable-seat` had flagged the same
hazard one round earlier and worked around it by exporting a clean snapshot; I did not take the
lesson.

Round 4 is void — both halves. `fable-seat`'s round-4 run was stopped for the same reason once the
contamination was noticed, rather than letting it audit a moving target.

**The rule now, and it is not optional: verification runs against a committed, frozen tree, and
nothing is edited until every seat has reported.** An acceptance round whose subject changed while
it was being examined has verified nothing, however good the findings happen to be.

## The finding that stands anyway

> 以 20 句正常工程任務測 `policy.permanent_halt`,17 句被擋,誤報率 **85%**。

Rerunning its corpus here: **19 of 20, 95%.**

| Ordinary brief | Was classified as |
|---|---|
| `Fix the token parser` | changing secrets |
| `Remove all unused imports` | hard delete |
| `Add production-grade error messages` | production deploy |
| `Migrate the tests to pytest fixtures` | data migration |
| `Add an invoice parser test` | moving money |

**A check that fires on two jobs in three is not a strict check. It is a check that gets switched
off** — and switching it off is one `--undeclared allow` away, at which point four changes of safety
work protect nothing. The false-stop rate is a safety property, not an ergonomics one.

### My own measurement of this was worthless

`tests/test_false_stops.py` had measured **0%** the day before, on twenty briefs I wrote. They were
the briefs *I* would write, and they unconsciously avoided the words my own check matched. A
benchmark you author for your own mechanism flatters it. The verifier's corpus is now kept verbatim
in that file alongside mine, and its half is the one that matters.

### The fix: narrow the backstop, because it is not the guarantee

The word lists were widened in round 2 when they were the *only* check. They are now the weakest of
four layers — brief, targets, declaration, words — and only exist to catch a red line mis-declared
as `ordinary` whose wording gives it away.

A phrase belongs on the list only if it **cannot plausibly describe safe work**. Single common verbs
— "delete", "deploy", "publish", "token", "permission" — are the vocabulary of ordinary engineering
and are out.

| | false stops (46 real briefs) | catches (18 verifier sentences) |
|---|---|---|
| wide | **69%** | 8 |
| narrow | **0%** | 6 |

*(The corpus was written as "36 briefs" here and "56" in the docs it produced; it is **46**. Corrected by CHG-20260823-08, which also made the figure computed rather than typed — six rounds of hand-written numbers being wrong is a process fact, not six accidents.)*

Trading two catches on the weakest layer for twenty-five false stops is not a close call, and the
three layers that carry the guarantee are untouched.

## The other findings

**Curated fields, the second time.** `_SPOKEN_FIELDS` read `instructions`, `objective`, `scope` —
three of the nine a spec has. A red line written into `done_criteria` or `acceptance_predicate` ran
to completion, reproduced before changing anything. This is the same mistake as reading only
`operation["description"]`, one round later. **Every** field is read now, and the paths a brief names
(`input_artifacts`, `expected_outputs`, `workdir`) go through the target rules as well — a node whose
expected output is `prod/manifest.yaml` has said something factual about what it touches.

**`settings.py` contradicted itself.** Its module docstring said a corrupt file yields the defaults;
`load()` directly below raises. The code was right; the paragraph is corrected.

**All 48 target regexes verified.** `codex-seat` tested each with an independent positive example
and all 48 match — the `\b`-placement class of bug from round 3 has not recurred.
