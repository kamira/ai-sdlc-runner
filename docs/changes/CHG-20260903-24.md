## Why it is withdrawn

The risk seat said it plainly in the sixth round and the other three measured the same facts from
their own angles. Three of them are decisive and none is about the design being *wrong*:

### The render already exists, on both surfaces, node-attributed

```
cli.py     print(f"panel:         {decision['node_id']} → {said} ({seat_line})")
console    block("adjudicated", ...) → node_id + " -> " + said + " (" + reason + ") [" + voices + "]"
```

Both loop every adjudication, both print `grade || outcome`, both name the voices, and **both carry
the node id**. `report.adjudications[-1]` carries it too — every append is
`{"node_id": node.id, **outcome, ...}`. What `[-1]` discards is not the id but the **binding to
the stopping node**: it is whichever adjudication happened last, which at `merge` is another
node's judgement entirely. The seventh draft said *the id*, which is false, and the risk seat
caught it. What this record would add is
**adjacency**: moving the relevant line into the *"Waiting for you"* box.

### The bound admits the two cells the record spent two sections protecting

Task 9 was *"shown only where the verdict is `confirm`"* — the risk seat's own correction, adopted.
Measured:

```
cells the bound admits   5   plan_confirmed@medium · feasibility_confirmed@medium
                             before_dispatch@medium · pr@high · merge@low
cells the record states  3
unstated and admitted    2   pr@high · merge@low
```

Task 10 was withdrawn so that no model speaks at `merge` before the person does. **Task 10 removed
the dispatch; the render was never bounded to the node.** At `merge`, `adjudications[-1]` is
`qa_accept`'s panel — a different node's judgement about acceptance, displayed as the one-way
door's pre-answer.

### On a default install it delivers nothing

```
pre-answers shown at the three stated cells
  node_models = {}         0
  one model per panel      0
  >= 2 models per panel    3
```

Which is verbatim the defect this record's own first section convicts its **first** draft of:
*"Zero of eight stops carried a pre-answer. The deliverable was a sentence and an exit code."*

**The seventh draft gave the wrong reason for that zero**, and the right one is worse for the
design. It said `single-ask path, no adjudications`. There *are* adjudications on a default
install — `lead_review` is a `seat_panel`, and `_adjudicate` appends regardless of
`node_models`. Driven to the merge stop:

```
merge@low, node_models = {}   adjudications 1   [-1] = lead_review -> pass | 3/3 seats passed
merge@low, panels             adjudications 6   [-1] = qa_accept   -> pass | 3/3 voices passed
```

So the zero holds only at the three *stated* cells. At `merge` the design fails **on a default
install, with no model configured anywhere** — it would show the code-review panel's verdict
on built work as the one-way door's pre-answer. The failure there is unconditional, not
contingent on anyone configuring a panel. Found by the risk seat, re-measured here.

## Status

**Withdrawn** — nothing was built, so nothing is owed an acceptance.

`withdrawn` is the vocabulary's own word for a decision that was made and produced no work:
`tools/ledger_check.py` excludes it from `AWAITING_DECISION` precisely because *"these say the
decision has **not been made yet**"*, and this one has. `closed` would have been wrong for the
same reason in the other direction — it sits in `DONE` and would demand an acceptance for a
record that produced none. `CHG-20260901-15` used the same word three days ago, so this sets no
precedent for withdrawing; what it is first at is withdrawing with **no successor**.

The adjacency got its own number: **`CHG-20260904-11`**, which built it — and not the way this
record proposed. `adjudications[-1]` is unbound; what shipped is `adjudication_here`, the
adjudication for the node the run is **stopping at**.

**`CHG-20260903-25` is also withdrawn**, one round later, on the conformance seat's ruling that a
record whose citations cannot be made true is an instrument rather than a proposal. So both halves
of `CHG-20260901-15` are now recorded as re-issued into records that produced nothing; that, and
「可以依節點 by pass」, are named in `README.md` § *Known gaps*, which is where this ledger puts a
requirement nothing owns. `-25`'s own real discovery — that `policy.relax` consults no node, so a
class relaxes everywhere or nowhere — is named there too, under its own entry.

What this record said about `-25`'s two conditions stands and is now history: its task 23 was

than `policy.check_routing`.
