## Read this first: as first drafted, this shipped nothing

Four seats reviewed the first draft. All four failed it and the conformance seat vetoed it. Two
things it claimed are false, and both are measured below rather than argued:

```
gates that hold a pre-answer at a stop, as first drafted, on a default install

  claimed  [======]  6
  measured [      ]  0
```

`ANSWERED_FIRST` shipped as `{}`, so `answering()` returned `("operator", "default")` for all ten
gates; and with `node_models = {}` the five model panels take the single-ask path and produce no
`outcome`, `reason` or `verdicts` at all. **Zero of eight stops carried a pre-answer.** The
deliverable was a sentence and an exit code.

`-25` states its own zero in its first section and this record did not. That discipline is the thing
the split was justified by, so it is here now.

### And "falsifies zero governing texts" was untested

The first draft justified `ANSWERED_FIRST`'s shape three times by `routed_to` / `HALT_ROUTING` /
`DEFAULT_RECIPIENT` — which is exactly *a project-configured store table read into a policy
function*. The conformance seat named three texts that would fall under that reading. **Re-measured, none of
them falls, and the third is already false for an unrelated reason:**

- `settings.py` is **scoped** — *"Settings cannot touch a gate verdict, a permanent halt, or the
  adjudication rule"* — and a per-gate answerer is none of those. It also would not arrive through
  `settings.FIELDS`.
- `settings.py`'s operator-facing refusal was rewritten by CHG-20260903-28 to be **derived from
  `FIELDS`**, so it names whatever the runner actually reads.
- `docs/structure/data.md` — *"everything about the governance is in `policy.py`"* — **is already
  false on `main`**, and neither split record made it so. `halt_routing` is a `CREATE TABLE` in
  `store.py`, written there, read by `store.halt_routing(db)`, carried on `RunConfig` and passed
  into `policy.routed_to(kind, routing)`. Who a halt is routed to is governance, it lives in a
  project store table, and `policy.py` reads it as an argument. Filed as **CHG-20260903-33**.

So the sweep's conclusion changes: a project override would falsify **no** text that is true today.
What it would do is make this record depend on -25's store table, reader, CLI surface and door
validation — which is the defect seat's finding and the reason the ruling below still stands.

**The ruling this draft takes**, and it settles both problems at once: `ANSWERED_FIRST` ships
**populated in `policy.py`**, the way `HALT_ROUTING` ships six rows, and there is **no `table=`
parameter and no project override.** Then:

- zero texts fall, because nothing configures it;
- the feature is not inert, because the table names real gates;
- and the record stops leaking into `-25`, which is the defect seat's finding below.

**What that costs, stated plainly: 「可以依節點 by pass」 is not delivered by this record.** A
per-node project setting needs a store table, a reader, a CLI surface and a door validation — which
are `-25`'s tasks 12 and 13. The first draft's `table=` parameter was a socket wired to a record
this one claims to be independent of.

## The design

### `ANSWERED_FIRST` — one bit, in `policy`, shipped populated

```python
#: Whether a stop is answered first by a person or by the node's own voices. Data, beside `GATES`.
#: Populated, the way `HALT_ROUTING` is — an empty policy table whose only consumer is a default is
#: the shape CHG-20260901-16 D4 was filed for. There is no project override and no `table=`: this
#: record has no configuration surface, and that is what makes it independent of CHG-20260903-25.
ANSWERED_FIRST: Dict[str, str] = {...}       # gate -> "node"
DEFAULT_ANSWERER = "operator"

def answering(gate: str) -> Tuple[str, str]:   # (who, source); str in, str out
```

`str` in, `str` out, keyed by the same thing its argument is — `routed_to`'s shape, minus the
override. `source` therefore has **two** values, not three, and the docstring says so rather than
copying a third that cannot occur.

Three earlier drafts got the key wrong in three ways, each killed by a seat: draft two wrote
`models`, a **value** of `adjudicate`'s `voices=` parameter — which at `lead_review` would have
silently stripped `conformance`'s veto, because that branch is documented *"No voice vetoes."*
Draft three wrote `voices`, the parameter's own name. Draft four returned four answerers from a
resolver in `policy.py` taking a `graph.Node`, reversing the only dependency edge this codebase has.

### Which arrangement answers is read in `engine`, from three inputs

The first draft's task said `(mode, grades_risk)`. Measured, `walk` selects on
`if node.mode == MODEL_PANEL and len(configured) > 1:` (`engine.py:2145`) with `if node.grades_risk:`
**nested inside it**. The selector is `(mode, len(configured), grades_risk)` — and the third input is
exactly what the chart's "needs >= 2 models" column is about. The first draft's own §"On a default
install" proves the pair is insufficient, two sections from the task asserting it.

### The pre-answer is the run's own adjudication record — and which entry

`walk` writes `report.adjudications.append({"node_id": node.id, **outcome, "verdicts": …})` at four
sites. **The idiom is to spread the adjudicator's own output**, not to enumerate a shared subset:
draft four enumerated five keys, carried `vetoed` (which `adjudicate_grade` never returns) and
dropped `grade` and `proposed` (which `adjudicate` never returns). `CHG-20260901-18` is titled *"the
grade a panel decides reached nothing that names it"*.

**Which entry, when a node has several.** The re-run loop appends one per round, so `lead_review`
failing once then passing leaves two entries and no key names the lap. The pre-answer is the **last
entry for that node id** — and `engine.py:2458` already does `report.adjudications[-1]` with **no
`node_id` filter at all**, which is a defect this record must not copy.

## The one open question, and its real cost

`lead_review` is the only `after` gate whose pre-answer is not free: `_adjudicate` runs *after*
`_gate("after")` and calls `_send_back`, which mutates the report.

The first draft named the report mutation. It did not name the routing, which is the sharper half:
`_adjudicate` is called **43 lines after** `_gate("after")` and after the `strictest` re-resolution,
so moving it ahead of the gate means that at `lead_review` @ high — where `GATES` says `HALT` — a
failing panel would route to `review_failed` through `_send_back` **before the human halt fires**.

This stays an open question and is **not** carried as a task with a done-when, which is what the
first draft did with it.

## Task 10, restated, because the first draft laundered a risk

The first draft said `pr` and `merge` *"need a new ask"*. Measured, both are `gate_when="before"`,
`mode="single"`, `role="lead"`, `can_execute=True`:

```
today    _gate("before") -> ask -> effects        the stop is first
drafted  ask (to produce the pre-answer) -> _gate  a model speaks first
```

Two texts say the stop comes first — `graph.py:307` (*"a one-way door — its gate is consulted
BEFORE, because the stop has to come before the door swings"*) and `docs/structure/logical.md:58`.
**Between the two split records nobody owned "a model now speaks at merge before the person does."**
The risk seat's words, and it is the finding that most damages the split's accounting.

So: a **recommendation order** with `can_execute=False`, and the node's real ask stays where it is,
after the gate. The stop keeps its place.

## Risk & rollback

- **Two gates gain a dispatch**, `pr` and `merge`, and it is a recommendation rather than the node's
  work. The other `after` gates gain none — which is now consistent with the chart above, where the
  first draft's Risk section contradicted its own chart sixty lines up.
- **A pre-answer is a recommendation a person may follow without reading.** The stop survives; the
  quality of attention behind it may not. Task 13 makes the *absence* of reading visible. Nothing
  makes the presence provable.
- **`lead_review` is the sharp one** and it is the open question, not a task.
- **This falsifies no governing text** — under task 3's ruling, and only under it. If a later record
  gives `ANSWERED_FIRST` a project source, `settings.py:25`, `settings.py:152` and
  `docs/structure/data.md` fall with it, and that record owes the sweep.
- Rollback: revert. Every gate answers cold.
