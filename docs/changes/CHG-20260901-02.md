## A correction that replaced a true statement with a false one

The worst of them. CHG-20260901-01 struck a before/after row as fabricated:

> `| a blank line carrying U+3000 | ~~excused~~ **already refused** | refused |`

Measured against the code that round was correcting, loaded from `38f2a39^` and driven directly:

```
break carrying U+3000    excused=True     ← the original row was right
break carrying a space   excused=False
```

The strike was applied under a **(VETO)** label, executed on a previous round's say-so without
re-measuring, and my own first attempt to check it used a fixture ending in a full stop — which the
sentence bound refused before the paragraph rule was consulted, producing `False` and appearing to
confirm the strike. The row is restored.

## The harness broke on a group nobody ran

`_import_fails` keyed on `path.parent.name == "ai_sdlc_runner"` and sent everything else to a
hard-coded `tools`. Three shipped mutations target `tests/test_subprocess_codecs.py`:

```
$ python tools/mutation_check.py --only codecs
3 of 9 did not report CAUGHT …
  - the rule matches a keyword spelled `text` rather than a process launch
  - going through `paths` stops counting as naming a codec
  - the file survey stops looking at bare open() as well
```

Three false `BROKE`s and exit 1 on a clean checkout, telling the author to re-anchor three correctly
anchored mutations — which is the failure the outcome exists to remove, reintroduced by fixing one
arm of it. The acceptance ran `stranded`, `closure`, `reach` and `console`; `codecs` is the one group
with a non-`src/` target and it was never run.

`test_every_mutated_file_still_imports_before_it_is_mutated` runs the probe over every target now.

## And the same 3.10 call was still shipped, in a documented command

`tools/render_cast.py:170` used `Path.write_text(newline=…)` — removed from a test last round
because it is 3.10+ and this project's floor is 3.9. It sits in `main()`, which no test calls, so CI
structurally cannot reach it, while `docs/RECORDING.md` publishes that script as the command to run.
An operator on the declared floor got a `TypeError` after all the render work was done. The tree is
swept: zero live calls remain.

## Two guards that decided less than they said

- **The record gate read four fields and decided one.** `path`, `original` and `mutated` were
  subscripted *above* it, so a record missing any of them raised `KeyError` first and `missing`
  could only ever be `['owner']` — with two of the three rows written to make it concrete passing
  through the older arm. The reads moved below the gate.
- **Its refusal still printed the sentence the fix was named for.** The `ValueError` was raised into
  the handler above, which wraps everything in *"it cannot be read … so this cannot tell which file
  was mutated or what it held"* — about a record whose `path`, `original` and `mutated` were all
  read and all fine. The shape gate has its own refusal now, and it names the field.
