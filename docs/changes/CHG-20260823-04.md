## The limit being closed

CHG-20260823-02 made the red lines a **declaration**: each operation says which of six kinds of
irreversible work it is, an undeclared one is refused, and word lists were demoted to a backstop.
That fixed the defaults, and two independent rounds agreed it holds.

Every round then ended with the same paragraph:

> **The declaration is only as strong as the planner.** An operation declared `ordinary` and
> described in words that give nothing away will be dispatched. The backstop catches carelessness,
> not intent. Deriving the kind from what the operation will actually touch — paths, commands,
> endpoints — is the stronger design and is not built.

It is built now.

## What changed

An operation may name the **targets** it will act on — commands, paths, URLs — and those are read
directly by `policy.derive`. Three layers decide, each able only to **add** a stop:

| Layer | Reads | May overrule | Why |
|---|---|---|---|
| targets | `kubectl apply -f prod/`, `rm -rf /srv/audit`, `secrets/key.pem` | the declaration | A target is a fact. `rm -rf` in a command is not a phrasing choice and a path under `secrets/` is not an opinion |
| declaration | the plan's `kind` | the backstop | A planner who says `delete` is believed about that. Undeclared is still refused |
| description | word lists | nothing | The backstop. 8 of 18 known attempts. Never trusted alone |

`derive` returns **every** matching kind rather than the first: `.env.production` is a secrets file
*and* sits in something called production, and stopping while naming one of them is a half-truth.

### What is recorded rather than solved

An operation that declares `ordinary` and names no targets is taken on the plan's word. It is **not
blocked** — an empty target list is exactly as forgeable as a wrong `kind`, so requiring one buys
ceremony rather than safety. It lands in the run report under `on_trust`, and the CLI prints it as
`unverified:`, so an auditor sees precisely which steps nothing checked.

That is the honest shape of the remaining trust: not removed, but no longer invisible.

### Risk & rollback

- Risk: **high**. This decides whether irreversible work proceeds.
- Named failure mode: **false stops**, and this direction has a real cost. A check that fires on
  `git commit` is one people route around with `--undeclared allow`, which would undo the previous
  two changes. Eight ordinary development targets are pinned as a test for exactly that.
- Second: **regex boundary bugs**. One shipped in the first draft of this change — the Slack pattern
  ended in `\b` after `post`, so `chat.postMessage` did not match, and the test caught it. Patterns
  that look right and match nothing are the KN-4 shape.
- Third: the target list is not exhaustive and cannot be. It is a **floor** under the declaration,
  not a replacement for it.
- Rollback: `git revert`.

### Not done, and not claimed

**The target list is a floor, not a ceiling.** It recognises what it recognises. An operation that
names no targets, or names ones nothing matches, still rests on the declaration — which is why the
trust is recorded rather than assumed away. Deriving targets from the work itself, instead of from
what the plan says the work will touch, would need the runner to execute or statically analyse the
step, and that is a different system.

**Acceptance.** `halt_independent` at high risk, and I am the implementer. Three rounds have run;
none has been a pass, and each found something real.
