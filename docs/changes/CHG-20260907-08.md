## Two findings that meet at `rejects_to`

**R-4 (risk seat).** `validate` accepted any `rejects_to` that existed and was not the node itself.
Retargeting each of the 48 edges to `merge`, `pr` or `done`, 68 of 144 passed; **all 24 retargets
of the eight rejection edges passed**, and the 76 refusals were all "unreachable node" — none about
direction. The shortest bad path: `qa_accept.rejects_to = "pr"` with `--confirm pr --confirm merge`,
so a person's **refusal** at acceptance ends in a **merge**.

**L-1 (defect seat).** `_WHOLE_CHANGE_REJECTED = ("review_failed", "acceptance_failed")` is a
hand-written list of exactly the nodes whose `.next` is `change_retry`. One word —
`qa_accept.rejects_to` to `next_module` — left `test_change_bound.py` and
`test_sendback_retry_reject.py` at **43 passed** while the bound stopped firing.

## Four structural rules, and why none of them is the repair

The seat proposed the first. All four were measured before anything was written.

| candidate | shipped edges | `qa_accept -> pr` | |
|---|---|---|---|
| the target reaches this node again | 8/8 pass | **passes** | vacuous — the flow is one cycle |
| this node is on every path to `merge` | **7/8** | refused | refuses `lead_task_review -> fix_pass`, which ships |
| the target is not downstream | 8/8 pass | **passes** | same cycle, same vacuity |
| answerable without passing `merge` | 8/8 pass | refused | **defeated below** |

The fourth survived my own attempts and was defeated by `codex`:
`qa_accept.rejects_to = "qa_verify"` reaches `qa_accept` again without touching `merge`, so the
rule accepts it — and the retry skips the whole-change `lead_review` gate. Measured:

```
gates on the normal return  acceptance_failed -> qa_accept :  lead_review, qa_verify
gates on the bypass         qa_verify         -> qa_accept :  qa_verify
```

**Which gates a refusal must pass is policy, and connectivity cannot express it.** That sentence is
the finding; the four rows above are why it is not a failure of imagination.

## What ships instead, in three parts

1. **A weak rule in `validate`**: a rejection may not name a target that cannot reach the node
   again. It refuses `qa_accept -> done` and `-> halt_change_rejected`, and **nothing else** — a
   refusal that ends the run is not a refusal. The comment beside it lists the four candidates, so
   the next reader asking "why not stricter" has the measurements rather than a shrug.
2. **`test_where_each_refusal_goes_is_pinned`**, naming all eight edges. This is what actually
   protects the property. Changing one is not forbidden; it is a decision, and this is where it has
   to be made.
3. **`_whole_change_rejected()`**, derived from `node.next == "change_retry"` instead of written.
   `qa_verify.rejects_to` is `next_module`, whose `.next` is not `change_retry`, so a QA refusal
   stays outside the bound — CHG-20260828-22's own decision, now preserved by deriving rather than
   by remembering to exclude it.

## One of mine, which the mutations reported twice

The first attempt made the derivation a module-level constant. `--only refusal-routing` said:

```
ANCHOR GONE  an acceptance refusal routes around the whole-change bound
NOT CAUGHT   the bound goes back to a hand-written pair of node names
```

The second is the interesting one. Reverting a derivation to the literal it equals **cannot be
detected**, because the two produce the same tuple — no test can tell. And computing it at import
made it a snapshot: `engine._MODULE_CYCLE` is exactly that, and round fourteen's defect seat
measured it disagreeing with `plan.py`, which asks per call, about a node added later. **The change
removing one hand-written copy introduced the very pattern this round reports elsewhere.**

It is a function now, asked per call, and
`test_the_whole_change_bound_reads_the_graph_rather_than_a_written_list` adds a **third** node
routing into `change_retry` and asserts the bound sees it. Under the written pair it does not.
