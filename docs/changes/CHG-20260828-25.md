## The gap

`sandbox.py:171`, inside `_seatbelt`:

```python
lines.append(f'(allow file-write* (subpath "{root}"))')
...
return [tool, "-p", " ".join(lines), *argv]
```

`root` is `os.path.abspath(workspace or os.getcwd())` (`:137`), interpolated into an sbpl string
literal with **no escaping**, and the assembled profile is handed to `sandbox-exec -p`.

macOS paths may contain `"`. A path that does turns a policy into a broken one — and a path chosen
to do so turns it into a **different** one:

```
root = /tmp/x") (allow network*) (allow file-write* (subpath "/
```

renders as a profile that allows the network the grade denied. The quoting is the whole of what
keeps the policy table and the enforced policy the same document.

## Why this is worth a record and not a one-line patch

Two reasons, and the second is the one that decides the fix.

**It is in the boundary.** Everywhere else in this repository a malformed input produces a wrong
answer. Here it produces a **wider** one, and the module's own docstring is about not making claims
nothing backs.

**sbpl has no escape for `"` inside a string literal.** So "escape it" is not available in the way
it would be for a shell or for JSON. The choices are to refuse such a path, or to encode it in a
form sbpl accepts. This record proposes **refusing**, because that is what `policy.sandbox_for`
already does one function over when it meets a write scope it does not implement:

> a typo in it is refused rather than absorbed

A path that cannot be expressed in the profile is the same shape of problem, and it should get the
same answer.

## The narrower question underneath

`_bwrap` takes the same `root` and passes it as an **argv element**, where quoting does not arise.
So the two mechanisms do not merely differ in what they enforce (CHG-20260828-04's subject) — they
differ in **which inputs they can represent at all**. A path legal for one is a refusal for the
other, and nothing today says so.

## Risk & rollback

- Task 1 makes some paths refusals that currently produce a broken profile. Both fail; this one
  fails with a reason.
- Task 5 is the false-stop guard: the fix must not refuse a path with a space or a CJK component,
  which are ordinary and which the current code handles correctly.
- Rollback: revert. Nothing on disk changes shape.

## Status

**Superseded** by CHG-20260903-30, which builds it.

This record sat as an open pull request for six days with green CI — green because a
docs-only branch passes trivially, not because anything was built. Its analysis is the one
CHG-20260903-30 follows, including the ruling that the path is **refused** rather than
encoded and the three things this record declined to claim. It is merged here rather than
closed so the reasoning stays where a reader can walk to it.

### Not claimed

**That this is exploitable today.** `root` comes from the operator's `--workspace` or `cwd`. An
operator who wants a wider sandbox does not need a crafted path; they can pass a flag. What this
fixes is a boundary that stops being one if that ever stops being true — and a policy that can be
altered by a filename is not a policy.

**That refusing is better than encoding.** It is the answer consistent with this file's neighbour.
If someone finds a representation sbpl accepts for every path, that is a better fix and this record
should be argued with rather than followed.

**That `"` and `\` are the whole set.** They are what breaks the literal. Whether sbpl has other
metacharacters inside `subpath` was not established, and task 1 should not pretend a blocklist is a
proof.
