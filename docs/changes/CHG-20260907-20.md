# CHG-20260907-20 - a permit list that named an address the socket has never opened

- Project: ai-sdlc-runner
- Branch: claude/chg-20260907-20
- Date: 2026-09-07 (UTC+0)
- **Measured against `origin/main` at `b9f7688`**, pinned by sha
- Type: behaviour. One constant loses a member, one loses two, one error branch splits in two.
- Risk: low - the removed member has never worked here, and nothing has ever passed
  `host=`. The user-visible change is that a failure which is not a port conflict stops being
  called one.
- Autonomy: high
- Target ACC: ACC-20260907-20

## The finding

`LOOPBACK`'s own comment calls it *"the only addresses this server will bind"*. One of its three
members has never been bound since the file was created. Measured on Windows, py3.11:

```
ThreadingHTTPServer.address_family is AF_INET, and serve's _OneRunner does not change it.

AF_INET bind    127.0.0.1         ok
                localhost         ok  (resolves to 127.0.0.1)
                ::1               gaierror [Errno 11001] getaddrinfo failed
                ::ffff:127.0.0.1  gaierror
AF_INET6 bind   ::1               ok
```

And the branch that reported it made the defect hard to see, because it named a cause the
exception does not establish:

```python
except OSError as exc:
    raise ServerError(f"cannot listen on {host}:{port} — … Something is already there. "
                      f"If it is another `runner serve`, stop it first …")
```

`socket.gaierror` is an `OSError`. So `serve(host="::1")` reported a resolver answer as a port
collision, and told the operator to go and stop a runner that was not running.

## Two lists, and which member of each goes

Found by review of CHG-20260907-19, which pinned the agreement of `LOOPBACK` and
`LOOPBACK_HOSTS` and deliberately left the socket alone. That was right for those tests and it
is why this is a separate record.

```
LOOPBACK        loses "::1"                     it is not an address this server binds
LOOPBACK_HOSTS  loses "[::1]" and "::1"         no listener can answer on either
```

The header spellings go with it because of what the guard is for. A browser sends
`Host: [::1]` only from a URL that connects to `::1`, where this server is not; the bare
`"::1"` was reachable only through an unbracketed authority RFC 7230 5.4 does not permit. Both
are surface a legitimate request cannot use, and the reverse test CHG-20260907-19 added is what
required them to leave.

`localhost` stays. It was proposed for removal on the grounds that binding it depends on
resolver ordering; measured, that is a property of choosing a family, not of binding under a
fixed one:

```
AF_INET bind "localhost"        -> 127.0.0.1
getaddrinfo("localhost") order  -> [AF_INET6, AF_INET]
```

The IPv6-first ordering cannot move a bind whose family is already `AF_INET`. And removing it
would have taken it out of `LOOPBACK_HOSTS` as well, refusing `Host: localhost:8765` - a request
a person makes by typing localhost into a browser.

## Why not build IPv6

It costs the guarantee `_OneRunner` exists for. Measured:

```
AF_INET  127.0.0.1:59180  held
AF_INET6 [::1]:59180      ALSO BOUND
```

`allow_reuse_address = False` guards one family. Two runners on one port answering at random is
the thing `_OneRunner` was written to stop, and family selection reintroduces it across
families. Nothing has ever asked for IPv6: no `--host` flag exists, `cli.py` calls
`serve(runner, operator, port=args.port, …)`, and every test that starts a server passes
`port=` alone. (One test passed `host="0.0.0.0"` - to be refused.)

## The error branch: two, not four

```
EADDRINUSE      keeps its sentence -- errno.EADDRINUSE is 10048 on Windows, measured, and
                `test_a_second_runner_cannot_bind_the_same_port` holds a real port against it
anything else   "cannot listen on {host}:{port} — {exc}." and no cause
```

One seat proposed four branches, with a bespoke sentence for the resolver and another for
`EACCES` carrying `netsh excludedportrange` advice. Both were declined, and `EACCES` is the case
that shows why: it is reported for a port another component has reserved on Windows and for a
port below 1024 on Linux, so any advice this file wrote would be wrong on half the machines it
runs on. Neither cause was reproducible here - `netsh interface ipv4 show excludedportrange
protocol=tcp` lists nothing on this machine - so both readings stay readings. The first draft of
this record and of the source comment stated the Windows one as *"the live case"*, which is a
cause asserted from a reading; the review caught it.

**And the argument had a premise nothing held.** Two branches are defensible only because the
plain one carries the operating system's own sentence. Measured after this shipped:

```
raise ServerError(f"cannot listen on {host}:{port}.")     the whole file: 135 passed
```

The test asserted only that the message does not claim a conflict, never that it still says what
happened. `bind` mutation 5 is that, and the assertion is `"permission denied" in said`.

## Also fixed, and it was caught by nothing

```
f"it listens on {LOOPBACK[0]} and nowhere else"
```

One address named, several accepted. Mutating it back was **NOT CAUGHT** by the whole file, so
the sentence changed with nothing requiring the change - `test_it_refuses_to_bind_anything_but_
loopback` matched only `"refusing to bind"`. It now asserts that the refusal names every address
`serve` takes.

## What is deliberately left

- **Both** normalisations become dead-by-data rather than dead code: `_loopback_origin`'s
  `strip("[]")` and `_loopback_host`'s bracket branch. Measured, removing either leaves the file
  green (135 passed each). They are what an IPv6 build would need back, and CHG-20260907-19
  already recorded that the pair was unfalsifiable while both forms sat in the table. Left, with
  a comment at the code saying which record decided that and why.
- The reverse test's **justification** is wrong for one member: `localhost` belongs in the header
  set because RFC 6761 fixes its loopback meaning in the resolver, not because it is a bind
  spelling. Today it is both, so the containment holds for the right reason and a wrong one. That
  is a defect in a merged record's reasoning, not in its assertion, and folding it in here would
  hide it. Its own record.
- IPv6 support, above.

## Tests

```
test_every_permitted_address_can_actually_be_bound   parametrised over LOOPBACK, opens a socket
test_a_bind_failure_is_not_reported_as_a_port_conflict
test_a_port_that_is_taken_still_says_so
test_an_ipv6_origin_is_refused_because_nothing_serves_one
test_it_refuses_to_bind_anything_but_loopback        now asserts what the refusal names
```

`http://[::1]:8080` moves from `test_our_own_origins_are_still_accepted` to a refusal, rather
than being deleted: it is a different origin from the one this server serves, and the day
somebody builds IPv6 that test is what has to be argued with.

Six mutations in `bind`; the last two were added in review of the build. The `loopback` group
from CHG-20260907-19 is re-anchored - four of its five entries survive the narrowing, and the
fifth is **deleted with its guarantee**: there is no permitted IPv6 address left for a bracketed
form to be lost from.

The sixth is the other kind of widening, and it settles a disagreement between the seats about
the socket test. One proposed weakening its assertion from `server_address[0] == "127.0.0.1"` to
`ipaddress.ip_address(...).is_loopback`, on the grounds that the exact address is a resolver
detail and that nothing showed the assertion was load-bearing. Measured, with `-x` off so every
objector speaks:

```
LOOPBACK gains "0.0.0.0"     refuses_to_bind[0.0.0.0], the forward header test,
                             and can_actually_be_bound[0.0.0.0]
LOOPBACK gains "127.0.0.2"   the forward header test, and can_actually_be_bound[127.0.0.2]

ipaddress.ip_address("127.0.0.2").is_loopback   True
```

So the assertion is load-bearing - the socket test objects to both - and the proposed weakening
would have missed `127.0.0.2` entirely, which is the address CHG-20260907-19 used to open this
whole thread. The strictness is kept and the mutation is registered so that it stays measured
rather than argued.
