## Read this first

`_split_cfg` with both workstreams pre-authorised by `alex@example.com`:

```
engineer_build   class in force: standard
lead_review      class in force: standard
merge            class in force: standard     <- the one-way door

cfg.change_class            None
report.class_authorised_by  ''                <- engine.py:1896 reads only cfg.change_class
relaxation(by=None)                           -> filed under the RUNNER
who actually authorised     alex@example.com  -> sitting in the plan the whole time
```

`conversations.relaxation`'s own docstring is the rule this breaks:

> *"`--store-remote allow` is the runner recording its own configuration, and a change class is a
> person pre-authorising a type. The first is the runner's voice; the second is not, and an export
> that files a person's pre-authorisation under `runner` misattributes it in the one dimension the
> document exists to record."*

## The gap is unconditional, not occasional

`cli.py:1228` **refuses** a run-level `--change-class` when the plan names several workstreams —
deliberately, because *"one sentence cannot have assessed all of these"*. So for a split programme:

```
declared_class    is necessarily None      the refusal at 1228 guarantees it
cmd_run:997       never fires              the export carries no declaration turn at all
cmd_serve:1347    never fires              the same guard, the same miss, one module over
cfg.change_class  is necessarily empty     so engine.py:1896 computes '' every time
```

**The per-workstream form exists for split programmes, and on split programmes the attribution
always fails.** Not a case that slips through — the only case there is.

**And the miss is in two places.** `cmd_run` and `cmd_serve` guard the declaration turn with the
identical `if declared_class and conversation is not None:`, so both drop it for a split programme.
CHG-20260903-36 was *“two fixes shipped into one module and never swept into their siblings”*; this
one is swept before it is written.

## Why one authoriser is the wrong shape

`class_authorised_by` is one string per run, and a split programme can have a different person per
workstream. Folding them into that one field would put several names against a gate only one of them
assessed — a second misattribution rather than a fix.

**But naming several people is right for a gate that belongs to no workstream.** `merge` relaxes
only if `policy.combined_class` finds *every* workstream pre-authorised, so it opened on all of
their authority at once, and listing all of them is the truthful answer there. This draft first
called that a misattribution too; the distinction is the scope of the claim, not the number of
names.

At the append site (`engine.py:2077`) `node` is in hand and `_class_in_force(cfg, node, today)` has
already chosen which class applies, so the authoriser **for that node's workstream** is reachable
exactly where the note is written.

Shapes considered:

| shape | why not / why |
|---|---|
| join the authorisers into `class_authorised_by` | as a **run-level** field, names several people for a gate only one of them assessed |
| make `relaxations_by_class` a list of dicts | `as_dict()` emits it and `docs/SCHEMAS.md` documents it — a schema break |
| **a parallel `note -> authoriser` map** | additive; the note is already the key the export iterates |
| recover the node by parsing the note's `f"{node.id}: "` prefix | parsing our own formatted string |

**Chosen: the parallel map**, named in `RunReport` and emitted by `as_dict()` — which
`test_the_report_emits_every_field_it_declares` will require, and that is the guard that makes the
new field reach a reader rather than stopping at the terminal.

## Task 3 needs no new test, and that was checked rather than assumed

`test_the_report_emits_every_field_it_declares` asserts `declared - emitted` over
`dataclasses.fields(RunReport())` **with no exemption list**, and its docstring refuses one:
*“A field the report should deliberately withhold does not exist yet, and when one does it should
be argued for here rather than skipped by a name in a set that nothing forces anybody to read.”*
So a new field that reaches no reader goes red on its own.

Written down because the reflex is to add a guard per task. CHG-20260903-39 nearly shipped a
duplicate of an existing one for the same reason — and, worse, the existing one there turned out to
be checking the wording rather than the property. Here it is checking the property, so nothing is
added.

## Risk & rollback

- **This changes what the durable record says about who opened a gate.** That is the point, and it
  is also the reason the risk is high: an export read before this change attributes to `runner`
  gates that a person pre-authorised, and re-exporting an old conversation will not repair a
  document already written — the turns are stored, not re-derived. **Old documents stay wrong**, and
  the record must say so rather than imply a retroactive fix.
- **A new `RunReport` field lands in `--json` and `docs/SCHEMAS.md`.** Additive.
- Rollback: revert. A split programme's gates go back to being filed as the machine's own act.
