## Motivation
Turn the read-only multi-panel dashboard into a **resident interactive control console**: launch
straight into it, keep it running across tasks, and drive runs / answer halt-gate approvals from a
bottom input box — without exiting after each run. The dashboard UI direction is approved; these 7
requirements make it interactive and always-on.

## Decisions & trade-offs
| Decision | Options | Assumptions | Why this choice |
|----------|---------|-------------|-----------------|
| Project model (empty start) | /open sets current vs per-task vs arg | user confirmed | **`/open <path>` sets the "current project"** (shown in Status); tasks/run/approvals target it. Also allow `runner <project>` to pre-open (cheap; coexists). |
| Q/A scope (v1) | approvals+task-input vs real-agent Q/A | user confirmed | **v1 = (a) task/requirement input + (b) HALT-gate approve/reject**. Real-agent free-form Q/A is a later CHG (needs a backend that surfaces agent questions). |
| Run integration | single-thread (blocking) vs background thread | stdlib-only, stub/fast runs | **Single-thread**: `on_event` redraws panels live; the interactive `approver` blocks for input at a HALT. Real *slow* backends block the UI during agent work — accepted v1 limitation (documented; threading is a follow-up). |
| Entry point | bare runner → dashboard vs keep menu | req 1 | Bare `runner` (TTY) → resident dashboard; **all subcommands + `runner menu` kept** for CI/scripting; off-TTY bare `runner` keeps existing menu/snapshot behavior. |
| Log growth | unbounded vs bounded | req 6 | Exec log + Agent log rendered **2-col, bounded height** (last N lines, N scales with terminal height) so Status + Verification stay visible. |

## Structure change summary
Adds a resident interactive mode to the dashboard (default TTY entry) with a 2-col bounded-height
layout, a bottom input (tasks + `/commands` + arrow-key halt answers), and live event streaming,
reusing `tui`'s arrow-key selection and `orchestrator`'s existing `approver`/`on_event` hooks. The
read-only snapshot path and all subcommands are preserved. Governance untouched.
