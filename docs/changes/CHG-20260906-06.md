## Read this first

```
git log --oneline -S'"--json"' --all -- src/    ->    0 commits
grep -rn '"--json"' --include=*.py .            ->    0 hits
```

**This repository has never had a `--json` flag.** Not on `main`, not on any branch, not in any
commit since the first one. It has nonetheless been named 33 times across 25 files, including three
comments in shipped source and one string inside a test.

That would be a spelling problem if the name were decorative. It is not: the name is used **as
evidence**, in sentences that grade how bad a defect was.

```
cli.py:1154   # `risk_settled` reached `--json` and the console and no terminal line (CHG-20260903-48).
```

Both halves are false. Measured:

```
risk_settled   cli.py 5   server.py 0   console/index.html 0
out_of_order   cli.py 3   server.py 0   console/index.html 0
frontier       cli.py 3   server.py 0   console/index.html 0
```

`server.py` builds its snapshot key by key — `asdict`, `vars` and `__dict__` appear in it zero
times — and `risk_settled` is not one of the 53 keys it names.

## What the name was actually pointing at

`RunReport.as_dict()` at `engine.py:437`. Every `.as_dict()` call in `src/` is on some other
object — `EffectOutcome`, `Survey`, `Attachment`, `ModelRegistry`, `Settings`:

```
report.as_dict() call sites in src/   ->   0
```

So a field "reaching `--json`" meant it appeared in a dictionary **only the test suite ever
builds**. Every record that used the phrase to say a defect was partial was describing a defect
that was total. The word made the problem look smaller than it was, for fifteen days.

## The one place it could have been caught, and why it was not

`tests/test_server.py` keeps `NOT_ON_THE_CONSOLE`: fifteen `RunReport` fields deliberately absent
from the page, each with the reason a reader can argue with. The reason for one of them read

> "the grade the run was governed by — reaches `--json` and the terminal only"

The exclusion itself is sound: `risk_settled` does reach the terminal, and only the terminal. But
half of the reason given for it named a surface that does not exist, and because the other half was
true the sentence read as a measurement. **The justification for a guard was itself unchecked.**

## What changes

- `cli.py` (2 comments), `engine.py` (1 comment), `tests/test_cli.py` (3), `tests/test_server.py`
  (1 comment + the justification string), `docs/SCHEMAS.md` (1 line): each now says what is true.
  Where a record's own wording was wrong, the new comment says so and names it.
- `NOT_ON_THE_CONSOLE["relaxations"]` cited `--store-remote allow`. That flag is **not** a phantom —
  it was real, added in CHG-20260823-17 and removed with Mongo in CHG-20260823-35, and
  `test_the_locality_flags_went_with_the_backend_that_needed_them` already pins its absence *from
  the parser*. But it is a dead example of a live mechanism, so the entry now names `--undeclared
  allow`, which really does record a relaxation:

  ```
  undeclared=allow    halted_at=done            relaxations=13
  undeclared=refuse   halted_at=intake_review   relaxations=0
  ```

- One new test, `test_no_exclusion_is_justified_by_a_flag_the_runner_does_not_have`, asks
  **`cli.build_parser()`** — never the source text — whether every flag named in those fifteen
  reasons exists.

## Why the guard is this narrow, which is a measurement and not modesty

A repository-wide version was written first and thrown away. Every long flag named anywhere in
`docs/`, `src/` and `tests/`, against every flag argparse declares:

```
argparse declares      35 long flags
named in prose but not declared    131
```

The 131 are `--ink`, `--accent`, `--surface-2` (the console page's own CSS custom properties),
`--porcelain`, `--oneline`, `--grep` (git), `--collect-only` (pytest), `--ephemeral` (codex). A lint
over prose is 131 false positives to 1 true one — **which is why this defect class keeps recurring
here and cannot be swept by a text rule.** The fifteen justification strings are a closed set whose
whole purpose is to be checkable, so that is where the check goes.
