## The gap

Reservations are how this repository stays honest: an acceptance that lists what it did **not**
establish is worth more than one that implies it established everything. Twice this week a
reservation turned directly into work — CHG-20260828-03 and CHG-20260828-07 both exist because one
was written down.

But a reservation is prose, and **nothing makes it stop being true when the thing it describes
changes.** Four had:

| record | claimed | actually |
|---|---|---|
| ACC-20260822-01 #5 | *"`main` has no branch protection, so a merge can proceed with checks red"* | five required checks, verified against the GitHub API |
| ACC-20260822-02 #5 | the same | the same |
| ACC-20260822-03 #4 | the same | the same |
| ACC-20260827-19 #6 | *"`test_nothing_is_unwired` has a false negative… reported, not fixed"* | fixed by CHG-20260828-02; reproduced as a test |

A reader taking the ledger at its word would believe this repository merges on red. It does not, and
has not since branch protection was set earlier today.

## Checked, not remembered

Both claims were **verified before being struck**, because "I think we fixed that" is how a record
becomes wrong in the other direction:

```
$ gh api repos/…/branches/main/protection
required: ledger, pytest×4     strict: false     enforce_admins: false

bare-name false negative still present: False
```

The branch-protection note also says what the protection does **not** do — `enforce_admins` is off,
so an admin can still override. Replacing one over-claim with another would be no better than
leaving it.

## Struck, not deleted

Every original sentence is kept and struck through, with the closing note beneath it. A reservation
that quietly disappears takes with it the evidence that somebody once knew the gap existed — and
that evidence is most of what makes the next reader trust the ones still standing.
