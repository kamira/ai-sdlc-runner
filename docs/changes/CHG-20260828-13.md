## The gap

`ACC-20260822-02` and `ACC-20260822-03` carry seven reservations between them about a **vendored
skill store**:

* *"`skills/` tops out at v1.16.0 while the published skill is v1.64.0"*
* *"the repo now carries five full skill copies"*
* *"51 scripts vs 7"*
* *"it hardcodes a store version that will rot"*

`ls skills` fails. The store was removed by **CHG-20260823-01** — *"our own governance, no skill
anywhere"* — **one day after** those acceptances were written. That change is why `policy.py` and
`tools/ledger_check.py` are this repository's own rather than a vendored skill's.

A reader taking these records at their word would believe the repository carries five skill copies
and is 48 minor versions behind, which contradicts both the code and §7 of its own guideline —
*"repo 內不存放也不讀取任何 skill"* — that every acceptance since has re-checked.

## Superseded, not struck

A note at the head of each Reservations section, and every original sentence left intact.

Striking them individually would be wrong twice over. They were **true when written**, and together
they are the record of *why the vendoring approach was abandoned* — the store being 48 versions
behind and carrying five copies is most of the argument CHG-20260823-01 acts on. Deleting the
reasoning would leave the decision looking arbitrary.

So the note says what a reader needs — **do not act on any of these** — and the reasoning stays
readable.

## `ACC-20260822-01` #1 is different, and is annotated rather than superseded

It is about an **upstream** repository (`skill-ai-sdlc-autopilot`), not the vendored copy, and it
says *"filing it upstream remains outstanding"*.

What has changed is the pathway: *"until a fixed skill version is installed or vendored"* names a
route this repository no longer has. Filing upstream may still be worth doing for that project's
sake; it cannot reach this one. **Whether to file it is not this repository's call, and it is not
marked done.**
