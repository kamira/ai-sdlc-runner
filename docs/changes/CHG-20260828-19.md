## Why

`Not claimed` accumulates, and normally nobody goes back. Three of the reservations shipped today
were **checkable claims** rather than judgements, which makes leaving them open a choice rather than
a limit.

## 1. `ACC-20260828-16`: "Only `subprocess` was surveyed, and by reading" — **holds, and is now checked**

> File I/O in this repository passes `encoding="utf-8"` explicitly, which is why nothing else
> surfaced. Nothing exercises that claim.

Surveyed on the syntax tree. It is true:

- `paths.read_text` / `paths.write_text` take `encoding: str = "utf-8"`, and most file I/O here goes
  through them.
- Every one of the four `paths.open_` callers passes `encoding="utf-8"`.
- The only text open without one is `open_` itself, which forwards `**kwargs` — it uses whichever
  codec its caller named, and every caller names one.

A test says this now instead of a sentence. `Path.read_text()` and a bare `open()` decode with the
caller's locale exactly as `subprocess` does; the difference is only that they raise in the calling
thread, so the failure is loud rather than a silent empty read.

## 2. `ACC-20260828-16`: "nothing in the project currently starts [a non-Python child]" — **wrong**

`git` is a non-Python child, and it is the **only** subprocess `src/` starts. That sentence was
false when it was written.

The conclusion survives, for a reason the record did not give: **git writes UTF-8.** Measured on
`git show origin/main:docs/changes/CHG-20260828-16.md` — 9088 bytes, 48 of them non-ASCII, which
decodes as UTF-8 and **raises** under cp950. That is the original defect, in the exact call this
change fixed.

So the reservation was right about the risk and wrong about the world. The correction is in the
record, struck through rather than quietly rewritten.

## 3. `ACC-20260828-18`: "Only `mutation_check` was surveyed" — **closed**

`frozen_tree.py` writes nothing. `session_record.py` writes one file — its own recording, to a path
the caller names, already with `encoding="utf-8"`. Neither touches a tracked source file, so there
is nothing for a killed run to strand. The reservation named a real gap in the survey; the survey
was done and the gap is empty.

## What the mutations found that the reading did not

The first mutation for the new check replaced the survey's filter with `if False` and came back
**NOT CAUGHT with fifteen tests green** — an empty result satisfies `assert not unnamed`. The
subprocess half of that file already had a floor against exactly this; the file half shipped without
one for a single run. It has one now.

Chasing that mutation somewhere it could land turned up a real hole. The survey **exempts**
`paths.read_text` and `paths.write_text` on the strength of a default it never read — and that
exemption covers most file I/O in the project. If the default stopped naming a codec, the survey
would go on exempting it and report clean. `test_the_helpers_this_survey_trusts_really_do_default_to_utf8`
reads the signatures now, and a mutation of the default is caught.

**A survey that exempts a helper because of its name is the same defect as a check that flags a
keyword because of its name.** This one was on the other side of it.

## The gap the AST cannot close, stated

`conv.open()` and `some_path.open()` are indistinguishable to a syntax tree, so the attribute form
of `open` is out of scope and a `Path.open()` in text mode would slip past. Nothing in `src/` or
`tools/` uses one — checked, not assumed — and
`test_no_path_open_has_appeared_since` pins the exact set of unclassifiable calls, so adding one goes
red and forces the decision rather than passing quietly.
