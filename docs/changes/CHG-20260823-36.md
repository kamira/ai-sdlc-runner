## 1 · `runner serve` could not start

```python
pv.add_argument("--settings", default=None, help="path to settings.json")
```

The `serve` subparser redeclared `--settings` and forgot its default, shadowing the global flag
whose default exists precisely so nobody has to pass it. `settings_mod.load(None)` reached
`Path(None)` and the dashboard — **in its plainest form, `runner serve`** — died with a bare
`TypeError` whose traceback named `pathlib`, not the flag.

Found by trying to use it. It is the second time this session a defect was found by running the
thing rather than reading it.

Two tests: one on `serve` specifically, one on **every** subcommand that declares `--settings`,
because a subparser shadowing a global and dropping its default is a hole any command could acquire.

## 2 · `examples/weather-spa` — the console path

`tide-spa` drives `runner run` from a plan file, and a CLI run **has no operator in it**: nothing a
person typed exists in the record, and the conversation is only ever the model's half. This example
starts `runner serve` and talks to it the way the console does.

| | what it does | outcome |
|---|---|---|
| **A** | types the brief, clicks `start the run`, then `approve merge` | four files built; `finished` at `done` |
| **B** | uses `start the run` for a *follow-up* instead of `add to the brief` | the first instruction is **replaced** — 1, not 2 |
| **C** | an agent that picks the next module by which file is missing | `walk exceeded 200 steps — the flow is cycling without progress` |
| **D** | a request with no operator token | shell `200`, every route behind it `401` |
| **E** | a non-loopback `Host`, and a cross-origin `Origin` | `403` and `403` |

D and E cannot be reached from `runner run` at all — they are the reason a second example exists
rather than a sixth scenario in the first one.

**B is not filed as a defect.** Both verbs are legitimate and the buttons say which is which. It is
filed as the thing to check first when a conversation holds fewer instructions than you typed —
which is how this project lost one, with nothing failing and nothing warning.

The page it builds: seven days, current conditions in a band **in the middle** — temperature and
humidity, plus feels-like and wind — and today's curve with a mark at now. No network call, at build
time or in the page, and a test asserts it.

## 3 · The same bug in `examples/tide-spa/agent.py`

```python
nxt = next((m for m in ORDER if m not in done), ORDER[-1])
```

Picking the next module by which **file** is missing works exactly once. On a second walk all four
exist, so the agent answers with the last module forever and `next_module: frontier` never advances.

That is scenario C, and the repository was shipping an agent that had it. Both agents now compare
**content** and report when there is nothing to do. The demo generator is what exposed it: it drives
an agent until it says it is finished, and `tide-spa`'s never did.

## 5 · Demo pages, generated rather than kept

[`examples/demo/`](../../examples/demo/index.html) — an index and one self-contained page per
example that builds one.

**They are generated from the agents that build them**, by `examples/demo/build.py`, and
`tests/test_demo_pages.py` regenerates and compares. A demo page copied by hand is a screenshot with
an `.html` extension: it goes stale the first time the agent changes and nothing notices. That is
the same failure as a README stating a figure nobody re-measures, which this repository has shipped
twice.

The generator also refuses to finish against an agent that cannot report itself done — which is what
caught §3.
