## Why

The user, verbatim:

> 需要決議或審查部分都要納入不同模型的設計 / 在不同維度上（舉例 資訊安全 UXUI CI 模組化等等）/
> 每個模型都要在這些對應角色中進行確認

They chose **both layers** — this repo's process (DIR-3) and the runner. For the dimensions:
*"能多少層面就增加多少層面，使用者可再依據需求設定那些需要使用"*. The user chose to build this in
parallel while CHG-20260929-01 waits for review quota.

## What exists today

- `policy.SEATS` has four seats: `conformance` (veto), `defect`, `risk`, `idiom`.
- `settings.review_seats` opens a **prefix** of them, never fewer than `SEAT_FLOOR = 3` except in
  high-risk mode.
- `seat_models` maps each seat to **one** model id or argv. The `SEAT_PANEL` asks each seat once.
- Several models on one question exist only in `MODEL_PANEL`, which is keyed by node, not by seat.

## What changes

1. **Fifteen seats.**
   - The four existing seats.
   - Eight more: `security`, `ux`, `ci`, `modularity`, `privacy`, `performance`, `portability`,
     `docs`.
   - Three that are off unless chosen: `observability`, `supply_chain`, `i18n`.
   - The eleven new seats' ids, labels and questions are the ones `config/panel.json` uses for
     DIR-3. The four existing seats keep their ids and labels (which match `config/panel.json`) and
     the questions the runner's panel has always asked, which `config/panel.json` words
     differently; changing them would change the existing panel. Only `conformance` keeps its veto.
2. **The user chooses which seats open.** New setting `review_dimensions`: a list of seat names, in
   the order they open.
   - When set, it replaces the `review_seats` prefix, and the floor applies to its length (high-risk
     mode can still lower it). It must include `conformance`, the veto seat, unless high-risk mode
     is on.
   - When unset, a run opens the first three seats, as today. `review_seats` takes a prefix of the
     twelve seats that are not opt-in, so a count never opens `observability`, `supply_chain` or
     `i18n`; only `review_dimensions` does.
3. **Several models per seat.**
   - `seat_models` values become a list of model ids (a single string is still accepted and read as a
     one-element list). An id may appear once per seat.
   - Each (seat, model) is its own session (KN-7).
   - A seat **passes only when every one of its models passes**; any `fail` is the seat's `fail`, and
     any model that names no verdict (unreached) makes the seat unreached unless the seat has a
     `fail`, which stands. The seat panel then adjudicates the seats' verdicts as
     today (veto, then majority, a tie decides nothing).
   - Store schema 4 → 5: `seat_models` keyed by (seat, position).
4. **Disclosure.** The run report lists which models answered which seat, and `single_model_panels`
   still fires when every voice is the same backend.

## Interpreted, and what it was chosen over

- **"每個模型都要…確認" is a conjunction inside a seat.** Every model on a seat must pass for the
  seat to pass. Chosen over a majority within the seat, which would let one model's objection on its
  own dimension be outvoted by models that were asked the same question.
- **The default does not change.** Fifteen seats exist, but an install that sets nothing opens the
  same seats as today. The user asked that the choice of seats be theirs. Opening twelve by default
  would multiply every run's cost on a choice the user did not make.
- **Vetoes are not extended.** Only `conformance` vetoes. A veto on `security` is a policy decision
  for the user, not an inference from the word.
- **A `review_dimensions` list may drop `conformance` only in high-risk mode** (round 1). Every
  prefix opens `conformance`, so a count never removed the only veto; a named list can. Without
  high-risk mode the list is refused at load, at save, in the settings screen and in the engine;
  with it the list is allowed, `runner settings` says no veto seat is open, and the run records
  "review opened without conformance, the veto seat" in `report.relaxations`, as it records a panel
  below the floor. `--no-high-risk-mode` drops such a list for that run, as it does one below the
  floor.
- **No seat count reaches an opt-in seat** (round 1). `review_seats` is at most 12 and opens the
  first N of the seats that are not opt-in; the three opt-in seats open only when `review_dimensions`
  names them. The seat field is `opt_in`, and the three are `opt_in=True`.
- **A seat's models are model ids, and a list is never a command** (round 1). A value is a string
  (a model id or, as before, a command line) or a list of model ids. Every id must be in the
  registry, none may repeat, and a list with no registry to check it against is refused. The one
  legacy argv form existed: `--seat-model` and `session_factory(seat_models=...)` took a flat list
  of words. It is kept for `cli.session_factory` only, and read as an argv only when the list's
  first word is not a registry model id (or there is no registry). A list that starts with a model
  id is ids, so `["opus", "missing"]` is refused naming `missing`. A flat argv in a plan or the
  store is not read that way: `cmd_run` and `serve` check those with the strict rule first. The
  argv-inside-a-list form (`[["python3", "agent.py"]]`) is gone. A single-word `--seat-model
  defect=opus` now names the model `opus` when the registry has it.
- **Unreached is a model that named no verdict** (round 1). The runner has no `unreached` word; the
  words are `pass`, `fail`, `undecided`. A session that names no verdict is the unreached case, and a
  single-model seat in that case already stops the run with an `EngineError` naming the seat. A seat
  with any unreached model and no `fail` is unreached and stops the run the same way. With a `fail`
  the seat's word is `fail` (an unknown cannot change it), and the adjudication lists the unreached
  models under `unreached`. A model that says `undecided` makes the seat `undecided` (not a
  stop); a word outside the three is still refused by `policy.adjudicate` by name.
- **A journaled answer belongs to the model it was asked of** (round 1). Each seat ask is journaled
  with the model id and the argv the factory resolves; a resume reuses it only if both are
  unchanged, and asks again otherwise. A journal entry with no identity (older) is reused as before.
