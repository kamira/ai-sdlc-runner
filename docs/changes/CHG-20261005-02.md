## Why

> 需要決議或審查部分都要納入不同模型的設計 / 在不同維度上（舉例 資訊安全 UXUI CI 模組化等等）/

They chose **both layers** — this repo's process (DIR-3) and the runner. For the dimensions:
*"能多少層面就增加多少層面，使用者可再依據需求設定那些需要使用"*. The user chose to build this in
parallel while CHG-20260929-01 waits for review quota.

## What exists today

- `policy.SEATS` has four seats: `conformance` (veto), `defect`, `risk`, `idiom`.
- `settings.review_seats` opens a **prefix** of them, never fewer than `SEAT_FLOOR = 3` except in
  high-risk mode.
- `seat_models` maps each seat to **one** model id or argv. The `SEAT_PANEL` asks each seat once.
- Several models on one question exist only in `MODEL_PANEL`, which is keyed by node, not by seat.

## What changes

1. **Fifteen seats.**
   - The four existing seats.
   - Eight more: `security`, `ux`, `ci`, `modularity`, `privacy`, `performance`, `portability`,
     `docs`.
   - Three that are off unless chosen: `observability`, `supply_chain`, `i18n`.
   - The ids, labels and questions are the ones `config/panel.json` uses for DIR-3, so the runner and
     this repo's process speak the same vocabulary. Only `conformance` keeps its veto.
2. **The user chooses which seats open.** New setting `review_dimensions`: a list of seat names, in
   the order they open.
   - When set, it replaces the `review_seats` prefix, and the floor applies to its length (high-risk
     mode can still lower it).
   - When unset, behaviour is **exactly today's** prefix of the first four.
3. **Several models per seat.**
   - `seat_models` values become a list of model ids (a single string is still accepted and read as a
     one-element list).
   - Each (seat, model) is its own session (KN-7).
   - A seat **passes only when every one of its models passes**; any `fail` is the seat's `fail`, and
     any `unreached` makes the seat unreached. The seat panel then adjudicates the seats' verdicts as
     today (veto, then majority, a tie decides nothing).
   - Store schema 4 → 5: `seat_models` keyed by (seat, position).
4. **Disclosure.** The run report lists which models answered which seat, and `single_model_panels`
   still fires when every voice is the same backend.

## Interpreted, and what it was chosen over

- **"每個模型都要…確認" is a conjunction inside a seat.** Every model on a seat must pass for the
  seat to pass. Chosen over a majority within the seat, which would let one model's objection on its
  own dimension be outvoted by models that were asked the same question.
- **The default does not change.** Fifteen seats exist, but an install that sets nothing opens the
  same seats as today. The user asked that the choice of seats be theirs. Opening twelve by default
  would multiply every run's cost on a choice the user did not make.
- **Vetoes are not extended.** Only `conformance` vetoes. A veto on `security` is a policy decision
  for the user, not an inference from the word.

**Interpretations made while building, for review:**
- SURVEY (`intake_review`) asks the same seat set as `lead_review`. Each answer from a multi-model
  seat is kept under `seat[model]`.
- A flat list of strings in `seat_models` is read as model ids only when every one is in the
  registry. Otherwise it is one argv, the old shape. This is ambiguous by construction, and the
  review should judge it.
