## Motivation

`github.com/kamira/ai-skills` — the repo this runner is built around — is **archived** (last push
2026-08-04). It was succeeded by **`github.com/kamira/skill-ai-sdlc-autopilot`**, which also changed
the skill's internal layout: the two skills `ai-sdlc` and `ai-sdlc-autopilot` merged into one at
v1.18.0, so the path `skills/ai-sdlc/` is now `skills/ai-sdlc-autopilot/`.

`ai-skills` still appears in **26 tracked files** here. Most are harmless prose, but three references
are not:

- **`.gitmodules`** declares a submodule whose `url` points at the archived repo. The submodule was
  never wired up and the `ai-skills/` directory has never existed in this tree.
- **`config/runner.yaml:20`** and **`src/ai_sdlc_runner/cli.py:112`** both carry the fallback
  `skill_path: "./ai-skills/skills/ai-sdlc"` — a path that is now doubly wrong (dead repo, and the
  wrong sub-path even if it were alive), duplicated across two files.
- **`README.md`** links to the archived repo twice (EN and zh-TW), the only outward-facing pointer
  this project has.

None of this breaks a passing build today — which is precisely why it would survive indefinitely.
The cost is misdirection: `agents.py` and `gates.py` currently raise errors that ask the reader
*"is the ai-skills submodule wired up?"*, sending whoever hits them to a repo that no longer exists.
The most recent victim was this agent: CHG-20260822-01 was written yesterday asserting the upstream
fix was unreachable, because every signal in the repo pointed at the archived name.

## Scope: why the `src/` refactor is NOT here

The obvious cleanup for the duplicated fallback is to delete the hardcoded twin in `cli.py` so
`runner.yaml` is the single source. The panel adjudicated that as **correct but out of scope here**:
`_resolve_skill_path` has **six call sites** across two modules (`cli.py:128`, `:140`, `:342`,
`:423`; `dashboard.py:629` via `:620`, used at `:649`), and removing the default means `config.get`
can return `None`, so every one of them needs a defined failure path plus tests.

That is a behavioural refactor riding on a rename cleanup. It ships as **CHG-ii** instead. This CHG
changes **no behaviour at all** — only text, one dead file, and one path value that was already dead.
