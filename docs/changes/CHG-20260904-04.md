## L-19 — the rule read half an argument list

```python
and any(isinstance(a, ast.Name) and a.id == "here" for a in n.args)
```

`n.args` only. A resolution written `resolve_verdict(node, grade, cfg.autonomy,
change_class=here)` was not counted as class-carrying, so the `>=` comparison below it silently
covered less. The `>= 2` floor does not help: it fires only when an existing **positional** call is
removed.

Measured, with a third class-carrying resolution planted in keyword form and recording nothing:

```
against the rule as it was    green — which is the defect
against the rule as it is     RED
```

No behavioural test can see this: the added resolution is byte-identical in effect. The rule is the
only guard, and it is the guard CHG-20260903-46 shipped **to replace a blind one**.

## The first rule I wrote for it permitted the defect

It required a citation to land on a line that is not blank, not a comment and not a bare delimiter.
Measured, `server.py:323` is `self._refresh_attachments()` — **real code**. The rule passed on both
of the seat's cases.

A line number in a comment cannot be verified without a companion string. That is the conclusion
this ledger already reached for change records — *stop pinning by address* — and it applies here
for the same reason. So the rule is the stronger, simpler one: **`src/` does not cite line
numbers.** A symbol name is greppable, survives insertions above it, and says what the number was
standing in for.

The rule found a third citation the seat had measured as correct: `scenarios.py:233`, accurate that
day and rotting on the same schedule. Now `scenario_c`.
