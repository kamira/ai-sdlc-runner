# CHG-20260827-19 — every red line stops at the same person

- Project: ai-sdlc-runner
- Branch: claude/chg-20260827-19-halt-routing
- Date: 2026-08-27 (UTC+0)
- Type: one roster extended, and a routing table that does not exist yet
- Proposed by: the decision to target a mid-to-large organisation shape, where the six permanent
  halts are six different people's decisions
- Risk: **medium** — a halt that reaches nobody is worse than a halt that reaches the wrong person,
  so the default path has to stay.
- Autonomy: high
- Related: CHG-20260823-01 (the role table)

## The gap

`PERMANENT_HALT_KINDS` names six things nothing automates: production deploy, data migration, hard
delete, moving money, changing access, publishing publicly.

In the shape now being targeted those are six different functions — release management, whoever owns
the database, finance, security, communications. Today all six stop the run and return to **one
operator**, who is whoever started it.

The role roster has the same shape problem: five roles (`pm`, `lead`, `engineer`, `qa`, `seat`) is a
small team's roster. There is no architect, no security reviewer, no release owner.

## What must not happen

A routing table is a new way for a halt to go missing. The rule: **an unrouted halt still reaches the
default operator.** Routing narrows who is told first; it never narrows who is told.

### Not claimed

**That naming a recipient means they are reachable.** This runner records who should be told. It has
no notification channel and this change does not add one.

**That the extended roster is the right one.** It is drawn from the six halts and the nodes that
exist. A real organisation's roster is a fact about that organisation, not about this flow.
