## The importer, for the third time

| | what it did |
|---|---|
| **CHG-41** | imported 3 of 7 turns of a dirty conversation, then called the stump "already here" |
| **CHG-42** | made it atomic, and preflighted **exactly the two shapes that had burned CHG-41** |
| **this** | stops trusting the input |

Both seats then broke CHG-42 six more ways. Five aborted the whole migration on the first bad file
— four as raw tracebacks — and one vanished with a clean report.

### Every conversation is independent, whatever goes wrong

The loop's `try` wrapped only `into.import_conversation` and caught only `ConversationError`.
`source.read`, `_assemble`, the header lookups and every non-sqlite error inside the import fell
outside it. So a bare `42` on a line, a `"seq": "x"`, a turn with no `kind`, a header with no
`project`, a filename disagreeing with the id inside it, or a **directory** named `*.jsonl` each
killed the migration and everything after it.

Now each conversation is read, checked and written inside one `except Exception`, and anything that
goes wrong lands in `refused` **by name**. Six parametrised tests, each with a good conversation
*after* the bad one — because a store with one conversation cannot test "does not stop the others".

### The silent one, and the worst

```
store root: 322 chars
plain Path.rglob sees : 0 file(s)
paths.listdir sees    : 2 file(s)
report: refused 0        <- junk.jsonl vanished, exit 0
```

The unreadable-header scan used `Path(root).rglob("*.jsonl")`. **Sixty lines above**,
`FileBackend.conversations` carries a comment saying glob must not be used here for exactly this
reason: it goes through the OS with the plain path, so a store past MAX_PATH lists as *empty*
rather than raising.

So the scan added specifically so that *"there were files I could not read"* could never be
reported as *"there was nothing"* did precisely that, using the call the same file forbids. It now
walks through `paths.listdir`, and a test builds a 322-character store to prove it.

### "Already here" means the same conversation

`_already_there` compared id and **count**. A target holding the same id and the same number of
completely unrelated turns was reported as `skipped, already here` while the source's content was
never imported. It compares the turns now, and refuses a same-id-different-content collision by
name rather than choosing between them.

## Three corrections to the ledger

1. **CHG-42** claimed *"one bad conversation no longer stops the others"*. False for every dirty
   shape except the two it was burned by.
2. **CHG-42** claimed a file with no readable header is *"reported by name rather than silently
   absent"*. False on a deep store — measured.
3. **CHG-44** claimed its forced-arrival test *"would be two walks if the flag were stranded"*.
   fable-seat reverted the gate and the test **passed** — the arrival lands inside the walk body,
   not inside the window. The same document's "Not claimed" section says the behavioural tests
   cannot catch it; that half was right and this claim contradicted it.

## The structural test was reading vocabulary too

CHG-44 replaced a vocabulary test with one that asserted two substrings appeared inside some `with`.
fable-seat mutated the gate to keep both strings in one block while clearing `_walking` on the wrong
branch — **it passed**. It now checks that the context manager is `self._lock` and that the clear
happens on the branch that found nothing waiting.

## Smaller

- `os.open`, `os.fdopen`, `sqlite3.connect` and everything in `tempfile` added to the write audit:
  fully dotted, statically identifiable, and absent while the honesty note listed only *dynamic*
  gaps. A stated limit that omits what it could have caught is not honesty.
- `store.py`'s `sqlite3.connect` is allowlisted with its reason — it takes a path string rather than
  a handle, and is given `paths.real(file)` two lines after `paths.check(file)`.
- `_advance`'s docstring still named `instruct()` among the ungated callers, which CHG-43 had
  already corrected in its own record.
- The `except BaseException` handler clears a pending wakeup. That is a **cost**, not a clean-up,
  and it now says so: the caller's action stays committed in state but is walked by nobody until an
  unrelated later caller.

## Risk & rollback

- **The importer refuses more.** Every refusal names the conversation and the reason, and leaves it
  on disk.
- Comparing turns rather than counting them costs one read of the target per already-present
  conversation. `_already_there` still calls `into.conversations()` per source conversation — O(n²),
  which both seats noted and which is not addressed here.
- Rollback: revert.
- 1283 collected; 1280 passed, 3 skipped.

## Status


Accepted (see docs/acceptance/ACC-20260823-45.md) -- Pass. This is the change that made CHG-42's and CHG-44's claims true, and every behaviour survives CHG-47's restructuring.

### Not claimed

**That the preflight is now complete.** It is a blanket `except Exception` around each conversation,
which is a different thing: it means an unknown shape is *refused by name* rather than *understood*.
That is the right behaviour and it is not the same as knowing what can go wrong.

**That the O(n²) listing is fixed.** Both seats named it; it is not addressed. On an 800-conversation
store fable-seat measured ~23ms per conversation, so it is a real cost at scale and not a defect at
the sizes seen here.

**That `except BaseException` no longer drops a wakeup.** It still does. The alternative strands the
flag instead. It is documented rather than solved.
