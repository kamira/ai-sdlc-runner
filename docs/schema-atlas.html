Key

Three axes, and they are independent

closed

A field outside the set is refused, not ignored. Five schemas are closed and it is enforced in code on every path in.

open

Unknown keys are silently accepted and do nothing. Five schemas are closed; the rest, and what each leaves unchecked, are in the table.

built

Code creates it, reads it, and writes it. Three of the five database tables.

designed

Written down and created by no code. A table nothing reads is a mechanism nobody invokes.

Storage

The SQLite store

Five tables designed, three built. Foreign keys are real — but only because PRAGMA foreign_keys = ON is set on every connection; it is off by default and per-connection, and without it REFERENCES enforces nothing.

modelsbuilt
  • PK id TEXT
  • vendor TEXT
  • name TEXT
  • transport cli | api
  • command_json TEXT
  • endpoint TEXT
  • key_env TEXT
  • note TEXT

No reach column. It is computed from (transport, endpoint) on every read and stripped on save — storing it would let a stale “local” label outlive an endpoint edit.

node_assignmentsbuilt
  • PK node_id TEXT
  • PK ordinal INTEGER
  • FK model_id → models.id

ordinal, not a set: a pool’s seeded choice and a model panel’s ask ids both read the list positionally.

halt_routingbuilt
  • PK kind TEXT
  •    recipient TEXT

Who a permanent halt stops in front of. No foreign key on recipient on purpose: an organisation names its own functions, and a table accepting only the five this runner ships would be unusable. The kind is validated instead, when it is typed.

seat_assignmentsbuilt
  • PK seat TEXT
  • FK model_id → models.id

One model per seat. A seat is one voice; a list would be a panel inside a panel.

conversationsbuilt
  • PK conversation_id TEXT
  • project_id TEXT
  • project_name TEXT
  • schema INTEGER
  • run_json TEXT

No opened_at — it would be a second copy of the opened turn’s at.

turnsbuilt
  • PK conversation_id → conversations
  • PK seq INTEGER
  • kind one of 9
  • at ISO 8601 UTC
  • body_json TEXT — body only

PRIMARY KEY (conversation_id, seq) is a real refusal of a duplicate turn — the guarantee the file backend could only report, never enforce.

Two pragmas persist; three reset on every connection

journal_mode and user_version live in the file. foreign_keys, synchronous and busy_timeout are per-connection and reset — getting that backwards is how a foreign key becomes decoration, and three review rounds stated it the wrong way round before it was measured.

For review

What is open, and what that costs

The plan file was the one open schema that mattered — it is closed now

Every other shape rides inside it, and it was the only entry point with no validation at all. Six reviews named it and one gave the case that decided it: a misspelt ship key made a run perform no side effects and report finished. A dry run wearing a shipped run’s report, produced by one typo nothing refused.

Closed at the top level and inside ship, by key and by shape. It is a behaviour change: a plan carrying a stray key now stops the run, and the refusal names the key and lists what is read.

  • Only the conversation document carries a version. Plans, answers, journals, the registry, settings, manifests and run reports all persist or cross a process boundary and none of them can say which shape it is.
  • Three names for one fact. A decision node’s answer is read as branch or verdict or outcome, first one winning — two of them can disagree inside one answer.
  • halt_independent does not check independence. It always stops for a person, and nothing records or compares who confirmed against who built. There is one operator identity.
  • An api model registers and cannot be dispatched to. It validates, it lists, it shows its reach — and the first ask routed to it raises.
  • Two processes on one store are not covered. A lock serialises threads in one process; busy_timeout is all there is between two, and each holds its own cache. Four review rounds have said the harness does not exist.
