## What the green now means, stated precisely

Before this change the toolchain gate produced **no signal at all** on this repo — `NOT_RUN` is
explicitly "the check did not run", and the handshake protocol's response to it is stop-and-provision.
Every session therefore either halted on a false negative or was waved past by hand.

After this change the gate answers exactly one question: **are the declared dev dependencies
importable in this environment?** It does *not* check `>=6.0` / `>=7.0`; bare names carry no floors,
and the probe's own parser rejects ranges. Those constraints remain in `pyproject.toml` and are
enforced by pip at install time, which is where they were enforced before and still are.

That is a real limit and is recorded here rather than left for someone to discover: the gate is now
green on a machine with, say, `pytest 6.0` installed, which `pyproject.toml` would reject. It is
still strictly more signal than `NOT_RUN`, which verified nothing.

## Reservations (disclosed, not waived)

1. **This is the second-best fix, and knowingly so.** The right fix is probe-side:
   `toolchain_probe.sh` should read `[project.optional-dependencies]`, at which point this file
   becomes vestigial. That fix belongs to **`github.com/kamira/skill-ai-sdlc-autopilot`** — the
   successor to `ai-skills`, which was archived 2026-08-04 — and that repo **is reachable**: cloned
   locally as a sibling directory, clean and current with its remote, still carrying the same
   unfixed probe. It is nonetheless a separate repo with its own governance, so it is outside this
   CHG, and a fix landed there would not reach this repo until a fixed skill version is installed or
   vendored. **Filing it upstream remains outstanding and is not covered by this CHG.**
   *(Corrected in-round: this reservation originally called the upstream repo unreachable and the
   fix un-landable "on any known timeline". Both were false when written — see the correction note
   in CHG-20260822-01. No check result or conclusion changes; the evidence in the table above was
   measured against the probe itself, not against any claim about the upstream repo.)*
2. **Dependency names are now stated in two files.** The test makes divergence a CI failure in all
   four cells, but it cannot make the duplication not exist. If a future dev dependency is added
   directly to `requirements-dev.txt` instead of to `pyproject.toml`, the test correctly fails — the
   fix is always to edit `pyproject.toml` first.
3. **The pyproject scan is a string scan, not a TOML parse.** Deliberate: `tomllib` is py3.11+ and
   CI's floor cell is 3.9, so a real parser would remove this guard from half the matrix. The scan
   handles the file's actual shape (`key = ["dist>=x"]`, one extra per line) and would need revisiting
   if the extras block moved to multi-line arrays. It fails loudly rather than silently — the test
   asserts the block was found and parsed non-empty.
4. **Every extra counts as a dev dependency.** The test derives from *all* extras, so a future extra
   for an unrelated optional feature would also become required in `requirements-dev.txt` and thus
   required-installed for the probe to pass. Correct for the current two (`yaml`, `test`); worth
   re-examining if an extra is added that a developer should not be expected to have installed.

## Summary

The ai-sdlc entry handshake's step-0 toolchain gate returned `NOT_RUN` on this repo on every session
— not "all clear" but "the check did not run" — because the probe reads `requirements-dev.txt` and
this repo declares its dev dependencies in `pyproject.toml` extras. A derived `requirements-dev.txt`
now gives the probe something it can parse: `TOOLCHAIN: PASS`, exit 0.

The content is bare names, and that detail was measured rather than guessed. Direct probe runs
showed that both intuitive answers — copying the extras verbatim, and a single `-e .[yaml,test]`
line — return `NOT_RUN`, i.e. they would have looked like fixes while leaving the gate dead. Two
independent engines (fable, codex) reached the same conclusion from the probe source before the
measurements were taken, and the measurements agreed with them.

`tests/test_requirements_dev_sync.py` keeps the file a derived view: four mutations were each
confirmed to fail it, and the range-reintroduction mutation fails the test and the probe *together*,
which is the specific silent regression worth guarding. Suite 157 → **161 passed**, 2 skipped;
`doc_integrity_check.py --repo .` exit 0; `src/`, `config/` and `skills/` untouched. **Accepted.**
