## The process fix is a promise, not a mechanism

CHG-27 records that its author edited the working tree while a verifier was auditing it — and that
the edit was to the safety check being audited. The lesson became KN-14: *freeze the tree before
verification, and do not touch it until every seat reports.*

Where that rule now lives: `README.md:524` and `docs/defect-log.md:49`. Both engines looked for an
enforcing mechanism and neither found one. There is **no hook, no script and no test** that checks
the reviewed tree is committed or pinned during a review round. CHG-30's statement that it did not
happen again is a statement in a record, not a check.

Stated plainly because the repo's own §8 says red lines are code, not a paragraph — and this one is a
paragraph. Making it a mechanism is a modification and needs its own CHG.

*(Small irony worth logging rather than hiding: this very acceptance round had subagents mutating
`src/` files to prove tests bite. They reverted cleanly — `git status` was verified clean afterwards
— but nothing enforced that either.)*
