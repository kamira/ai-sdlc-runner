## The guards, and what it took to make them real

The two prose guards were defeated by where a line wrapped — measured by the idiom seat: the same
wrong count on one line was caught and, rewrapped, left 2145 tests passing. They read flowed text
now, and both are pointed at planted wrappings rather than waiting for one.

**The floor for the widened citation rule was empty twice before it was real:**

1. It looped over `CITED_ROOTS` itself, so narrowing the rule narrowed the floor — self-referential
   and green either way.
2. Rewritten to derive from what `src/` actually cites, the heredoc that wrote it turned `` into
   **byte 0x08**. The pattern matched nothing, `set() <= anything` is `True`, and it passed
   vacuously. `cat -A` shows it; `Read` and `sed` do not.

Repaired, it reported a live finding immediately: `src/` offers a reader paths into `docs/`,
`tests/` and `tools/` as well, and the rule read two directories. Widened to the five it measured,
every citation resolves.

## Three mutations retired rather than faked

Reverting the flowed read, or the guard's read of its own file, re-opens a hole nothing currently
exercises: no live sentence is wrapped wrongly, and this file no longer states the claim it forbids
**because the floors that test those two assemble their plants from fragments**. What is pinned is
the check, pointed at planted text. Same call `CHG-20260904-15` made for the sibling inventory, and
the registry says so where the group sits.

## Reservations

1. **`CITED_ROOTS` is now five names read from a measurement taken once.** The floor asserts
   `offered <= set(CITED_ROOTS)` on every run, so a source file citing into a sixth directory turns
   it red — which is the property. What it cannot do is notice a directory that stops being cited.
2. **The banned-claim guard reads two files.** `settings.py` and its own test file. A third file
   stating the sentence — a document, a record — is not covered, and the sentence has been false in
   `docs/` before.
3. **`policy.py`'s comment is scoped, not fixed.** A bare executor name still reads as `ordinary`
   because `_REPO_PATH` is tested first. The comment now says so; whether that ordering is right is
   a `policy` question this record does not answer.
