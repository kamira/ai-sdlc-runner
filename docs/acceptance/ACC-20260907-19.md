## Evidence

### Two spellings, three readers, no test

```
LOOPBACK        serve             the address serve permits as a bind argument
LOOPBACK_HOSTS  _loopback_host    the Host header, brackets kept
LOOPBACK_HOSTS  _loopback_origin  the Origin header, brackets stripped

tests naming either constant:      0
tests sending a bracketed Host:    0
```

Every other mention in the repository is a historical record. The `call` fixture sends
`Host: 127.0.0.1:{port}` and every positive case rides on it, which is why the bracketed form
had no coverage to lose.

### Round one: the set arithmetic was not what the server does

Both seats read `_loopback_host` and refuted the first draft on the same grounds. Measured:

```
"[::1]" removed from LOOPBACK_HOSTS
    first draft of the test    passed
    whole file                 128 passed        (the draft's own test included)
```

A server on `::1` would refuse the `Host` every browser sends it, and the test written to catch
exactly that said nothing.

### Round two: the words claimed a bind that was never measured

`LOOPBACK` is what `serve` **permits**. One member cannot be bound at all - measured with a raw
socket, `AF_INET` refuses `::1` with a `gaierror`. Both seats said the same thing about the
rewrite: a test named for what the server *binds*, and a message saying *"are not addresses this
server will bind"*, assert something false today. Renamed and rewritten to say what is read: the
list, with the socket left to its own record.

### The member nothing required, and the member nothing should

```
removed from LOOPBACK_HOSTS   who objects
127.0.0.1                     test_a_cross_origin_request_is_refused
localhost                     test_our_own_origins_are_still_accepted[http://localhost:8765]
[::1]                         nothing -- 127 tests passed        <- the hole
::1                           nothing, before or after (129)     <- correct: unreachable
```

The bare `"::1"` is redundant for `_loopback_origin`, which strips brackets, and reachable in
`_loopback_host` only through `Host: ::1:8765`, an unbracketed IPv6 authority RFC 7230 5.4 does
not permit. One seat proposed a mutation removing it; measurement refused the proposal, and the
non-entry is recorded in the group's comment so the next reader does not re-add it.

### The five mutations

```
CAUGHT  the bind list may permit an address no request may name again
CAUGHT  a permitted IPv6 address may lose the bracketed form a browser sends again
CAUGHT  the header check may be tightened below what the bind list permits again
CAUGHT  the bind list may lose an address the header check still accepts again
CAUGHT  the rebinding guard may accept a name this server never answers on again
```

The second is round one's finding, registered because it was NOT CAUGHT before. The third is
caught by the new test under `-k` and, in a whole-file run, reported against
`test_our_own_origins_are_still_accepted` - `-x` stops there first, so the harness output names
that test and not the new one.

### Why containment and not equality

One seat proposed normalised equality in round one and withdrew it in round two on measuring
that equality is **blind to the finding**:

```
{h.strip("[]").lower() for h in HOSTS} == {a.lower() for a in LOOPBACK}
    today                      True
    with "[::1]" removed       True     <- equality cannot see mutation 2
```

The forward behavioural test implies forward containment, so behaviour-forwards plus
containment-backwards is strictly stronger than equality in both directions.

## What this does not do

It does not derive `LOOPBACK_HOSTS` from `LOOPBACK`. Both seats said the derivation is one
expression and measurably equal today, and the first draft of this record was overstating when
it called that *"a design question about one of them owning the boundary"* - it is a
straightforward follow-up that would make both rules here unfalsifiable rather than checked. It
changes production code, so it is a separate record, and the CHG hands that record a measurement
it will need.

It does not fix `::1` against an `AF_INET` server. That is a defect in what `LOOPBACK` claims,
measured during this review and filed; production never passes `host`, so it is latent.

## Verdict

**Pass**, after two rewrites. The first asserted the overlap of two constants and would have
shipped believing it had closed a hole both seats then opened by hand. The second closed it and
then described it in words the same measurement had already refuted. What ships asks the two
functions the same question a browser asks them, and says *permits* where only a permit was
measured.
