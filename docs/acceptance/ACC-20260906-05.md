## Evidence

### The gap, and the reason it was not the reported one

```
grep -rln '"/attachments"' tests    ->    (empty)
```

The finding arrived as *"no test posts to `/attachments` over HTTP"*. The first attempt at writing
one answered:

```
POST /attachments  ->  409 {"error": "this runner has no attachment store"}
```

The `live` fixture builds its `Runner` through `_runner()`, which never passed a `store`. A test at
that layer could not have reached the route — it would have stopped at that refusal. **The gap was
not an oversight; the fixture could not hold the test.** An oversight is fixed by remembering; this
needed the fixture changed, and saying which it was is the useful part of the record.

### The mutations pin the route, not the store

`attachments.py` already has its own group. These three are about the trip through HTTP:

```
CAUGHT  the route stops refusing a body that is not base64
CAUGHT  the route reads a field the page does not send
CAUGHT  the filename the operator sent is dropped on the way through
```

The second is the one worth naming: `data_base64` versus `data`. The console sends `data`, the page
documents `data`, and a route reading the other name would have failed silently for every upload —
with the store-less fixture, nothing at that layer could have noticed.

### One of mine, worth the line

The README count went in through `sed -i 's/# 2234 tests/# 2236 tests/'`. This branch is off
`49d88a8`, where the README says **2233** — so the pattern matched nothing and the command reported
success. The guard caught it; the lesson is the repository's own, one file over: *check the state,
not the silence*. The replacement is an assertion now, so a miss is loud.

## Verdict

**Pass.** A documented route has an executable pin for its body, its row and two of its three
refusals, and the fixture that speaks HTTP can now hold an attachment — which is what had made the
absence structural rather than accidental.
