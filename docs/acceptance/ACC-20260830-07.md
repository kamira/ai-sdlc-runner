## The finding that matters most

`ACC-20260830-06` recorded `--only stranded` 9/9 and 91/91. **The instrument that produced those
numbers could not tell a mutated tree from an unmutated one.** `apply()` writes the real in-flight
record, the guard asserts it does not exist, and `_pytest` runs with `-x`, so every mutation in the
group stopped at test nine and the four tests written to pin the lock never ran. Pristine source and
mutated source gave byte-identical output.

Two rounds looked at this change's verification and did not reach the instrument. The round-3
conformance seat re-ran `--only stranded`, read 9/9, and listed it under *what checked out* — it was
fooled the same way I was. Only the defect seat asked whether the output discriminates. That is the
argument for a panel rather than a reviewer: the seats disagreed, and the one who *constructed an
input* was right.

It also says something narrower and worth keeping: **a green mutation report is a claim about an
instrument, not about the code.** The guarantees here were genuinely pinned all along — run without
`-x` and without a sentinel, all four mutations went red in the right test. What was broken was the
reading, and nothing in the report said so.

## A platform truth written as a universal one

The first push of this change was **green on Windows and red on both Ubuntu jobs**. The new test for
exit code 259 asserted its own fixture first — `assert exited.returncode == 259, "the fixture did
not produce the code this test is about"` — and that assertion is what fired: POSIX keeps only the
low eight bits of an exit status, so `SystemExit(259)` there gives **3**.

Worth recording for two reasons. The guarantee really is Windows-only — 259 is `STILL_ACTIVE`, and
the POSIX branch of `_alive` does not consult exit codes at all — so the fix is a `skipif`, not a
rewrite. And the fixture assertion did exactly the job it was put there for: without it the test
would have called `_alive` on a process that had not done the thing the test is named for, got
`False` for the wrong reason, and passed. That is the failure this whole session has been about, and
this time the guard caught it before a reviewer had to.

It is the third instance of this shape in the repository: `test_a_cjk_name_is_judged_by_the_platform
_that_will_store_it` and the `[Errno` wording in `test_plain_in_strips_the_prefix_from_a_real_os_error`
were both platform truths written as universal ones, and CI caught both.

## Reservations (disclosed, not waived)

1. **Written by the implementer, again.** Three rounds have now found 35, 36 and 33. Round 3's
   largest finding sat in the instrument used to verify round 2 — a layer two panels had not looked
   at. There is nothing in that history that predicts round 4 is empty.

2. **The mutation report is trusted for the other eleven groups.** This change proved the reading
   was false for `stranded` and fixed the cause, which was specific to that group's tests asserting
   on the sentinel. No other group asserts on the harness's own state, so the same failure is
   unlikely there — but "unlikely" is the word, not "checked". A general guard would be a mutation
   run that first proves the chosen tests are green on pristine source *with the sentinel present*.

3. **A reused pid still reads as alive**, and now more often, since a denied `OpenProcess` also
   reads as alive. The refusal that results says the file is still mutated, says the record holds
   the only copy of the original, and names `git checkout --`. It is a loud failure with an exit,
   which is the direction to fail in — not a safe one.

4. **The 35 out-of-boundary sites have a weaker excuse than was given.** 27 of them catch a named
   type — `ValueError`, `sqlite3.OperationalError`, `json.JSONDecodeError`,
   `subprocess.TimeoutExpired` — which `CAN_CARRY_A_PATH` could decide by name. The reason they are
   out is that widening the rule produced a source file that did not parse, not that no static rule
   could tell. `ACC-20260830-06` gave the stronger-sounding reason; this one gives the true one.

5. **The LF restore is still not fixed**, and it fired twice more during this round's verification.
   `git status` names files nothing happened to, and `git status` is what three separate refusals in
   this module tell an operator to read. It is the next change.

6. **Risk's round-1 observations remain untouched** — `reach_of` grading every single-label host
   `internal`, the secret scan reading only the query string, two markdown formats pinned by test,
   the constant-time test foreclosing hashed tokens.
