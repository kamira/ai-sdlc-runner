## The mutation that had nowhere to land

The first mutation for the new check disabled the survey's filter and came back **NOT CAUGHT with
fifteen tests green** — because an empty result satisfies `assert not unnamed`. The subprocess half
of that file had a floor against exactly this; the file half did not.

Looking for somewhere that mutation *could* land found the better finding. The survey **exempts**
`paths.read_text` and `paths.write_text` because their signatures name UTF-8 — and it never read
those signatures. Most file I/O in this project goes through them, so the exemption is load-bearing
and was resting on nothing. If the default changed, the survey would keep exempting and keep
reporting clean.

**A survey that exempts a helper because of its name is the same defect as a check that flags a
keyword because of its name.** This repository has now found that shape on both sides of the same
file, in the same week.

1. **Three of about fifty.** Fourteen acceptances carry roughly fifty reservations. Three were
   picked *because they were checkable*; the rest are judgements about wording, scope or

   file this project reads and writes today. A file in another encoding would be read wrongly and

4. **`git` was measured on one repository, on one platform.** It emits UTF-8 here. A git configured
   with `i18n.logOutputEncoding` would not, and nothing checks that.
