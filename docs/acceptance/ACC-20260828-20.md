## Why the cutoff is where it is

`TESTS_MUST_EXIST_FROM = "20260828"` puts the boundary at today, which looks like the check letting
itself off. The measurement says otherwise: 0 records from that date break the rule, and 97 before
it do — because the 97 point at `executors.py`, `dashboard.py`, `workspace.py` and the tests that
went with them, from an architecture this project no longer has.

Rewriting those to name today's tests would be **inventing a past**, not fixing one.
`BRANCH_REQUIRED_FROM` makes the identical argument nine lines up in the same file.

## The first record it caught was this change's own

Written and wired, the check immediately reported CHG-20260828-20 — for two *illustrative* names,
invented to show what a pointer looks like. Backticked, they are indistinguishable from a claim,
which is exactly what the rule says.

The fix was the record, not the rule: both were replaced with
`test_one_node_one_kind_of_work`, a real test in `test_flow`, so the illustration is now also true.
A record that demonstrates pointers with fake ones was teaching the habit it exists to stop.

Then it reported **this acceptance**, for quoting those same two names while explaining that they
were fake. That one is not a defect in either the record or the rule — it is the rule making a
distinction markdown does not: backticks mark *code*, and this repository uses them for both *"the
thing I am pointing at"* and *"the string I am discussing"*. The convention that falls out is that a
name being talked about goes in prose, which the rule already exempts, and only a name being
**relied on** gets backticks. That is a better convention than the one it replaces, and it was not
designed — it was discovered by the check refusing its own paperwork twice.

## The check is wired in, and that is its own test

`test_the_check_runs_as_part_of_the_ledger` exists because writing a guard and not calling it is a
failure this repository has shipped — CHG-20260827-22's `interfaces` never reached `RunConfig`, and
every unit test passed. A mutation removes the call and that test goes red.

## Reservations (disclosed, not waived)

1. **The ninety-seven are not fixed.** This stops the pile growing; it does not shrink it. Each one
   needs a judgement — renamed, or deleted with its subsystem — and that is ~97 judgements, which is
   the work `ACC-20260828-08` reserved and this does not do. Closing a reservation by building a
   guard against *future* instances is a narrower thing than closing it.

2. **A pointer that resolves is not a pointer that supports the claim.** A record citing a real test
   for a guarantee that test does not make passes this check. That is the defect
   `tools/mutation_check.py` exists for, approached from the other side, and the two do not meet.

3. **`src/…py` references are not checked.** The same survey found 23 dangling ones. A record naming
   a module deleted years later is usually legitimate history, and a rule that could not tell that
   from a broken pointer would be noise. So the asymmetry is deliberate and it is a hole.

4. **The cutoff is a date, not a decision per record.** A record written before it that *does* name
   a live test gets no credit, and one written after it inherits the rule whether or not its author
   knew. That is the cost of prospective rules and it is the same cost `BRANCH_REQUIRED_FROM` pays.

5. **Verified by the implementer**, on a reservation the same implementer's earlier session wrote.
   The measurement is the part that is not self-referential: 97 is a count, not an opinion.
