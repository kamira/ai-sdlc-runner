## The reservation: the same hole, in the tool shipped alongside

The record's phrasing — *fixed at the JSON level* — reads as a property of the change. It was a
property of one file.

`tools/render_cast.py`, shipped by **this same change**, carried the identical hole. CHG-20260823-38
reproduced the breakout: recording a command that merely mentions `</script>` poisoned the rendered
page. It is fixed now (`render_cast.py:140-143`), and pinned twice —
`test_recording.py::test_a_recorded_command_cannot_end_the_script_block`, and
`::test_the_two_escapers_stay_identical`, which guards against the two copies drifting apart again.

The second test is the interesting one: the underlying cause was **two copies of one idea**, and the
fix keeps both copies while pinning them together. That is a defensible answer to a duplication
problem, and it is worth noting it was arrived at only after the duplication had already caused the
bug once.
