## Evidence

### The list promised what the socket refuses

```
Windows, py3.11:
AF_INET bind    127.0.0.1  ok     localhost  ok     127.0.0.2  ok
                ::1        gaierror [Errno 11001]   ::ffff:127.0.0.1  gaierror
AF_INET6 bind   ::1        ok
```

The family mismatch is portable and the exact exception is not: a v6 literal fails
`inet_pton(AF_INET)` and then `getaddrinfo` with `ai_family=AF_INET`, which is read from
CPython's address parsing rather than run on Linux. The first draft of both records said *"on
any platform"* and the review would not let it stand.

`socket.gaierror` is an `OSError`, and `serve` had one `except OSError` saying *"Something is
already there"*. So the constant promised an address, the socket refused it, and the refusal
sent the operator after a runner that was not running.

### The design was reviewed before it was written

The two seats split:

```
codex   LOOPBACK -> ("127.0.0.1",)          drop localhost too; the parameter is false
                                            configurability
fable   LOOPBACK -> ("127.0.0.1","localhost")  drop only what cannot bind
```

Three measurements settled it, and codex changed its ranking on the first:

```
1  AF_INET bind "localhost" -> 127.0.0.1;  getaddrinfo order [AF_INET6, AF_INET]
   the resolver cannot move a bind whose family is already fixed -- the hazard codex named
   is real for (a) and for the connect side, not for this
2  LOOPBACK = ("127.0.0.1",):  FAILED test_no_host_is_accepted_that_the_bind_list_does_not_permit
   dropping localhost forces it out of LOOPBACK_HOSTS too, refusing Host: localhost:8765
3  AF_INET 127.0.0.1:59180 held, AF_INET6 [::1]:59180 ALSO BOUND
   family selection reintroduces exactly what _OneRunner exists to stop
```

### A proposal of mine that both seats refused

I proposed replacing the merged reverse test's relation with *"accepted authorities are names
that resolve to an address `serve` binds"*. Both refused it, independently and for the same
reason: that set contains `evil.example` the moment its A record points at loopback, which is
the attack the guard exists for. The closed form one seat gave is the one this record uses:
`LOOPBACK_HOSTS` is the authority form of every address in `LOOPBACK`, plus names whose loopback
meaning is fixed by the platform rather than by DNS - a set with exactly one member, `localhost`
(RFC 6761 6.3).

### The mutations

```
bind      CAUGHT  the permit list may name an address the socket cannot open again
          CAUGHT  the header set may accept an authority no listener can answer on again
          CAUGHT  every way a bind can fail may be called a port conflict again
          CAUGHT  the refusal may name one address for a list of several again
          CAUGHT  a failure may stop saying what the operating system said again
          CAUGHT  the permit list may take an address the whole network can reach again
loopback  CAUGHT  the bind list may permit an address no request may name again
          CAUGHT  the header check may be tightened below what the bind list permits again
          CAUGHT  the bind list may lose an address the header check still accepts again
          CAUGHT  the rebinding guard may accept a name this server never answers on again
```

Two of the six were **NOT CAUGHT** when first run, and both are about a sentence rather than a
value. The fourth: the refusal's wording had been changed and nothing required the change - the
assertion was added rather than the change reverted, because a refusal naming fewer addresses
than it takes reads as a narrower rule than the one enforced. The fifth is worse and was found
by review of the build: **the premise of this record's own two-branch decision was unpinned.**
Two branches are defensible only because the plain one carries the operating system's sentence,
and removing that sentence left the file at 135 passed. The test asserted the negative half and
not the positive one.

The sixth settles a split between the seats. One proposed weakening the socket test's
`server_address[0] == "127.0.0.1"` to `is_loopback`, saying nothing showed the exact address was
load-bearing. Measured with `-x` off: `0.0.0.0` in `LOOPBACK` draws three objectors and
`127.0.0.2` draws two, the socket test among them both - and `127.0.0.2` **is** loopback, so the
weaker assertion would have missed the address that opened this whole thread.

### The repository caught the rest of it

The first full run after the fix failed three ways, all of them this record's own:

```
test_no_shipped_mutation_has_a_stale_anchor    all five loopback entries, both constants edited
test_the_test_count_the_readme_states_is_the_real_one
test_every_change_id_the_source_cites_has_a_record   the comments cite a record not yet written
```

Four of the five stale entries were re-anchored. The fifth - *"a permitted IPv6 address may lose
the bracketed form a browser sends"* - was **deleted**, because its guarantee left with `"::1"`:
there is no permitted IPv6 address for a bracketed form to be lost from. Re-anchoring it would
have kept a mutation that pins nothing.

One run in between failed once on `test_store.py`'s concurrency test with a `WinError 10061`

**The sentence that stood here was wrong, and CHG-20260907-22 replaces it.** It said the one
mechanical explanation -- the default listen backlog of 5 -- had been *refuted* by measurement,
64 concurrent connections producing zero refusals. That measurement was of the wrong condition:
it let the acceptor run, and a queue that is being drained never fills. Against an acceptor that
is not draining, `socketserver`'s default of 5 refuses everything past the fifth connection with
exactly the `10061` seen here, deterministically. The explanation was correct and the refutation
was not.

## What this does not do

It does not build IPv6, and the measurement above is the reason rather than the effort. It does
not touch `cli.py`: the unbracketed `http://{host}:{port}` it prints was only wrong for an
address this server no longer permits. It does not repair the merged reverse test's
justification for `localhost`, which is its own record.

## Verdict

**Pass.** A constant that called itself the only addresses this server will bind now names only
addresses it opens, proven by opening them; and a failure that is not a port conflict is no
longer reported as one.
