## Summary

`executors.py:87-88` — the clause that turns a failed process launch into a legible `ExecutorError`
instead of letting a raw `FileNotFoundError` escape — had been covered only by five *failing* tests,
and CHG-20260817-09 removed that accidental coverage when it fixed them. One portable test now drives
it deliberately, asserting both the exception type and that the message names the command that failed
to start. A mutation check confirms the test is real: with the `except` clause removed it fails with
the raw OS error. Module coverage 85% → **87%**, above the pre-CHG-20260817-09 86% and this time with
both the success and failure paths genuinely exercised. Suite 156 → **157 passed** locally, 159 on
Linux in CI; all 5 CI jobs green on PR #6; `doc_integrity_check.py --repo .` exit 0. **Accepted.**
