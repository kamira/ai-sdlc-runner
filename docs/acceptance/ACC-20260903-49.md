## The seat's seventeen is fifteen

```
RunReport().as_dict() fields                     30
server RunState().snapshot() keys                19
report fields the console never NAMES            17
of those, whose content reaches it renamed        2
report fields reaching no console at all         15
```

`snapshot()` sends `report.halted_at` as `"at"` and `report.halt_reason` as `"reason"`. A
name-based count flags both — the class of error this round has been finding, appearing inside one
of the round's own findings. Taking seventeen at face value would have built this record on a wrong
number, as CHG-20260903-25 was built on a wrong address.

The fifteen are one thing, not fifteen things: the grade, the class and what it dissolved, what the
run did, and the store's failures. **The console renders what the run is doing and nothing about
what governed it.**

## The rule that was cited is honestly named; the citation was not

`test_every_key_the_server_sends_reaches_the_console` iterates the snapshot, and its name says so.
CHG-20260903-24 retired CHG-20260901-15 task 24 on the ground that it would catch *"the next field
to go unrendered"* — a report field, which cannot fail a rule that iterates the snapshot. **The
record cited a guard for a scope the guard never claimed.** That correction belongs to `-24`'s next
draft; the gap the citation was covering belongs here.

## Criterion 7 — and the first mutation was aimed at the wrong link

```
a field is emitted and nobody says where it goes   ██████████  red
the inventory loses an entry                       ██████████  red, both guards
the rule counts names instead of content           ██████████  red, both guards
```

The first was written as *"add a field to `RunReport`"* and **survived**: `as_dict()` builds a
literal dict, so a new dataclass field never reaches it. That link is held by
`test_the_report_emits_every_field_it_declares`. The link this rule owns is *emitted and
unaccounted*, and mutating that turns it red.

A survived mutation is first a question about what was mutated. The chain is
`declared → emitted → rendered or written down`, and the two rules meet at the join.

## Reservations

1. **This does not build the fifteen views.** That is CHG-20260901-15 task 24's actual scope and it
   is named as a feature with an owner rather than adopted inside a defect fix or retired on a
   false ground. The seat's condition was *"adopt the scope, name an owner, or decline it
   explicitly — but not on the ground that the suite catches it"*, and this is the second.
2. **The inventory requires a reason string, not its truth.** A reason written once and never
   revisited is how an exemption list rots. The rule refuses a silent addition; it cannot refuse a
   stale sentence.
3. **`_reaches_console` reads the snapshot's AST**, so a field routed to the page by some other
   path than `snapshot()` would read as unreached. There is no such path today; if one is added,
   this is the helper to widen rather than the inventory to grow.
