`effects.py` carried **0 of 238** registered mutations before this change. It now carries a group,
and every entry reverts the line this change edited rather than a helper it introduced:

```
CAUGHT  an unanswerable probe walks out of the process again

CAUGHT  a halted node leaves no record of its effects in the run report
```

One entry was written and then rewritten before it was registered: the escape mutation first
narrowed the `except` clause to a class name that does not exist, which would have **broken** the
module rather than re-opened the hole - a `BROKE` outcome reads as caught while pinning nothing.
It narrows to `ValueError` instead, a real class the probe never raises, so the foreign exception
escapes exactly as it did before the fix.

## Reservations

### 1. One seat finding is recorded as reversed, not fixed

The risk seat measured that one untracked file flips `ship`'s composed `commit` probe and proposed
`--untracked-files=no`. Re-measuring reversed the fix:
`tests/test_ship_refuses.py::test_a_commit_over_a_dirty_tree_is_not_finished` pins both halves of
that probe deliberately, and the dirty file it uses is itself **untracked**, so the proposed change
would make that test's own scenario read clean and revert a decision `CHG-20260830-03` made on
evidence. No change was made to `ship.py` or `probes.py`.

### 2. One question is open, and could not be measured here

What the seat's observation actually points at is one step later: whether re-applying `commit` over
a dirty tree produces a second commit carrying the same CHG id, and whether anything refuses it.
Creating a fresh git repository under the temp directory hung past a 60s timeout twice in this
environment - raw `git init` / `git commit` hung the same way, so it is not the runner, and a probe
of the same shape had run correctly earlier in the same session. **Nothing about this is settled.**
It is carried forward as an open item and is the reason this acceptance is not a clean pass on the
whole round's finding list.

### 3. The conformance seat's veto is held open on three claims, not on this change

It did not veto `effects.py` as shipped. It holds the veto against any *future* change that

- introduces a production caller of `run(..., dry_run=True)` - **closed by this change**, since the
  dry branch no longer reports a clean-looking empty list for a world that is not clean;
- claims a node's effect outcome is in the run report - **closed by this change** on the failure
  path, which was the only path where it was false;
- claims `effects.py` is covered - **narrowed, not closed**. It has a mutation group now. It did not
  have one, and 12 tests were green against every finding in this round, so "covered" remains a
  claim to make about specific named classes rather than about the module.

The document repairs the seat asked for regardless - the `D6.2`-`D6.5` labels, the misplaced
"unanswerable raises" sentence in `data.md` and `design.md`, `ACC-20260823-01` row 11's six dead
citations, and `data.md`'s incomplete effects-field description - are **not** in this change. They
are documentation with no behaviour attached, and they go in their own record so that the
behaviour change here can be reverted without taking true sentences down with it.

## Verdict

**Pass.** The three findings all four seats converged on are fixed, each with a test that fails when
the fix is reverted, in a module that had no revert check at all. One finding is reversed on
re-measurement and says so. One question is open and says why.
