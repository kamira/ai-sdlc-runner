## My measuring instrument was wrong

The probe reported **ten of ten pinned**. The harness reported **nine**. The harness was right: the
prefix guarantee is pinned by nothing, which I then confirmed by hand — the mutation applied, five
candidate test files run individually, all green.

I do not know why the probe said otherwise, and the run is gone. What I do know is that I built a
second, worse instrument when the repository already had a good one. `mutation_check.py` has a
green-baseline check, anchor-uniqueness, an ambiguity outcome and a crash sentinel; my probe had a
sentinel and nothing else. **The lesson is not to trust the probe less — it is that the probe should
not have existed.** The harness could have answered the same question by pointing the mutations at
the existing test file first and reading which came back `NOT CAUGHT`, which is exactly how the last
two holes were found.

## A test asserting the absence of something never present

The first version of the fix's test opened a junk file and asserted the prefix was absent. It
passed, and would have passed with the guard deleted: SQLite's message for that case is `file is not
a database`, with no path in it at all.

That is the fourth time in this session a test has been written that cannot fail for the reason it
names, and the second time it was mine. The pattern across all four is the same — the test is
arranged near the guard rather than *through* it.

## Reservations (disclosed, not waived)

1. **Nobody knows whether an operator ever hit it.** For the prefix to reach a reader, SQLite must
   quote the path back — which it does on some failures and not on the one the existing test uses.
   The guarantee was stated, believed, and not delivered; the frequency is unmeasured.

2. **Only messages that already called `plain` were fixed.** `cli.py` interpolates `{exc}` raw in
   several places. Those never promised to strip anything, so they are not this defect — but whether
   they should promise it is a question this change did not ask.

3. **`plain_in` is a string replacement, not a path parser.** A message that legitimately contains
   the four characters `\\?\` outside a path would be altered. No such message exists here, and the
   alternative — parsing paths out of arbitrary driver text — is worse.

4. **The nine already-pinned guarantees were recorded, not re-argued.** Their tests were read to
   confirm they exist; whether each pins the *whole* of what its guarantee claims was not examined,
   and the mutation only proves the tests notice one specific break.

5. **Verified by the implementer**, on a module the implementer did not write, with the defect found
   by an instrument the implementer built badly. The finding stands because the harness and a manual
   check agreed against the probe.
