## The rule the record left open, decided here

The proposal says a standard class means *"individual instances do not stop"*. Read literally that
dissolves a `halt` as readily as a `confirm`.

**Decided: `confirm` → `auto`, and nothing else.** `confirm` means *a person is asked and may say
yes*; pre-authorising a type is saying yes in advance about every instance of it. `halt` says
something stronger — stop, and put this in front of somebody. A pre-authorisation is a person's
**approval**; it is not a person's **attention**.

The class changes who has to be *asked*. It never changes who has to *look*.

## Two defects, and what found each

**The closed work-order schema caught fields I should not have added.** `policy.verdict` carries a
comment on its `autonomy` branch — *"Reported through `source` rather than as an extra key: the
verdict's shape is fixed so a work order's closed schema can carry it"* — and the first draft added
`relaxed` and `change_class` keys to that dict, in that function, having read that comment.
`workorder.render` refused them.

The replacement is better than what it replaced: the engine asks what the verdict **would have been
without the class** and compares. `merge at risk low would have been 'confirm'` is the sentence an
audit needs, and a flag on the verdict would never have produced it.

**The permanent-halt message had gone stale in a copy a search could not see.** The message
enumerates what cannot relax a permanent halt — *"No risk grade, confirmation or mode"* — and a
change class is now a member of that family. There were **two** copies; the second is split across
source lines, so a single-line search found one and missed the other. A test asserting the message
caught it, and the file was then swept by rejoining continuations before searching again.

Both are the same shape as this repository's recurring finding, from opposite directions: a
contract stated in one place and not honoured in another.

## Reservations (disclosed, not waived)

1. **A type does not stay safe because it was safe.** The record says this itself. The expiry is a
   floor under the drift, not a fix for it, and a class renewed without thought is a rubber stamp
   with a calendar. This change makes the renewal visible; it cannot make it considered.

2. **Nothing chases an emergency.** Task 6's second half, above.

3. **The export is not verified to carry the class.** Task 4 says "in the report and the export".
   The report is checked here, on every run, and the declaration is written as a `RELAXATION` turn —
   so it is *in* the conversation. That the export renders it is **not** asserted by any test, and
   the check table above says report-and-turn rather than claiming the export.

4. **The class is a run-level scalar.** CHG-20260827-18 made risk per-workstream; a class is not.
   A programme with a `standard` copy tweak and a `normal` schema change gets one class for both,
   and the strictest reading is not applied because there is nothing to compare. This composes badly
   with workstreams and is not addressed.

5. **Verified by the implementer.** Both defects above were found by a schema and by a test, not by
   review, which is the argument for the guards rather than for the reviewer.
