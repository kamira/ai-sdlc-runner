## The finding this acceptance most wants on the record

**My first fix for L-22 was governance-wrong, and a test written for a different change caught it
the same hour.**

Carrying `relaxations_by_class` into the durable conversation is correct. Doing it through
`conversation.relaxation(relaxed)` is not: that files it under the **runner's** voice.
`test_a_declared_class_is_exported_as_the_operators_act` turned red immediately, and
`conversations.relaxation`'s own docstring is the rule I had crossed:

> `--store-remote allow` is the runner recording its own configuration, and a change class is a
> person pre-authorising a type. The first is the runner's voice; the second is not, and an export
> that files a person's pre-authorisation under `runner` misattributes it in the one dimension the
> document exists to record.

A gate opened by a class was opened on a **person's** standing authority. The fix now carries
`by=report.class_authorised_by`, and that is a new field rather than a name parsed back out of
`report.change_class`'s prose sentence — parsing it would have been a name standing in for a fact.

## Reservations (disclosed, not waived)

1. **Written by the implementer**, on defects somebody else measured. Twenty-three for
   twenty-three.

2. **My first L-21 fix was wrong and I measured it before shipping.** It raised on any exit code
   other than 0 and 1 — and `git rev-parse --verify` exits **128 for both** "no such branch" and
   "not a repository", so the probe would have refused to answer a question it could answer. The
   substitution to `show-ref` is the actual fix and the measurement is in the CHG, because the
   first version looked right.

3. **My first L-22 fix was governance-wrong** — see the top of this record. It is the second time
   in one change that a fix I believed was correct was refused by something already in the
   repository, and both times the refusal was a sentence somebody had written down.

4. **L-20's forwarding hop is unbounded in principle.** It re-keys once per visit while nothing can
   consume the message. On the shipped graph the longest chain is three hops
   (`review_failed → change_retry → next_module → engineer_build`), and the walk's own `max_steps`
   bounds it — but nothing in this change counts hops, and a graph with a roleless cycle would
   carry a message around it.

5. **`class_authorised_by` is a new `RunReport` field**, so it widens `as_dict()`, `--json` output
   and `docs/SCHEMAS.md` §13. That is CHG-20260901-16 D4's rule applied — a declared field must be
   emitted — but it is a field added to a governance record to serve an attribution, and a seat may
   prefer it derived at the call site instead.

6. **L-23 changed the message at all four call sites**, not only the two that were wrong: "seat"
   became "voice" throughout, because the function serves seat panels, surveys and model panels
   alike. Anything matching that string exactly stops matching.

7. **`_adjudicate`'s signature changed.** One production caller and one test. A third caller written
   against the old shape would now unpack a tuple into a string.
