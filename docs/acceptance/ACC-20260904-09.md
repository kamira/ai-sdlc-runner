## L-37 - what the suite could not see, and why

```
tests/test_server.py       82 passed   under the swap
tests/test_api_schema.py   19 passed   under the swap
the happy-path refusal      1 failed   "this run is waiting at 'plan_confirmed', not 'pm_confirm'"
```

All four `reject` tests assert a 4xx. The swap only makes refusals **more** likely, so no
arrangement of those four could notice. That is a coverage shape, not an oversight: a method whose
every test is about being refused has no test that it works.

`CHG-20260904-06` moved the rule from the parameter *names* to the argument *values*, which was
right and still is. What it did not do is ask **which value went to which name** - and both names
appear on both sides of a swap, so the set comparison is satisfied by the defect.

## L-35 - the mark and the thing it counts, on different objects

```
run A stop 1   instructions 1   mark 1   history 1
run A stop 2   instructions 2   mark 2   history 2
run B stop 1   instructions 1   mark 2   history 0     <- 1 > 2 is false
```

`RunState.intake_history`'s own comment says the escalation *"depends on this being **counted**
rather than remembered"*. The counter was remembered on the runner and the count was on the run.
Moving the mark onto `RunState` makes `start` unable to carry it without saying so.

## Criterion 5 - and the reproduction that failed first

The first attempt used the default runner, whose stop is **not** incomplete. Run 1 recorded `0`,
run 2 recorded `0`, the test failed - **for the wrong reason**, and would have been read as the
defect. The floor is now asserted before the claim: run 1 counts twice, and only then is run 2's
silence a finding. Third time in this review that a first reproduction passed over the defect it
was aimed at, and the first time the floor was written as a task rather than noticed afterwards.

## Reservations

1. **The rule still scans three methods by name.** `test_the_rule_looks_at_the_three_methods_that
   _exist` is the floor and asserts exactly `{approve, reject, rule}`, so a fourth is a
   conversation rather than a silent gap. Unchanged here.
2. **`RunState` gains a field that no surface renders.** `snapshot()` is a dict literal and does
   not enumerate fields, so `--json` and the console are unchanged - which also means nothing
   would show a reader that the mark reset. That is acceptable for a count nobody reads, and it is
   why criterion 4 is about `intake_history` rather than about the mark.
