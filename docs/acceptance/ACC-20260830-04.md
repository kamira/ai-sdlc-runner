## The finding

The three refusals that were already pinned are the three with a comment beside them saying what
they refuse:

> *"Refusing to report 'not pushed' — an unreachable remote is not an empty one."*
> *"An unreachable forge is not an absent PR."*

`git log`, `git status` and the timeout make the identical guarantee, in the same file, a few lines
apart. Nobody wrote the sentence, and nothing held them.

**The comment earned the test; the guarantee did not.** That is worse than yesterday's "failure
paths are under-tested", because it means the tests were written by reading the prose — and the
prose is what a reviewer checks against. A guarantee stated only in code is invisible to both.

Five modules in, this is the first finding that generalises to *how* the tests were written rather
than to what they cover.

## The one that matters most

`working_tree_clean` returning `True` when git could not be asked. `ship`'s commit probe is
`commit_exists_for(...) and working_tree_clean(...)`, so `True` marks a half-committed tree as
finished and the resume pushes it — exactly the failure CHG-20260830-03 pinned one layer up,
defeated from underneath by the layer it rests on. Pinning the top without the bottom would have
been a guarantee with a floor missing.

## A test that could not tell

The first `--fixed-strings` test used `a?b` and left the mutation `NOT CAUGHT`. Git's default grep
is a *basic* regular expression, where `?` is a literal — so removing the flag changed nothing for
that input. `.` is the discriminating character.

Sixth instance this session of a test that cannot fail for the reason it names; fourth of them
mine. Each was caught by the mutation rather than by review.

## Reservations (disclosed, not waived)

1. **The timeout is pinned on `_run`, which is the shared path — but on one command.** The test
   calls `probes._run` directly with a slow stub, so every probe is covered for that refusal rather
   than inheriting it. What is *not* checked is that each probe passes a sensible `timeout`, and
   `_run`'s missing-binary refusal is still driven only through `pr_open_for`.

   *This reservation previously said the timeout was driven "through `pr_open_for`" and disclaimed
   an inheritance the test does not rely on. It named a route the test never takes; corrected in
   CHG-20260830-05 by the review panel's conformance seat.*

2. **The ledger probes are pinned, not argued.** Whether `Branch:` and a tick mark are the right
   postconditions is D6.1's claim; this holds them steady and says nothing about whether they are
   correct.

3. **`commit_exists_for` is checked on one metacharacter.** `.` discriminates; whether every BRE
   construct behaves as expected through `--fixed-strings` is not surveyed, and does not need to be
   — the flag either applies or does not.

4. **Six modules measured, five to go.** `attachments`, `effects`, `intake`, `settings` and `tui`
   remain. The ratios — 7/9, 9/10, 5/8, 11/12, 3/7, 6/10 — still have no pattern; what does
   generalise is the two findings about *where* the gaps sit, and both were only visible after
   several modules.
