## The measurement, on a clean worktree

```
                                        before            after
pytest -k example_path, fresh worktree   1 failed          1 passed
the same, after test_change_classes      1 passed          1 passed
mutation_check --only provenance         BASELINE RED      baseline ok, all 4 caught
```

Two runs of one command on one commit gave two verdicts. The harness was honest — it printed
`BASELINE RED` and refused — but only on a tree nobody had run the suite in, so the two mutations
under that baseline were unmeasurable on a clean checkout while the records reported green.

## Why provenance and not an exemption

`worktree.py` cites `examples/minimal/greet.py` three times and every one is **about it being a
build artefact**. A file whose point is that a run produces it is deliberately not committed, and
`.gitignore` is where that decision is written down. Asking `.exists()` is neither *a reader can
open this* nor *this is an artefact* — it is *something put it here*, and something did.

An allowlist naming `greet.py` would have made this one green and left the class open. Asking git
closes the class: tracked, or ignored, or the defect.

## Two things that went wrong while writing it, both about the question rather than the answer

1. **The path went to git through a text pipe.** Python translated the separator on Windows, git
   received `examples/minimal/greet.py`, matched nothing, and answered *not ignored* — which
   reads exactly like the defect. NUL-separated bytes both ways now.
2. **Two skip arms could not be told apart.** Written as two checks, the first fires in a directory
   that is not a repository, so a mutation of the second was invisible and reported `NOT CAUGHT`.
   One question, one message, and the message names which command could not answer — which is also
   what the second mutation now pins.

## Reservations

1. **The suite still writes into the tracked source tree.** `examples/minimal/agent.py` produces
   `greet.py` beside the config it is given; moving the subprocess's `cwd` to a temporary directory
   changes nothing (`88 passed`, and the file appears anyway). What this record removes is the
   **dependence** — a verdict can no longer turn on whether that ran first. That the tree is still
   dirtied is a different subject and is stated rather than left.
2. **The rule now needs `git`.** Where it cannot answer, the test skips with a message naming the
   command, on the same argument `tools/ledger_check.py` makes for an unresolvable ref. A skip is
   not a pass, and it is not a green either — a reader has to notice it, and nothing forces them to.
