## Evidence

### The disagreement between the two engines, laid out rather than split

`codex`: add `intake_safety` to `policy.GATES` at `halt_independent`, answered by a targeted
`Approval`; asserted explicitly that this reverts no recorded decision.

`fable`: that cannot be built. Four guards, which I then read myself:

```
tests/test_policy.py     assert set(graph.gates_used()) == set(policy.GATES)
tests/test_intake.py     assert graph.BY_ID["intake_review"].gate is None
tests/test_documented_numbers.py   any "N gates" in a document must equal len(policy.GATES)
src/ai_sdlc_runner/engine.py:2085  an Approval whose gate is not in policy.GATES is refused
```

`codex` anticipated the objection and answered that its gate is *dynamic* rather than
unconditional. That does not reach the first guard, which is about membership of `policy.GATES` and
indifferent to when the gate fires. And the second guard's docstring is not a rule to satisfy but
an argument against the shape:

> *A gate that fires on a **complete** requirement would be asking a person to approve the absence
> of a problem.*

**The evidence behind the two answers was not equal, and that is the part worth recording.**
`fable` ran the suite and reproduced the defect through the engine, the terminal and the server.
`codex`'s sandbox refused to execute Python; it said so plainly and reviewed by reading, which is
the honest thing to do and was the right call in its previous three rounds. On a question about
which guards fire, the engine that could run them was right.

Taking `fable`'s shape is not preferring an engine. It is preferring the answer that survived being
checked. One piece of `codex`'s design does survive and is used: `fable`'s shape has no way to tell
a first run from a second, which the operator's rule requires, and `codex`'s journal marker is that
way.

### The four seats agreed before any of that

Round thirteen's central finding needed no adjudication: conformance, defect, risk and idiom
reported it separately, and I drove it myself before reading any of them. Three of the four then
declined to propose a repair, because the repository had never decided what an unsafe answer should
do — `CHG-20260823-13` task 4 decided only that it is *kept apart*. Conformance held its veto open
and wrote that the repair *"begins in governance"*. It did; the operator decided; this is that
decision built.

### What the existing guards caught while it was being built

Three, all of them real:

```
test_only_attach_reaches_advance_without_a_state_gate
    ['attach', 'proceed'] != ['attach']
    -> `proceed` had written its own state check beside `_require_suspension`. Two mechanisms for
       one fact. It now goes through the shared gate, which learned a parameter the way it already
       had one for the tie.

test_the_page_does_not_say_reason_belongs_to_one_question_when_two_carry_it
    section 4 has 3 conditional groups; this test reads two
    -> `safety` is now carried by two questions, so by that test's own rule it belongs above both
       group dividers, where `reason` already sits. I had left it under one and added a comment.

test_the_route_count_the_page_states_is_the_real_one
    the page says eight GET and ten POST; the server answers 8 and 11
```

The first is the useful one to record: the guard's subject is *which entry points reach `_advance`
without a state gate*, and it caught a method that had one — just not the shared one.

### And one I tripped over myself

`SUSPENSION_FIELDS["safety"]` was `()`, the only dict-valued field on that line whose empty was a
tuple. `_suspension` rendered it `[]` on every shape that does not set it, while the type is
`Dict[str, List[str]]` and `docs/API.md` documented `{}`. Printing the findings on every shape hit
`.items()` on a list within a minute.

```
grep -rn 'safety.*==.*\[\]' tests/   ->   0
```

Nothing depended on the wrong value, which is why it had survived: `test_api_schema` checks that
each key is **named** on the page, never what its value is. Presence rather than property — the
shape this entire round has been about, found inside the change that was about it.

The last one had two answers. Its exemption list takes an entry naming why a *command* cannot
supply a field — and `cmd_serve` genuinely cannot, since both values are per-walk state that
`_walk_once` sets from what the run is suspended on. But that list is **empty**, and its own
comment says so deliberately: two entries came out of it when CHG-20260903-22 closed the gap that
justified them, and *"an exemption that outlives its reason is a permission nobody re-reads"*.
`cmd_serve` now writes both empties out. They are true at the moment it starts, and two dead-looking
arguments are a smaller price than being the change that reopened that list.
