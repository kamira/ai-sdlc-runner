## What was worse than reported

The module **already computes the right number**, twelve lines from the one that does not:

```
intake.py  stop_reason     times_asked(history, aspect) + 1     counts the ask being made now
intake.py  needs_options   times_asked(history, aspect)         does not
```

So the operator was shown the correct count and the decision beside it used a different one:

```
run 3   told "(asked 3 times)"   decision: asks again        <- three declarations say options here
run 4   told "(asked 4 times)"   decision: OFFERS OPTIONS
```

The lap is not lost in `>=`, which is right. It is lost in what the history holds at the moment of
the check: `server.py` walks with a snapshot of `intake_history` and appends this run's stop only
after the walk returns.

## Two tests were named for the third ask and asserted the fourth

Both guards agreed with the defect, in the same confusion that caused it — which is the whole
answer to *why did 2075 tests not see this*.

```
test_options_are_offered_only_after_the_third_time
    docstring   "the third unanswered ask is the one that has failed, not the fourth"
    body        two recorded stops -> asserts the runner must NOT offer options

test_the_command_line_can_reach_the_escalation_it_documents
    message     "fires on the ASK_LIMIT-th unanswered ask and not before"
    assertion   [False] * ASK_LIMIT + [True]                   <- the FOURTH
```

The second contradicts its own failure message inside one statement, and its docstring is about a
**previous** defect in this same area (CHG-20260901-17). The ground was walked twice and the
vocabulary was never fixed.

**Both were rewritten, which is stated rather than buried**: changing a test so a change passes is
otherwise the move that most deserves suspicion. They are rewritten because they measured a
different quantity than their own names claim.

## Criterion 6 — the mutations, on the changed lines

```
needs_options reads the raw tally again        ██████████  4 red
stop_reason re-derives its own + 1             ██████████  1 red — the rule, and only the rule
the one name stops counting the ask in flight  ██████████  5 red
```

The middle result is the one worth keeping. Re-deriving `+ 1` inside `stop_reason` is
**behaviourally identical today**, so no behavioural test can see it — only the rule does. That is
what a rule is for: it refuses the arrangement that let two readers drift, not the symptom they
drifted into.

Mutating the line the change edited rather than the helper it introduced is deliberate. Two changes
ago that distinction was the difference between a guarded fix and an unguarded one shipping green at
2066 tests.

## Reservations

1. **A person is offered options one ask sooner than yesterday.** That is what three declarations in
   `intake.py` already promise, but anyone whose expectation came from watching the program rather
   than reading it will see a change in behaviour.
2. **`ASK_LIMIT = 3` is not re-argued here.** Whether three is the right number is a separate
   question; this change makes the program do what the file says it does.
