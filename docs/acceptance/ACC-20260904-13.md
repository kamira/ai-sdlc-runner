## L-44 - the seat's measurement holds and its explanation does not

The seat reported `None` at every stop of a default install *"including `lead_review` - the seats
have already voted"*. Measured, they have not: `walk` returns the suspension from `_gate("after")`
**before** the branch that calls `_adjudicate` for a `SEAT_PANEL`. So `None` there is correct.

The real gap is that `CHG-20260904-11` shipped three guards - one driven, asserting `None`, and two
over a hand-built report no walk produces. Task 4, *the box renders it*, rested on a fixture. It is
driven now, and the reach is written down: **two or more models on a panel, at that panel's own
gate**, and nothing on a default install at any stop.

## What it took to make six mutations catchable

```
first registration    4 BROKE        the import probe put only `tests/` on PYTHONPATH, so any
                                     test module importing the package it tests was called broken
second run            3 NOT CAUGHT   the rule was extracted AND left inline; the mutations hit the
                                     copy nothing reads
third run             1 NOT CAUGHT   the planted source could not tell reading `_answering`'s
                                     signature from writing the two names
fourth run            6 CAUGHT
```

The first is a defect in the harness and is fixed here: `_import_fails` now puts `src` on the path
alongside the file's own directory. A test module that imports the package it tests is the ordinary
case.

The third is the one worth keeping. A plant only measures a rule if the two readings **disagree on
it**: `_answering(*, gate, node_id)` gives the same answer either way. The plant that works renames
the helper's parameter and hands it a literal - under the written pair the intersection is empty,
`all([])` is `True`, and the method passes.

## And one mutation was replaced rather than made to pass

*The sibling inventory reads the page with its prose again* cannot be caught: reverting
`page = _console_code()` is invisible while no snapshot key is prose-only, and none is. Rather than
leave a `NOT CAUGHT` line or fake it, the registry now mutates the strip itself, and the floor -
`test_a_key_named_only_in_a_comment_does_not_count_as_rendered` - plants a prose-only key against
`_without_comments` directly. What is pinned is the strip; what is not pinned is that the inventory
uses it, and that is stated rather than hidden.

## Reservations

1. **The inventory's use of the strip is unpinned**, as above. A key named only in a comment is
   caught by the floor; the inventory silently reverting to the raw page is not.
2. **`_without_comments` is a scanner, not a parser.** It tracks quotes and escapes, which is what
   distinguishes a comment from a URL, and it does not know regex literals - `/x\/y/` would end a
   string it never started. Nothing in the console uses one; if that changes, the strip is where to
   look.
3. **`reason`'s grouping is checked by reading the page.** The truth comes from a run - an
   incomplete stop is driven and its `reason` asserted non-empty - but *where the page puts it* is
   still a text search over §4. A page that reorganised its dividers would need this test rewritten
   rather than merely re-run.
