## The reservation: the second ordering fix has no test that bites

This change caught two of its own placement defects, and its record is eloquent about why placement
matters — *"a check in the wrong order is a check that does not exist"*, *"a report that is only
correct when the run succeeds is not a report."* The lesson became KN-12.

The first is properly pinned: mutating `_spoken_halt` back to its wrong position turns eleven tests
red.

The second is not. The `fable` engine mutated `_finish` to emit the unspent-confirmation report
**only when `halted_at == "done"`** — precisely the pre-fix behaviour this change existed to correct
— and the suite stayed green. The one behavioural test
(`test_settings.py::test_a_confirmation_the_run_never_reached_is_reported_not_dropped`) ends at
`done`, so it exercises the one exit that always worked. The halt and suspend exits are covered only
by source-text assertions (`test_undecided.py:170`, `test_suspend_resume.py:205`) that check
`_finish` is *called* — not that its report survives the path.

The wiring is correct today. What is missing is the test that would notice if it stopped being.
Recorded, not fixed: fixing it is a modification and needs its own CHG.
