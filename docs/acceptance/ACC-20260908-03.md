## The defect, made to happen before it was fixed

The rule CHG-20260901-11 added is guarded on one of the two panel modes. Measured by renaming the
one seat-panel node's branches and validating the result:

```
lead_review with branches approve/reject, panel_branches {}   validate PASSES
```

It would then reach `engine`'s branch lookup, `node {id!r} has no branch {choice!r}` — the same
line, the same death, that CHG-20260901-11 was opened for and closed on the model-panel side only.

With the rule in place, both shapes are refused:

```
renamed branches          "node 'lead_review' is routed by the review seats, whose 'pass' names
                           no branch of its ['approve', 'reject']"
declared panel_branches   "node 'lead_review' is routed by the review seats and declares
                           `panel_branches`, which nothing routes through there — and it would
                           misname the word meaning ratified"
```

## Why the seat rule is stricter, and why that is not an inconsistency

| | takes its branch by | `panel_branches` |
|---|---|---|
| `MODEL_PANEL` | `node.panel_branches.get(panel_outcome, panel_outcome)` | consulted — declaring it is a real escape |
| `SEAT_PANEL` | `_adjudicate(...)` returns the outcome as the branch name | **never routed through** — but read once more at `engine.py:3075`, after the branch, to name the word meaning ratified. Rule 1 forces its branches to contain `pass`, so that read resolves without a declaration and a declaration could only misname it |
| every other mode | `answer_decides`, or the plan | same second read, and it is the **only** way to name the ratified word, because the branches are the node's own. `pm_signoff` settles because it declares one |

So the model-panel message can offer *"Declare `panel_branches` on it, or name its branches in the
panel's own words"* and the seat message cannot offer the first half. Two rules rather than one
widened guard, because the escapes differ.

This is also what makes the queue item's *"`lead_review` qualifies identically"* wrong. It names
`pass`/`fail`, so it is one of the four nodes that do — but it is not in the population those two
comments count, because they are about a table its path does not route through.

## What the repository's own guards caught, in this record

1. **`test_every_shipped_mutation_has_a_unique_anchor`** — adding a second `try`/`finally` to
   `_graph_swap.py` gave an existing mutation two occurrences of its anchor, so it would have
   reverted whichever came first rather than the one it names. Re-anchored.
2. **`test_every_change_id_the_source_cites_has_a_record`** — `graph.py` and `engine.py` cited
   `CHG-20260908-03` while the record was still in a scratch directory.
3. And the gap the first of those exposed: a **new shared `finally` that nothing guarded**. The
   module's own docstring says what that costs — the functions sharing that one `finally` had no
   named guard until one was written — and the fix added a second
   one. It now has the twin test and its own mutation.

## What this does not do

- No node routes differently. The shipped graph passes both new rules unchanged.
- `validate_with` is written in terms of `swapped_graph`. The first version of this record kept
  them apart and said the swap's callers rest on it closing before they see anything — true,
  and not a reason, because a `with` closes before its function returns. A seat measured the fold
  and so did this record: the three modules that call it — `test_graph_validation`,
  `test_execution_mode`, `test_risk_adjudicated` — are 81 tests and all pass folded. An earlier
  figure here said 68, having counted `test_module_built` instead of `test_risk_adjudicated`, which
  is one of the callers the fold changed. One restore is left in the module whose first line says
  "once".
- The deliberate half-swap in `test_graph_validation` is left alone, for the reason its own
  docstring gives — it exists to be wrong so the two-view rule has something to refuse.
- Nothing is done about the two function-local `import dataclasses` statements this record read
  past. They are unrelated, and a record that tidies whatever it passes is one nobody can review.
