## Two drafts that would have shipped a test unable to fail

Both were caught by running the tests against the previous commit, not by writing them carefully.
Recording them because the pattern is the point.

**Draft one ran only from the repository root** and claimed all three examples failed there. `minimal`
passed — and passed for a worse reason than failing would have been. Its path
`examples/minimal/agent.py` resolves from the root to the **original example still in the
repository**, so the copy under test never ran its own agent, and no assertion could tell. A second
working directory removes the coincidence.

**`test_a_shipped_example_writes_only_inside_itself` passed against the unfixed code**, because the
fossil was already there: `greet.py` sat in the repository root, so "what appeared during the run"
was empty. Deleting the committed artefact is what gave the test teeth. A test whose subject is
already present in the baseline measures nothing.

**And the `.gitignore` guard I wrote was itself a coarse check.** It tested
`"/greet.py" not in text` — and `examples/*/greet.py`, added moments earlier, *contains* that
substring, so the guard reported "already present" and silently added nothing. Rewritten to compare
whole lines. That is the same defect class the log names most: a check answering safe about
something it had not examined.

## Reservations (disclosed, not waived)

1. **This relocates output for every existing user, not just this repository.** Any `agent.py`
   anywhere that writes a relative path has been writing into the operator's shell directory and
   will now write beside the config. That is the intended behaviour and it is still a relocation
   nobody asked for on the day they upgrade. Documented in README *Where the agent runs*.

2. **Only `agent_command` was fixed.** `--plan`, `--ask-journal`, `--store-root` and `--token-dir`
   are all paths, and nothing here checked whether each means what it should relative to the config
   that named it. A survey is the honest next question and was not done.

3. ~~**The example run is not idempotent.** Running `weather-spa` twice with `site/` already
   populated produced `walk exceeded 200 steps — the flow is cycling without progress` rather than
   recognising there was nothing to build.~~

   **The cycling is gone, and what replaced it is different from what this asked for**
   (verified 2026-08-28, two consecutive runs: `36 nodes, 26 asks, finished` both times).

   Two changes moved it. CHG-20260823-50 made `{"module": ""}` an answer the frontier reads instead
   of discarding, which is what stopped the cycling. CHG-20260827-21 then gave each module a tree
   cut from a **commit**, so a second run no longer sees the `site/` left by the first: it rebuilds
   everything and finishes.

   So a second run is now **deterministic** rather than **short-circuiting**. That is arguably the
   better property — the old behaviour depended on leftover files in the working directory, which is
   the non-determinism the isolation exists to remove — but it is not "recognising there was nothing
   to build", and saying it was would be claiming a property this repository does not have.

4. **`tests/test_example_weather_spa.py` still invokes the agent directly** — unchanged, and
   confirmed 2026-08-28: that file contains **zero** CLI invocations.

   What has changed is the coverage gap behind it. `tests/test_worktree_isolation.py` now drives
   `weather-spa` through the real command three times, including a full multi-module build — added
   by CHG-20260828-04, which exists because **no test drove a multi-module run through the CLI** and
   a regression shipped through the hole.

   The concern is covered; the sentence above is still true of that file. Left standing rather than
   struck, because striking it would imply a rewrite that did not happen.

5. ~~No mutation entry was added.~~ **Closed rather than disclosed.** Two entries were added to
   `tools/mutation_check.py` under a new `examples` group, so the check is re-runnable rather than a
   one-time stash:

   | mutation | caught |
   |---|---|
   | the agent runs in the operator's shell directory again (`cwd=self.cwd` → `cwd=None`) | **yes** |
   | `agent_cwd` stops defaulting to the config file's directory | **yes** |

   ```
   python3 tools/mutation_check.py --only examples
   ```

   Both still only prove that a *named* class is pinned. The table cannot propose a class nobody has
   thought of, and reservation 2 is exactly such a gap left open.
