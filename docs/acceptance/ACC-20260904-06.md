## What was wrong

```
rule                                       shipped by   passed by
the class-carrying resolution scan         -46 / -04    `_aliased = here`
the operator-decision scan                 -01          keyword-only params; `gate=None`
the src/ line-number ban                   -04          "and line 515 reads"
```

Every one of these rules was written to replace a weaker one. Every replacement asks about the
**text of the code** rather than the property it is named for. That is four consecutive rules in one
chain — `-41` → `-46` → `-01` → `-04` — and this record is the fifth attempt at the same thing.

The decision scan is the sharpest: it collected `kw.arg`, the **parameter name**, so
`self._answering(gate=None, node_id=None)` read as compliant. **Worse than the defect it replaced,
because it looks like it passes the values.**

## Criterion 5 — and a reservation I wrote was false when I wrote it

`ACC-20260904-04` reservation 1: *"The rule bans a pattern that now appears nowhere."*

Measured: `plan.py` says *"`engine.py` joins any `--instruction` text onto the node spec's own, and
**line 515** reads `own = spec.get("instructions") or ()`"*. `engine.py:515` is a **blank line**;
the quoted string is at three places inside `_brief` and `_order_for`. Written twelve days ago by
`CHG-20260823-34`.

So the pattern appeared, in a spelling the rule could not see, in the tree the reservation was
written against. **A claim about absence is a claim about the search**, and the search was one
regex wide.

## And tuning the window was the wrong second attempt

The first widening allowed 60 characters between the module name and the number. The live case sits
**62 characters apart and across a line-wrap**. Widening again would have been fitting the rule to
the instance. What makes a citation a citation is the number, not its distance from a filename —
two patterns, no window.

## And the rule flagged its own explanation, for the fifth time

The comment recording what the rotten citation used to say reproduced it, so the ban caught it.
Described rather than reproduced now. Fifth instance in three days — a rule that reads prose will
read the prose explaining the rule, and each time the answer has been to change the explanation
rather than the scope. That is the right answer, and its recurrence is worth naming: **writing a
rule about text means writing text the rule will read.**

## Reservations

1. **The citation ban is broader than the defect.** A comment saying *"line 40"* about anything is
   now refused, including about a file outside this repository. Deliberate — the number is the
   fragile part regardless of what it counts — but it will refuse a legitimate sentence one day,
   and the rule is the place to argue it rather than the thing to except.
2. **Criterion 2's comparison is still structural.** It asks that the same *names* the method took
   are the expressions handed over. A method that renames its parameter before passing it would
   read as non-compliant, and one that passes a correctly-named alias of the wrong thing would
   read as compliant. It is stronger than the name-set check it replaces and it is not a proof.
3. **Nothing here is behavioural.** Three test predicates and a comment. The suite cannot tell
   whether these rules work — only a planted counterexample can, which is why the seat's four are
   in the tree rather than described in this record.
