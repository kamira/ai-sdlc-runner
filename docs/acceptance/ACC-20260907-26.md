## Evidence

### The default was the minority value

```
runner       15        model_panel   6        single  4  <- the default
pool          2        follows       2        survey  1        seat_panel 1     (31)
```

and the hazard, on a real node:

```
lead_task_review, rebuilt from its own fields minus `mode`   -> 'single'   (really model_panel)
validate() over that graph                                    -> ACCEPTED
```

`validate` already refuses a **role-less** node that is not `RUNNER`, so the runner case was
covered; a role-bearing node had nothing. Both seats verified this independently. The abandon
condition - "an intentional supported API with a documented majority use case" - is not met: one
construction in the repository omits `mode` (`tests/test_rerun_idempotence.py:118`), no document
describes a default (`grep -rni default docs/ README.md | grep -i mode` -> only `high_risk_mode`),
and the majority value would be `RUNNER` at 15/31.

### The shape, and why not the other one

Both seats refused a field with no default at all. The reason that settles it, from the defect
seat: omission becomes a `TypeError` from a constructor, outside `validate`, naming no node - and
**no test in this suite could pin it**, because every refusal here is `validate_with(...)` plus
`pytest.raises(GraphError)`. The sentinel keeps the omission sayable, which is the reasoning
CHG-20260907-11 recorded for `gate_when`. Re-measured: the most positional arguments any of the 31
`Node(` calls passes is 3, so reordering would break no call - it would only move a field and its
comment block above seven others for no reader.

Both seats also asked for a dedicated message. Measured without one:

```
node 'pm_plan' has unknown mode None
```

which sends a reader after a typo when what happened is an omission.

### The count, and the rule declined

```
role == "lead"                    5   lead_assess, lead_task_review, re_review, pr, merge
at 988ef22, the commit that wrote "three"   5   (grep -c 'role="lead"' -> 6, incl. the comment)
```

False on arrival, sixteen days. A seat corrected the draft's citation: KN-17 governs a count with a
*qualifier* and does not apply; the rule that does is CHG-20260907-12's *"name the referent"*, in
`test_a_field_count_in_prose_is_checked_against_the_thing_it_counts`. It is named in the record and
declined, with the measurement that decides it:

```
spelled-out "<word> nodes" phrases across the swept files   12
of those, true counts of a SUBSET                           11
```

so widening `test_the_node_count_in_the_documents_matches_the_graph` from digits to words - it
compares against `len(NODES)` - would fail eleven true sentences, including `graph.py:22`'s own.
The digits-only match is a design, not a gap.

### Scope, decided rather than shrugged

Both seats independently said **folds in** for the stale test name
`test_the_modes_partition_all_twenty_three_nodes` (at :52 - the brief said :61 and a seat
corrected it), removed in CHG-20260907-26 and replaced by `test_the_modes_partition_every_node`. The conformance seat's reason: this record already edits that file, and leaving a
known-false number in a file being edited is worse than the discipline that would protect. Unlike
A and B it was **true when written** - the same commit `988ef22`, when the graph had 23 nodes.
Renamed `test_the_modes_partition_every_node`; the two seats proposed slightly different names and
this record took one rather than inventing a third.

A seat also found scope the brief had missed: `tests/test_execution_mode.py:73` says *"SINGLE is
the dataclass default, so a node added without thinking about its mode lands here"* - true until
this change and false after it. Rewritten in this record.

**Nothing is registered for the count removal**, and the group comment says why rather than
