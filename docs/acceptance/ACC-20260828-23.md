## The measurement contradicted the proposal

The survey that produced this change said eleven modules have no mutation, listed their 86 `raise`
statements, and concluded their guards were *"in the state `ledger_check` was in"*. For this module
that was **wrong**: seven of its nine guarantees were already caught by tests written about other
things.

No mutation record does not mean no coverage. The two are different claims and only one of them was
measured — and the honest version of the survey is *"eleven modules whose coverage is unknown"*,
which is a smaller and less alarming statement than the one I made.

## The two real holes

**The structural guard was annotated as unexercised, in the source.**

```python
raise WorkOrderError(                                # pragma: no cover - structural guard
```

Removing the whole check left the suite green. A `pragma: no cover` on a guard is the code saying
nothing drives it; that is a note to a coverage tool, and it reads as a decision when nobody follows
it up.

**`to_json` promised sorted keys and nothing checked.** LF and UTF-8 were pinned; the determinism the
docstring leads with was not. CHG-20260828-16 made the encoding of these exact bytes matter a few
hours ago, which is what made the omission worth more than tidiness.

## A test that would have passed either way

The first version of the schema test asserted a *correct* order has the right shape — true whether
or not the guard exists. The mutation came back **NOT CAUGHT**, and a second test now widens
`WORK_ORDER_FIELDS` so `render` produces a wrong order and has to refuse it.

That is the third time this session a mutation has found a test asserting *around* a guard rather
than driving it: the dispatch-depth bound, the emergency chase, and this.

## One full-suite failure, most likely self-inflicted

One test failed once in a full run and passed alone, in a subset, and in two later full runs of the
same tree. The likeliest cause is the throwaway script that took this change's measurement: it
rewrites `workorder.py` in place and had no crash record, so a terminate could leave the file
mutated under a concurrent run. It is not proven — the process is gone.

What follows either way is that a script which rewrites source needs the same sentinel the harness
has, which is CHG-20260828-18's subject and had to be applied a second time here.
