## Why the end-to-end case is the one that matters

The defect was **not** in `_VOICES`. Two renderers each called
`_VOICES.get(str(turn.get("kind")), …)` directly — there was no resolver to get wrong. A unit test
of a resolver would therefore have passed against the broken code, because the resolver did not
exist until this change created it.

So the test that pins this drives the real CLI, stores a real conversation, exports it, and reads
the `who` out of the rendered HTML. `test_a_declared_class_is_exported_as_the_operators_act` also
asserts that *some* relaxation is present before asserting anything about all of them — otherwise
an export carrying none would pass vacuously.

## Reservations (disclosed, not waived)

1. **Naming a person does not make them accountable.** `by` is whatever the operator typed after
   `--change-class`. Nothing verifies it is a real person, that they exist, or that they agreed.
   The record is now honest about *what was claimed*; it cannot be honest about whether the claim
   is true.

2. **Other attributions are unexamined.** `ASK` is filed under `runner`, and the runner does send
   it — but the *question* came from the plan, which the PM wrote. Whether that is the right voice
   is a question this change did not ask.

3. ~~**Only the two renderers that existed are covered.**~~ **Closed while writing this.** A third
   export format could have reintroduced the defect exactly, and the mutation on `_voice_of` would
   not have noticed — it only proves the resolver works for whoever calls it.
   `test_no_renderer_reads_the_voice_table_directly` asserts the structural property instead:
   `_VOICES` is read in exactly one function, checked over the syntax tree so a docstring
   mentioning it does not count as a use.

4. **Verified by the implementer**, and found by reading a reservation the implementer wrote — which
   is an argument for writing reservations, not for the reviewer.
