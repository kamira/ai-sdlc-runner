## Evidence

### The refutation I recorded was of the wrong condition

```
acceptor draining (my probe in CHG-20260907-20):
    64 concurrent connections              0 refused    <- a queue being drained never fills

acceptor NOT draining:
    request_queue_size = 5                   5 held, the 6th refused, WinError 10061
    request_queue_size = 128               128 held, the 129th refused
    request_queue_size = socket.SOMAXCONN  200 held, the 201st refused
```

`10061` is *connection refused*, which is also what a client gets from a port with nothing
listening. The server was listening.

**The boundary, drawn where a seat insisted it be drawn.** Measured: a full backlog refuses.
Inferred: that the live acceptor was starved enough for this to be what happened. Not
established: that it *was*. The acceptor was running during the sighting, so starvation is a
reconstruction, and the honest statement is that the hypothesis was **not refuted** rather than
that it was confirmed.

### On the shipped path

```
server.serve(..., port=0).request_queue_size            128
20 connections, acceptor never started                  20 held, 0 refused
```

### The value, and the seats disagreeing about it

The first draft used `128` and justified it with *"`http.server.HTTPServer` uses it"*. It does
not, on any supported version - both inherit `socketserver`'s 5. One seat checked the claim I had
not, and proposed `socket.SOMAXCONN` instead, on the ground that a constant states a policy where
a bare number states nothing. The other measured the platform:

```
listen(200)              200 held
listen(201)              200 held    <- the clamp
listen(socket.SOMAXCONN) 200 held    the constant is 2147483647, and is truncated
```

`SOMAXCONN` would write a number Windows silently rewrites. **128 stays, with the argument it was
missing**: above the largest burst anything here makes, below the clamp. The objection was right
about the draft, and the clamp answers it - which is what laying a disagreement out instead of
averaging it is for.

### The refusal is not immediate, which nothing had recorded

```
listen(5), the 6th connection      refused after 2.03s, every time
```

The SYN is dropped, the client retransmits, the RST follows that. Every version of this record and
its source comment had said Windows answers with an RST, implying at once. It also makes the
test's `settimeout(3)` load-bearing at one second over an unrecorded two: at 2, the same refusal
would arrive as `TimeoutError` with no errno, and the assertion would fail describing the wrong
thing. Both are written down now.

### The mutation

```
CAUGHT  the listen backlog may go back to five again
```

**One entry, after a second was deleted.** It replaced the attribute with `pass` so the default
would be inherited by accident, and both seats said the same thing about it: `pass` and `= 5`
produce the identical class attribute, so no test can tell them apart and anything catching one
catches the other. It read as a second class only to a human reading the source. Both name
`tests/test_server.py::test_a_burst_of_connections_is_queued_rather_than_refused` rather than the
file: a bare edit to this class trips other tests first, and a `CAUGHT` earned by collateral says
nothing about the guarantee - a lesson from CHG-20260907-21, applied at the start here rather
than after review.

## What this does not do

It does not establish that the backlog caused the original failure. It does not touch
`tests/test_store.py` - nothing measured says that test is wrong. And it does not claim a
capacity: `SOMAXCONN` is a request and the platform answers it, so the number that results is the
platform's and the test asserts only that a burst of twenty is not refused.

## Verdict

**Pass**, after a round that corrected this record twice over: a number given a provenance it did
not have, and a cause claimed where only a mechanism was measured. A server that answered its
sixth caller by saying nothing was there now queues it, and a merged record that called a viable
explanation refuted says what the second measurement found instead.
