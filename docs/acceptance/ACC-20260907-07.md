## Evidence

### Five of my own tests were hollow, and only the mutations said so

All fifteen passed on the first write. `--only graph-validation` reported **5 of 16 NOT CAUGHT**.
Not one was a missing test. Each was a `match=` loose enough for a *different* rule to satisfy:

```
decision branch count   "branch"            also in the panel rule's "…names no branch of its […]"
step successor          "next|successor"    also in "unreachable node(s): [… 'next_module' …]"
role exists             "role"              also in the gate and mode messages beside it
rejection needs a gate  "gate|reject"       in very nearly every message this function raises
self-follow             —                   the entry named the wrong test file
```

The second is the one worth keeping: **the pattern matched a node's name**, `next_module`, inside
a list another rule prints.

This is the same defect as the alternation this change removes from
`test_a_node_cannot_follow_itself` — committed five times, in the change that removes it. Fifteen
green tests, a plan reviewed by two engines, and only the mutation run could see it.

### The rule that had never run

```
node 'engineer_selfverify' follows 'engineer_selfverify', which follows something else
```

A node following itself *is* a chain of follows, so the chain rule always fired first and said the
node followed "something else" while pointing at itself. The rule written for the case never ran,
and its test accepted either message — so *"a node cannot follow itself"* had never been tested.
Reordered; both rules now fire for their own case.

codex's contribution here was the negative one I asked for: it identified this rule as unreachable
and said it *"should not receive a pretend reverse test"*. Reordering makes it reachable instead,
which is better than either pinning a dead rule or deleting it.

### What was left alone, and why that is recorded rather than done

The **conformance seat's veto** stands on *"no node claims a gate phase without a gate"*.
`validate` refuses only `gate_when == "after" and not gate`, while an ungated node carrying the
default `"before"` also has a phase and no gate. Its message — *"has a gate phase but no gate"* —
states the contract in full while the condition implements half.

Three **gated** nodes rely on that default, and tests and records preserve it. The repair is either
a `None` phase on `Node` — touching the public shape and its server, API and schema readers — or
narrowing the published documentation. That is a decision about a contract, not a coverage gap, and
it gets its own record. `test_an_after_phase_may_not_name_no_gate` pins the enforced half and its
comment names the half that is not — that test was **removed in CHG-20260907-11**, which made
`gate_when` optional so both halves became sayable, and replaced it with
`test_a_phase_without_a_gate_is_refused` and `test_a_gate_without_a_phase_is_refused`.

## Verdict

**Pass.** The flow's only guard can now fail when it is broken, in sixteen places where it could
not. Including the one a previous repair installed, and the one that had never executed at all.
