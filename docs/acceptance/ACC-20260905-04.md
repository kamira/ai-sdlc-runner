### Two seat fixes, reversed on re-measurement

**The obvious fix for the headline was wrong.** Routing `order_paths` through `path_for` adds its
*existence* check, which silently drops a missing attachment from every work order — precisely what
`missing()` exists to prevent (*"it becomes visible"*). Criterion 2 is the test that pins the
difference, and the second registered mutation is that exact wrong fix.

**The 32-character truncation was not widened.** The defect seat measured, correctly, that the
docstring's three-paragraph justification is stale — `paths.py` supplies the extended-length prefix
now, and 64 characters was measured working under a 400-character store directory (465-character
full path). Its proposed fix was to use the full digest. Re-measured one step further:

```
manifest id (full 64-hex) / file on disk 32 chars / missing() -> []
--- after _NAME_CHARS = 64, same store ---
missing()                          ['ec3f4a4cd18a...']   <- every existing attachment
order_paths points at a real file? False
```

There is no migration path in the module and none was added. The collision surface is real and is
closed by **detection**; the width is not what makes it safe.

### Four existing fixtures were handing the store bytes that contradicted the names they test

The signature check broke four tests whose subject is filenames, not content. Their bytes were made
honest rather than the check weakened — the subject of each test is unchanged. One of them is worth
naming:

```python
store.add("wireframes.png", b"\x89PNG fake")
```

Whoever wrote that built a deliberate near-miss of the PNG signature: the first four bytes match and
the next four do not. It is exactly the mismatch this change refuses, written by hand, four rounds
before anything checked it.

A fifth test then failed on a hard-coded expectation. It already derived the digest from the bytes —
it was pointed at the old constant, not rewritten.

### The startup refusal follows the file's own idiom

The first version raised `CliError`. Measured: `cmd_serve` has no handler at that point and `main`
catches nothing, so the refusal would have reached the operator as a traceback — for a message whose
entire job is telling them which directory to change. Every other refusal in `cmd_serve` prints
`error: …` and returns 2. It does that now, and the test asserts the operator got a message rather
than a stack.

### The first run of that group did not report - it hung for an hour

```
output after 60+ minutes: "attachments group registered"   (30 bytes, nothing else)
in-flight marker         : tools/.mutation-in-flight.json, stuck on cli.py, owner PID 2344
```

The cause was **the test I had just written**. The registered revert of the startup refusal lets
`cmd_serve` reach the socket, and the test drove `cli.main([... "serve" ...])` expecting the refusal
to return first. With the refusal reverted, `serve` bound a port and served forever.

A test that hangs under its own mutation verifies nothing, and it is worse than one that fails:
`NOT CAUGHT` is a result, and a wedged run is not. The test now replaces `server.serve` with a
raiser, so reaching the socket is an immediate failure:

```
before   the mutation run wedged with no output for over an hour
after    1 failed, 71 deselected in 1.11s
```

Recorded rather than quietly fixed, because the fault was in how the test drove the code and not in
the code, and because nothing in the harness would have told me: `mutation_check` has no per-mutation
timeout, so a hanging test is indistinguishable from a slow one.

## Recorded as out of scope, with the reason

1. **The HTTP body is read before it is bounded** (risk R4, defect L-8). `_body` reads
   `Content-Length` with no cap, so a 26 MB attachment is refused only after ~35 MB is resident and
   a lying `Content-Length` parks a handler thread. That is the request layer, it applies to every
   route, and it belongs in a change about the request layer.
2. **`Runner.attach()` calls `_advance()`** (risk R4), so every accepted attachment re-walks the run
   and re-dispatches models, without requiring the run to be idle. Deliberate per `server.py`'s own
   comment; re-costing it is a decision, not a defect fix.
3. **Control characters in filenames** (defect L-9). NUL, CR/LF, BOM and U+202E round-trip. The
   render path is `textContent`, so the harm is cosmetic.
4. **`instruction` reaches no surface** (idiom L-2). Its own comment says it exists *"so a later
   brief can say where a document came from"*, and the console renders filename, media type and size
   only. Fixing it is a console change, and the console is not otherwise touched here.

Also unclosed, and named in the change that closes it: the **docstring sentence** this whole finding
rests on — *"no operator-chosen segment"* — is still false, because the store directory is
operator-chosen. The startup refusal makes the consequence unreachable; the sentence is corrected in
`CHG-20260905-05`, with `path_for`'s inverted docstring and the three records that quote an
overclaimed test.

### One warning this change introduced, and caught

```
compile(attachments.py) before this change -> 0 invalid-escape warnings
compile(attachments.py) after              -> 1, at line 276
```

The docstring I wrote for `order_paths` spelled a Windows traversal path out in full, and `\.` is
not an escape sequence. Fixed by describing the path rather than reproducing it - the same rule the
last two rounds arrived at for guards, applied to a docstring. The identical mistake was made in the
test file first and fixed there; the module's copy survived one more full-suite run before the
warning count was compared against `origin/main` rather than read past.

## Verdict

**Pass.** The check moved to the door that is actually wired, the manifest cannot be destroyed by an
interruption, an unreadable manifest can no longer wedge the runner or escape as the wrong exception
class, a stored-name collision is refused instead of silently merging two documents, a declared type
has to match the bytes, and a store directory that would halt every run is refused at launch with
the directory named. The module has a mutation group for the first time.
