## What the review found, and what it cost

The seat returned nine findings. Three of them changed code, one changed a test, three changed
records, one was a wording fix and one was an argument the record now carries. They are listed
before the criteria because two of them were the record asserting things that were not true.

**1. A second copy of the rule, in the same file, added by the record that removes second copies.**
`_loopback_origin` carried `literal = f"[{host}]" if ":" in host else host` - byte-identical to the
body of the `_authority` this change lifted into `src/`, ninety lines away, in the file whose entire
subject across four records is *one boundary written twice*. The draft record closed by asserting
*"There is no second copy."* It now reads `_authority(host)`, and that call site turns out to be the
one where the bracket is **reached in production**: every request carrying an IPv6 `Origin` goes
through it, and `test_an_ipv6_origin_is_refused_because_nothing_serves_one` sends three on every
run. The rule inventory in the record was wrong in the direction that mattered - three rules before,
not two - and is corrected.

**2. `142 tests passed` was the finished tree's number on a measurement of a different tree.** The
sentence that carries the whole narrowing decision. The seat collected all three trees:

```
c014889 (merged main)                        tests/test_server.py collects 139
c014889 + LOOPBACK = ("127.0.0.1",) only                                   138
the finished change                                                        142
```

Re-measured here on merged main with only the narrowing applied, no derivation and no test edited:
**138 passed, nothing failed.** The claim survived; the number did not.

**3. Three assertions that could not fail.** CHG-20260907-21's shape conditions - every member of
`RESOLVER_FIXED` is a bare lowercase name that `ipaddress.ip_address` refuses - were carried into
the new test beside a literal pin of the same set. Beside a *derived* expected set they constrained
something that could vary; beside the pin they iterate `["localhost"]` and assert three constants,
and every single-edit widening is refused by the pin or by the live `Host` test first. They are
removed, and the rule is stated at `RESOLVER_FIXED` in `server.py` instead, addressed to whoever
adds the second member. A record whose own principle is *an entry that cannot fail must not be
registered* could not ship an assertion that cannot fail.

**4. The ledger's ghost-test rule was green by accident.** This change deletes
`test_the_header_set_is_the_bind_list_plus_the_one_name_a_standard_fixes`, a name removed in
CHG-20260907-24 because deriving the header set made the equality it asserts true by construction,
and one that is backticked in CHG-20260907-19 and CHG-20260907-21. Both of those passed
`check_named_tests_exist` - but excused by the removal clause belonging to the *other*, older test
name in the same sentence, which happened to fall inside `EXCUSE_WINDOW`. Both records now say the name was removed in CHG-20260907-24, and the
new clause was falsified rather than assumed: standing alone with no other removal sentence near it
it excuses the name, and with it deleted the name is refused.

**5, 6.** A docstring said the replaced test *"could not fail"*; it could - `_loopback_host`'s port
strip is not supplied by any derivation, and the ported form is still sent. And a registry `says`
read *"an address that is not this machine"* for `127.0.0.2`, which **is** this machine - it is in
127.0.0.0/8, and that is exactly why ACC-20260907-20 refused the `is_loopback` weakening of the
socket test. Both corrected.

**7.** The seat pressed the `_authority` argument: *"wrap an unreachable branch in a function, call
it from a test, declare it falsifiable"* generalises badly. The answer is finding 1 - the rule has a
reachable call site now, and it is the one the seat found.

**8.** An accepted criterion is inverted. ACC-20260907-20 criterion 4 is *"`localhost` still binds
and is still accepted"*. It is retired by name in the change record rather than left in a diff.

**9.** This acceptance had been drafted with a `Pass` and a placeholder in it before the review
returned. That is the finding this section exists because of.

## Evidence

### The table is the same table

```
LOOPBACK        before  ('127.0.0.1', 'localhost')   after  ('127.0.0.1',)
LOOPBACK_HOSTS  before  ['127.0.0.1', 'localhost']   after  ['127.0.0.1', 'localhost']
```

Nothing a request can say changes. The one behavioural change is on the other side of the call:
`serve(host="localhost")` is refused. Searched for a caller that breaks - `src/`, `tests/`, `tools/`,
`docs/`, `config/`, `examples/`, `README.md`, `AGENTS.md` - and the seat searched independently.
There is no `--host` flag; `cli.py` calls `serve(runner, operator, port=args.port, ...)`; the only
`host=` callers in the repository are two tests. `models.py` uses the string `"localhost"` to
classify a model endpoint as local, which is a different code path and is untouched.

### The measurement that decided the open question

```
                                    derived table                equal to shipped?
LOOPBACK = ("127.0.0.1","localhost")
    with   | RESOLVER_FIXED         ['127.0.0.1', 'localhost']         True
    without                         ['127.0.0.1', 'localhost']         True    <- the finding
LOOPBACK = ("127.0.0.1",)
    with   | RESOLVER_FIXED         ['127.0.0.1', 'localhost']         True
    without                         ['127.0.0.1']                      False

Run as a mutation on a tree with `localhost` put back and the union term dropped, `-x` off:
2 failed, 142 passed, and both failures are this record's own assertions, which encode the decision
itself. **No behavioural test objected** - not the two live `Host: localhost` tests, not the
`Origin` test. That is the statement: with `localhost` in both constants, deleting RFC 6761 from
the server changes no answer it gives, which is what would have shipped had the name stayed.

### Two edits nothing can catch, both written down instead of registered

```

Deriving a table that already had the right members, and de-duplicating an expression, are both
behaviour-preserving today. That is what a refactor is. Neither is registered, and the
`derived-hosts` group comment says so and says why.

Four entries were **deleted with their guarantees**, each named with the state that no longer

not the file.

`bind` entry 4 was re-anchored for a different reason, and it is a cost of the narrowing rather than

address those are the same string - measured `NOT CAUGHT`. The assertion behind it is unchanged; the
entry now mutates the refusal into naming no address at all, which is `CAUGHT`.

## What this does not do

It does not build IPv6, does not touch `cli.py`, and does not decide whether `LOCALHOST.` or
`*.localhost` should be accepted. It does not claim the derivation is checked by a test: the
refactor's correctness today is an identity, and what is newly checkable is the rule, on inputs the
constant does not have.

## Verdict

**Pass, after the review changed the change.** A boundary that was written twice is written once,
and the name that made the standard's half of it unfalsifiable was measured out of the other half
rather than argued about for a fourth record. Two of the things this record asserted before review
were false - a second copy it said did not exist, and a number belonging to a different tree - and
both were the kind a green suite cannot find. One seat found them; two would have been the standard
this thread set.
