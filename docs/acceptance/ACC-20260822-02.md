> **Superseded 2026-08-28 (CHG-20260828-13): the vendored skill store no longer exists.**
>
> `skills/` was removed by [CHG-20260823-01](../changes/CHG-20260823-01.md) — *"our own governance,

> reservation below about the store's version, its size, or what it would take to update it
> describes a subsystem this repository no longer has.
>
> They are left standing rather than struck: each was true when written, and they are the record of
> why the vendoring approach was abandoned. **A reader should not act on any of them.**

1. **The fallback value is dead by construction, and knowingly so.** `./skills/v1.16.0` is reached
   only when `./skills` resolves to nothing — in which case that path is missing too. It was chosen
   for *diagnostic coherence*, not reachability: the resulting error now names the governed local
   store instead of an archived repository. CHG-ii deletes it.
2. **It hardcodes a store version that will rot.** `v1.16.0` will be wrong once the baseline moves.
   Bounded, not eliminated: it sits beside `contract_version` in the same file and is bumped by the
   same discipline, and CHG-ii removes it. Named here so the next baseline bump does not miss it.
3. **CHG-ii is not yet opened**, and this CHG's value depends on it existing: the duplicated default
   across `runner.yaml` and `cli.py` remains, as does the `None`-return hazard the panel identified.
   The panel specified the fix concretely (a `SkillPathError`, surfaced house-style at all six call
   sites, with tests) but left one point open — codex would define it in `cli.py`, fable in
   `skillstore.py` to avoid the `cli`↔`dashboard` import cycle that `dashboard.py:629`'s lazy import
   currently dodges. **That placement question must be settled in CHG-ii's own round.**
4. **The vendored store is 48 minor versions behind.** `skills/` tops out at v1.16.0 while the
   published skill is v1.64.0. Untouched here and unrelated to the rename, but it is the reason the
   probe fix cannot arrive by simply updating the store. Still open.
