## The proposal named a mechanism that cannot do the job

Task 1 said to make `lead_assess` adjudicated with `adjudicate(voices="models")`. **That function
cannot grade.** It counts how many voices said `pass` and returns pass / undecided / fail — it is
binary, and a grade is one of three. Asking it for `"medium"` returns a count of passes.

So `policy.adjudicate_grade` exists, and its docstring says why it is not the other one. Recorded
here because the proposal is otherwise sound and this is the only part of it that could not be
built as written.

## Two rules that must not be collapsed

| | rule | why |
|---|---|---|
| **deciding** the grade | strict majority; anything else is `undecided` and reaches a person | `policy.adjudicate`'s own docstring: a model panel has **no veto**, because every voice answers the same question and there is no per-voice subject for a veto to be about. "Any voice saying `high` makes it high" is a veto wearing another name |
| **protecting** an open question | `strictest(...)` of every candidate | this is not a decision about what the grade *is*; it is how much protection an unsettled question gets |

Collapsing them would let one cautious voice decide alone — the exact thing this change removes.

## An existing invariant refused my first attempt, and it was right

`graph.validate` refuses `MODEL_PANEL` on anything but a `DECISION`:

> several models on one question are voices to adjudicate, and a node that reaches no verdict has
> nothing to adjudicate. Work-producing nodes with several models are not settled

That reasoning is correct. The rule it is really enforcing is **a panel must adjudicate something** —
a `DECISION` reaches a branch, and `lead_assess` reaches a grade. So the condition was widened by
exactly one case rather than dropped, and what the guard exists to refuse — a plain work-producing
step with several models, which is why `engineer_build` is a `POOL` — is still refused.

A second invariant was added in the same place: a node that grades risk and is **not** a panel is
refused. Without it, this whole change could be undone by editing one field back to `SINGLE`, with
nothing going red.

## The mutation table caught a test passing for the wrong reason

`--only risk` reported one **NOT CAUGHT**: disabling the panel-on-a-step invariant left all 18 tests
green.

The test for it asserted `"adjudicate" in str(exc.value)`. With the invariant disabled a *different*
check fired — the one about settling a grade nobody proposes — whose message contains
*"unadjudicated"*, which contains the substring. **The assertion matched the wrong error.**

Now `"that grades nothing"`, plus the node id. The neighbouring test had the same weakness in another
form — `assert A in msg or B in msg`, which passes if either error fires — and is now the one phrase
it means.

This is the second time in two days that `mutation_check` has found a loose *test* rather than loose
code, and both times the looseness was a substring that matched something else.

## Reservations (disclosed, not waived)

1. **A panel grading risk well is not established by any of this.** Three voices agreeing on `low`
   is three voices, not a fact. What this buys is that one voice can no longer decide alone and
   silently — which is a different and smaller claim than "the grade is now right".

2. **No end-to-end run drives a grading panel through the real CLI.** Checks 1–14 exercise
   `adjudicate_grade`, `_grade_in_force` and `validate` directly. The seam between them — a
   `lead_assess` panel actually answering with grades in a walked flow — is covered by wiring and by
   the existing panel machinery, not by a test that walks it. That is the same gap CHG-20260827-19's
   acceptance closed for itself and this one has not.

3. **`risk_settled` falls back to `cfg.risk` when no grading node ran.** That is the resumed-run and
   no-models case. It is the honest default, and it means a run with no models configured behaves
   exactly as before this change — including the circularity, because there is only one grade.

4. **Task 3 says "gates up to and including `pm_signoff`".** What is implemented is "until
   `settles_risk` passes", which is the same set today because `pm_signoff` is the only ratifier. If
   a later change adds a second, the phrase and the code would diverge.
