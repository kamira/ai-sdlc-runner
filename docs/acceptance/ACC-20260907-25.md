## Evidence

### The measurement that reversed two seats

CHG-20260907-10 recorded both reviewers recommending a `conftest.py` fixture, and
`_validate_one`'s docstring called it *"the agreed repair"*. What that round did not have:

```
                                    signature changes at call sites   new lines per file
support module in tests/                       0                      1 import  (3 total)
fixture in tests/conftest.py                  39                      0
```

Behind the `0`, measured by running it rather than by reading pytest's documentation: a throwaway
`tests/_probe_support.py` imported as `from _probe_support import MARKER` gave `1 passed` invoked
as a single file, and resolved under a whole-suite collection as well (`29 passed, 2306
deselected`). Both probe files were deleted before the seats were convened; the tree they reviewed
was clean at `c014889`.

The measurement went to both seats with the instruction to decide, not to average. Both chose the
support module, and each brought a reason the brief did not contain:

- **fable:** this suite already shares test-side helpers by bare sibling import **36 times across
  20 files**; the `conftest.py` fixture idiom exists for injection, and its one existing member
  proves it - `py_stub` consumes `tmp_path`. Re-measured here: `from test_flow import ...` at
  module top level in **8** files (`git grep -c '^from test_flow import' HEAD -- tests/`), and 36
  sibling-import statements before this change, 39 after (AST over every `Import`/`ImportFrom`
  whose top module is a `tests/` sibling).
- **codex:** a fixture would be **wrong**, not merely expensive. Fixture teardown runs after the
  test body, so a test that catches the expected `GraphError` and then reads `graph.NODES` or
  `graph.BY_ID` would see the hypothetical graph. Keeping the inner `try/finally` prevents that,
  and once it is kept the teardown buys nothing.

Collision checks, so the choice is measured: `importlib.util.find_spec("_graph_swap")` -> `None`;
`tools/` holds no such name; one flat unpackaged `tests/`, so the duplicate-basename hazard cannot
arise; pytest collects `test_*.py`, so the module is not collected;
`tests/test_nothing_is_unwired.py` globs `test_*.py` only.

Row one is 43 objectors of which 41 are collateral: `validate` raises its identity refusal and
their own `match=` string stops matching. Measured over all 34 distinct `match=` patterns in the
three files, **exactly one** - `"rebound separately"`, the deliberate half-swap's own - matches
that message, so a file-level `CAUGHT` would be reporting 41 regexes missing rather than the swap.
The node registered is the one whose docstring states the guarantee: *"Swapping both views instead
refuses it, for a reason about the graph rather than about the rebinding."*

Row three is why the new test exists. Before it, nothing named could notice the `finally` going -
the catches were later tests inheriting a polluted graph, which is collection order, and
`pytest-randomly` is not installed so that order is stable, which makes the collateral reliable and
no more meaningful. Registering the restore mutation against a file would have produced a clean
`CAUGHT` over a hole. Row four is the same mutation against the test written for it.

The new test asserts **identity**, not equality: `graph.NODES == original` would also hold for a
`finally` that rebuilt an equal tuple, and an equal tuple is precisely what CHG-20260907-10's
`BY_ID.get(node.id) is not node` refuses.

**One mutation is absent on purpose**, and the group comment says so: nothing is registered for
`_validate_one`'s arity, because its splice and `_mutate` build the same tuple for the cases its
two callers exercise, so no edit between the two shapes is observable by any test. Inventing one to
round the group up to three is the thing `mutation_check.py`'s own docstring warns against.

## What was not run, and why

**`pytest -q` over the whole suite.** The operator's standing rule is one full suite at a time
across all worktrees, announced before it starts, and a second track was running in parallel in
another worktree for the whole of this build. A background agent cannot announce before the fact,
so the honest outcome was to not start one. Criterion 12 is **outstanding**, not passed, and it is
the operator's to run.

What that leaves: the three files this change edits are green together (74), every guard file that
reads the tree's shape is green (174), the README's collected count is the measured one, and no
`src/` line moved - so the population a full run would add is the tests that neither import the
helper nor read the documents. The risk is low and it is not zero, and this record says which.

## Verdict

**Pass.** Three copies of one stateful swap are one, decided by two seats that reversed their
predecessors on a measurement those predecessors did not have; the deliberate counter-example and
both out-of-scope sites are untouched; three false sentences are gone and the two measurements
inside them are rehomed; and the shared `finally` that 39 test functions now depend on is pinned by
a test written for it rather than by collection order. Subject to the full suite, which this record
declines to start.
