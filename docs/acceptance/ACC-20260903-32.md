## Reservations

1. **`test_a_crash_part_way_through_a_migration_leaves_nothing_behind` does not test `store.py`.**
   It builds its own connection and demonstrates the `sqlite3` semantics both ways — which is why
   it stayed **green under the revert**. What pins `store.py` is
   `test_every_migration_block_opens_its_transaction`, a source-level rule counting version stamps
   against `BEGIN`s. That is weaker than driving the real migration to a crash, and a stronger test
   would inject a failing statement into `_SCHEMA_1`. Named rather than implied.
2. **Task 7 documents a gap instead of closing it.** `commit` and `worklog` remain unbuilt, so the
   flow's *"three ordered effects"* is still a comment on work nothing does — one layer in from
   where it was. What a `commit` effect probes for is a design question with an operator in it, and
   a seat may rule this should have built them.
3. **`Trees.report()` was deleted, not repaired.** It has no caller in this repository and appears
   in no document, so this is safe here — but it is a public-looking method on a public-looking
   class, and a downstream reader could have been calling it. The comment left in its place says
   what it did and why it went, which is the most a deletion can do.
4. **Task 1 changes crash behaviour, from repair to rollback.** A partially written store used to be
   recovered by `CREATE TABLE IF NOT EXISTS` and `_verify_or_refuse`; it is now rolled back and the
   next open starts clean. That is what the paragraphs promise, and it is still a behaviour change
   on the one path nobody exercises deliberately.
