## Reservations (disclosed, not waived)

1. **CI is not enforced.** `main` has no branch protection, so these checks are advisory: a merge can
   still proceed with them red. Making them required is a repo-settings change (outward, and the
   user's to make), deliberately not performed here. Until then CI reports, it does not gate.
2. **No coverage gate, by design.** Measured coverage is 55% overall with `cli.py` at **0%** (384
   statements, the largest module in the repo) and `orchestrator.py` at 21%. This CHG does not
   address that, and the recorded reason for not adding a threshold — that coverage rated
   `executors.py` at 86% while it was completely broken on Windows — is an argument against the
   metric as a *gate*, not against improving the underlying tests. The `cli.py` and `orchestrator.py`
   gaps are real and remain open.
3. **`executors.py:87-88` (launch failure → `ExecutorError`) is uncovered**, a gap created by
   CHG-20260817-09 removing the tests that reached it by crashing. Assigned to its own CHG per the
   user's decision; not fixed here.
4. **The pinned actions will break on a future runner change.** Every job carries the annotation
   "Node.js 20 is deprecated. The following actions target Node.js 20 but are being forced to run on
   Node.js 24: `actions/checkout@v4`, `actions/setup-python@v5`." The run is green today because the
   runner force-upgrades them, but that compatibility shim is temporary. Bumping to `checkout@v5` /
   `setup-python@v6` is a one-line-each change and belongs in its own CHG; recorded here so it is not
   rediscovered as a surprise breakage.
