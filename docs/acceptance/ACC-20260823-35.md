## The defect: a refusal no user can reach

The CHG showcases this transcript:

```
$ runner export --store mongo
the mongo store was removed in CHG-20260823-35 ...
```

What actually happens, run on 2026-08-27:

```
runner export: error: argument --store: invalid choice: 'mongo' (choose from 'sqlite', 'file')
```

Exit 2, from argparse. The cause is one line: `--store` is declared with
`choices=conv_mod.BACKENDS` (`cli.py:556`), and `BACKENDS` does not contain the retired names. Both
CLI callers of `backend()` — `cli.py:429` and `cli.py:577` — are fed from that argument, so the
`RETIRED` branch at `conversations.py:764` is **dead from the CLI**.

`git show 52017b4:src/ai_sdlc_runner/cli.py` — this change's own commit — already has the `choices=`
constraint. So this is **not drift**: the showcase line was never true of the CLI.

Two things make it worth writing down rather than shrugging at:

- It is **KN-8-shaped**: a correct mechanism that nothing which matters can reach. This repo's named
  recurring failure, found again by an acceptance round rather than by the suite.
- The existing test passes and always would. `::test_a_removed_backend_is_refused_by_name_...` calls
  `backend()` directly. It would still pass with the CLI wire cut, because the CLI wire was never
  there. **A test that asserts the current behaviour proves nothing** — §8 of the guideline, and here
  it is.

Not fixed in this round: fixing it is a modification and needs its own CHG.
