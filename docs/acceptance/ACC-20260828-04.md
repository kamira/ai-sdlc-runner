## How it was found, and how it should have been found

Found by **running `examples/weather-spa`** while taking the wall-clock measurement CHG-20260827-21
task 6 asks for. Not by a test, and not by review: the change had shipped hours earlier with a full
green suite and five green CI checks on two platforms.

It should have been found by a test that runs a multi-module build through the real command. There
was none, and the reason is worth keeping:

| test | why it missed this |
|---|---|
| `test_example_weather_spa.py` | drives the console and the server — **zero** CLI runs |
| every other end-to-end test | uses `examples/minimal`, which has **one** module |
| `test_worktree_isolation.py` | two modules, but the artifacts were written *by the test*, not by an agent that reads them back |

Each is a real test. Together they left exactly the shape that matters uncovered: **several modules,
built by an agent that reads what the last one wrote.**

## The second cause was inside the first fix

Carrying artifacts forward did not work on its own, and the reason is the finding:

`git status --porcelain --ignored` reports an ignored **directory** as a single entry with a
trailing slash — `examples/weather-spa/site/` — not the files inside it. The code checked
`is_file()` on that entry and copied **nothing at all** for the case it had just been written for.

The check carried a comment saying *"a directory entry; its files are listed separately"*. That
sentence is false. It was written when `carry` was first added, it was never verified, and it read
as an explanation rather than as an assumption — which is why it survived a review by the person who
wrote it.

`test_an_ignored_directory_is_carried_whole` now asserts `artifacts(...) == ["out/"]` directly, so
the collapsing is a checked fact rather than a remembered one.

## Reservations (disclosed, not waived)

1. **The regression was mine, shipped four hours earlier, with everything green.** Full suite, five
   CI checks, two platforms, four Python versions, and 7/7 mutations. None of it covered a
   multi-module CLI run. A green table is a statement about the tests that exist.

2. **The mutation that pins the directory case takes eight minutes**, because breaking it makes
   `weather-spa` cycle to the step cap before the test fails. That is the correct failure and it is
   slow; a faster proxy would be a weaker one.

3. **Not every filesystem-reading agent is fixed.** One that reads a database, a cache, or a
   directory above the repository still sees whatever is there. This is about files git was told to
   ignore *inside* the tree.

4. ~~**A halted run keeps its trees and nothing prunes them.**~~ **Closed, after it bit.**
   ACC-20260827-21 disclosed this as reservation 3 and it was not theoretical: 156 registrations
   made `git status` take minutes and the suite take twenty-two. Kept trees are now unregistered
   and left on disk.

5. **Nothing prunes the artifact set.** Everything ignored-and-present is copied into every
   subsequent tree, so a build that leaves a large ignored directory pays for it once per module.
   Measured on `weather-spa` it is four small files; it is not measured on anything larger.
