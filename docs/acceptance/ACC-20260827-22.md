## Four defects, and what found each

Recording *what found them*, because three of the four were found by something other than my
judgement, and the fourth was found by a mutation after I had already written the test I thought
covered it.

**`MAX_DISPATCH_DEPTH = 3` was wrong — found by `test_nothing_is_unwired`.** The guard refused a
constant nothing computed. Computing it showed the real depth is **2**: `reconcile` returns to the
runner's main line, so `pm → planner` and `lead → engineer` are siblings, not a chain. The prose I
wrote in the change itself (*"pm → planner → lead → engineer is three dispatches"*) is what misled
me, and the engineer note it replaced — *"the tree stays two deep"* — had been **true while its
stated reason stopped being true**. That is this repository's own dominant defect class, reproduced
inside the change that removes it.

**`conflict → pm_plan` cycled — found by writing the test.** `pm_plan`'s answer cannot change
`cfg.interfaces`; they come from the plan file. So a conflict routed back is unchanged by
definition and the flow spins to `max_steps`, where the operator is told only that something
looped. Bounded to one revision pass — the bound `re_review` already puts on a fix.

**`interfaces` never reached the run — found by the end-to-end case.** `plan.load` parsed it,
`RunConfig` had the field, `conflicts()` was correct, and every unit test passed. `cli.py` never
passed `plan.get("interfaces")` into `RunConfig`. The unit tests could not have found this and the
E2E control-versus-subject pair found it on the first run.

**The depth bound was not enforced where I claimed — found by a mutation.** Deleting
`policy.check_dispatch_depth(...)` from `engine.walk` left the whole suite green: my test called the
function directly and nothing drove it through a run. **The same defect as the first one, in the
same change, after I had supposedly fixed it** — a guarantee stated in one place and checked in
another that never meets it. Now driven through `walk`.

## Two things fixed that the change did not set out to fix

**A halt reported itself as a normal finish.** Every `TERMINAL` node set `state = FINISHED`, whose
docstring says *"the flow ended where it was designed to"*, while `STOPPED` is documented as *"a
permanent halt"*. So `halt_second_fail` — a run that gave up — was indistinguishable from `done`,
which is precisely the distinction the state vocabulary exists to draw. Found because
`halt_unreconciled` halted correctly and announced success.

`Node.permanent` is declared, not matched on a `halt_` prefix: a naming convention is not a
constraint, and a terminal added tomorrow and called `abandoned` would report success with nothing
to say so. `graph.validate` refuses it on a non-terminal.

**This changes `halt_second_fail`'s reported state**, which is outside the change's stated scope.
Stated in the CHG rather than slipped in. Fixing it only for the new node would leave two halts
disagreeing about what a halt is.

**A test read source text instead of behaviour.**
`test_finished_and_suspended_are_not_the_same_shape` asserted
`"report.state = FINISHED" in inspect.getsource(engine.walk)`. The line became
`STOPPED if node.permanent else FINISHED`; `done` still reports `FINISHED`, nothing it cared about
changed, and it failed. It matched **vocabulary** for a claim about **behaviour** — a named failure
class in this repository. Replaced with a run that reaches `done`.

## The mutation anchors caught two mutations that would have lied

The uniqueness check I put in front of the mutation list refused two anchors that appear twice:

* `if name not in workstreams:` — the other guards `node_workstream`, so the mutation would have
  reverted a different guarantee than its label claims and been "caught" by an unrelated test.
* `interfaces=plan.get("interfaces") or {},` — `cmd_run` and `cmd_serve` both build a `RunConfig`.
  Mutating the console path leaves the tested path working, and the mutation reports a pass it did
  not earn.

Both narrowed. This is worth recording because a mutation suite's failure mode is *silent*: a
mis-anchored mutation reads as coverage.

## Reservations (disclosed, not waived)

1. **A sub-plan's *content* is not reconciled — only its declared interfaces.** Two planners can
   agree on `fetch(id) -> User` and still plan incompatible work behind it. The node compares
   declarations, which is what a declaration is for; it is not a design review, and nothing here
   should be read as one.

2. ~~**The signature is an opaque string.** `(id) -> User` and `(id)->User` are a conflict…
   it is a false stop and it is not measured here.~~

   **Half closed by [CHG-20260828-11](../changes/CHG-20260828-11.md).** This sentence conflated two
   things, which is why it stayed open: *"normalising would mean parsing a type language"* is true
   of **semantic** normalising and not of **whitespace**. Spacing around punctuation is no longer a
   conflict; `List[int]` against `list[int]` still is, and that half needs the type language the
   reservation correctly says this runner lacks.

   Also still true: the false stop was never **measured**, and is not now.

3. **`can_spawn` is still not enforced at the process level.** The planner's `can_spawn=False` is
   policy, and CHG-20260827-23 says the same of every role. The bound is real in the graph and in
   `check_dispatch_depth`; it is not enforced against an agent that decides to spawn anyway.

4. **The second tier is unexercised at scale.** Everything here runs with two workstreams. A
   programme with eight is the shape this was built for and is not what was tested.

5. **Verified by the implementer.** The four defects above were each found by a guard, a test, or a
   mutation rather than by review, which is the argument for the guards and not for the reviewer.
