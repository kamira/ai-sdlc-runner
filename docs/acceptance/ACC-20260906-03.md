## Evidence

### Before and after, the same run

```
                                     before                    after
attach one file to a finished run    17 nodes re-dispatched    5 nodes
                                     merge re-dispatched       merge NOT re-dispatched
                                     state stays 'finished'    state becomes 'suspended'
                                     no stop for a person      stops at plan_confirmed
                                     "nothing further was      the gate asks again, and says
                                      asked for"                which approval was retired
```

### The rule was already here, for models only

```
engine._ask     "Reuse the answer only if the question is the same one. Anything else is
                 answering the new brief with words said about the old one."
engine.walk     "A confirmation is spent, not standing … because the operator confirmed *that*
                 stop having seen it."
```

`Approval`'s docstring says `node_id` and `run_id` are *"what make refusing a stale or misdirected
answer possible"*. Neither changes when the brief does. Attachments already carried the stamp this
needed; approvals did not.

## Three tests refused my first fix, and each refused it differently

I first refused `attach`/`instruct` on a run that was over. This is the part of the round worth
keeping:

1. `test_a_finished_run_does_not_still_carry_the_failure_before_it` — **adding to the brief is the
   recorded recovery path** for a run stopped by a raise (`CHG-20260903-29` / `-34`). Refusing
   `stopped` closes the recovery, not the hole.
2. `test_an_action_arriving_as_the_walk_decides_to_stop_is_not_stranded` — refusing without checking
   `_walking` **strands** an action that raced the walk's decision to stop.
3. `test_an_agent_that_cycles_is_stopped_by_the_step_cap` — its shipped scenario carries the comment
   `# a second walk over finished work`. The workflow I was refusing is one the repository
   demonstrates on purpose.

The third reframed the question. Both engines were asked it again with that evidence and answered
the same way independently: **the defect is the approvals, not the restart.** `codex`, on whether to
adjust the example instead: *"changing the shipped example to accommodate the narrow refusal would
hide the compatibility failure rather than fix the approval-lifetime defect."*

I did not edit the example. It passes untouched.

## The constraint that makes this safe

A re-walk with no brief change must keep its approvals, or every resume stops at the gate it just
cleared:

```
no brief change   8 approvals, run reaches 'finished', retired_approvals == []
brief changed     'finished' -> 'suspended' at plan_confirmed, merge/pr/qa_accept not re-dispatched
```

Two of the six mutations pin exactly those two directions, so neither can be lost without the suite
saying so.

## One mutation was NOT CAUGHT, and it was the same shape as the round

```
NOT CAUGHT the operator is never told an approval was retired
```

My tests asserted the **field** and the **console HTML** and nothing asserted the **snapshot** — the
only thing the console and `--json` ever see. That is this round's recurring shape, one level up
from where it usually appears: a fact that reaches one layer and stops. The test now asserts the
snapshot, and it is caught.

The repository's own guard caught the sibling of this a step earlier: adding `retired_approvals` to
the snapshot without rendering it failed `test_every_key_the_server_sends_reaches_the_console`
immediately. That guard exists because this project keeps shipping fields nobody can see, and it
worked.

## Three guards this repository already had, and I tripped all three

A new field has to reach a person, and this project has been bitten enough to have built the
checks. In one change I failed each of them once:

```
test_every_key_the_server_sends_reaches_the_console      added to the snapshot, not rendered
test_the_snapshot_section_lists_every_key_the_snapshot_carries   rendered, not documented
--only approval-lifetime, "the operator is never told"   documented, not asserted through the snapshot
```

None of the three is redundant: they catch the same idea leaving by three different doors, and each
caught me at a different one.

## What is left, and recorded rather than bundled

- **R12-6, the per-upload walk cost.** Three documents attached to a parked run cost three walks
  where one would do. Not a defect — it is the design `instruct` already commits to — and the
  console-side batching that would fix it is a separate change.

## Verdict

**Pass.** A person's answer is now scoped to the brief they were shown, the same way a model's
already was. Nothing is refused, the recovery path and the shipped example are untouched, and a run
whose brief changed stops at its gates instead of walking through them on answers given for a
different question.
