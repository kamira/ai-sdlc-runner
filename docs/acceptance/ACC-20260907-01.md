## Evidence

### The measurement that made the case, and it needed no harness

```
$ cli._Stub() driven through engine.walk on main
nodes asked: ['intake_review', 'intake_review', 'intake_review', 'pm_plan', 'pm_confirm']
raised at  : node 'pm_confirm' decides on its answer, but the answer named no branch
```

Three seats asked, three keyless answers, survey complete, the run **planned**, and the refusal
came from the node after the one whose contract was broken. This is the default path: `_Stub` is
what `runner run` uses when no agent is configured.

The seat reported the defect as *"an agent that printed prose"*. The measured version is worse and
more ordinary: the agent that answers `{"verdict": "pass"}` — correct at every other seat node in
this runner — was counted at intake as having looked and found nothing.

### codex's PARTIAL, re-measured rather than accepted or dismissed

It raised two conflicts. They are not the same kind.

**`test_a_complete_requirement_says_so`.** codex read it as a test that depends on keyless answers
continuing. It does depend on that. But its docstring states its subject — *"problems do not make a
requirement incomplete — missing aspects do"* — and seat `"b": {}` is filler for a second seat.
Depending on a behaviour is not being about it; this repository has made that distinction before,
in `CHG-20260904-15`, against itself.

**`cli._Stub`.** This one holds, and the answer is that the change moves a failure rather than
creating one. Teaching the stub to answer the contract was considered and rejected: a stub that
says *"I looked and found nothing"* would make a dry run report a **passed** intake review. A
failure is better than a false pass, and an earlier failure naming the right contract is better
than a later one naming branches.

codex proposed escalating the stub question to governance. It was not escalated, and the reason is
stated rather than assumed: nothing previously forbidden is being permitted. An existing failure is
being moved to its cause.

### The doubles are the finding at a second layer

The contract is written in three places and honoured by almost nothing:

```
honoured   3    test_flow.Recorder · one sendback dispatcher · examples/minimal/agent.py
did not   34    18 test files, plus the shipped cli._Stub
enforced   0    until this change
```

216 tests went red on the first run. **Not one failed on an assertion.** Every failure was a double
answering a survey node with a verdict. The repair was additive everywhere:

```
git diff --stat -- tests/    18 files, 194 insertions(+), 10 deletions(-)
```

The ten deletions are the `return {"verdict": "pass"}` lines that were wrapped in a branch, not
assertions removed.

### It has bitten before, twice, and was fixed locally each time

Three doubles carry comments about this exact confusion, written by whoever hit it:

```
test_flow.Recorder            "A survey, not a panel. It is asked what is wrong and what is missing"
test_sendback_retry_reject    "Counting its asks towards the review panel's rounds had the panel
                               pass before it was ever asked to object"
test_resume                   "a review panel that says nothing no longer passes for one that
                               voted no (CHG-20260903-27)"
```

The third is this rule, for panels, already decided and in the ledger. Each earlier encounter
repaired the double in front of it and left the rule unwritten, which is why the next double had to
learn it again. This change writes the rule where it cannot be walked past.

## Verdict

**Pass.** The survey now refuses a seat that says nothing about the requirement, for the reason it
already refused an aspect it does not recognise: a survey that treats silence as agreement is
agreeing with a voice that did not speak.
