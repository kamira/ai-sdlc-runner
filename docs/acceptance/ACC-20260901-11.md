## A new field on `Node` is pinned in three places, and all three fired

Adding one field to a frozen dataclass turned three tests red, which is the repository working:

| test | what it holds |

| `test_the_node_entry_lists_every_field_of_a_node` | `docs/SCHEMAS.md` enumerates every field |

`panel_branches` is **withheld** from `/flow`, alongside `answer_decides`, `grades_risk` and
`settles_risk`, for the reason that page already gives: the console draws the flow and does not
adjudicate it. This is the sharpest case of that rule — the field exists *only* to translate an
adjudication into a node's own words.

Two of the three document edits were silent no-ops on the first attempt: the documents are CRLF and
the search strings were LF. Caught by re-running the tests, not by the edit reporting success —
which is the same class as the `PYTHONPATH` miss above, and the second time in one change that a
tool reported success while measuring nothing.

## Two things the fixing found out about itself

**The first revert measured nothing.** Reverting `engine` and running the panel file reported
`1 error in 0.69s`, which reads like a red. It was a collection error: the subprocess did not inherit
`PYTHONPATH=src` and could not import the package. Re-run with the environment, the same revert is
`2 failed`. A red that is not about the code is this repository's oldest recurring measurement
defect and it took two minutes here.

**The first source comment was false.** It said `graph.validate` makes an unroutable node "a startup
error rather than a run that dies mid-flight". `validate()` is called by `cli.cmd_flow` and by three
test files, and by **nothing** on a `run`. Corrected before shipping; the true statement is in the
source and in reservation 3.

## The test the suite never had

`tests/test_panel_and_pool.py` configured several models on `lead_task_review`, `engineer_build` and
`qa_verify` — every one a `pass`/`fail` node. The two `yes`/`no` nodes appear there only in a
single-model answer map, which never reaches the adjudicator. So the file that exists to prove the
mode does something at run time proved it for the three nodes where the vocabularies happened to
agree.

The replacement is parametrised over `graph.NODES`, so a node added tomorrow with a third
vocabulary is covered by existing code. Two things it had to learn while being written:

- **A panel's voices answer in the panel's vocabulary.** The harness answered `"yes"` at
  `pm_confirm`; `policy.adjudicate` counts `pass`, so two voices saying `yes` adjudicate to `fail`
  and the run looped `pm_confirm → pm_plan` 66 times until `max_steps`. The node's own words are
  what the *outcome* is routed to, never what a voice says.
- **`re_review` is not on a green path.** It exists only after `lead_task_review` fails. It is
  reached by answering `fail` there — named in the test rather than skipped, because a node this
  test cannot reach is a node it is not testing, and quietly passing on one is how the gap it closes
  stayed open.

## Reservations (disclosed, not waived)

1. **Written by the implementer**, on a defect somebody else found. The design panel's prototype is
   what surfaced it; nothing in this repository's own suite would have.

2. **The three `pass`/`fail` nodes declare nothing, and that is a choice.** Requiring every panel
   node to declare a mapping — including an identity one — would be more uniform and more noise.
   `validate` enforces *routability*, not declaration, so either shape passes and neither can be
   silently wrong.

3. **`validate()` does not run on a `run`.** It is called by `runner flow` and by the tests. A graph
   edited to be unroutable is therefore caught by the command and by CI, and a `run` still finds out
   at the node with `has no branch`. Making `run` validate is cheap and probably right, and it is a
   behaviour change to every run's startup — its own change, not this one.

4. **`policy.adjudicate`'s vocabulary is now load-bearing in two files.** `graph.validate` imports
   `policy` to know what a panel can answer. That import already existed for gates and roles, so
   this adds a second reason rather than a new coupling — but two files that must agree about a
   vocabulary is the shape this ledger has watched drift before.
