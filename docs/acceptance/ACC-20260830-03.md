## The finding is the shape, not the count

Three of seven is the worst ratio of the five modules measured, but the number is less interesting
than where the line fell:

* **pinned** — the intent is recorded first; the PR step asks whether one is open; the push step
  asks whether the branch is on the remote.
* **unpinned** — every guarantee about what happens when a step *fails*.

`tests/test_kill_resume.py` drives the sequence end to end and asserts what landed, so the success
side is well covered by construction. Nothing drove a step that goes wrong. That is not an accident
of this module: a test written by asking *"does the thing work"* covers exactly the half that
answers yes.

The four modules before this one produced holes that looked unrelated to each other. This one
produced four holes with a single cause, which is the more useful kind of result — it says where to
look next in every other module, not just this one.

## Why these four cost more than most

`ship` pushes branches and opens pull requests. A sequence reporting success on a failed push is
worse than one that never ran, because the operator stops looking. `_refuse` is the same shape as
CHG-20260828-15's `record_module` — an effect that reports success having written nothing — in the
module that writes governance records.

## Reservations (disclosed, not waived)

1. **`probes.py` is underneath all of this and was not measured.** Every effect delegates its probe
   there. A probe answering wrongly defeats all seven guarantees from below and nothing here would
   notice — it is the sixth of the eleven with no mutation record and should be next.

2. **The ordering is pinned as a name, not as a sequence.** The `record-intent` mutation renames the
   first effect, which the test catches. That it is *first* because a record written afterwards can
   be lost by a crash is `test_kill_resume`'s argument; this change did not strengthen it.

3. **`_git`'s refusal is checked on one failing command.** `git checkout no-such-branch` returns
   non-zero, which is enough to pin the check. Whether every failure mode of every git command in
   the sequence produces a useful message is not examined.

4. **Nine cases, four of them the opposite direction.** That is deliberate — a refusal that fires
   always would pass a test that only asserts refusals — but it means roughly half the new cases
   assert that nothing happens, which is the weaker half of any suite.

5. **Verified by the implementer.** The holes were found by the harness. Reading `ship.py` did not
   surface them, and three of the four sit under comments explaining exactly why they matter.
