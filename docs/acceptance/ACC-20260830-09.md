## The shape of this round

Round 4's finding was that the guard's skip disarmed the detector. The fix added a test to prove the
guard works. **That test is what round 5 found**, and it did more damage than the defect it was
written about: it deleted the harness's live record on every mutation, so a kill in that window left
a mutated file with no record, no `--recover` path, and a guard that could not fire.

Three seats reached it independently. It is the fourth consecutive round where the largest finding
sits inside the previous round's fix, and the second where the instrument of verification was itself
the defect.

The second veto is the same shape one layer up: correcting a record, I deleted a sentence that said
*this number is another seat's and I did not verify it* — and marked a different correction in the
same hunk. The rule I keep breaking is not "mark corrections"; it is that **deleting a limitation is
a correction**, and it reads as an improvement while it is happening.

## What the seats ruled

Both governance questions handed over in CHG-20260830-08 came back decided, and both are taken:

- **The veto rule stands; its message was wrong.** A seat able to decline its own veto makes the veto
  advisory. The `reason` string reported a speech act where the code knows a rule. One string.
- **A void acceptance should reopen its change**, scoped to verdicts saying the finding never held —
  not to `superseded`, which is history. It fires on exactly one pair today, so it needed no
  grandfathering.

The conformance seat also noted that `policy` and the seat prompts use "veto" for two different
things, and that reconciling them is a person's decision. That is reservation 2.

## Reservations (disclosed, not waived)

1. **Written by the implementer.** Five rounds: 35, 36, 33, 31, 28 findings, every one `fail`. Four
   of the five had their largest finding inside the previous round's fix.

2. **"Veto" means two things in this system.** `policy` means *a veto seat did not pass*; the seat
   prompts ask for a per-finding mark meaning *disqualifying*. The message no longer asserts the
   second, but the collision is unresolved and is a design decision for a person.

3. **`MUTATION_IN_FLIGHT` is coverage by accident.** Nothing tests that the override is honoured —
   the guard test depends on it, so breaking it breaks that test. That is not the same as pinning it.

4. **A second environment knob on the harness.** `MUTATION_RUN` now has to match the record's owner,
   which closes the leak the risk seat named. `MUTATION_IN_FLIGHT` has no such check; a leaked value
   points the harness at a file it will not find, which fails loudly rather than silently.

5. **The floors are equalities now**, so any new module or in-scope handler fails the survey until
   the number is re-made. That is the intent — the number is a coverage claim — but it will read as
   a spurious failure to whoever adds the module.

6. **Risk's round-1 observations remain untouched** — `reach_of` grading every single-label host
   `internal`, the secret scan reading only the query string, two markdown formats pinned by test,
   the constant-time test foreclosing hashed tokens.
