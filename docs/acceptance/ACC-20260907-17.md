## What changed a reviewer's mind

Its survey said *"of 40 hits, only three are load-bearing"* — right about the count. The evidence
that moved it was that **CHG-20260907-14 walked over one of these clauses**: a page reworded, a
strong branch turned false, the weak branch catching it, and no report of the loss. An escape
clause is what a loss looks like when nothing reports it.

It then found the site that outranks that one, and it is worse than either of us had said:

```
GET /run/events, no token   -> HTTP/1.1 401 Unauthorized, 135-byte body, server closes
  opening = recv(400)       -> 172 bytes of headers        truthy, so "the stream did not open" passes
  sleep 3.0; recv(200)      -> the buffered error body     truthy, so `or True` is never consulted
  next recv                 -> empty: closed before the sleep began
```

The guard for a shipped change was measuring a refusal, and the line above it —
`operator_token = …__dict__  # unused; token comes from the request below` — was false: nothing
below carried a token. The fixture held the operator and did not hand it over, so the test could
not have sent one.

## Evidence

### Both halves of the stream repair are load-bearing

```
no token    assert b'200' in b'HTTP/1.1 401 Unauthorized'    1 failed
no publish  (a bare recv, as the old shape)                  1 failed
```

`_stream` blocks on the queue and sends nothing of its own, so a bare read waits out the socket
timeout whether the stream is alive or closed — which is how the `or True` came to be written. And
the opening frame is drained rather than sampled: `recv(400)` took the first four hundred bytes of
a longer snapshot, so the read after the deadline returned the *old* frame's tail. Three runs,
stable.

### The escaping assertion was wrong twice

Measured on the replay page: `<img src=x` absent, `&lt;img` absent, and the six characters
`<` present. The strong branch expected an escaping this page does not use; the weak branch
was a missing backslash that made it the single character `<`, true of any HTML. The product was
correct throughout, and removing the tautology is what revealed the other branch had never held.

### The lint, both directions

```
or True                            FLAGGED
weaker branch                      FLAGGED
two JSON spellings (legitimate)    allowed
upper and lower (legitimate)       allowed
```

No exception list: the one deliberate site became a comment, which is what a statement that cannot
fail has always been.

## What this does not establish

The reviewer that reversed also drew the line, and the record keeps it: the `SCHEMAS.md` evidence
does **not** show the page was ever wrong — the block listed exactly the persisted fields and named
the computed ones throughout. It shows the narrower thing, which is enough: a strong branch went
false and nothing said so.

And the rule holds shapes, not the class. Three kinds escape it, named in the CHG — a clause true
by the container's type, a fallback that is tautological only when reached, and an assertion whose
subject was bound to a name first. The last of those is in the very test this record repairs, and
**reading found it where scanning reported zero**.

## Verdict

**Pass.** Six assertions now fail when the thing they name stops being true, the rule refuses the
two shapes that can be recognised, and the shapes it cannot recognise are written down rather than
implied to be absent.
