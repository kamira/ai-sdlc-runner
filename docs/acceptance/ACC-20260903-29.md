## Criterion 9 — the half that did not reproduce

L-27 was stated as two halves. The second — *"`RunState.error` is never cleared on a successful
walk"* — is **false**, and no fix is shipped for it:

```
error, then start() again   -> start() builds a fresh RunState:  state=finished  error=''
error, then approve()       -> ServerError: "this run is stopped; there is nothing waiting
                               for an answer."
```

`self.state.error` is indeed assigned at exactly one site (`server.py:510`) and never reset, but the
state machine closes both routes to a successful walk carrying a stale error. Recorded so nobody
re-derives it from the same reading.

## Reservations

1. **Criterion 1's test now makes every new snapshot key a console obligation.** Adding a field to
   `RunState.snapshot()` fails the suite until the console names it. That is the point of a rule
   over a list — it is what would have caught L-27 — but it is a real cost on a surface that may
   legitimately want to ship data before it has a place to draw it. A future record that wants that
   should widen the rule deliberately rather than delete it.
2. **The decisions section does not paginate.** A long run prints one line per adjudication. The log
   section above it has the same shape, so this is consistent rather than newly wrong — but a run
   with many rounds will make the page long.
3. **The dot-token scan is narrow.** It catches a selector written into `class="…"`; it says nothing
   about a class that is simply never defined, which is the neighbouring and equally silent
   failure. Narrow on purpose, and not a proof that the console's classes all exist.
