## What the review found

### 1. Blocking, from both seats in different words: the command line was left exposed

The first build filled `RunConfig.intake_ask_in_flight` on the server and left `cmd_run` at the
default, arguing the CLI's rule was knowable only after the walk. The codex seat refused the
argument in one sentence:

> the claim that the fact is knowable only after `walk()` is too strong: by the time the engine
> evaluates `needs_options`, it has already performed the intake survey asks and has populated
> `report.resumed`.

That is right, and it is the design the change now carries. `engine.walk` measures *"did this node
open a session?"* over the survey's own asks, after the seats and before the escalation, and ANDs it
with what the caller declared. Two inputs, because neither can answer for the other: the conjunct
cannot see an attachment, and the declaration cannot see a journal hit.

Both seats reproduced the exposure and the closure independently:

```
                              resumed  asks  options?  stops after
base   --resume, same brief        3     4    YES          3      <- exposed
after  --resume, same brief        3     3    no           2      <- closed
```

And the rejected alternative stayed rejected on a measurement, not an opinion. The second seat drove
the case the record named — `--resume` with a **new** instruction, which re-dispatches every ask
because the order changed:

```
base   resumed 0, asks 4, options YES, stops 3
after  resumed 0, asks 4, options YES, stops 3      <- unchanged
```

`not cfg.resume` would have suppressed that real escalation. The conjunct does not.

### 2. Blocking, process: the tree the seats were given was not the tree

The second seat found `cli.py` changing under it mid-review, and said so before saying anything
else: it had been pinned to `fa36077`, and seven files of first-round repairs were uncommitted by
the time it read them. It declined to certify a commit that would not ship. The repairs are

*"measures out sound"*.

This is the reason "give reviewers a pinned worktree" exists, and it was half-followed: the tree was
pinned when the seats started and stopped being pinned while they ran.

### 3. An assertion that measured nothing on the lap it was added for

### 4. A mutation that measured its own spelling

### 5. A comment describing a race the state machine forbids

The new assignment's comment said an `instruct` arriving mid-walk could make the pre-walk read and
the post-walk guard differ, and called that harmless. The second seat measured that it is **not
reachable**: `start`, `instruct` and `attach` all set `state = "running"` under the lock before
calling `_advance`, and `instruct` refuses anything but `suspended`, `idle`, `finished` or
`stopped`. `attach` can arrive mid-walk and does not touch `instructions`. A comment that documents
an impossible divergence is worse than one that documents none — it reads as licence for a real
one. Corrected to state the guarantee.

### 6. A gap the change created and nothing measured

`cmd_serve` walks with `resume=True` and a journal (`cli.py:1571-1572` on `3a8caf2`), so the new
conjunct is live there too. It is inert on the `instruct` and `attach` laps because both change

### 8. Blocking: the conjunct is not inert on `serve`'s `start`

The record said *"start, instruct and attach each change instructions or artifacts, so the order and
the journal differ and every seat asks again."* False for `start`. `Runner.start` builds a fresh
`RunState`; `cmd_serve`'s journal lives at `token_dir/asks`, persists across processes, has no run
id and nothing clears it. The same brief started again replays every seat — **when the journal's
last intake walk was on exactly that brief**, a clause the third round adds because without it the
finding claims more than the journal does. The journal keeps one order per ask id and the last walk
overwrote it, so `start a, instruct b, restart, start a` compares a brief of `a` against an order
for `a + b` and re-asks everything.

```
                                       declared  resumed  asks  tally  the <p>
3a8caf2  start, finish, start same brief   n/a       3      3      1   (asked once)
28afbc2  start, finish, start same brief   True      3      3      1   (asked 0 times)

4b9ec61, third round, the clause measured through the real `Runner`
         start a, restart, start a        True      3      3      0   (not asked yet)
         start a, instruct b, restart, start a
                                          True      0      3      1   (asked once)
```

An operator meets the difference as one extra instruction: without a restart the second instruction
puts options on the table, and after a same-brief restart it takes three, because the restarting
`start` asks nobody, records no stop and advances no count. Measured on the same runner.

The append guard read `told > instructions_when_last_asked` — true, the mark restarts at `-1` — so
the stop was recorded and the counter said 1. The engine read that AND *"did this node open a
session?"* — false — so the sentence counted the ask out, and the spelling table had no entry for 0.
One box, two answers: the defect CHG-20260903-42 closed, reintroduced by this record's own conjunct
on the path it had declared unaffected. The append guard had become a **third** reader.

### 12. Blocking: a sentence the code refutes, carried at four sites

`server.py`'s guard comment, this document and the record all said *an option ask is dispatched only
where `in_flight` already held*. `intake.needs_options` refutes it in one line:

```
needs_options = times_asked + (1 if in_flight else 0) >= ASK_LIMIT

recorded=3  in_flight=False  ->  3 >= 3  ->  True
```

An attach past the limit dispatches an option ask with `in_flight` false. Swept rather than probed —
every sequence of `instruct` / `attach` / same-brief restart up to five operations, 2004 walks
through the real `Runner`:

```
where the option ask fired    the engine's in_flight    the guard's `told > mark`
instruct, 151 walks           True                      True
attach,    43 walks           False                     False
```

The guard's **conclusion** survives, on two legs neither document had: `in_flight` is a conjunction,
so where it is false either the requirement did not grow — and the guard's first conjunct has
already refused — or the survey came back wholly from the journal, which with a grown brief is
impossible (the journal keeps one order per ask id) except on a replayed `start`, whose fresh
`RunState` has an empty history and so cannot escalate at all. Measured: all 363 swept walks with
`told > mark` and a fully resumed survey are restarts, every one with an empty history and no option
ask; and across the 2004 walks the option ask changed the guard's answer **zero** times.

This is the class finding 5 blocked earlier in this same record, in the **mirror direction**, and
the difference is worth stating rather than glossing: there a comment described a race the state
machine forbids — reachable in the prose, unreachable in the code; here the prose says unreachable
and the code reaches it. One class, a reachability claim the code does not support, and this
direction is the more dangerous of the two, because the reader's conclusion is right and only the
reason is rotten. Corrected at all four sites.

### 15. The assumption both guards rest on, stated twice and pinned by nothing

`Runner._walk_once`'s `len(report.resumed) < len(report.asks)` is **report-wide**; `engine.walk`'s

Two closures were offered. **The pin was chosen over the scoping repair**, and the reason is the

decision. It would trade an unpinned graph assumption for an unpinned id format, inside a guard
whose subject is two readers of one fact. The test costs nothing at runtime, fails by name the
moment the graph moves, and names the alternative repair in its own failure message.

`test_nothing_asks_anybody_before_the_node_the_append_guard_counts_over` checks both halves of the
