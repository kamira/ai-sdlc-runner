## The reservation: the importer, and the fixture that could not catch it

The losslessness measured here — 306 turns, turn for turn — used a **clean** fixture. That is the one
input incapable of detecting the failure CHG-42 then found: on dirty input the importer truncated
3 of 7 and reported *"already here"*, in violation of `DATABASE.md` §6.

Also false at this commit: *"a second run skips"* was not true for a stump, per CHG-42.

The lesson is not that the measurement was dishonest — it is that **a losslessness claim measured
only on clean input measures the wrong thing**, and the fixture chosen made the defect invisible.
That is the same shape as CHG-06's finding about self-authored benchmarks, arriving in a different
subsystem.
