## What the reviewers refused

**`fable` refuted a measurement I had already written into the source.** I had recorded that a
misspelled kind is always still caught, by some other rule naming some other node. Re-run per node,
four shipped nodes accept it outright — `record_module`, `done`, `plan_scope`, `module_built`. I
had measured the nodes that happen to have a neighbour to trip over. The refuted sentence is gone
from `graph.py`; the measurement that refuted it is there instead, and the four nodes are a
parametrised test so a partial repair cannot pass.

**`codex` and `fable` reached the same second finding independently**, neither prompted for it: the
two edge shapes are not exclusive, and `validate` unions what a run chooses between. They described
its mechanism differently and only one description survived measurement — see the CHG record. The
rule refuses both directions; the record keeps the distinction because the harms differ.

**Both refused `Node.__post_init__`**, for the same reason arrived at separately: a construction-
time rule would make `dataclasses.replace(node, kind="stpe")` unbuildable, and that expression is
the shape of every reverse test in `test_graph_validation.py` and of sixteen pinned mutations.

## Evidence

### The vocabulary was open, and it cost a run its ending

```
kind='terminal'   state='finished'   halted_at='done'
kind='termnial'   state='finished'   halted_at=None
```

Measured through a real `engine.walk` with every gate confirmed. `finished` there is the dataclass
default at `engine.py:392` surviving, not an answer computed — the same shape as CHG-20260907-06.
The loss reaches the durable record too: `engine.py:2077` closes the conversation with
`at_node=report.halted_at`.

### The guard was measuring a graph that does not run

Moving `reconcile`'s `unresolved` branch onto its `next` — a change no rule refused:

```

a run can actually reach : 30 nodes
counted but unreachable  : halt_unreconciled
```

### A closed set does not refuse the wrong member

`LOOP` appears in one condition in `graph.py`, shared with `DECISION`, and nowhere else in the
repository. Both loops relabelled `DECISION` validates; 5 of the 10 decisions accept being
relabelled `LOOP`. Neither structural candidate separates them — *on a cycle* and *has a back-edge*
both hold for 25 of 31 nodes, the same vacuity that defeated two of CHG-20260907-08's four
candidates. So it is pinned, not derived.

### The mutations

```
CAUGHT  a node's kind may be nonsense again
CAUGHT  a node may declare an edge no run can take again
CAUGHT  the closed set may quietly gain a member again
CAUGHT  which nodes are loops may change unnoticed again
```

The third was written before anything could catch it: `test_which_nodes_are_loops_is_pinned`
asserted only that the shipped kinds were *drawn from* `KINDS`, which a set that gains a member
still satisfies. The membership is asserted now. A set that is closed and refuses nothing is not
closed.

## Verdict

**Pass.** A node's kind is drawn from a written set, a node may no longer declare an edge that no
run can take, and the two facts a closed set cannot express — which member each node is, and which
members the set has — are written where changing them is a decision.
