## Why the gap was unconditional

`_change_classes` **refuses** a run-level `--change-class` when the plan names several workstreams,
deliberately — *"one sentence cannot have assessed all of these"*. So a split programme can only use
the per-workstream form, `cfg.change_class` is necessarily empty there, and the attribution failed
**every time**. The per-workstream form exists for split programmes, and on split programmes it was
the only case there is.

The declaration turn was missing on both `cmd_run` and `cmd_serve`, guarded identically. They now
call one function — CHG-20260903-36 was *"two fixes shipped into one module and never swept into
their siblings"*, so a third caller should not be able to diverge in the first place.

## Criterion 2 — naming several people is the truthful answer here

The change record's first draft called joining the authorisers a misattribution. That is right for a
**run-level** field and wrong for a gate belonging to no workstream: `merge` relaxes only if
`policy.combined_class` finds *every* workstream pre-authorised, so it opened on all of their
authority at once. Corrected in the record rather than left standing.

## Reservations

1. **Old documents stay wrong.** `by` is written into the turn at run time and `export_conversation`
   reads the stored turns, so re-exporting an existing conversation will not repair it. Any export
   taken before this change attributes to `runner` gates that a person pre-authorised. Stated rather
   than implied, because a reader could reasonably expect a re-export to fix it.
2. **A new `RunReport` field lands in `--json` and `docs/SCHEMAS.md`.** Additive; no existing key
   changes.
3. **`class_authorised_by` survives beside the new map** and is still read as the fallback. It is
   correct on the single-class path and empty on every split one — a field that is right about half
   the shapes it can be asked about. Left in place because removing it would move the run-level path
   this change is not scoped to touch.
