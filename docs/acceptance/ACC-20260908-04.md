## The measurement that was wrong twice

Both wrong answers were **zero**, and only one of them was a typo. The first counted with `os.walk`
on an unprefixed path, which is the defect measuring itself: the walk cannot reach what the tests
built, so it reports nothing left behind. The second used the shell's `/c/...` spelling, which
Python on Windows does not resolve, so it walked a directory that does not exist — and `os.walk` of
a missing path also yields nothing.

Two different mistakes, one identical output, and the output was the one that would have closed the
item as a non-defect. It is recorded because the general form is worth more than this fix: **a
measurement whose failure mode and whose negative result look the same is not evidence.** The third
attempt walks `paths.real` of a real Windows path and disagrees with both.
