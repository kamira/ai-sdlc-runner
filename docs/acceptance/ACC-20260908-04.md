# ACC-20260908-04 - the directories pytest's own cleanup cannot remove

- Project: ai-sdlc-runner
- Target CHG: CHG-20260908-04
- Date: 2026-09-08 (UTC+0)
- Reviewed by: **two independent seats**, cross-consensus, each given a pinned read-only worktree.
  **Both refused the first build**; what is below is the second.
- Conclusion: **Pass, after both seats refused**

## What the first build got wrong

The change was right and almost every sentence about it was not. The blocking finding was shared:
`shutil.rmtree(..., ignore_errors=True)` cannot fail, so a removal that silently does nothing leaves
every test green while the directories accumulate — a guard that cannot fail, written into the
repair for another defect.

The running seat then measured, and refuted six more:

| the first build said | measured |
|---|---|
| *"nobody could delete them, not `rmdir /s`"* | `cmd /c rmdir /s /q` → exit 0, gone |
| *"`os.walk` stops at 227 characters"* | `os.listdir` succeeds at 250, first fails at 256 |
| *"the first count reported zero because the walk could not descend"* | plain `os.walk` returns 74–75 of 79–83; both zeros came from a `/c/…` path Python does not resolve |
| *"320-character chains"* | `_deep` stops at the first boundary at or past 320; 345, 359, 365, 402 measured |
| *"11.7s against 1.1s"* | 0.87–1.38s against 0.66–0.82s; no teardown over 0.01s |
| *"each holding four of these chains"* | three from `test_paths`, one from `test_conversations_sqlite` |

And it found what the first round had listed as *still open*: a **second module** building a chain
with no cleanup, `test_conversations_sqlite.py:483`. The basetemp that this record's own first suite
run produced held six entries past 259 characters, every one of them from that test.

## What the seats' disagreement produced

Both seats reached the same blocking finding from different directions — the reading seat from the
shape of `ignore_errors=True`, the running seat by constructing a case where it bites. Neither would
have produced the second module: that came from a sweep the reading seat could not run and the first
round had deferred.

The narrowing of the warning came from running it. Its first condition — *warn whenever the
directory survives* — was written from the same reasoning that produced the fix, and it took one run
to show that condition was wrong in a way no reading would have caught: 41 warnings on directories
that are nobody's problem.

## What is still open, and belongs elsewhere

- The stranded basetemps already on the machine. `rmdir /s /q` removes them; that is an operator
  action, not a change.
- Whether any module outside `tests/` builds a deep chain. The sweep covered `tests/` and `tools/`.
- `tests/test_attachments.py` builds 235/252-character directories through `mkdtemp` and removes
  them with a prefixed `rmtree` in a `finally`. Measured clean, and left alone.
