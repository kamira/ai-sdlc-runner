## Evidence

### The framing, which the two engines did not share

`codex`: *"one change record, three defects in one state machine."*

The second `fable` seat: **two definitions of one count, plus a journal defect intake merely
exposes** — and it measured the second half outside intake, where a `pm_confirm` answer naming no
branch is journaled, replayed with nothing dispatched, and refused again. That makes `read_options`
an instance rather than the thing itself, and it is why the repair went into `_ask` with the
acceptance rule passed in, rather than into the option site.

### The reversion claim that was checked and did not hold

`codex` asked for part of CHG-20260901-17 to be explicitly superseded, on the grounds that its
table counts repeated CLI invocations as stops. Measured on the repaired tree:

```
plain 1..5   stops 1,2,3,4,5      unchanged
--resume     stops 5,5,5          was 6,7,8
```

`already` is populated only inside `if cfg.resume:`, so those five invocations asked the seats each
time and each stop was real. The table stands; no supersession is needed. Reasoned by codex,
refuted by running it.

### The reversion claim that was found only because someone looked for a third

Both `or not self.intake_history` and `mark = -1` produce identical counts over every sequence. The
second `fable` seat enumerated that, then checked something neither engine had been asked about:

```
under `or not intake_history`   CHG-20260904-09's mutation stays GREEN
under `mark = -1`               it goes RED
```

Same behaviour; one of them silently turns an existing guard into a test that cannot fail. That is
the reason `-1` was chosen, and it is not a behavioural reason at all.

### The one only the mutation found, and it was mine

`refused-answer`'s first entry came back **NOT CAUGHT** with 53 tests green.

```
NOT CAUGHT an answer the walk refused is reused from the journal again
             53 passed in 0.39s
```

`AskJournal.refuse` reads the file `record` wrote — status `pending`, **no `result`** — because
`_ask` validates *before* it journals an answer. Its docstring said *"the result is kept rather
than dropped."* It was not. `answers()` requires a `result`, so the poisoned-journal test wrote a
payload nothing would ever reuse, and the test written to prove the reuse check was hollow.

A method whose comment claimed a behaviour it did not have — **written in the round whose entire
subject is that defect** — pinned by a test that could not fail. Two engines reviewed the plan and
neither saw it. The suite was green. Only the mutation reported it, and the tool's own wording is
why it was not mistaken for coverage:

> *a missing test, a stale anchor, a duplicated anchor, a red baseline, or a module that would not
> import are five different faults, and only the first is about coverage*

Re-running after the repair also produced `ANCHOR GONE` on the second entry, because the fix
changed the line it named — reported as *"stale, which is not the same as caught"*, and
re-anchored rather than assumed.

## Verdict

**Pass.** Both writers now apply the same rule to the same count, the first stop of a run that
began on nothing is an ask, and an answer the walk refused is neither replayed nor lost — including
in journals written before this change, which is the only version of the repair that helps somebody
already stuck.
