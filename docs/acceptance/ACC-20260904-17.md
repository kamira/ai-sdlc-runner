## What the round found, and why the order was forced

`settings.py` is the answer to 「在 GUI 上設定」. The GUI reached **two of its three fields**, and
the obvious fix - adding the `ordinary_commands` row - would have inverted save and discard:

```
operator types 3  ->  "3. Vouched commands"      edit() SAVES and closes
operator types 4  ->  "4. Save and close"        edit() DISCARDS
```

`edit()` compared `tui.select`'s bare index to the literals `2` and `3` while the labels lived in a
separate list, and `_edit_seats` kept `options` and `values` as parallel lists with one condition
written twice. **Nothing in the repository asserted what label sits at any index**: swapping two
rows left 2145 tests green. So the keying was fixed before the row was added.

The six screen tests typed numbers. They now name the row, through a `_Picks` driver that raises
when no row matches rather than answering something else - and it earned that immediately, telling
me the confirmation prompt is itself a menu with its own labels.

## Criterion 3, and the guard that was not enough

The first version of the reachability guard read the rows' **labels**. Replacing the vouch row's
effect with *discard* left it green, because the label was still there. Naming a row is not the
same as it doing anything - the same distinction six rounds of this review have turned on - so the
row is now driven end to end: pick it, add `npm`, save, and read `ordinary_commands` back.

what a vouch is.

## Reservations

1. **The screen still cannot remove a setting it did not add.** `_edit_vouched` offers *Add* and
   *Remove <name>*, both operating on the tuple in memory; a file hand-edited to hold something the
   validator refuses is still repaired by hand, because `cmd_settings` loads before it renders. The
   change makes that unreachable **through the screen**; it does not make a bad file openable.
2. **`FIELDS` reachability is checked by word, not by binding.** The guard asks whether a row's
   label or detail contains a word from the field name. A fourth field named, say, `retry_budget`
   with a row labelled *Retries* would pass while binding nothing. What is pinned properly is the
   seat options' label-to-value agreement and the vouch row's behaviour; the general binding of a
   row to a field is not, and a `FIELDS`-to-effect map would be the way to close it.
