## The bounds, each with the patch that produces it

Three rounds gave three different numbers for the same bounds because "reverting the bound" is not
one operation, and because the fixture translated newlines. Both are settled; the patch is recorded
beside the figure so the next reader can reproduce it exactly.

| bound | patch | rows red |
|---|---|---|
| `_PARAGRAPH_BREAK` | `re.compile("(?!x)x")` | 6 |
| the sentence rule | delete the `_SENTENCE_END.search(said)` guard | 7 |
| `_SPAN`'s backtick bound | `_SPAN = r"(?:.\|\n)*?"` | 2 |
| `EXCUSE_WINDOW` | `len(said) <= EXCUSE_WINDOW` → `True` | 1 |
| the change id must exist | ~~`if (names in ledger_ids` → `if (True or …`~~ **that conjunct alone** | ~~8~~ **1** |
| ~~— the same bound, *loosened* rather than disabled~~ ~~widen `_CHANGE_ID`~~ | — | ~~1~~ **withdrawn** |
| the name matched case-sensitively | restore `re.IGNORECASE` on the compile | 1 |
| the rename must resolve | `if False and …` | 3 |
| *(case-insensitivity of the verbs — a widening)* | drop the `(?i:…)` | 2 |

Two rows of that table are corrected in CHG-20260901-04 (VETO). `if (True or names in ledger_ids
and len(said) …` does not disable the id bound: `and` binds tighter than `or`, so it disables the
id, `EXCUSE_WINDOW` **and** `_PARAGRAPH_BREAK` together — 1 + 1 + 6 = the 8 recorded. Replacing
only that conjunct measures **1**. And the "loosened rather than disabled" row reproduces under no
widening tried: `(?:CHG|ACC)-[\w-]+`, `[\w-]+`, `(?:CHG|ACC)-\d+-\d+`, `…\w*` and a
case-insensitive spelling all give **0**, and the three greedy ones — `(?:CHG|ACC)-.+`, `\S+`,
`.+` — give **24** on this tree, all eight measured for this correction. Never 1. It is withdrawn
rather than re-figured. That is the same criticism this record makes of the struck `11` two rows
down, committed in the table written to end it.

## The measurement that decides the structural finding

The same revert, on the same code, before and after the fixture was fixed:

| | POSIX | Windows |
|---|---|---|
| before — `Path.write_text` translates | 7 | 5 |
| after — `io.open(newline="")` | 7 | 7 |

`Path.write_text` turned the two rows written with an explicit CRLF into `\r\r\n`, which reads back
as a paragraph break — so on Windows `_PARAGRAPH_BREAK` refused them before the sentence rule was
consulted. Two rounds of corrections were arguing about a number that depended on the platform, and
neither round said so.
