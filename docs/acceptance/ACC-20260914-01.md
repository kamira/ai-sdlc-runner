## The finding the registry produced

A fourth mutation was registered first: put `len(report.resumed) < len(report.asks)` back **where
the engine assigns the fact**. It came back `NOT CAUGHT`, and the reason is the sharpest sentence in
this record:

> at that point the option ask has not been appended yet, so the report-wide pair and the
> node-scoped delta give the same answer.

**The defect is the moment, not the expression.** The same comparison is right before the
escalation dispatches and wrong after it, and both callers evaluated it after. So the repair is not
"stop using a bad expression" but "evaluate it once, where the answer is knowable, and hand it on" —
and the source-side reversion is a *move*, which a before/after string cannot stage. That is written
at the group, because `NOT CAUGHT` and "nothing tests this" look identical from outside and are not
the same fault.
