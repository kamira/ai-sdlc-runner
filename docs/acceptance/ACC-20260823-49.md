## The survey script was the defect it was looking for

The first version passed `--plan` as an **absolute** path, then asserted the recorded value was
absolute. It printed `OK` beside a description reading *"stored as typed, not resolved"* — the
description was correct and the assertion could not fail. A coarse check answering safe about the
single field it existed to examine.

Caught by reading its own output, not by anything structural. That is the fourth instance today of
this class and the third inside something written to catch the class:

1. CHG-47's `assert imported or refused` — passed on the abort it forbade
2. CHG-48 draft one — `minimal` passed by resolving to the original example still in the repo
3. CHG-48's `.gitignore` guard — `"/greet.py" not in text`, satisfied by `examples/*/greet.py`
4. this survey — an absolute input to a check for absoluteness

The pattern is stable enough to name: **when I write a check, my default input is the one that makes
it pass.** `mutation_check.py` exists for exactly this and did not help here, because the flaw was in
a throwaway script rather than in a shipped test.

## What the suite caught, for the third change running

`test_documented_numbers::test_the_test_count_the_readme_states_is_the_real_one` failed again: the
README said 1305, the suite collected 1308. Fixed the README, not the guard — CHG-47, CHG-48 and now

Three in a row is worth a sentence rather than a shrug. A count written in prose is *structurally*
destined to go stale; what makes it acceptable is that a program checks it every run. The number in
the README is not trustworthy because somebody is careful — it is trustworthy because it is tested.
That is the same argument as `mutation_check.py`, applied to documentation.

## Reservations (disclosed, not waived)

1. **The recorded plan is a path, not the plan.** If the file changes after the run, the record still
   points at it and says nothing about what it contained. A content hash would be the honest version;
   this is not that.

2. **Relative defaults are unchanged.** `--settings` defaults to `config/settings.json`,
   `--assignment-store` to `.runner/config.sqlite`, `--token-dir` to `.runner`. So `runner settings`
   typed in one directory and `runner serve` in another read different files — and `--settings`
   holds the review seat count and the high-risk bypass. Ordinary CLI behaviour, now written down in
   the CHG rather than left to be discovered.

3. **The survey covered CLI flags and config keys, not every path in the system.** Paths inside a
   plan file's `targets`, and anything an agent is handed on stdin, were not examined.

4. **Nothing reads `run.plan`.** The fix improves a field with no programmatic consumer. That is
   argued in the CHG as the reason to fix it; it is also the reason the fix cannot be shown to change
   any outcome, and the tests assert the record rather than any behaviour depending on it.
