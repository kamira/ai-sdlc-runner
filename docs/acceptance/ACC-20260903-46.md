## The reproduction

```
lead_assess    gate feasibility_confirmed, gate_when after, grades_risk True
  feasibility_confirmed:  low -> auto     medium -> confirm     high -> halt

  entry, graded low        the gate is `auto`; nothing relaxed, nothing noted — correctly
  the panel grades medium  the gate re-resolves to `confirm`
  `standard` class         relaxes it to `auto`, and no note block sat there

no class          suspended at lead_assess          a person is asked
standard class    finished                          the stop is gone
                  relaxations_by_class: no lead_assess entry
                  relaxation_authorisers: no entry
                  and therefore no export and no footer
```

A `grades_risk` node exists **for** the two grades to differ, so this was the designed path and the
case where the class matters most — the entry grade never stopped anything.

## Why the rule shipped this morning did not see it

`test_every_class_relaxation_carries_an_authoriser` (CHG-20260903-41) counts
`relaxations_by_class.append` sites against `relaxation_authorisers` writes. **It cannot see an
append that was never written.** It was right about what it checked and silent about what was
missing — which is the difference between a rule over the code that exists and a rule over the
property.

Criterion 4's replacement counts *resolutions that carry a class* against calls to the one recorder,
so a third resolution cannot be added without recording.

## Criterion 5 — the first reproduction passed over the defect


It passed on the broken code by never reaching it. A single answer is not a panel; the working shape

claim it exists to make, so a future edit that stops reaching the defect fails rather than passes.

## Reservations

1. **More is written to `relaxations_by_class`**, which reaches `--json`, the console and the
   export. Anything counting those entries sees a higher number — because more relaxations are
   being *reported*, not because more are happening.
2. **This is the second time in one day that a fix of mine missed a sibling site**, after
   CHG-20260903-44 found `approve`'s two. Both were found by a seat rather than by the suite, and in
   both cases the shipped change had written a rule that could not see the gap. A rule that
   enumerates what exists is not a rule about what must exist; that distinction is the one worth
   carrying out of this record.
