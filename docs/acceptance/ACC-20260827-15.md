## Why no behavioural test was added

The obvious response to "the behavioural test does not catch it" is to write a better one. That
would be wrong here, and the reason is worth recording rather than assumed.

The window needs a specific interleaving: a walk deciding to stop, between releasing its flag and
re-checking. A test cannot make the scheduler produce that; it can only run the code many times and
hope. A test that hopes is a test that passes for reasons unrelated to the property, which is
precisely how these two came to be cited for a window they never touched.

Reading the source for the shape that makes the window **impossible** - `_walking = False` and the
check inside one `with self._lock` - is the stronger instrument for this defect. Not in general.
For this one.
