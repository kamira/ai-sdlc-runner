## Evidence

### The shared name is the mechanism; the race only picks the loser

```
suite A builds its tree, file exists            True
suite B starts -- rmtree of the same base, its first line
suite A's file exists now                       False
```

No concurrency needed to show it, which is the honest way round: two processes are what makes it
happen, and one name is what makes it possible.

### Why not `tmp_path`

The test grows a 235- and a 252-character path and skips itself if the base is already over 120.
`tmp_path` is about sixty before anything is nested, and the file's own comment records that
thirty-nine fixtures in it use `tmp_path` and none could see this case.

```
the old fixed name   ...\Temp\aslr_deep       46 chars   shared by the machine
mkdtemp              ...\Temp\aslr_ixzkwmcm   50 chars   unique per process
the guard                                     120
```

### The sweep, and a criterion that had claimed more than it ran

ACC criterion 4 first said *"the sweep found every instance"* on the evidence of one grep. A seat
called that broader than what was run, and ran the wider one itself - other temp APIs, fixed
ports, sqlite paths, registries, journals, lock files, home and config paths - and found nothing
else that two pytest processes would collide on. So the conclusion holds and the wording did not.

```
gettempdir() in tests/, asked of the syntax tree   0 after, 1 before
callers of this _deep                              1
tests/test_paths.py's _deep                        takes tmp_path, already per-test
server tests                                       port=0, except the deliberate same-port test
src/ and tools/                                    mkdtemp and TemporaryDirectory, unique per call
```

### The rule, not the instance

The first draft added no test, on the ground that the property needed two pytest processes. It
does not: it is a rule about the source, and this repository already holds rules that way.

```
test_no_test_module_builds_a_path_from_the_machine_s_temp_directory
  today                          0 offenders
  with _deep reverted            test_attachments.py:497
--only shared-temp               1 of 1 CAUGHT
```

(One claim of mine along the way - that this `rmtree` never deleted anything - was my probe
losing a backslash to a heredoc, not the test; re-measured through a script written to disk, the
delete happens. Kept here only because it says why the evidence above is trusted.)

### A red seen in one run, attributed rather than re-run away

`test_a_connection_that_says_nothing_does_not_hold_a_thread_forever` failed once during this
record's suite runs. It is a wall-clock assertion -- eight idle connections, a 2s handler deadline
and a 3s wait -- and it passed 3 of 3 in isolation.

The obvious suspect was CHG-20260907-22, which had just made the server accept connections it used
to refuse. Measured, with the acceptor draining as it is here:

```
backlog 5    -> 8 handler threads for 8 idle connections
backlog 128  -> 8 handler threads for 8 idle connections
```

Identical, for the same reason my first probe in CHG-20260907-22 was wrong: a queue being drained
never fills, so the depth changes nothing while somebody is accepting. **Not caused by 22, and not
by this record either.** It belongs to the class a seat named while reviewing phase 0 -- wall-clock
assertions whose margins shrink under a second track -- which is queued rather than fixed here.

## What this does not do

It does not sweep `src/` or `tools/` for the same rule. Both use `mkdtemp` and
`TemporaryDirectory`, which are unique per call, and neither invents a shared name - measured, by
a seat and again here - so a rule there would have nothing to hold today. It does not touch
`tests/test_paths.py`'s same-named helper, which takes `tmp_path` and was never shared. And it
leaves the stranding named above unfixed: a killed process keeps its unique tree.

## Verdict

**Pass.** A path derived from the machine is now derived from the process, and the phase that
had to land before the queue fans out is complete.
