## The measurement that decides veto 1

`--only closure` before and after, on the same group:

```
before:  CAUGHT   the excuse stops being bounded …    1 error in 0.47s
after:   CAUGHT   the excuse stops being bounded …    1 failed, N passed
```

`1 error` is a collection error. The module did not import, so every test in it "failed" and the
harness read that as coverage. The bound the mutation names — the one round 10's veto 3 was
about — was measured by it not at all.

`N` is written as `N` on purpose. It is the number of rows in `tests/test_ledger_check.py` on the
day, it moves whenever a row is added, and three records in a row published it stale. What the
before/after turns on is `1 error` becoming `1 failed`: a collection error against a real failure
(CHG-20260901-04, conformance seat).

The general fix is `test_no_shipped_mutation_makes_its_file_unparsable`: it applies every shipped
mutation and compiles the result. This is the instrument checking itself, which is the fourth time
in eleven rounds the instrument rather than the code was the finding, and the first time a standing
guard was added for it.

## Reservations (disclosed, not waived)

1. **Written by the implementer.** Eleven rounds, every verdict `fail`. Ten of the eleven had their
   largest finding inside the previous round's fix. This round's two worst findings were both mine,
   both from a `replace(..., 1)` matching the wrong occurrence, and all four seats found them.

2. **Nothing checks that a mutation's `says` describes what its replacement does.** That is the
   class veto 2 belongs to, and the parse guard does not reach it. `if True:` and `if False:` are
   both syntactically fine and both "caught"; only a reader can tell that one of them measures the
   class the sentence names. Worth its own change.

3. **The bystander case in `_excused` is still open**, bounded by four things and pinned by all
   four: one sentence, `EXCUSE_WINDOW` = 400 characters measured on the match, no backticks crossed
   except test names, and a change id — in the href as well as the text — that names a record that
   exists. A live test named inside a run of names ending in a removal note is excused with them,
   because a list and a bystander are the same sentence to a regex.

4. **The per-occurrence scan is O(len(text)) compiled matches per name.** Measured over the real
   ledger the lint runs in well under a second, but it is a linear scan where a `finditer` was, and
   nothing pins the cost.

5. **`build_factory` still has no handler**, fourth round running. The round-11 risk seat reached
   it: editing the store while `serve` is up and posting a run gives `200` with the `ModelError` in
   the run's own state rather than a configuration refusal. `server.py:633` is the same gap from
   the library side.

6. **The command scan reads line starts and backticks only.** An instruction printed mid-sentence
   and unbackticked is invisible to it. This is a narrowing from last round, made deliberately: the
   arm that covered it was measured dead and read prose as commands.

7. **`isn't done` still reads as finished**, and `_alive`'s coupling to `_owner` is still deferred,
   six rounds running.

8. **`test_concurrent_config_edits_and_model_adds_do_not_deadlock` is load-sensitive**, seen red
   under concurrent pytest processes in five rounds now, green alone.
