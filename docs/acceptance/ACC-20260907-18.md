## Evidence

### Said in four places, required in none

```
graph.py    SINGLE = "single"   #: exactly one model, one session
graph.py    a `SINGLE` with three configured is a configuration error, not a panel
README.md   | `single` | exactly one model | 1 |
test docstring   Three models there is a configuration error, not a panel
```

```
plan.check, pm_plan      1 ACCEPTED   2 ACCEPTED   3 ACCEPTED
the engine, three models on each SINGLE node:  asked once, 0 adjudications, no complaint
```

Two of three models vanish silently — *"a setting that looks configured and does nothing"*, which
is the reason `plan.py` gives one screen above for refusing an unknown key.

### The test's docstring and its body disagreed

`test_the_mode_and_not_the_node_name_decides` opened with *"Three models there is a configuration
error"* and asserted the run **proceeds**. Four lines above it, a panel short of voices is refused
with `EngineError("short of a voice")` — the vocabulary existed and had never been pointed here.

### The rule bites only where it should

```
pm_plan        single       1 model   ACCEPTED
pm_plan        single       2 models  refused
qa_verify      single       3 models  refused
lead_review    seat_panel   3 models  ACCEPTED
engineer_build pool         3 models  ACCEPTED
```

### Blast radius

A scoped AST sweep of every `node_models=` argument in `tests/` and every `examples/**/*.json`
found **one** offending site — the test above — and nothing in `examples/`. It is rewritten rather
than removed, and reaches the engine's tolerance around `plan.check` on purpose, saying so.

### The mutations

```
CAUGHT  a single node may be given a panel's worth of models again
CAUGHT  the rule may start biting a panel or a pool again
```

The second matters as much as the first: `plan.check`'s own history records the shape rule's first
draft refusing what it should have accepted, and twenty-five tests catching it.

## What this does not do

`store.set_node_models` and the console are not touched. The rule is at the plan, which is where a
configuration is written down; a value that reaches the store another way is still read by an
engine that asks once. Whether the store should carry the same rule is a separate question about a
second surface, and this record does not answer it.

## Verdict

**Pass.** A sentence that four places stated and nothing required is now required where a
configuration is written, and the one test that had been stating it asserts it.
