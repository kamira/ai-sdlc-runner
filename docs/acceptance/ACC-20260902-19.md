## The finding this acceptance most wants on the record

**The guarantee in ① already had a test, and it was green while the guarantee was false.**

`test_a_class_cannot_undo_a_tightening_the_change_asked_for_itself` has existed since
CHG-20260827-20 and passes on `main`. It uses `self_verify` at `low` — graded `auto` — with
`autonomy=halt`. Measured:

```
relax('halt',    'standard') -> halt      <- relax cannot touch a halt whatever the code does
relax('confirm', 'standard') -> auto      <- the rung with teeth, and nothing tested it
```

It is not a vacuous test; the case it covers is real. It is a **named** guarantee exercised only at
the cell where it cannot fail. I found it by colliding with its name —
`test_no_test_module_defines_the_same_test_name_twice` refused my duplicate — which means the guard
that caught this was looking for something else entirely.

The new test is named for the distinction and says so in its own docstring, rather than being a
second test with the same name testing the half that matters.

## Reservations (disclosed, not waived)

1. **Written by the implementer**, on defects somebody else measured. Eighteen for eighteen.

2. **② is larger than what was reported to me**, and I found it while fixing ①. The seat's aside was
   about ① alone. Widening a defect fix on my own reading is the thing a seat should check: the
   matrix is measured and in the CHG, but the decision that `confirm → halt` is a tightening worth
   honouring is a judgement, not a measurement.

3. **The order in ② is read off `relax`, and `relax` is one line of policy.** If `relax` ever allows
   a second rung, this branch's order changes with it silently. It is derived rather than duplicated
   deliberately — but derived from something small enough to move.

4. **`halt` ↔ `halt_independent` is still not honoured**, and a change asking for it now gets a
   sentence saying so. That is a new sentence in a work order every model reads, on a case nothing
   in this repository exercises. It may read as noise before it reads as a report.

5. **③ is a refusal and it can break a plan that `main` accepts.** Measured that none of the three
   shipped examples uses `node_workstream` at all — but a project outside this repository that
   assigned one to `pr` was getting a grade it did not mean, and its next run stops at the door
   rather than quietly correcting itself. That is `plan.py`'s stated posture and it is still a
   behaviour change to somebody.

6. **③ does not touch `_grade_in_force`.** The engine would still honour a change-level workstream
   assignment if one reached it by another path — a `RunConfig` built directly, which the tests and
   `serve` both do. The door refuses it; the room does not.

7. **The duplicate-name collision was luck.** Had I named my test anything else, two tests for one
   guarantee would have shipped, one of them unable to fail for it, and nothing would have said so.
