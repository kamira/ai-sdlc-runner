## Reservations (disclosed, not waived)

1. **Written by the implementer**, on defects somebody else measured. Five for five this review.

2. **`before_dispatch` is now redundant on this path, and is kept.** With `feasibility_confirmed`
   firing at the raised grade, a run whose assessment raises it stops twice in consecutive nodes.
   That is the flow as designed — the lead's assessment and the PM's sign-off on it are two acts —
   but it is two stops where there was one, and an operator will feel it before they read this.

3. **Only `after` gates are re-resolved.** A `before` gate resolves before its node's work by
   definition and there is nothing new to read. If a node ever carried a `before` gate whose height
   depended on something computed in the same visit, this would not catch it.

4. **`report.resumed` will read lower than it did**, on every resume with a changed brief. Anything
   that treated the old number as a measure of work avoided was reading a wrong number; nothing in
   this repository does, but the CLI has been printing it.

5. **The four call sites are now silent about resumption**, and one of them left a variable behind
   that nothing used. Deleted here. That is the shape of a check removed from four places at once
   and it is worth a second reader.
