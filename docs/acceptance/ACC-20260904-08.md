## A seat's finding whose obvious fix was wrong

The conformance seat reported `_supersedes` reading one line as *"luck, not design"*. Re-measured,
widening it inverts the result: both real records wrap the field and the continuation line names
the **sibling**, so a multi-line read invents `-25 -> -24` and `-24 -> -25` and then demands each
say the other back. Under that mutation `test_this_repos_own_ledger_passes` goes red on the real
tree. The narrowness is pinned by a test rather than removed.

## And a sixth reader of the same family, found while writing this

Quoting `-25`'s field verbatim inside a fenced code block made the lint read **the example as this
record's own declaration**: `CHG-20260904-08: says it supersedes CHG-20260901-15`. `_supersedes`
matches `^[-*]\s*...` under `re.M` and cannot tell a fence from a field. Filed separately - the fix
touches `_status_line`, `_target_chg` and both supersession readers, and this record's subject is
the edge, not the parser.
