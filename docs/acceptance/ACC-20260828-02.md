## The finding that argues for the work rather than for care

`COLLIDING` was a list of eighteen names, and deleting it costs **nothing measurable** — the strict
rule reports zero unconfirmed symbols across `src/`. It was not buying tolerance for any real
symbol. It was only deciding which orphans were allowed to hide, and `MAX_DISPATCH_DEPTH` was caught
in CHG-20260827-22 purely because its name happened not to collide with anything.

## Two anchors had rotted, and neither author was careless

CHG-20260828-01 checked mutations for **ambiguity**. Nothing checked for **staleness** — `ANCHOR
GONE` is reported correctly, and only to whoever runs that group.

* `examples/a --seat-model command…` broke when CHG-20260827-23 added `risk` and `can_write` to the
  `_Process` call it anchored on.
* `planning/the declared interfaces never reach the run` broke when CHG-20260827-20 inserted
  `change_class=` between its two lines — **the same day the mutation was written**, by the same
  session.

Both are the same shape as CHG-20260828-01's own finding: *a later change moving the ground under an
anchor that was fine*. Both re-anchored, both re-run, both catching.

## What could not be mutated

Mutations revert a guarantee in `src/` or `tools/` and require a test to notice. Two of the three
fixes live in **test files**, where that model does not apply:

* The strict unwired rule is pinned by construction instead — the check and the fixture share
  `_unconfirmed`, so reverting the rule fails the fixture. The first draft had the fixture
  reimplement the rule inline, which would have let the rule be reverted with the fixture green.
* The table count is a **deletion of a permissive branch**. There is no separate guarantee left to
  revert; the derived assertion runs against the real page every suite run.

`--only guards` is therefore 2/2 and covers the ledger fix only. Reporting "8/8 tasks, all mutated"
would be the exact move this repository keeps catching.

## Reservations (disclosed, not waived)

1. **The guards are not now correct, only less wrong.** `test_nothing_is_unwired` still cannot see a
   symbol reached only through `getattr` or a string lookup. `ledger_check` still reads statuses as
   words from a closed list.

2. **A green ledger does not mean the records are true.** It means they are shaped correctly and
   point at each other. Nothing reads what an acceptance *says*, and this acceptance is subject to
   that limit like every other.

3. **`_count` covers zero to ten.** Past that a page writing "twelve" would be told to write "12".
   That is a worse message than it could be, and a better outcome than an unchecked claim.

4. **Verified by the implementer.** The two rotted anchors were found by a sweep written for a
   different purpose, which is again the argument for the checks rather than for the reviewer.
