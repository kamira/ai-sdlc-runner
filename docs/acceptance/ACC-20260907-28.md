## The measurement that decided it, and the one that moved the scope

**The finding's own citation was wrong, and correcting it is what produced the change.** It was
handed over as *"`GET /run`'s snapshot carries `assignable`"*. `RunState().snapshot()` has 21 keys
and `assignable` is not one of them - the key is on `GET /config/nodes`. Had the original citation
been right, `test_every_key_the_server_sends_reaches_the_console` (CHG-20260903-29) would already
have caught it five days ago - `CHG-20260903-29` is dated 2026-09-03 and this record 2026-09-08. It did not, because that rule iterates the snapshot, and
`test_every_report_field_is_rendered_or_written_down` (CHG-20260903-49) iterates `RunReport`. **No
rule of any kind watched `GET /config/nodes`.** The misleading sentence was the instance; the
unwatched route was the defect.

**And `assignable` was not alone on it.** Measured by name in `_console_code()`, four of the route's
six keys reach no console: `node_models` and `seat_models` are folded into `by_model` by the route
itself, and `source` and `assignable` are silences. `source` carries the paragraph that says *"an
override nobody can see is worse than no override"*, and the console it describes is the one this
repository ships.

## Three things the seats corrected, and one they refused to let stand

**1. The rule inventories four keys, not two.** The draft assumed `_reaches_console`'s content half
could be reused. It cannot: it walks `snapshot()`'s dict for `report.<attr>` reads, and this route's
fold happens in two loops inside `do_GET`. The seat's position was that hiding the folds behind a
hand-written content map would be the list CHG-20260903-29 exists to refuse, and that 4/6 should be
written down as the finding it is. It is.

**2. The same false claim lived in code, not only on the page.** `server.py:1268` said *"so the
console can grey out the rest"*. Fixing only `docs/API.md` would have left the claim standing where
the next reader looks first. Corrected in the same change.

**3. `source`'s inventory reason was wrong twice, and the second seat caught the second version.**
The first draft said the field reaches nothing anywhere. The first seat corrected it to the
`risk_settled` idiom - *reaches the terminal only, as a count* - on the strength of
`cli.py:1208-1212` and `cli.py:1692-1694`, which do each print one aggregate. **The second seat
refused that too, and was right**: neither line reads this response. `run` counts
`assignment_source` directly and `serve` calls `store_mod.overrides(...)` itself, so what the
terminal prints is the same *fact* computed twice from the store - not this value being consumed.
A related fact computed independently is not a consumer, and an inventory that says otherwise is
the kind of sentence this whole record exists to remove. The entry now reads *read by nothing*,
with the two independent counts named beside it and the correction kept in the line so nobody
re-derives the comfortable version.

**4. The guards prove a name occurs, and the records had to stop claiming more.** The second seat's
blocking finding: `test_..._is_drawn_or_written_down` - as the guard was first named - reads
comment-stripped page text for the identifier, so a dead `var schemaNames = ["by_model", "models"];`
would satisfy it while `drawModels` read neither property. The test is renamed
`..._is_named_by_the_console_or_written_down`, both docstrings now state the reach, and the criteria
above say *named by the console*. The same limit is true of the rule this borrows from -
`test_every_key_the_server_sends_reaches_the_console` reads names too, under a verb that claims
more - and the honest statement of both is *the page mentions it somewhere a comment cannot*. The
mutations show the current spelling can be removed and the assertions fail; they do not show the
assertions reject an inert occurrence, because they cannot.

**5. Option (1)'s stated ground is half false, and it was not allowed to pass as a reason.** The
proposal to delete the key rested on *"nothing tests the meaning of"* it. The meaning is
`store.py:428-433`, and `tests/test_store.py::test_every_refusal_reaches_the_operator_as_409`
tests that refusal by name. A record that costed the rejected options against a premise nobody
checked would be the invented citation this repository caught once this week already.

## Reservations

1. **The two console guards read text, not behaviour, and neither the tests nor the records claim
   otherwise any more.** A name occurring in comment-stripped page source satisfies them; a dead
   array of schema names would. Proving a key is *rendered* needs a harness that runs the page, and
   this repository has none - so what these hold is the boundary CHG-20260904-13 established, that
   a comment cannot stand in for the thing. The pre-existing `-29` rule holds exactly the same
   boundary under the word *reaches*. Read the criteria above as *named by the console*, because
   that is what they say. **A live instance, measured by a seat rather than hypothesised**:
   `\bmodels\b` is satisfied by `$("#models")` and by `<div id="models">` as well as by
   `assign.models`, so deleting the one line that reads the key leaves the guard green. Named here
   rather than left for somebody to discover.
2. **The corrected comment at `server.py:1271-1275` is pinned by nothing, and that is a choice.** No
   guard reads `server.py`'s comments; `_console_code()` strips comments from the *console*, which
   is a different file for a different reason. Writing a second vocabulary check over source prose
   would pin a comment's wording and nothing else. The page is the copy three surfaces are written
   against and the page is the copy pinned. If the comment drifts back, nothing says so. Both seats
   agreed this is acceptable **provided the ACC does not elsewhere claim every fix is guarded** -
   criterion 10 was reworded for that reason.
3. **Half of the page guard holds words, not meaning - and a closed *shape* as well as a closed
   vocabulary.** `_A_DENIAL` is a closed set of phrases: a writer who denies the console reader in
   words outside it turns the guard red with no defect present, and one who keeps a phrase and
   reverses the sentence around it passes with one. The docstring says that. What the docstring does
   **not** say, and a seat added: the guard only examines a paragraph that *begins*
   ``**`<key>`` — so the same false claim re-introduced in the section's opening lines, or in the
   `known: false` paragraph, is not examined at all. Both limits are the price of a rule over prose.
4. **The inventory itself is hand-written**, exactly like `NOT_ON_THE_CONSOLE`. A key nobody
   classifies fails the rule rather than passing it, which is the safe direction. A *reason* nobody
   keeps true is prose, and two of the four reasons - whether any client outside this repository
   reads `assignable`, and where the fact `source` carries does and does not go - are claims about
   the world that no test here can hold. One of those two was already corrected twice during this
   review; see finding 3.
5. **`GET /config/nodes` now costs something to extend.** A seventh key must be named on the page
   or written down. That is the same cost CHG-20260903-29 accepted for the snapshot, and it is the
   point.
6. **The provenance view is named and not built.** ACC-20260903-39 reservation 2 said the same thing
   five days ago (`ACC-20260903-39`, 2026-09-03) and its measurement was true by name and false by content - the console has
   drawn assignments through `by_model` since `02b4e29`. Re-measured and said out loud here; the
   accepted record is not edited.

## What belongs to another record

- **The sibling `POST /config/nodes` has the same drift, and this rule does not cover it.** The new
  sketch guard is scoped to the `### \`GET /config/nodes\`` section, which is the route this record
  is about. Applying it by hand one section further down: `docs/API.md:196-198` documents the POST
  answer as `{ "node_models": { … }, "seat_models": { … }, "source": { … } }` — three keys. Measured
  live through the `_Console` harness, that route answers **four**:

  ```
  POST /config/nodes  200  ['node_models', 'seat_models', 'source', 'version']
  GET  /config/nodes  200  ['assignable', 'by_model', 'models', 'node_models', 'seat_models', 'source']
  ```

  `version` comes from `server.py:1026` (`{**out, "version": runner.state.version}`) and the page's
  sketch omits it. Found by this record and not fixed by it: widening the guard to both assignment
  routes is a change with its own scope, and the record that makes it should decide whether the two
  sketches are one rule or two.
- **`known` is the same shape one level down, and the rule is top-level by design.** `by_model`'s
  per-entry `known` has its own paragraph on the page - *"`known: false` marks a model a plan names
  and the registry does not have"* - and the console never reads it: its only occurrence in
  `index.html` is the CSS rule `.mdl .u.unknown .k`, and the "not in the registry" badge is drawn
  from `meta[id]` being absent, not from `use.known`. The sketch rule reads top-level keys because
  outer indentation is what distinguishes them from nested ones; a nested accounting is a different
  rule and belongs to whoever writes it.
- **`tests/test_server.py:2274`** says the `-29` rule *"watches the 19 keys `RunState.snapshot()`
  builds"*. Measured: **21**. Both seats called it incidental to this decision and separate. Not
  touched here.
- **A provenance marker in `drawModels`.** Where it sits, how plan precedence reads, and how a node
  the plan and the store both name is drawn are design questions this record does not answer.
- **`test_a_connection_that_says_nothing_does_not_hold_a_thread_forever` is flaky under load.** It
  failed once in a six-file run, passed on an immediate re-run of the identical set, and passed in
  the full suite (**2338 passed, 4 skipped**). It asserts on `threading.active_count()` after fixed sleeps. This change's
  helper was tightened - `server_close()` and a `join` beside the `shutdown()` the file's existing
  helper does alone - so it contributes nothing to the pressure, but the test's own timing
  assumption is untouched and is somebody's record.
