## The reproduction

`class_in_force` compares `review_by < today` as text; its docstring calls that *"compared as ISO
strings, which sorts correctly"* — a precondition nothing enforced.

```
review_by                                  class in force   merge@low
  2026-12-31   a real future date            standard         auto
  2026-01-05   a real PAST date, padded      normal           confirm     <- correct
  2026-1-5     the SAME past date, unpadded  standard         auto        <- the door opens
  26-12-31 / 31/12/2026 / whenever / asap    standard         auto
  2026-13-45   sorts above today             standard         auto
```

**The same day, written the way a person ordinarily writes it, took the one-way door from *a person
is asked* to *it happens*** — on a review that fell due eight months ago.

## Why refusal rather than degradation

The branch directly above already refuses a **missing** review date, and its stated reason is
exactly this harm: *"Without one it never expires, and a class that never expires outlives the
assessment it was granted for."* A date nobody can parse never expires either — same harm, and the
code refused one case and admitted the other.

Degrading a malformed date to `normal` would have been the quieter choice and the wrong one: it
turns a typo into a silently weaker run rather than a stopped one, and the person who typed it never
finds out.

## Criterion 5 — why two readers and not one

`check_review_date` is called where the value is **compared** and where a person **types** it. Two
rather than one because a project table would reach `class_in_force` without passing the CLI at all
— which is what CHG-20260903-25 task 12 proposes, and its task 8 says the expiry contract can be
discharged by copying `class_in_force`'s expired-degrades / malformed-refuses asymmetry. Measured,
that asymmetry **had no malformed branch to copy**. It does now.

## Reservations

1. **A run that worked yesterday can be refused at startup.** Anyone whose `--change-class` carried
   `2026-1-5` was running on a class that should have lapsed in January; they will now be told and
   the run stops. That is the point, and it is a behaviour change at the command line.
2. **`emergency` is affected identically** — the class typed in the most hurry, and the one whose
   relaxation is widest.
3. **`today` is still unvalidated.** It comes from the runner rather than from a person, so it is
   not the exposure this record is about; the comparison is nonetheless only correct if both sides
   are ISO, and only one side is now checked. Stated rather than implied.
