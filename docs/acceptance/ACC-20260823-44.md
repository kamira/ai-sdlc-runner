## The reservation: the behavioural tests do not test the thing

The task table claims *"three walks for two attachments … would be two if the flag were stranded."*
The `fable` engine reintroduced the exact CHG-43-shaped window — clearing the flag in a **separate**
lock acquisition — and both behavioural tests passed. CHG-20260823-45 reported this at the time; this
round reproduced it independently.

What this leaves is a real fix guarded by a **structural** test only: one that reads the source and
asserts the context manager is `self._lock` and that the branch is where it should be. CHG-45
hardened that test from a substring check to exactly this, which is why it bites at all.

Worth stating plainly, because it cuts against the repo's own instinct: **for this defect the
structural test is the load-bearing one.** A race window narrow enough to need a scheduler
coincidence is not reliably reachable from a test; reading the code for the shape that causes it is.
The honest position is not "add a behavioural test" but "know which of your tests is actually holding
the property" — and the ledger now says so.
