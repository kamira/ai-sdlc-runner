## L-19 — the rule read half an argument list

`n.args` only, so `resolve_verdict(node, grade, cfg.autonomy, change_class=here)` was not counted
as class-carrying and the comparison below silently covered less. The `>= 2` floor fires only when
an existing **positional** call is removed.

```
a third class-carrying resolution, keyword form, recording nothing
  against the rule as it was    green — the defect
  against the rule as it is     RED
```

No behavioural test can see this — the added resolution is byte-identical in effect — so the rule
is the only guard, and it is the guard CHG-20260903-46 shipped **to replace a blind one**.

## L-18 — and the first rule I wrote for it permitted the defect

```
server.py:323   claimed the sole `Approval` mint site   was `self._refresh_attachments()`
cli.py:1228     claimed the split-programme refusal     was a docstring line
```

Both wrong at the commit that wrote them: `-44` inserted `_answering` above `approve` and `-41`
inserted `_declare_classes` above `_change_classes`, each writing its address in the same commit.
**Both point into the function that displaced them.**

My first rule required a citation to land on a line that is not blank, not a comment, not a bare
delimiter — and `server.py:323` is `self._refresh_attachments()`, **real code**. It passed on both
cases. A guard weaker than the defect it is written for is the shape this whole review has been
finding, and it took a mutation to see it here too.

The replacement is the conclusion the ledger already reached for change records, applied one layer
down: **a line number cannot be verified without a companion string, so do not write one.** `src/`
cites symbols. That rule cannot rot.

It immediately found a third citation the seat had measured as *correct* — `scenarios.py:233`,
accurate that day and rotting on the same schedule. Now `scenario_c`.

## Criterion 6 — and my first mutation was set backwards

```
a bare line number comes back into src/                       ##########  red
a third class-carrying resolution, keyword form, unrecorded   ##########  red
the same, against the rule as it was before                   ..........  green
```

The third row is evidence, not a failure: the defect, demonstrated. My first attempt reverted the
rule **and** planted the resolution, then reported *"survived"* — but that arrangement **is** the
defect, so green was the correct answer to a question asked backwards. What proves a rule fix is
planting the thing alone and watching the **fixed** rule go red. Written down because a survived
mutation was read as a gap twice today before it was read as a question about the mutation.

## Reservations

1. **The rule bans a pattern that now appears nowhere.** That is deliberate — it cannot rot — but
   it also means the rule has no live instance to guard, and its floor is the planted mutation
   rather than a fixture in the tree. If a future citation style needs a line number, the rule is
   the place to argue it rather than the thing to except.
2. **`docs/` is out of scope and stays out.** A change record states what was true at a sha it
   pins; a comment in code is read against whatever the file says today. The two have different
   contracts and one rule over both would be wrong for one of them.
