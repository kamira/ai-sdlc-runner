## Why the count was fixed by asserting it rather than by correcting it

The paragraph carried three numbers. Two were right and one was wrong, and the difference between
them is not care: **the two right ones are asserted somewhere and the wrong one was not.**
`test_the_inventory_is_fifteen_…` holds the fifteen. The field-count rule in
`test_documented_numbers.py` resolves the thirty against `engine.py`. The nineteen was held by
nothing, so it was right on the day it was typed and wrong from the next key onwards.

So the repair is the assertion. `len(server.RunState().snapshot()) == 21` now sits beside the
inventory's own size check, in the same test, and the preamble states no number at all — it points
at the assertion. The mutation proves the assertion is not vacuous: adding a key to `snapshot()`
turns it red.

## The guard that exists for this class, and why it did not fire

`tests/test_documented_numbers.py` is this repository's answer to hand-typed figures, and its
docstring opens by naming six consecutive rounds that each found one. It did not catch this one:
its `DOCS` tuple covers `README.md`, six pages under `docs/`, and five files under `src/`. It covers
**no file under `tests/`**, and not `server.py` either.

**That is a separate record, not this one.** Each of those four claims needs its own judgement —
the "17 nodes" is a past-tense measurement inside a docstring, which is the case that file's own
message tells you to enter in its exemption list *with the reason*, and the three field mentions
include one true sentence about `as_dict()`, one historical note about a seat's corrected count, and
one comment about `docs/API.md`. Deciding four of those inside a record about four other things is
how a record stops being reviewable. The measurement is written down here so the next record starts
with it instead of re-taking it.

## What this does not do

- No route changes what it answers; `src/` is untouched.
- It does not make `known` read, or delete it. `docs/API.md` now says it is built and read by
  nothing, beside `assignable`, which is the same fact about the same route and was left open by
  CHG-20260907-28. Answering it for one nested key would decide it for the other by accident.

- The assertion-message correction is **not** registered as a mutation, and the group's comment says
  why: the message is only built when the test fails, so a mutation that leaves the test green never
