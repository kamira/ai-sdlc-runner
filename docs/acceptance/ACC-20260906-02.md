# ACC-20260906-02 - the request body is read before anything decides whether it should be

- Project: ai-sdlc-runner
- Target CHG: CHG-20260906-02
- Date: 2026-09-06 (UTC+0)
- Reviewed by: **cross-review on two engines in independent sessions** - `fable` through the agent
  tool, `codex` through `codex exec --ephemeral --ignore-user-config`. Both agreed all three

## Evidence

### Before and after, same three requests

```
                                    before                     after
A  38.1 MB honest body              409 after the whole read   413 in 0.0s, unread
B  200 MB promised, nothing sent    no reply, thread held      413 in 0.0s (over the cap)
B' under the cap, nothing sent      no reply, thread held      409 at the deadline
C  Content-Length: abc              500                        409, naming the header
C' Content-Length: -1               no reply (read to EOF)     409, its own sentence
   a JSON array body                500 at body.get(...)       409, naming the shape
   bare connections                 one thread each, forever   released at the deadline
   the event stream                 —                          survives an idle longer than it
```

### The engines disagreed twice, and measurement settled both

**B's root cause.** `codex` framed it as a missing body-read deadline. `fable` measured that a
connection sending **nothing at all** holds a thread too, and that a request already refused with
401 keeps its thread while its socket is open — so bounding the body could never have fixed B.
Verified here: 20 bare connections, 20 threads; closing them released all 20. That also downgrades
the severity: it is one thread per open connection, not a leak, and `shutdown()` was measured at
0.00s.

**The status code.** `codex` argued 400 (the table reserves 409 for *understood* requests, and a
malformed header was not understood). `fable` argued 409. Settled on evidence neither cited: this
server already answers **409 for a body that is not JSON**, the same class of malformed input, and
has no 400 anywhere. Splitting an existing category to gain a distinction the page does not draw
would make the page less true.

### Three gaps the mutation run found in my own tests

```
NOT CAUGHT a connection may hold a thread for as long as it likes again
NOT CAUGHT a negative Content-Length is read to EOF again
NOT CAUGHT a body that arrives short is parsed as if it were whole
```

1. **The fixture overrode the attribute the mutation changes.** `wire` lowers `Handler.timeout` so
   its cases finish quickly, and that is the very value `timeout = None` mutates. A fixture that
   patches the thing under test can only agree with it. A separate test now asserts the deadline on
   a server nobody has patched.
2. **One fix masked another.** With the negative-length check removed, `read(-1)` reads to EOF, the
   deadline fires, and the answer is *still* a 409 — so asserting the status alone could not tell
   the two apart. Each shape now asserts its own sentence.
3. **Nothing sent a short body.** And the first attempt at that test hit the deadline instead,
   because the socket stayed open; `read(n)` only returns short at EOF. The test half-closes its
   write side, which is also the real case — a client that sent part of its body and went away.

All seven caught afterwards.

### What the deadline could have broken

`_stream` blocks on its queue rather than on the socket, so a stream idle for longer than the
deadline still delivers its next event — measured, 5 seconds idle against a 3-second deadline, 143
bytes delivered. Without that check the fix would have traded a parked thread for a console that
goes quiet.

### A fourth gap, in me rather than in the tests

The README count went in as **2226**, from adding the run's `2222 passed` to its `4 skipped` — and
forgetting that the run also had one failure, which is a collected test too. `--collect-only` says
2227. The rule this repository already carries is *derive the count, never compute it*, and I
computed it. Recorded because the guard caught it and the guard is the only reason it is not in the
README now.

## Verdict

**Pass.** The body is bounded before it is read, on every POST rather than the one route that had a
limit under it; the limit is derived from the attachment limit so the two cannot drift into refusing
legal uploads; a connection cannot hold a thread indefinitely; and three shapes that used to answer
500 or nothing at all now answer 409 with a sentence. Seven of seven mutations caught, three of them
only after the harness found that my own tests could not see them.
