## The reservation: "one transaction" was not one transaction

Fix 4 claims the schema version is set inside the same transaction as the schema. At commit
`4c9ee99` the writer was `db.executescript`, which **autocommits** — so the property claimed did not
hold, and a crash between statements could leave a half-built store.

Worse, the `IF NOT EXISTS` recovery written alongside it would then **bless** that half-built store
rather than refuse it. That was CHG-27's headline finding against this change.

Both are fixed today, by CHG-27: individual `db.execute` statements inside `with _locked(db), db:`
(`store.py:161-196`), and `_verify_or_refuse` checking column for column (`store.py:283-296`).
`grep -rn "executescript" src/` returns zero calls.
