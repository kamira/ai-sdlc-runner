## Reservations

1. **The long-path behavioural test is only a real test on Windows.** On a runner with no `MAX_PATH`
   it passes with or without the fix. That is why the AST rule exists beside it — it fails
   everywhere the moment a bare read comes back — but the pair is the answer, not either alone, and
   CI's two Windows cells are what make the first half load-bearing.
2. **The AST rule is a shape check and shape checks calcify.** It names five method names; a read
   through some sixth path (`os.stat`, `open()`) slips past it. It is narrow on purpose — the five
   are what this module actually used — but it is not a proof that no read escapes, and a later
   reader should not treat it as one.
3. **`settings.py`'s counting paragraph has now been corrected twice for the same class of error.**
   Its own docstring already recorded the first: it said *"or corrupt yields the defaults"* and
   contradicted `load()` directly below it. It then said *two* settings while `FIELDS` held three.
   The count is now asserted against `FIELDS` rather than proof-read, which is the only version of
   this fix that does not invite a third round — but the prose still describes the three fields by
   hand, and that half is still proof-reading.
