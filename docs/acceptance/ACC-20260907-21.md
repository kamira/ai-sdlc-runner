## Evidence

### The right rule for the wrong reason

```
permitted (bind spellings)   ['127.0.0.1', 'localhost']
accepted  (normalised)       ['127.0.0.1', 'localhost']
accepted - permitted         []
```

Green - and `localhost` satisfies it by being a bind spelling, not because RFC 6761 6.3 fixes
what the name means. The two coincide today, so the containment held for the right reason and a
wrong one.

### The three futures that separate the shapes

```
state                             containment   equality over authority forms
today                             passes        passes
localhost leaves LOOPBACK only    passes        passes
localhost leaves BOTH             passes        FAILS
a name is smuggled into HOSTS     FAILS         FAILS
```

Row three is a person typing `localhost:8765` and being refused. A subtraction can say
*tolerated*; only an equality says *required*.

### The circular vote, named

ACC-20260907-20's second measurement used **this test's failure** under `LOOPBACK =
("127.0.0.1",)` as a reason to keep `localhost` in the bind list. The test objected because of
the justification this record replaces. After this change nothing in `tests/test_server.py`
objects to that narrowing, which is correct and re-opens the question on its merits. This record
does not take it.

### What both seats refused, and the measurement that decided it

I proposed the exemption plus a resolution check. Both refused; the sharper reason:

```
getaddrinfo(name, AF_INET)
  localhost               ['127.0.0.1']
  localhost.localdomain   ['127.0.0.1']   <- this resolver, not RFC 6761
  foo.localhost           gaierror        <- RFC 6761 covers it; this OS does not
```

*"Resolves to loopback"* is the rebinding attacker's precondition. ACC-20260907-20 already
recorded both seats refusing that relation; my check would have made it a **necessary condition**
on the exemption, and would have licensed `localhost.localdomain` - the drift it existed to
prevent. What makes the exemption honest is its position in an equality, not a check beside it.

### The mutations

```
resolver-fixed  CAUGHT  the header set may lose a name a standard fixes again
                CAUGHT  an authority form nothing derives may be accepted again
loopback        CAUGHT  x4, after entry 3 was re-anchored
```

The second `resolver-fixed` entry is a bracketed IPv4 literal, which the old containment accepted
because it stripped the brackets and found `127.0.0.1` permitted.

One entry was written, run **CAUGHT**, and then **withdrawn as fake**: it claimed to remove
`localhost` from both constants and in fact applied one edit with a comment appended. The harness
takes one replacement per entry and the constants are separate statements, so that state is
unreachable by any anchor. Registering it would have been a mutation whose `says` describes
something it does not do - which is the defect class this whole series has been removing. It is
measured in the table above instead.

### The re-anchor

`loopback` entry 3 went `NOT CAUGHT` under the new assertion. That is the record working: its
guarantee *was* the wrong justification. Re-anchored to `LOOPBACK = ("localhost",)` and restated
with the word it was missing - the bind list may lose an **address** the header check still
accepts; a name a standard fixes may stay.

## What this does not do

It changes no `src/` line, does not derive `LOOPBACK_HOSTS`, and does not decide whether
`localhost` stays in `LOOPBACK`. The equality does settle one thing neither earlier record did,
visible only if IPv6 returns - the bracketed form of an IPv6 bind address is required and the
bare form forbidden - and the derivation record is told it must pick the same side.

## Verdict

**Pass.** A test that asserted the correct thing for a reason that had already been load-bearing
in a merged decision now states the relation it means, with the one exempt name required rather
than tolerated and the request it protects sent for real.
