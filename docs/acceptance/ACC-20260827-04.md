## The defect this found

`_gate` finishes its own report - it has `cfg.conversation` and the call site in `walk` does not -
and `walk` then ran the same report through `_finish` a second time. `report.confirmations` is a
list and `_finish` extends it, so one over-confirmed gate produced **two identical complaints**:

```
['merge was confirmed 2 more time(s) than the run stopped at it',
 'merge was confirmed 2 more time(s) than the run stopped at it']
```

The count inside each sentence was right both times, which is why nothing looked wrong unless you
read the report rather than checked it. Both `_gate` call sites in `walk` now return the finished
report as-is.

Traced by spying on `_finish` and printing the call stack: two calls, `engine.py:1330` inside
`_gate` and `engine.py:1532` in `walk`. Not a reading exercise - the exit had simply never been
driven, which is the same sentence as the finding that opened this change.
