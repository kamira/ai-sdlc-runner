## Evidence

### Four rules measured, none of them sufficient

| candidate | shipped | `qa_accept -> pr` | verdict |
|---|---|---|---|
| the target reaches this node again | 8/8 | **passes** | vacuous — the flow is one cycle |
| this node is on every path to `merge` | **7/8** | refused | refuses `lead_task_review -> fix_pass`, which ships |
| the target is not downstream | 8/8 | **passes** | the same cycle |
| answerable without passing `merge` | 8/8 | refused | defeated below |

I settled on the fourth. `codex` broke it with `qa_accept.rejects_to = "qa_verify"`, which returns
to `qa_accept` without touching `merge` — and skips the whole-change gate:

```
gates on the normal return  acceptance_failed -> qa_accept :  lead_review, qa_verify
gates on the bypass         qa_verify         -> qa_accept :  qa_verify
```

Its conclusion, which I accept: *"a generic validator cannot infer that policy solely from graph
connectivity. Pinning the exceptional routes remains necessary."*

**Which gates a refusal must pass is policy.** The weak rule ships anyway — it refuses a refusal
that ends the run, which nothing else did — with the table above beside it in the source, so the
next reader asking "why not stricter" gets measurements instead of silence.

### The mutation reported my own repair twice

```
ANCHOR GONE  an acceptance refusal routes around the whole-change bound
NOT CAUGHT   the bound goes back to a hand-written pair of node names
```

The first was a fragment anchor: `rejects_to="acceptance_failed"` sits mid-line among other fields.

The second is the one worth the record. **A derivation reverted to the literal it equals cannot be
detected** — both produce the same tuple. Worse, I had written it as a module-level constant, which
is precisely `engine._MODULE_CYCLE`'s shape: an import-time snapshot that the same round's defect
seat measured disagreeing with `plan.py`, which asks per call. *The change removing one hand-written
copy had introduced the pattern this round reports elsewhere.*

It is a function now, and the test adds a **third** node routing into `change_retry` and asserts
the bound sees it. Under the written pair it does not — which is what makes the mutation CAUGHT.

### Two older mutations went stale, and were re-anchored rather than assumed

`test_no_shipped_mutation_has_a_stale_anchor` failed on two `bounds` entries naming
`_WHOLE_CHANGE_REJECTED`. Their guarantees are unchanged, so both were re-pointed at the lines that
now carry them, and the group re-run: **6 of 6 CAUGHT**. Re-anchoring is not evidence on its own;
running them again is.

### What was checked for reversion

`CHG-20260828-22` deliberately leaves `qa_verify.rejects_to = "next_module"` outside the bound.
Deriving from `node.next == "change_retry"` preserves that without an exception clause, because
`next_module.next` is not `change_retry`. Pinning `qa_accept.rejects_to = "acceptance_failed"`
preserves its shared-bound guarantee. Neither part refuses a shipped edge.

## Verdict

**Pass.** A refusal can no longer be routed to a place the run never returns from, the eight edges
that carry the policy are written where a change to them is a decision, and the bound reads the
graph instead of a copy of it.
