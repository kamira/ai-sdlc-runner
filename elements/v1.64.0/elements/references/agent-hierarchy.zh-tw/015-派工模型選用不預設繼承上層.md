## 派工模型選用(不預設繼承上層)

**派工的模型不預設繼承 Master/上層——由派發者依角色需求選定。** 沿用上層模型是一個決定,不是預設值;把它當預設,會讓「施工與審查同模型」在無人察覺下常態發生,而那正是 `independent-acceptance` 警告的失效模式(同模型共享同一組訓練偏誤與盲點,某些錯會系統性地一起看不到)。

選用依據三軸:

| 軸 | 問什麼 | 傾向 |
|----|--------|------|
| **判斷密度** | 這個角色要下多少判斷?機械照做還是要權衡取捨? | 判斷密集(分析、審查、裁決)→ 強模型;機械性(套模板、格式轉換、清單彙整)→ 小模型即可 |
| **獨立性需求** | 這個角色是否要挑出另一個角色的錯? | 審查/驗收/審議角色**盡量異於被審者的模型**;越高風險越該異 |
| **成本** | 這個角色會被呼叫幾次? | 逐 task 反覆呼叫的角色,用最強模型的代價會被次數放大 |

規則:

- **審查角色盡量異於施工者**(cross-model);高風險變更尤其如此。
- **各角色實際使用的 model 要留痕**:worklog 記錄派工時的 model;驗收面沿用 ACC 既有的「實作模型 / 驗收模型」欄。沒留痕就無法事後判斷該輪審查的獨立性。
- **單模型平台**:退而用「乾淨 context + 不同角色/system 設定」降低相關性,並**明確註明此限制**——不可靜默當成已跨模型。
- 平台中立:本節不綁定任何廠商或模型名稱;「強/小」是相對於該平台當下可用的選項。

> 與既有規則的關係:`independent-acceptance`(驗收者跨模型)、`review-panel`(席位跨模型)、`acceptance-verification`(ACC 記兩個 model)**要求不變**——本節是把同一原則從「驗收/審議」推廣到**一般派工**,並補上先前未言明的預設值。
