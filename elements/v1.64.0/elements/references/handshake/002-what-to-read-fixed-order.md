## What to read (fixed order)

0. **Toolchain probe** (before reading any document): `bash skills/ai-sdlc-autopilot/scripts/toolchain_probe.sh` (or the target project's equivalent carrier). Three states, and **the default is not "pass"** — only `PASS` proceeds; `BLOCKED` (it worked out what is missing) and `NOT_RUN` (it could not even determine) both **stop and provision first**, and both go into the ack. Two things to keep straight: (1) **This is not fault diagnosis.** In an environment where the machine image is rebuilt every session, the interpreter and its dependencies are **guaranteed absent every round**; treating that as a fault to investigate produces one manual install and one hand-written note per session (measured: three consecutive sessions did exactly that, and the reason was simply "the machine is new"). Probe and provision — do not diagnose. (2) **The probe must not require the thing it probes for.** A Python script that checks whether Python exists cannot start when Python is missing, so "no output" and "everything is fine" look identical to the caller (KN-003) — hence a shell carrier. And **never pipe a gate's result through `| tail`**: the exit code gets replaced by the last stage of the pipeline.
1. **Current branch, working tree & remote baseline**: confirm which branch you're on (see branch-isolation) and run `git status` — note any uncommitted changes for step 5's reconciliation; afterwards only reference that branch's requirements/acceptance. **Then check the remote baseline** — `git status` only sees your machine, and **a clean working tree does not mean an up-to-date baseline**: `python3 scripts/doc_integrity_check.py --repo . --check-baseline` (equivalent to `git fetch && git log --oneline HEAD..@{u}`). **If you are behind, align before starting work**; the cost of building on a stale tree has been measured, and all three forms actually happened: **id collision** (the same CHG number used on both sides), **wasted work** (upstream already fixed it, and better — the whole commit gets skipped on rebase), and **stale numbers in the docs** (file/spec counts that no longer match upstream). No git, no upstream, or a failed fetch all **degrade** (the check exits 0 and says plainly that this is not "behind") — a degraded run belongs in the ack, not silently skipped. **Switching branches mid-session counts as a new entry: redo this handshake.** **No git?** Commit anchoring, the commit scan and `--commits-since` don't apply — state the degraded mode in your ack; CHG step ticks + the worklog become the only interruption markers, reconciliation is manual (files vs CHG steps). Recommend `git init` before anything else.
2. **`docs/ai-guideline.md`**: the current Guideline — goals, scope, current **version**, open items. **Skill version self-check**: compare the `Skill:` version in recent CHG/ACC against your running skill version — records newer than your skill mean **you are outdated: upgrade before working** (an old skill silently misses newer rules); records older than your skill are fine (new rules apply prospectively, see doc-integrity).
3. **`docs/knowledge/` — via its INDEX, not the whole file**: read the index, then load only **global entries + entries whose tags intersect your current scope** (directives, deep/shallow pattern records, known errors — see knowledge). Deep records you'll be applying belong in your ack. **Missing in a governed repo? Bootstrap it now**: if `docs/changes/` exists but `docs/knowledge/` doesn't (a repo governed before the founded-at-start rule), create the skeleton (zero-entry INDEX + seed `vocabulary.json`) as part of this handshake and note it in your ack — reading tolerates absence, but the recording mechanism can't fire into a directory that was never created (see knowledge; the doc-integrity lint enforces it).
4. **`docs/coordination.md`**: org/claims — your role, locked scope, read/write permission, others' in-progress work.
5. **`docs/changes/` + `docs/acceptance/`**: any unclosed stage (CHG not accepted / missing ACC); close first, then start new. **Reconcile the working tree**: every uncommitted change noted in step 1 must map to some CHG's modification steps (or a worklog entry); an unmatched change means an interrupted or ungoverned edit — treat it as drift (see doc-integrity) and resolve it before new work. **Scan commit history too**: from the last governed anchor (the newest ACC's Commit field, or the last commit referencing a CHG) to HEAD, every commit message should reference a CHG id (see modification-guide "commit granularity"); a commit referencing none is ungoverned work — same drift handling (in squash-merge workflows the trunk is scanned at squash-commit granularity — see modification-guide "PR / squash / rebase"). Machine aid: `scripts/doc_integrity_check.py --commits-since <anchor>`.
6. **`docs/structure/`**: current structure, check for drift vs code (see doc-integrity).
