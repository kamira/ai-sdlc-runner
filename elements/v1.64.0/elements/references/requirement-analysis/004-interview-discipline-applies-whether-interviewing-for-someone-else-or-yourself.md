### Interview discipline (applies whether interviewing for someone else or yourself)

1. **Walk the decision tree, one question at a time.** Resolve dependencies in order: later decisions usually hinge on earlier answers, and asking several at once puts interdependent decisions to the user simultaneously — bewildering and hard to answer. Ask one, wait for the answer, then ask the next.
2. **Give your recommended answer with each question.** Don't just pose the question — state the option you'd pick and why. This lowers the user's effort and exposes the agent's default position so it can be overruled.
3. **Look up facts; ask only about decisions.** Anything discoverable from the environment (files, config, versions, existing conventions, git state) is a **fact** — go find it rather than asking. Only **decisions** are the user's; put each one to them and wait. (Same principle as the entry handshake's "reconcile the facts first".)
4. **Stopping condition = the user confirms shared understanding.** Don't start building before that; what's confirmed is "we agree on what we're doing", not "you've finished asking".
