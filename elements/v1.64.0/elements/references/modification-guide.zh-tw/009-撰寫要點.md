## 撰寫要點

- **結構與記錄必須跟上程式**:本 skill 最大的價值是讓文件不落後。改了結構卻沒更新 `docs/structure/`,等於沒做完。
- **記錄「為什麼」,不只是「改了什麼」**:決策與取捨是未來最值錢的資訊。程式能看出改了什麼,看不出為何這樣選。
- **影響分析要往外看一層**:不只改動點本身,還要看相依它的東西會不會壞。
- **保持可追溯**:變更記錄連回需求編號與驗收報告,形成完整鏈路。
- **使用者故事寫使用者看得見的行為**:一條一個能力,格式「作為<角色>,我要<功能>,以便<效益>」;涵蓋各面向而非只寫快樂路徑。**故事是驗收條件的第一順位來源**——驗收時逐條勾稽,不從修改步驟反推。故事寫的是**行為**,不是實作(檔案路徑、函式名屬「決策與取捨」與「修改指引」)。中/高風險記錄要求(Skill ≥ v1.19,前瞻適用——既有記錄豁免);CHG-lite 不強制。
