### 提問紀律(代問與自問皆適用)

1. **走決策樹,一次一題。** 依相依順序逐一解決:後面的決策常取決於前面的答案,一次丟多題會讓相依決策被同時發問,使用者難以作答。問完一題等回覆再問下一題。
2. **每題附上你的建議答案。** 不是只丟問題——給出你推薦的選項與理由。這降低使用者負擔,也把 agent 的預設立場攤開來讓人否決。
3. **事實自查,決策才問。** 凡是能由環境查得的**事實**(檔案、設定、版本、既有慣例、git 狀態),自己去查,不要問使用者;只有**決策**是使用者的——逐一提出並等他回答。(與進場握手「先對帳事實」同源。)
4. **停止條件=使用者確認共識。** 未確認前不要動工;確認的是「我們對要做什麼有共同理解」,不是「你問完了」。
