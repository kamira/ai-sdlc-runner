## 工作流程

1. 讀 Guideline,列出要被結構回應的需求(尤其 P0 與非功能需求)。
2. 由抽象到具體依序產出:邏輯 → 設計 → 資料 → 目錄(順序可依專案調整,但四份都要有)。
3. 確認四份彼此一致:邏輯的模組要能對到目錄的資料夾、設計的元件、資料的實體。
4. 在每份文件標註它回應了哪些需求編號(可追溯到 Guideline 的 FR/NFR)。
5. **附圖交回使用者檢視修正,確認後才進實作**。四份結構文件裡最該被人看過一遍的就是圖——它是唯一能讓人一眼看出「你把這個模組接錯邊了」的東西,而那正是這個階段最便宜、事後最貴的錯誤。呈給使用者、依指正改圖、改到他確認為止;**在他確認之前不要往下做**。使用者可以決定不看(在 Guideline 的「AI 開發約定」註明),但**預設是畫給他看**——沒說要跳過就是要畫。
